# 第四批开发：测试样例库与 MVP 验收标准

## 目标

第四批不加新功能，而是让前三批功能可信、可演示、可封版。

MVP 封版目标：

> 拖入一个 Delphi/VCL 项目文件夹，DeepSpec 能扫描目录、识别文档/代码/UI/配置文件，解析基础 `.dfm`，生成 UI 层次树、模块树、候选功能树，并在主窗体和两个悬浮窗中清晰呈现。

## 样例项目库

### Sample01_MinimalVCL

测试基础链路。包含一个主窗体、一个按钮、一个菜单、一个状态栏。

验收：能识别 Delphi 项目、1 个 DFM、UI 树、模块树、按钮 Caption 候选功能。

### Sample02_MultiForms

测试多窗体与模块树。包含 Forms、Core、Render 等目录。

验收：UI 树按 Form 分组；模块树按目录分组。

### Sample03_ComplexUI

测试复杂 DFM 层级。包含 Panel、Splitter、PageControl、TabSheet、TreeView、ListView、ActionList、MainMenu、ToolBar、StatusBar、TEdgeBrowser。

验收：正确处理 object/end 栈，识别 PageControl/TabSheet 层级、按钮、菜单、Action。

### Sample04_DocsRich

测试文档分类和候选功能提取。包含 README、需求说明、CHANGELOG、TODO、AGENTS.md、CLAUDE.md、config.yaml。

### Sample05_BrokenProject

测试容错。包含缺少 dproj、只有 pas 没有 dfm、损坏 dfm、binary dfm、乱码文件、超大文件、未知扩展名。

验收：不能崩溃，能记录问题并显示在问题 Tab 和日志里。

## 验收清单

### 打开与扫描

可以拖入文件夹、打开文件夹、记录最近项目、重新扫描、忽略 `.git/bin/obj/__history/node_modules`，并生成扫描日志。

### 文件分类

识别文档、代码、UI、配置、AI 规则、资源、未知文件；Delphi/VCL 必须识别 `.dpr / .dproj / .pas / .dfm / .res / .ini`。

### 扫描报告

必须生成多个小 HTML，不生成巨型单页。至少生成 index、scan-report、documents、code-files、ui-files、config-files、ai-rules、ai-reference、node-detail。

### UI 层次树

能解析 text DFM，识别 Form、控件层级、控件名、控件类型、Caption、Action，并在结构树窗显示。Binary DFM 可不支持，但必须记录问题。

### 模块树

能按目录生成模块树，显示 `.pas` 文件，识别 FormUnit、DataModule、Frame、普通 Unit，显示来源路径。

### 候选功能树

能从 Button/Menu/Action Caption 及 README/TODO 标题提取候选功能，显示来源、可信度，并合并同名功能。

### 基准确认

可确认单个节点、整棵树、三棵树，并保存 baseline yaml。

### AI 参考摘要

生成 `ai-reference.md` 和 `ai-reference.html`，包含项目类型、模块树摘要、UI 层次摘要、候选功能摘要、重要约束。

## 界面验收

主窗体必须包含工具栏、可折叠顶部摘要区、WebView2 主浏览区、可折叠底部信息区。

左悬浮结构窗必须包含模块树、UI 层次树、候选功能树，使用 VCL 原生树控件。

右悬浮探查窗必须显示当前节点名称、类型、来源文件、状态、可信度、关联信息、备注。

## 最小 Demo 场景

打开 DeepSpec → 拖入 Sample02_MultiForms → 显示扫描报告 → 查看 UI 层次树 → 点击 BtnOpenFolder → 探查窗显示控件信息 → 查看模块树 → 查看候选功能树 → 确认三棵树为基准 → 生成 AI 参考摘要 → 复制节点给外部 AI。

## 封版标准

> 拖入一个标准 Delphi/VCL 样例项目后，DeepSpec 能稳定生成扫描报告、模块树、UI 层次树、候选功能树，并支持基准确认和 AI 参考摘要导出。

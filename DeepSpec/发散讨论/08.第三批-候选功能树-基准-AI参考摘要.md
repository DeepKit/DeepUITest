# 第三批开发：候选功能树 + 基准确认 + AI 参考摘要

## 目标

让 DeepSpec 从“读出了项目结构”升级为“能推断候选功能，并把三棵树变成后续 AI/人工开发可使用的基准”。

第三批完成：

1. 生成候选功能树；
2. 建立功能 / 模块 / UI 的简单关联；
3. 支持确认基准；
4. 支持复制节点给 AI；
5. 生成 AI 参考摘要。

## 为什么叫候选功能树

模块树来自目录和单元，UI 树来自 DFM，较客观；功能树来自 Caption、Action、Menu、文档标题和事件名，属于推断结果，必须叫“候选功能树”。

## 来源

- UI 控件 Caption；
- Action Caption；
- Menu Item Caption；
- 事件处理器名称；
- README / Markdown 标题；
- TODO / CHANGELOG。

## 候选功能节点字段

```pascal
TFunctionNode = class(TDeepSpecNode)
public
  FunctionName: string;
  FunctionKind: string;
  Priority: string;
  SourceKind: string;
  SourceText: string;
  Confidence: Double;
  RelatedUINodes: TArray<string>;
  RelatedModules: TArray<string>;
  RelatedFiles: TArray<string>;
end;
```

## 功能归类规则

- 打开 / 新建 / 保存 / 导入 / 导出 → 文件与项目；
- 扫描 / 解析 / 识别 / 分类 → 项目分析；
- 树 / 节点 / 基准 / 确认 → 结构树；
- 报告 / HTML / 摘要 → 报告与导出；
- 设置 / 配置 / 选项 → 设置；
- 日志 / 问题 / 错误 → 状态与日志。

## 去重规则

同名、去快捷键符号后同名、Action/Button/Menu 指向同一事件时合并为一个功能节点，并记录多个来源。

## 可信度评分

| 来源 | 可信度 |
|---|---:|
| Action Caption | 0.95 |
| Menu Caption | 0.92 |
| Button Caption | 0.90 |
| ToolButton Caption/Hint | 0.85 |
| Event Handler | 0.70 |
| README 标题 | 0.65 |
| TODO | 0.45 |
| CHANGELOG | 0.50 |
| 方法名推断 | 0.40 |

多个来源指向同一功能时提高可信度。

## 三棵树关联

最小关联：

```text
功能 → UI
UI → 功能
功能 → 模块
模块 → UI
```

## 基准确认

支持：

```text
candidate → confirmed
```

可确认单个节点、整棵树、三棵树。生成：

```text
baselines/
  function-tree.baseline.yaml
  module-tree.baseline.yaml
  ui-tree.baseline.yaml
```

## 复制节点给 AI

结构树节点右键“复制给 AI”，生成该节点的名称、类型、来源、关联功能、关联模块、约束说明。

## AI 参考摘要

生成：

```text
.deepspec/html/ai-reference.html
.deepspec/ai-reference.md
```

内容包括项目类型、模块树摘要、UI 层次摘要、候选功能摘要、重要开发约束、给外部 AI 的建议。

## 第三批不要做

不自动调用 AI，不自动改代码，不做完整 Git Diff，不做自动 UI 截图对比，不做复杂语义理解或调用链分析。

## 结论

第三批只做：

> 候选功能、简单关联、确认基准、给 AI 看的参考材料。

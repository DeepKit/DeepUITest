# DeepSpec 深范｜主窗体与 Spec Inspector 设计

## 1. 总原则

主窗体要瘦，悬浮面板要强。

主窗体只做：

- 导航；
- 审阅；
- 基础命令；
- 状态显示。

属性、问题、决定不得挤在主窗体里。

---

---

## 3. 主窗体不放什么

主窗体不放：

- 属性列表；
- 问题列表；
- 决定列表；
- AI 聊天框；
- 大型日志窗口；
- 复杂编辑器。

这些都进入悬浮窗口或独立页面。

---

## 4. Spec Inspector 定位

Spec Inspector 是当前文档的规范检查器。

它回答三个问题：

| 页签 | 回答 |
|---|---|
| 属性 | 它是谁？在哪里？和谁有关？ |
| 问题 | 它缺什么？为什么不能冻结？ |
| 决定 | 为什么这样定？谁确认过？ |

---

## 6. 两种模式

### 6.1 跟随模式

主窗体当前选择什么文档，Spec Inspector 就显示什么文档。

### 6.2 锁定模式

Spec Inspector 固定显示某个文档，即使主窗体切换到其他文档，也不改变。

用途：

- 对照功能树和技术方案；
- 对照问题和 HTML 页面；
- 阅读一个文档时检查另一个文档的决定。

## 10. 与 WebView2 联动

HTML 页面只发送意图，不直接改文件。

例如：

```json
{
  "cmd": "open_inspector",
  "tab": "issues",
  "spec_id": "03.feature-tree"
}
```

Delphi 接收后：

```text
WebViewBridge
→ CommandDispatcher
→ SpecInspector.Show
→ 切换到问题页
```

## 12. EventBus

窗体之间不要互相乱调。

使用事件总线：

```text
CurrentSpecChanged
SpecValidated
SpecRendered
SpecStatusChanged
DecisionAdded
IssueChanged
TraceScanned
ReviewPackBuilt
```

主窗体发布当前文档变化。  
Spec Inspector、Trace Panel、状态栏订阅变化。

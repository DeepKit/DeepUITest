# DeepSpec 深范：产品定位与三阶段路线

## 一、当前总定位

DeepSpec / 深范 是一个面向 AI 编程时代的软件开发结构基准系统。

它不从第一版开始做 AI 开发器，而是先从项目目录读取、结构树生成、开发文档呈现做起。

---

## 二、三阶段路线

### 阶段一：MVP

# **项目开发文档与结构树读取呈现系统**

用户把已有项目文件夹拖入 DeepSpec，DeepSpec 读取项目中的文档、代码、UI、配置、AI 规则文件，生成：

- 项目扫描报告；
- 软件模块树；
- UI 层次树；
- 候选功能树；
- AI 参考摘要。

这一阶段不接管开发，不调用 CLI，不治理 AI Agent。

---

### 阶段二：中期

# **AI Agent 开发旁路治理系统**

中期才做：

- Context Pack；
- Review Pack；
- Git Diff / 文件变化扫描；
- 规格漂移检测；
- AI 错误记录；
- 规则回流；
- Handoff 交接卡；
- 与 Codex / Claude Code / OpenCode / Cursor 等外部工具协同。

这一阶段仍然不直接接管主线开发。

---

### 阶段三：未来

# **规格驱动 CLI 开发工作台**

未来才进入：

- 调用 Codex CLI；
- 调用 Claude Code；
- 调用 OpenCode；
- 调用 Git；
- 调用编译器；
- 调用测试工具；
- 调用 DeepUITest；
- 执行开发任务；
- 监控结果；
- 生成 Review Pack；
- 支持确认、回滚、继续下一轮。

---

## 三、阶段顺序

DeepSpec 的成长顺序是：

```text
读取已有项目
  ↓
形成结构基准
  ↓
辅助 AI / 人工开发对齐
  ↓
旁路治理 AI 开发
  ↓
未来调度 CLI 完成开发任务
```

不是：

```text
先做 AI Agent
  ↓
再补文档
```

也不是：

```text
先做问答生成需求
  ↓
再分析项目
```

---

## 四、当前必须坚持的边界

MVP 第一版的根本任务是：

> **从项目文件夹中读出结构，而不是从用户问答中生成结构。**

用户如何与 AI 沟通、如何写需求、如何开发代码，不是 DeepSpec 第一版要管的事情。

DeepSpec 第一版只负责：

> **读取、分析、呈现、确认基准。**

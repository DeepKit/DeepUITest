# DeepSpec 深范｜Context Pack 与 Review Pack 规范

## 1. 基本定位

DeepSpec 不接管外部 AI 主线。  
因此它需要两个旁路包：

| 包 | 时机 | 作用 |
|---|---|---|
| Context Pack | 开发前 | 给 Codex / Claude Code / IDE AI 的上下文 |
| Review Pack | 开发后 | 给人类和 DeepSpec 的规范审查包 |

---

## 2. Context Pack

### 2.1 定义

Context Pack 是 DeepSpec 生成的、可复制到外部 AI 工具中的任务上下文包。

它回答：

```text
这次要做什么？
必须遵守什么？
哪些已经决定？
哪些不能推翻？
哪些文件相关？
完成后必须输出什么？
```

---

## 3. Context Pack 信息来源

1. 当前用户任务；
2. 当前 Spec；
3. 关联上游 Spec；
4. 关联下游 Spec；
5. 项目宪法；
6. 已确认决定；
7. 当前问题；
8. 禁止事项；
9. 验收标准；
10. 代码/文件范围。

## 3. 必须遵守的项目原则

- YAML 是事实源，HTML 是审阅层。
- 主窗体保持干净。
- 属性、问题、决定进入 Spec Inspector。
- AI 不能直接冻结文档。
- 所有操作走 CommandDispatcher。
- UI 刷新走 EventBus。

## 6. Review Pack

### 6.1 定义

Review Pack 是外部 AI / IDE / CLI 完成开发后，由 DeepSpec 根据工程事实生成的审查包。

它回答：

```text
实际改了什么？
影响了哪些规格？
有没有规格漂移？
哪些文档要更新？
哪些决定要确认？
哪些测试要补？
能不能进入下一阶段？
```

---

## 7. Review Pack 信息来源

1. Git status；
2. Git diff；
3. Git diff --stat；
4. 修改文件列表；
5. 新增文件列表；
6. 删除文件列表；
7. 测试输出；
8. 编译输出；
9. 用户粘贴的 AI 摘要；
10. DeepSpec 当前九类规格；
11. 当前决定记录；
12. 变更日志。

## 10. Context Pack 与 Review Pack 的关系

```text
开发前：Context Pack
    ↓
外部 AI / IDE / CLI 开发
    ↓
开发后：Review Pack
    ↓
人类确认
    ↓
Handoff Pack
    ↓
下一轮 Context Pack
```

---

## 11. Handoff Pack

Handoff Pack 是每轮开发结束后的交接卡。

它包含：

- 当前项目状态；
- 已完成事项；
- 未完成事项；
- 已确认决定；
- 禁止推翻事项；
- 当前问题；
- 下一步建议；
- 下一轮 AI 应读文件；
- 下一轮 Context Pack 初稿。

保存位置：

```text
packs/handoff/handoff-YYYYMMDD-HHMMSS.md
packs/handoff/handoff-latest.md
```

# DeepSpec 用户痛点、痒点与竞争超越点

## 一、用户核心痛点

### 1. AI 做出来不是我想要的

尤其是 UI：

```text
界面布局不对
按钮位置不对
区域层级不对
信息密度不对
风格不像专业软件
```

### 2. 功能说过很多次，但没有形成树

功能散落在：

- AI 对话；
- README；
- TODO；
- Markdown；
- 按钮 Caption；
- 临时笔记。

### 3. 模块没分清，代码容易乱

AI 容易把功能写进错误模块，甚至把大量逻辑写进窗体。

### 4. 旧项目没人敢改

尤其 Delphi/VCL 老项目：

- 窗体多；
- 控件多；
- 事件多；
- 代码混；
- 文档缺失；
- 交接困难。

### 5. 开发后无法对照原始想法

用户不知道：

- 原来想做什么；
- 后来为什么改；
- 哪些决定已经确认；
- 当前结构是否偏离原设计。

---

## 二、用户痒点

### 1. 拖入项目马上看到结构

> “我只拖了一个文件夹，它就读出项目结构了。”

### 2. 一眼看到 UI 层次树

> “原来我的窗体和控件是这样组织的。”

### 3. 一眼看到模块树

> “原来我的代码模块是这样分布的。”

### 4. 候选功能树自动出现

> “系统从按钮、菜单和文档里帮我提取出了功能。”

### 5. 可以确认三棵树为基准

> “以后 AI 修改不能偏离这个基准。”

### 6. 可以生成 AI 参考摘要

> “我可以把这个摘要交给 Codex / Claude Code / Cursor。”

---

## 三、需求点

DeepSpec MVP 应满足：

```text
读取已有项目
扫描文档与代码
识别 UI 文件
生成 UI 层次树
生成模块树
生成候选功能树
可视化呈现
确认基准
导出 AI 参考摘要
```

---

## 四、竞争环境

现有工具多集中在：

- AI 写代码；
- AI 对话；
- Agent 执行；
- 规则文件；
- Spec 驱动流程；
- IDE 插件。

它们不一定专注于：

```text
从已有项目目录中读取结构
把 UI / 模块 / 功能整理成三棵树
将其作为 AI 修改和项目交接的基准
```

---

## 五、DeepSpec 超越点

DeepSpec 不和 AI Agent 竞争。

它的超越点是：

# **开发结构基准层**

包括：

- 功能基准树；
- 模块基准树；
- UI 基准树；
- UI 层次树；
- 项目扫描报告；
- AI 参考摘要；
- 后续可对比、可调优、可交接的基准。

---

## 六、最短竞争表达

> **别人让 AI 更快写代码，DeepSpec 让 AI 不要写偏。**

或：

> **Codex / Claude Code / Cursor 负责生成，DeepSpec 负责让它们知道不该偏离什么。**

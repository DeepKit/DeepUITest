# DeepSpec 深范｜项目宪法

> 本宪法用于约束 DeepSpec 的产品方向、技术边界、AI 边界、文档状态、红绿灯门禁和后续扩展。  
> 凡与本宪法冲突的功能设想，应优先回到本文件讨论，而不是直接开发。

---

## 第一条：DeepSpec 是旁路规格治理系统

DeepSpec 不接管主线开发。

主线开发仍然发生在：

- Delphi IDE；
- VS Code；
- JetBrains IDE；
- Codex CLI；
- Claude Code；
- Cursor；
- GitHub Copilot；
- 其他外部 AI / IDE / CLI 工具。

DeepSpec 只做旁路辅助：

- 生成 Context Pack；
- 观察文件变化；
- 读取 Git Diff；
- 读取测试/编译输出；
- 生成 Review Pack；
- 发现规格漂移；
- 沉淀决定；
- 更新变更日志；
- 生成交接卡。

---

## 第二条：YAML 是事实源，HTML 是审阅层

DeepSpec 必须坚持双层结构：

```text
YAML = 机器事实源
HTML = 人类审阅层
```

禁止把 HTML 当作唯一事实源。  
禁止让 AI 自由生成不可结构化的最终 HTML。  
HTML 应尽量由 YAML + 模板生成。

---

## 第三条：主窗体必须保持干净

DeepSpec 主窗体只负责：

- 顶部工具栏；
- 左侧项目/文档树；
- 右侧 WebView2 审阅区；
- 底部状态栏。

属性、问题、决定不得挤在主窗体上。

它们进入独立悬浮面板：

> **Spec Inspector｜规范检查器**

---

## 第四条：Spec Inspector 是一等界面

每一份开发文档必须有：

1. 属性；
2. 问题；
3. 决定。

三者分别回答：

| 页签 | 回答 |
|---|---|
| 属性 | 它是谁？在哪里？和谁有关？ |
| 问题 | 它缺什么？为什么不能冻结？ |
| 决定 | 为什么这样定？谁确认过？ |

---

## 第五条：AI 不是最终裁判

AI 可以：

- 生成草稿；
- 补充字段；
- 提出问题；
- 生成建议；
- 生成 Context Pack；
- 生成 Review Pack；
- 生成 Handoff Pack。

AI 不可以：

- 直接冻结文档；
- 绕过 Schema；
- 修改 frozen 文档而不生成变更记录；
- 推翻已确认决定；
- 绕过人类确认写入最终决策；
- 在 DeepSpec 内接管主线编程。

---

## 第六条：红灯不能冻结

任何文档在存在 blocker 问题时不得冻结。

文档冻结前必须满足：

- 必填字段完整；
- 当前 Schema 校验通过；
- 无红灯问题；
- 必要决定已确认；
- 必要验收标准存在；
- 必要关联文档不存在明显断裂。

---

## 第七条：冻结文档不能静默修改

文档进入 `frozen` 状态后，必须写入冻结 Hash。

如果 frozen 文档内容发生变化，系统应标记为：

```text
conflict 或 changing
```

并要求说明：

- 为什么修改；
- 谁修改；
- 影响哪些文档；
- 是否需要重新审阅；
- 是否写入变更日志。

---

## 第八条：问题可以转为决定

DeepSpec 不只报错，还要推进工程治理。

当某个问题不是简单缺字段，而是涉及取舍时，应允许用户将其转为决定。

例如：

```text
问题：MVP 是否支持文件监控？
转为决定：是否把文件监控放入 MVP？
```

决定确认后，应写入：

- 当前 Spec YAML；
- `08.discussion-log.yaml`；
- 必要时写入 `09.change-log.yaml`。

---

## 第九条：决定是一等工程资产

决定不是聊天记录，也不是随手备注。

每条决定必须记录：

- 议题；
- 背景；
- 选项；
- 最终选择；
- 选择理由；
- 影响范围；
- 确认人；
- 确认时间；
- 关联问题；
- 关联文档；
- 后续动作。

---

## 第十条：DeepSpec 必须支持旁路闭环

DeepSpec 的标准闭环为：

```text
规格准备
→ Context Pack
→ 外部 AI / IDE / CLI 主线开发
→ 文件变化 / Git Diff / 测试输出
→ Trace
→ Review Pack
→ Spec Impact
→ 人类门禁
→ 更新规格 / 决定 / 变更日志
→ Handoff Pack
```

任何新功能都应服务这个闭环，而不是让系统变成另一个 AI 聊天工具。

---

## 第十一条：Docs-as-Code 原则

DeepSpec 生成的重要文件必须可进入 Git：

- YAML；
- HTML；
- Review Pack；
- Context Pack；
- Handoff Pack；
- 讨论记录；
- 变更日志。

数据库只能作为缓存、索引、运行日志，不应成为唯一交接来源。

---

## 第十二条：第一版必须克制

MVP 不做：

- 多人协作；
- 云同步；
- 权限系统；
- PDF 导出；
- CI/CD 深度集成；
- 复杂 Git 平台集成；
- 自动代码修改；
- 在线富文本编辑；
- FMX 跨平台版；
- 内置 AI 主聊天框。

MVP 只做：

- 打开项目；
- 扫描九类文档；
- 左树导航；
- 右侧 HTML 审阅；
- YAML 生成 HTML；
- Schema 检查；
- 红绿灯；
- Spec Inspector；
- Context Pack；
- Git Diff / 文件变化扫描；
- Review Pack；
- Handoff Pack 初版。

---

## 第十三条：技术路线

第一版技术路线：

- Delphi；
- VCL；
- WebView2 / TEdgeBrowser；
- YAML；
- HTML；
- 可选 SQLite 缓存；
- 本地文件系统；
- Git 命令旁路读取。

不使用 FMX 作为第一版主线。

---

## 第十四条：长期目标

DeepSpec 的长期目标不是成为文档软件，而是成为：

> **AI Coding 时代的软件工程规格治理底座。**

它最终要能服务：

- DeepDev；
- DeepUITest；
- DeepGuide；
- DeepConfig；
- OCGS-Delphi；
- Delphi 老项目交接；
- AI 编程旁路治理；
- 小团队工程规范。

# DeepSpec 三棵基准树设计

## 一、三棵树总览

DeepSpec MVP 的核心不是普通文档，而是三棵结构树：

1. **软件功能树**
2. **软件模块树**
3. **UI 层次树**

在进一步优化后，它们应被理解为：

1. **功能基准树**
2. **模块基准树**
3. **UI 基准树**

---

## 二、功能基准树

### 回答的问题

> 这个软件应该能做什么？

### 来源

候选功能树从以下来源提取：

- 按钮 Caption；
- 菜单 Caption；
- Action Caption；
- README 标题；
- TODO 列表；
- CHANGELOG；
- Markdown 小标题；
- 文档中的功能清单；
- 函数名 / 类名中的关键词。

### 重要原则

功能树第一版必须叫：

# **候选功能树**

因为它从已有文档、UI Caption 和代码中推断，不可能一开始完全准确。

用户可以将其调整后标记为：

```text
已确认基准
```

---

## 三、模块基准树

### 回答的问题

> 这个软件内部应该怎么拆？

### 来源

模块树从以下来源生成：

- 项目目录结构；
- `.dpr`;
- `.dproj`;
- `.pas`;
- Unit 名称；
- Class 名称；
- Forms / Core / Render / IO 等目录；
- uses 关系；
- DataModule / Form / Service 等命名。

### 价值

模块树可以防止：

- 代码混在主窗体；
- 逻辑写进 UI 层；
- AI 把功能写错模块；
- Delphi/VCL 项目出现“窗体肥胖症”。

---

## 四、UI 基准树

### 回答的问题

> 用户看到的软件界面是什么层级？

### 来源

UI 层次树从以下来源生成：

- `.dfm`;
- `.fmx`;
- HTML 原型；
- UI 文档；
- 截图说明；
- 手工补充。

### 对 Delphi/VCL 的价值

`.dfm` 可以读出：

- Form；
- Panel；
- Button；
- TreeView；
- PageControl；
- TabSheet；
- StatusBar；
- TEdgeBrowser；
- Menu；
- Action。

UI 层次树是第一版最有视觉冲击力的功能。

---

## 五、三棵树之间的映射

三棵树不应是孤立的。

必须预留三类映射：

```text
功能 → 模块
功能 → UI
UI → 模块
```

示例：

```text
功能：导入文档
  ↓
模块：DocImportService
  ↓
UI：TopToolbar.BtnImport
```

---

## 六、节点状态

每个树节点应支持状态：

```text
candidate   候选
confirmed   已确认基准
changed     已变化
ignored     已忽略
deprecated  已废弃
unknown     来源不明
```

MVP 第一版至少支持：

```text
candidate → confirmed
```

---

## 七、产品价值

三棵树的作用是：

```text
开发前：先对齐结构
开发中：按树调优
开发后：按树验收和交接
```

最短表达：

> **开发前先定三棵基准树，AI 才不会乱长。**

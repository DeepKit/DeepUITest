# DeepSpec MVP 产品定位与边界

## 1. MVP 最终定位

DeepSpec MVP 的最终定位是：

> **项目开发文档与结构树读取呈现系统。**

一句话：

> 用户把一个 Windows 项目文件夹拖进 DeepSpec，DeepSpec 读取其中已有的文档、代码、UI 文件、配置和 AI 规则文件，生成项目扫描报告、软件模块树、UI 层次树和候选功能树，并以可视化方式呈现，作为后续人工或 AI 开发、对比、调优和交接的基准。

## 2. 为什么这样定位

用户在 AI 辅助开发中的核心问题不是“不知道怎么填问卷”，而是：

- 已经和 AI 或开发工具沟通过，但结果散落在项目文档、代码、README、TODO、配置中；
- AI 生成出来的 UI 与用户想的不一致；
- 功能没有形成树，模块没有分清，UI 层级不明确；
- 开发后无法对照“原来想要什么”；
- 旧项目尤其是 Delphi/VCL 项目，窗体多、事件多、代码混、文档少，难以交接和改造。

DeepSpec 的切口是：

> 读取已有项目，从真实项目文件中提取结构，而不是先让用户重新录入需求。

## 3. MVP 输入方式

第一入口：

```text
拖入项目文件夹
```

第二入口：

```text
打开项目文件夹
```

不以粘贴内容、问答采集、内置 AI 聊天或直接调用外部 CLI 为主流程。

## 4. MVP 输出对象

1. 项目扫描报告；
2. 软件模块树；
3. UI 层次树；
4. 候选功能树；
5. 文档文件清单；
6. 代码文件清单；
7. UI 文件清单；
8. 配置文件清单；
9. AI 规则文件清单；
10. AI 参考摘要；
11. 可确认的结构基准。

## 5. 三棵树

### 软件模块树

回答：这个软件内部由哪些模块组成？

来源：项目目录结构、`.pas` 单元、`.dpr / .dproj`、Unit / Class / Form / DataModule、文件命名和目录命名。

### UI 层次树

回答：这个软件界面由哪些窗体、区域和控件组成？

来源：`.dfm`、后续的 `.fmx`、HTML 原型、UI 文档、截图说明。Delphi/VCL MVP 中，`.dfm` 是最重要来源。

### 候选功能树

回答：这个软件可能有哪些功能？

来源：Button Caption、Menu Caption、Action Caption、Event Handler、README 标题、TODO / CHANGELOG、文档小标题。必须明确叫“候选功能树”，因为它是推断结果，需要用户确认。

## 6. MVP 边界

第一版不做 AI Agent，不调度 CLI，不自动改代码，不接管用户与 AI 的沟通，不做完整规格漂移检测，不做多人协作或企业权限。

## 7. 产品哲学

> 先定形，再生成；先对齐，再开发；先留痕，再迭代。

在 MVP 中体现为：

> 先从项目目录中读取真实文档和代码，再形成模块树、UI 层次树和候选功能树，供后续开发与 AI 修改时对齐。

# DeepSpec 红绿灯、状态机与冻结规则

## 一、红绿灯定义

| 灯色 | 含义 |
|---|---|
| 绿灯 | 结构完整，可以冻结 |
| 黄灯 | 有缺项，但不阻塞 |
| 红灯 | 关键字段缺失，不能冻结 |
| 灰灯 | 未开始 |
| 蓝灯 | AI 建议或待确认内容 |
| 紫灯 | 变更中 |
| 黑灯 | 冲突或异常 |

---

## 二、基础状态

```text
empty
draft
reviewing
frozen
changing
deprecated
conflict
error
```

---

## 三、状态流转

```text
empty → draft
draft → reviewing
reviewing → frozen
reviewing → draft
frozen → changing
changing → reviewing
reviewing → frozen
frozen → deprecated
```

---

## 四、冻结规则

1. 红灯文档不能冻结；
2. AI 不能直接冻结文档；
3. frozen 文档不能静默修改；
4. frozen 文档如果内容变化，自动标记 conflict 或 changing；
5. changing 必须填写变更原因；
6. 冻结时必须写入 Hash；
7. 关键冻结必须写入变更日志。

---

## 五、AI 行为规则

AI 可以：

- 生成草稿；
- 优化表达；
- 提出补充建议；
- 生成候选方案；
- 标记问题。

AI 不能：

- 直接冻结；
- 直接确认决定；
- 静默修改 frozen 文档；
- 自动删除关键文档；
- 替用户做最终责任判断。

---

## 六、问题转决定

当问题不是简单缺字段，而是涉及选择时，应转为决定。

例如：

```text
是否第一版支持 AI API？
是否第一版生成 AGENTS.md？
是否第一版内置 Git Diff 扫描？
```

这些都不应只作为问题，而应进入决定页。

---

## 七、红绿灯与 MVP 的关系

MVP 阶段的红绿灯只检查需求文档完整性。

阶段二再扩展到：

- Git Diff 影响；
- 规格漂移；
- AI 行为越界；
- Review Pack 风险。

阶段三再扩展到：

- CLI 执行结果；
- 测试门禁；
- 回滚判断；
- 发布门槛。

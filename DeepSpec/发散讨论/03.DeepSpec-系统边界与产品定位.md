# DeepSpec 深范｜系统边界与产品定位

## 1. 核心定位

DeepSpec 是：

> **AI Coding 时代的旁路规格治理系统。**

它在外部 AI / IDE / CLI 旁边运行，帮助用户守住：

- 规格；
- 证据；
- 决策；
- 测试；
- 变更；
- 交接。

---

## 2. 主线与旁路

### 2.1 主线

主线是用户真实开发发生的地方：

```text
用户
  ↓
IDE / CLI / Codex / Claude Code / Cursor / Copilot
  ↓
代码修改 / 命令执行 / 测试运行 / Git Diff
  ↓
项目文件变化
```

### 2.2 DeepSpec 旁路

DeepSpec 不进入主线抢控制权，而是在旁边观察和治理：

```text
DeepSpec
  ↑
文件变化 / Git Diff / 测试输出 / AI 摘要 / 规格文档
  ↓
Context Pack / Trace / Review Pack / Spec Impact / Handoff
```

---

## 3. DeepSpec 负责什么

DeepSpec 负责：

1. 规格文件结构化；
2. 文档状态管理；
3. 红绿灯检查；
4. 决策沉淀；
5. 变更影响分析；
6. 上下文包生成；
7. AI 后审查；
8. 交接卡生成；
9. 规格漂移提醒；
10. 软件开发文档规范化。

---

## 4. DeepSpec 不负责什么

DeepSpec 不负责：

1. 替代 IDE；
2. 直接编辑代码；
3. 接管 Codex / Claude Code 的对话；
4. 运行 AI Agent 主循环；
5. 内置完整 AI Chat；
6. 管理所有项目任务；
7. 替代 Git；
8. 替代测试框架；
9. 替代 CI/CD；
10. 替代项目管理系统。

---

## 5. 为什么不接管 AI 主线

原因：

1. Codex / Claude Code / Cursor 等工具已经占据 AI 编程主入口。
2. DeepSpec 如果再做聊天框，会重复建设。
3. AI 对话长、乱、隐私复杂，不适合作为唯一事实源。
4. Git Diff、文件变化、测试输出、规格文档更稳定。
5. DeepSpec 的价值在工程后果治理，而不是“再聊一次”。

---

## 6. 最佳角色分工

| 系统 | 角色 |
|---|---|
| IDE | 编码环境 |
| CLI | 命令执行环境 |
| Codex / Claude Code | AI 编程主线 |
| Git | 版本事实 |
| 测试框架 | 行为验证 |
| DeepSpec | 旁路规格治理 |
| DeepUITest | UI 行为验证 |
| DeepDev | 软件构建辅助 |
| DeepGuide | 企业能力旅程引导 |

---

## 7. 旁路信息来源

DeepSpec 的信息来源包括：

1. DeepSpec 自身 YAML 规格文档；
2. HTML 审阅层；
3. 文件系统变化；
4. Git status / diff / log；
5. 测试输出；
6. 编译输出；
7. 用户粘贴的 AI 摘要；
8. 外部 AI 工具生成的旁路文件；
9. 人类确认后的决定；
10. 变更日志。

---

## 8. 旁路信息不包括

DeepSpec 第一版不强制读取：

- 完整 AI 聊天记录；
- 外部 AI 工具内部状态；
- IDE 私有上下文；
- 云端对话历史；
- 未经用户确认的敏感内容。

---

## 9. 产品差异化

普通文档工具关注：

```text
写了什么文档？
```

DeepSpec 关注：

```text
这份文档是什么状态？
缺什么？
能不能冻结？
为什么这样决定？
实现变了以后规格有没有漂移？
下一轮 AI 如何继续？
```

---

## 10. 最终产品表达

> **外部 AI 负责写代码，DeepSpec 负责让规格、决策、测试、变更和交接不失控。**

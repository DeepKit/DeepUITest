## 4. 当前权威原则

后续设计如果冲突，按以下原则判断：

```text
旁路，不接管；
查阅，不替代；
框架 LLM 调用，不聊天；
提示词可导出，但不是第一层主流程；
非重大战略问题由执行者按既定原则直接决策并写入文档；
实现细节、MVP 页面组织、树与 HTML 联动、JS Bridge、文件拆分、校验合并流程等问题由执行者直接定，不再逐项提问；
后续只把产品定位、阶段边界、事实源边界、责任边界、免费/付费切分、商业化路径等重大战略问题交给用户讨论；
第一层通用免费，不绑定 Delphi/VCL；
第一阶段是需求可视化，包括建议；
第二阶段是需求所见即所得，即代码与需求一致；
第三阶段是调用用户 CLI 实现软件功能；
产品一句话：DeepSpec 是软件开发的需求可视化审阅层，把项目材料转成可追溯的规格化需求 B，并用三棵树和 HTML 图表让人看清、确认和校准 AI 的理解；
首个市场楔子是 AI 重度开发者的需求可视化审阅工具，Delphi/VCL 是强样板和差异化 Pack，不是第一层主定位；
第一版开源免费；
开源协议使用 Apache-2.0；
第一层免费目标是呈现可视化需求体系和建议，边界止于需求可视化 + 建议 + B 内决策，不提供代码与需求校正；
付费目标从 A/B 需求校正、代码与需求一致性校正、Review Pack、漂移检测和后续 CLI 功能实现开始；
对外承诺是把 AI 对项目需求的理解变成可审阅、可追溯、可决策的图表界面，不承诺一键生成正确产品；
部署策略是本地优先 + 用户配置模型 / API Key / 框架 LLM 模块，云端账号由 deepkit.top 网站提供并由客户端直接对接，企业私有模型和内网版属于后续付费能力；
进入第二层前，第一层必须在 3-5 个真实项目上验证 B、三树、HTML、来源、问题和决策写回稳定有效；
DeepSpec 不承担 B 的语义生成责任，B 的语义内容由框架 LLM 模块调用用户配置或已有的 AI 能力，根据 DeepSpec 提供的提示词模板、Schema 和上下文生成；
DeepSpec 的责任是 LLM 任务编排、提示词工程、上下文组织、Schema 校验、来源追溯、可视化呈现和 B 的事实源管理；
DeepShell 已有，直接复用；
DeepSpec 基于 DeepBase / DeepShell 开发，不自建壳、账号、LLM、安全存储、WebView2 自动化和商业授权；
DeepBase DB1 ConfigDB 保存配置、布局、Secret、LLM 配置、账号授权状态；DeepSpec B 事实源仍保存到项目 `.deepspec` YAML；
三棵树是结构骨架，图表挂在三棵树上；
需求总览图是功能树的图表化表达；
功能-视图、功能-模块关系优先作为树节点挂接和联动能力，不默认做独立 P0 大图；
首页呈现当前文档状态，不做简单闭环判定；
页面决策不是 UI 状态，而是需求事实的一部分；
DeepSpec 默认读取原始需求目录 A，生成 `.deepspec` 规格化需求目录 B；
B 是 DeepSpec 内部的规格化事实源，A 是原始输入材料和证据层；
B 不是文档摘要，而是由需求节点、关系边、来源证据、状态和人类决策组成的规格化事实层；
B 的总入口是 `.deepspec/project-spec.yaml`；
`project-spec.yaml` 只做总索引和摘要，不复制完整事实内容；
B 的事实拆到 trees/ relations/ evidence/ issues/ decisions/ 等目录，不使用一个巨大 YAML 保存全部事实；
AI 读 YAML，人类看 HTML；
HTML 是审阅界面，不是事实源；
Prompt / LLM 任务和 HTML 页面点击都是交互入口，但最终都必须写回 B 中的 YAML 事实文件；
HTML 点击先生成候选 Decision Record，用户确认后才写入 B；
LLM 输出先作为候选 B，经 Schema 校验、来源检查、冲突检查后由 DeepSpec 合并进 B；
HTML 使用生成式页面 + JS Bridge，点击事件交给 DeepShell / DeepSpec；HTML 不直接写 YAML，不保存事实状态；
第一层所见即所得是 B 中需求事实与三树 / 图表 / HTML 显示一致；
第一层图表交互只做点击审阅和需求决策，不做拖拽改树、直接改名、手工连线或完整画布编辑器；
MVP 节点点击后必须显示来源、问题、关系、状态、置信度和决策按钮；
第二层所见即所得是代码结果与 B 中需求事实一致；
给用户 AI 的上下文包以 B 为主，按需引用 A；
B 保留当前工作集和历史摘要；
当前规格判断 = A 的解析结果 + B 中 accepted decisions 覆盖层；
三棵树节点显示来源层级标签；
A 与 B 冲突时，主视图以 B 为当前规格判断，但必须标记 A 未同步或 A 有旧描述；
B:AI推断 可以进入图表，但必须标记低置信 / 待确认，不能覆盖人工决策；
免费层只显示 `A 未同步` 状态标签；
`A 未同步` 专门待办队列、需求校正 Prompt/Patch 属于第二层付费能力；
人类决策应写入 B 中可追溯的规格化需求文档和结构化 Decision Log，并影响后续 AI 需求撰写；
A 的正式修改由用户自己的 AI、用户手动编辑，或第二层用户确认后的 Patch 完成；
第一层免费边界包括 B、三树、HTML、问题、人类决策和可视化需求体系呈现；
第一层不包括 A/B 需求校正、自动改 A、代码实现一致性检查、Git Diff 治理、用户 CLI 调度；
第二层和第三层统一以 B 为规格事实源和任务入口；
视图树是功能树中交付界面部分的简化表达；
HTML 是交互审阅层，也是 LLM 任务入口和提示词导出口；
第一层优化 B 中的规格化需求表达，不修补生成视图；
A 中底层文档的正式修订属于第二层需求校正能力；
YAML 是 B 的机器事实数据，HTML/DeepShell 原生控件是审阅界面；
用户继续使用原来的 AI/IDE 工具；
第一层默认直接调用成熟的框架 LLM 模块生成 / 更新 B。
```

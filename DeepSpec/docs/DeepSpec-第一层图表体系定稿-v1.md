# DeepSpec 第一层图表体系定稿 v1

> 日期：2026-05-14  
> 状态：第一层图表体系定稿  
> 讨论来源：产品定位、需求工程、信息架构/可视化、UX、AI 提示词闭环五个专家视角  
> 当前范围：只讨论“人类需求如何从项目材料中被图表化表达”，暂不讨论 AI 生成代码后的实现一致性。

---

## 1. 总原则

DeepSpec 第一层不是“多画几种图”，而是围绕三棵树建立一个可审阅、可追溯、可生成 Prompt 的需求空间。

三棵树关系保持不变：

```text
功能树 = 需求本体
视图树 = 功能树中交付界面部分的简化表达
模块树 = 功能树中实现组织部分的简化表达
```

图表关系：

```text
功能树
  ├─ 需求总览图
  ├─ 来源证据图
  ├─ 需求健康图
  ├─ 功能-视图映射图
  ├─ 功能-模块映射图
  └─ 三树闭环矩阵
```

HTML 页面不是静态报告，而是：

- 交互审阅层；
- 来源证据层；
- 问题定位层；
- Prompt 出口。

---

## 2. 最终图表清单

定稿为 **6 个 P0 + 2 个 P1**。

| 优先级 | 图表 | 挂载位置 | 定位 |
|---|---|---|---|
| P0 | 需求总览图 | 功能树 | 功能树的图表化表达，一屏看懂需求本体。 |
| P0 | 来源证据图 | 主挂功能树，兼容视图树/模块树 | 解释每个需求从哪些项目材料中来。 |
| P0 | 需求健康图 | 主挂功能树，聚合三树问题 | 汇总缺失、冲突、低置信度、无来源、未映射问题。 |
| P0 | 功能-视图映射图 | 功能树 + 视图树 | 判断需求是否被交付界面表达。 |
| P0 | 功能-模块映射图 | 功能树 + 模块树 | 判断需求是否有实现组织承接。 |
| P0 | 三树闭环矩阵 | 功能树 + 视图树 + 模块树 + 来源 + 问题 | 项目首页总控图，检查需求是否形成闭环。 |
| P1 | 用户路径 / 场景流图 | 功能树 + 视图树 | 检查需求是否能组成真实用户流程。 |
| P1 | 术语与对象关系图 | 功能树 + 来源文档 | 统一需求中的核心概念、术语、对象关系。 |

---

## 3. P0 图表定义

### 3.1 需求总览图

本质：

```text
需求总览图 = 功能树的图表化表达
```

它和功能树是同一批内容，不是第四棵树，也不是三棵树汇总。

显示内容：

- 功能域；
- 子功能；
- 叶子需求；
- 业务规则；
- 异常和边界；
- 缺失节点；
- 冲突节点；
- 低置信度节点；
- 未关联视图/模块的功能节点；
- 节点来源和置信度。

核心交互：

- 按层级折叠：只看功能域、只看功能点、只看问题节点；
- 点击节点打开详情；
- 查看来源片段；
- 查看置信度和问题；
- 复制“补充/澄清/拆分该功能”的 Prompt。

### 3.2 来源证据图

回答：

```text
这些需求是从哪里来的？
哪些材料被有效吸收？
哪些需求没有明确来源？
```

显示内容：

- 文件列表；
- 每份材料贡献的功能节点数量；
- 来源片段；
- 来源覆盖率；
- 未被吸收的材料；
- 无来源功能节点；
- 同一来源被多个需求复用的情况。

核心交互：

- 点击材料，过滤相关功能节点；
- 点击来源片段，定位到需求节点；
- 标记“无来源需求”；
- 复制“重新阅读某材料 / 补齐遗漏 / 移除无依据推断”的 Prompt。

### 3.3 需求健康图

回答：

```text
当前需求表达哪里不健康？
哪些地方最需要用户和 AI 回去修文档？
```

它合并以下图的 P0 价值：

- 问题图；
- 冲突关系图；
- 低置信度热力；
- 孤岛节点图。

第一版不必做复杂雷达图，建议做成问题分组面板 + 严重度 + 可点击入口。

问题类型：

- 缺来源；
- 表述模糊；
- 需求冲突；
- 颗粒度不一致；
- 业务规则缺失；
- 异常流程缺失；
- 与视图树未映射；
- 与模块树未映射；
- 孤岛节点；
- 低置信度节点。

核心交互：

- 按严重程度筛选；
- 点击问题进入对应树节点；
- 查看问题原因和来源证据；
- 复制“修复该类问题 / 修复单个问题”的 Prompt。

### 3.4 功能-视图映射图

回答：

```text
需求是否被用户可见界面表达？
```

注意：

这里的视图树是需求侧视图树，不是代码控件树。

显示内容：

- 功能节点；
- 视图节点；
- 功能到页面、区域、组件、交互入口的映射；
- 无视图承载的功能；
- 无功能来源的视图；
- 重复承载；
- 入口不清；
- 映射置信度。

关系类型：

- 入口；
- 展示；
- 编辑；
- 确认；
- 反馈；
- 异常处理。

核心交互：

- 点击功能，看它在哪些界面出现；
- 点击视图，看它承载哪些功能；
- 只看未映射、重复映射、疑似错误映射；
- 复制“补充页面/调整界面表达/删除无依据界面内容”的 Prompt。

### 3.5 功能-模块映射图

回答：

```text
需求是否有实现组织承接？
```

注意：

当前不做代码实现对照，只看需求文档或架构文档中的模块组织投影。

显示内容：

- 功能节点；
- 模块节点；
- 功能到模块、服务、能力域、数据对象的映射；
- 无模块承接的功能；
- 无需求来源的模块；
- 模块职责过宽、过散、重复；
- 模块职责冲突。

关系类型：

- 负责；
- 依赖；
- 复用；
- 配置；
- 数据提供；
- 状态管理。

核心交互：

- 点击功能，看应由哪些模块承接；
- 点击模块，看它负责哪些需求；
- 筛选无模块承接功能；
- 复制“调整模块划分 / 补充模块职责 / 拆分职责边界”的 Prompt。

### 3.6 三树闭环矩阵

定位：

**第一层项目首页总控图。**

它不是需求总览图。需求总览图是功能树表现；三树闭环矩阵是管理视角，用来检查每个关键功能是否闭环。

建议形态：

| 功能域 / 功能点 | 来源 | 视图 | 模块 | 问题 | 确认状态 |
|---|---|---|---|---|---|
| 项目导入 | 完整 | 已映射 | 已映射 | 无 | 待确认 |
| 文档扫描 | 部分来源 | 已映射 | 缺模块 | 黄灯 | 待确认 |
| 报告导出 | 无来源 | 缺视图 | 已映射 | 红灯 | 待确认 |

核心交互：

- 点击单元格跳到对应图表；
- 筛选未闭环需求；
- 筛选高风险需求；
- 生成某个功能域的一揽子修复 Prompt。

## 4. P1 图表定义

### 4.1 用户路径 / 场景流图

回答：

```text
需求是否能组成真实用户流程？
```

显示内容：

- 用户角色；
- 目标任务；
- 关键步骤；
- 涉及功能；
- 涉及视图；
- 异常分支；
- 断点。

核心交互：

- 点击路径步骤，联动功能树和视图树；
- 标记缺页面、缺规则、缺异常、缺权限；
- 复制“补全用户场景或异常流程”的 Prompt。

P1 原因：

它非常有价值，但不是所有项目一开始都有足够清晰的用户流程材料。

### 4.2 术语与对象关系图

回答：

```text
需求里的核心概念是否一致？
```

显示内容：

- 术语；
- 别名；
- 业务对象；
- 属性；
- 对象关系；
- 未定义概念；
- 同义词；
- 歧义词。

核心交互：

- 点击术语查看定义、来源、出现位置；
- 关联到功能节点；
- 标记同义词、歧义词、未定义概念；
- 复制“统一术语 / 补充对象定义 / 消除歧义”的 Prompt。

P1 原因：

复杂项目很需要，但第一屏优先级低于三树、来源、问题和映射闭环。

## 5. 暂不固定实现的图表

以下图表不是废弃，而是不进入第一层固定清单：

| 图表 | 处理 |
|---|---|
| 状态转换图 | 作为特定需求节点的局部图，后续按需生成。 |
| 权限 / 角色 / 功能矩阵 | 有权限材料时按需生成，不作为通用第一层固定图。 |
| 端到端链路图 | 由功能-视图映射、功能-模块映射、三树闭环矩阵组合表达。 |
| 变更影响图 | 更适合第二层或用户主动修改需求时生成。 |
| 风险热力图 | 合并进需求健康图。 |
| 孤岛节点图 | 合并进需求健康图。 |
| 置信度热力图 | 合并进需求健康图。 |
| 代码调用图 / 实现差异图 | 属于第二层，不进入第一层。 |

## 6. 首页建议

第一层首页不要平铺 8 张图。建议：

```text
左侧：功能树 / 需求总览图
中间：三树闭环矩阵
右侧：需求健康图
底部 Tab：来源证据、功能-视图映射、功能-模块映射
```

P1 图表放二级 Tab：

- 用户路径 / 场景流；
- 术语与对象关系。

---

## 7. 通用交互标准

所有 P0 图表必须支持：

- 点击节点：打开详情面板；
- 查看来源：显示原文片段、文件名、位置；
- 查看问题：显示问题类型、严重程度、原因；
- 跳转关联：功能树、视图树、模块树之间互跳；
- 状态过滤：只看缺失、冲突、无来源、未映射、低置信度；
- 用户确认：标记正确 / 错误 / 待确认；
- 复制 Prompt：指导原 AI 工具修改底层项目文档。

Prompt 不能只复制节点文本，必须带：

- 节点路径；
- 问题类型；
- 当前描述；
- 来源证据；
- DeepSpec 判断；
- 期望修改方向；
- 受影响节点；
- 禁止直接改代码的约束。

## 8. 定稿结论

第一层固定图表为：

```text
P0:
1. 需求总览图
2. 来源证据图
3. 需求健康图
4. 功能-视图映射图
5. 功能-模块映射图
6. 三树闭环矩阵

P1:
7. 用户路径 / 场景流图
8. 术语与对象关系图
```

一句话：

**DeepSpec 第一层先生成可信的功能树，再把它投影成视图树和模块树，并用来源、问题、映射和闭环矩阵让用户审阅 AI 到底把需求理解成了什么。**

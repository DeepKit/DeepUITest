> 日期：2026-05-20  
> 范围：DeepSpec 工程文档、protocol 文档、schema、开源入口

## 已确认的问题

1. `tree.schema.json`、`data-tree.schema.json`、`project-spec.schema.json` 不是合法 JSON。
2. 对外入口缺失：根目录没有 `README.md` 和 `SPEC.md`。
3. protocol 文档仍以三棵树为主，未同步 `data-tree`。
4. CTF 文档要求正交状态，但协议仍大量使用单一 `status`。
5. `x_` 与 `x-` 扩展前缀混用。
6. conformance 文档描述的 `run.sh` 和分层目录与实际文件不一致。
7. protocol README 引用了尚未发布的 `npx deepspec-*` 命令。
8. 任务清单中的编译统计与协议完成状态表达过满。

## 本轮处理原则

```text
DeepSpec 是对外工程品牌。
CTF 是 DeepSpec 的方法内核。
ODD 是下游验证与封存层。
data-tree 是第四投影，不是 risk-tree。
risk_score 是字段或派生视图，不是独立树。
execution_status 不属于 CTF/DeepSpec。
```

# DeepSpec 产品愿景与 MVP 约束

> 本文档为圆桌讨论阶段总结，用于团队对齐，非最终定稿。

---

## 一、一句话定位

> **DeepSpec 帮用户把已有的开发文档变成结构化的、人类可审阅、AI 可消费的产品规格。**

解决的核心问题：**开发文档非所见即所得。**

---

## 二、核心架构

```
YAML = AI 可理解（开发侧，机器事实源）
HTML = 人类可审阅（意图侧，人类审阅层）
```

双层结构，YAML 是事实源，HTML 由 YAML 生成。禁止 HTML 成为唯一事实源。

---

## 三、三棵树

| 树 | 含义 | 回答的问题 |
|---|------|-----------|
| **功能树** | 意图 | 这个软件要做什么？ |
| **模块树** | 功能结构 | 软件内部怎么拆？ |
| **视图树** | UI 及层次 | 用户看到的界面是什么样？ |

三棵树的 YAML 由 AI 生成，DeepSpec 渲染为 HTML + 树控件供人类审阅。

---

## 四、用户工作流

```
① 用户照常使用自己的 AI 工具（Claude Code / Cursor / Codex / IDE）
   和 AI 讨论、写代码、生成文档
                ↓
   项目中自然产出文件：
   README.md、CLAUDE.md、需求文档、设计文档、代码、DFM、配置……

② DeepSpec 读取这些已有文件
                ↓
③ DeepSpec 打包项目文件内容，配上 Prompt 模板
                ↓
④ 发给 AI（用户的 AI）→ AI 生成三棵树的 YAML
                ↓
⑤ DeepSpec 解析 YAML，渲染为：
   - VCL 树控件（交互、导航、对照）
   - HTML 视图（WebView2 审阅、所见即所得）
                ↓
⑥ 人类审阅 → 确认 / 修改 → 得到结构化的 PRD 规格文档
```

**关键原则：不改变用户习惯，不替代用户已有的 AI 工具。**

---

## 五、MVP 约束（已确认）

| 约束 | 说明 |
|------|------|
| 界面复用 DeepShell | 壳层、悬浮窗、Provider 模式从 DeepBase 复用 |
| 三棵树可同时挂载 | 左右悬浮窗同时显示，用户可对照查看 |
| 只读审阅 | MVP 阶段不编辑树内容，只展示和审阅 |
| 不改变用户工作流 | 用户照常用自己的 AI，DeepSpec 只做后处理 |
| 不内置 AI | 不调用 AI API，由用户自己的 AI 生成 YAML |
| Delphi 是加分项 | DFM/PAS 解析是 Delphi 项目专属增强，不是核心 |
| YAML 由 AI 生成 | 不做正则提取，不猜功能，让 AI 读文档生成结构化内容 |

---

## 六、MVP 核心功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | 读取项目文件 | 扫描目录，识别文档/代码/UI/配置/AI 规则文件 |
| 2 | 文档树展示 | 按目录结构在悬浮窗展示，点击导航 |
| 3 | 文档渲染 | Markdown → HTML、YAML/JSON → 可视化、代码高亮 |
| 4 | 上下文打包 | 把项目文件打包成 AI 可消费的上下文 + Prompt |
| 5 | YAML 解析 | 解析 AI 返回的三棵树 YAML |
| 6 | 三棵树展示 | VCL 树控件 + WebView2 HTML 视图 |
| 7 | Delphi 增强 | DFM → 视图树、PAS → 模块树（Delphi 项目专属） |

---

## 七、产品核心价值链

```
人类意图（散乱的文档/想法/聊天）
        ↓ AI 生成
YAML（结构化，AI 可消费）
        ↓ DeepSpec 渲染
HTML（可视化，人类可审阅）
        ↓ 确认后
结构化 PRD（功能树 + 模块树 + 视图树）
        ↓ 交付给
AI 开发（Claude Code / Cursor / Codex 照着规格开发）
        ↓ 最终
所见即所得的程序（因为设计阶段就结构化了）
```

---

## 八、与原方案的关键变化

| 原方案 | 新方案 | 变化原因 |
|--------|--------|---------|
| 从代码中提取结构 | 让 AI 从文档生成结构 | 提取准确度不可控 |
| 候选功能树（推断型） | 功能树（AI 生成型） | 避免垃圾信息 |
| 扫描器是核心 | 文档渲染 + Prompt 模板是核心 | 定位回归"文档展示" |
| Delphi 代码分析为主 | Delphi 是加分项 | 市场不限于 Delphi |
| DeepSpec 不碰 AI | DeepSpec 为 AI 准备上下文，但不调用 API | 不替代用户工具 |

---

## 九、待讨论问题

以下问题需要团队继续讨论，一次一个：

1. **AI 生成 YAML 的触发方式**：用户复制粘贴到自己的 AI？DeepSpec 调 API？混合模式？
2. **三棵树的 YAML Schema**：每棵树具体什么字段？AI 返回的格式必须固定。
3. **Prompt 模板设计**：给 AI 的 Prompt 怎么写？上下文包包含什么？
4. **人类审阅交互**：用户如何在 DeepSpec 里审阅和修改 AI 生成的树？
5. **YAML → HTML 的渲染规则**：每种树怎么渲染成 HTML 视图？
6. **迭代循环**：用户确认后修改了代码，如何重新触发 AI 更新树？

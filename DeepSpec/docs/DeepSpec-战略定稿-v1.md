## 1. 产品一句话

DeepSpec 是软件开发的需求可视化审阅层：把项目材料转成可追溯的规格化需求 B，并用三棵树和 HTML 图表让人看清、确认和校准 AI 的理解。

更完整表达：

```text
DeepSpec 读取用户已有项目材料 A，
通过框架 LLM 模块生成 .deepspec 下的规格化需求事实层 B，
再把 B 渲染成三棵树、图表、来源证据、问题清单和 HTML 审阅界面，
让开发者在软件开发过程中，尤其是 AI 写代码前，看清、确认、裁决和校准 AI 对项目需求的理解。
```

## 2. 免费 / 付费边界

### 2.1 免费层

免费层只到：

```text
需求可视化 + 建议 + B 内决策
```

包括：

- 扫描 A；
- 调用框架 LLM 模块生成候选 B；
- 校验和合并 B；
- 呈现三棵树；
- 呈现需求图表；
- 呈现来源证据；
- 呈现问题清单；
- 呈现当前文档状态；
- 支持用户在 B 内做需求决策；
- 生成 B 内审阅建议；
- 导出 Prompt 作为兜底。

免费层不提供：

- A/B 需求校正工作流；
- 自动修改 A；
- 文件级 Patch；
- 代码与需求一致性检查；
- Git Diff / Review Pack；
- 漂移检测；
- 用户 CLI 调度开发。

### 2.2 付费层

一旦能力进入以下范围，就属于付费能力：

- A/B 需求校正；
- `A 未同步` 专门队列；
- B -> A 需求修订 Prompt / Patch；
- 代码与需求一致性校正；
- Git Diff / Review Pack；
- Spec Drift 检测；
- 规则回流；
- Handoff；
- 调用用户 CLI 实现软件功能；
- 企业内网、私有模型、团队协作和高级合规能力。

## 3. 首个市场楔子

对外主打：

```text
AI 重度开发者的需求可视化审阅工具。
```

首批用户：

- AI 重度独立开发者；
- 小团队技术负责人；
- AI 代理工作流使用者；
- 需要在开发前审阅 AI 理解的人。

Delphi / VCL / Legacy 是强样板和差异化 Pack，不是第一层主定位。

不优先服务：

- 只想“给一个提示词就输出产品”的用户；
- 不愿审阅需求体系、不愿做需求决策的用户；
- 一开始就要求大型合规需求管理、多人审批、企业流程的客户。

---

## 4. 对外承诺边界

DeepSpec 可以承诺：

```text
把 AI 对项目需求的理解变成可审阅、可追溯、可决策的图表界面。
```

DeepSpec 第一层不承诺：

- 自动生成正确产品；
- 自动生成完美 PRD；
- 第一层检查代码实现一致；
- 第一层自动修改 A 中底层文档；
- 替代 Claude Code / Cursor / Codex / IDE；
- 替代 Jira / Confluence / Productboard / DOORS；
- 让不审阅需求的人一键完成产品。

DeepSpec 的可信度来自：

- 来源证据；
- 低置信标记；
- 冲突提示；
- 人类决策；
- B 的事实分层；
- HTML 可视化审阅；
- 第二层再做代码一致性校正。

## 5. LLM / 隐私 / 账号 / 部署策略

第一版采用：

```text
本地优先 + 用户配置模型 / API Key / 框架 LLM 模块
```

原则：

- DeepSpec 读取本地项目；
- 第一层默认调用成熟框架 LLM 模块；
- 用户可以配置模型、API Key 或已有 AI 能力；
- Prompt 导出保留为兜底；
- DeepSpec 不强制把项目迁移到云端；
- 云端账号、用户体系、官网分发和后续授权由 `deepkit.top` 网站提供，DeepSpec 客户端直接对接；
- 企业私有模型、内网版、离线部署作为后续付费能力。

隐私口径：

```text
DeepSpec 默认是本地项目旁路审阅工具；
是否把上下文发送给外部模型，取决于用户配置的 LLM 提供方和授权。
```

账号口径：

```text
DeepSpec 客户端不自建独立云端账号系统；
直接对接 deepkit.top 的账号和授权服务。
```

第一版分发策略：

```text
第一版开源免费。
开源协议使用 Apache-2.0。
```

开源免费不改变免费 / 付费能力边界：第一版先用开源免费方式获取用户、样例和反馈；后续付费能力仍从 A/B 校正、代码与需求一致性、Review Pack、CLI 调度、企业内网和私有模型能力开始。

## 6. 进入第二层门槛

不能过早进入第二层。第二层会引入代码一致性、Diff、Review、Patch 和更多语言/框架复杂度。

进入第二层前，第一层必须满足：

1. 能稳定读取 A；
2. 能稳定生成候选 B；
3. 能稳定校验和合并 B；
4. 能生成三棵树；
5. 能渲染 HTML 图表；
6. 能呈现来源证据和问题清单；
7. 能支持人类决策写回 B；
8. 能在 3-5 个真实项目上验证；
9. 用户能在 10 分钟内看懂项目需求结构；
10. 用户能用 DeepSpec 找出 AI 对需求的误解、缺口或冲突。

达不到这些门槛前，不启动第二层主线开发。

---

## 7. 当前战略路线

```text
第一层：需求可视化（包括建议）
  第一版开源免费，通用，本地优先，不绑定 Delphi/VCL。

第二层：需求所见即所得（代码与需求一致）
  付费，以 B 为基准做 A/B 校正、代码一致性、Review Pack 和漂移检测。

第三层：调用 CLI 实现软件功能
  高阶付费，以 B 为任务入口，受控调用用户 CLI / Agent / 编译器 / 测试工具。
```

战略判断：

```text
先占住“软件开发的需求可视化审阅层”这个位置；
不要过早变成 AI IDE、PRD 生成器、需求管理平台或 CLI 开发器。
```

## 一、必须修改逐项确认

### 1. §4.1 kind 扩展机制 — 通过

`x_` 前缀约定、解析器不报错仅警告、§11.1 和 §13 配合 — 全部到位。Delphi 枚举映射提供了功能树的示例。

**降级建议**：模块树和视图树缺少 Delphi 枚举映射示例，建议补充但非阻塞。

### 2. §4 节点时间戳 — 通过

`created_at` / `updated_at` 加入必需字段组，§4.2 明确由 DeepSpec 自动填充，§11.1 列入允许缺省。

### 3. §4 并发控制 — 通过，但有设计隐患

`content_hash` + `revision` + §4.3 计算规范 + §11.2 并发控制 + §12.2 `base_content_hashes` — 完整链路已建立。

**隐患**：§4.3 将 `decision_refs` 和 `issue_refs` 纳入 hash 计算。用户对节点做决策 → `decision_refs` 增加 → content_hash 改变 → 下次 LLM 增量调用命中假冲突，但节点语义内容实际没变。

**建议修改**：从 content_hash 计算中移除 `decision_refs` 和 `issue_refs`，仅含语义字段。§11.2 的并发控制只检查 content_hash。

### 4. §4.4 source_layer 枚举 — 通过

`parsed_from_a / human_decision / ai_inferred / generated_summary` — 纯英文蛇形，闭环。

### 5. §9.1 决策类型对齐 — 通过

12 种类型全部列出。`supplement` → `gap_fill` 与写回文档一致。

**命名差异需确认**：写回文档用 `conflicts_resolved`，协议用 `resolved_issues`。语义接近但概念不同。建议明确 `resolved_issues` 包含 `conflicts_resolved` 的语义，或在写回文档同步更新。

### 6. §11.2 严格模式节点级保护 — 通过，需澄清一处

LOCKED / GUARDED / OPEN / REJECTED 四级定义清晰。

**需澄清**：LOCKED 节点规则"拒绝任何字段变更"，但用户应始终有权推翻自己的决策。建议追加：**人类决策（created_by: human）对 LOCKED 节点有 override 权限**。

### 7. §4.1 kind 精确拼写 — 通过

### §12.2 增量模式两点说明

**点 A**：`base_revision: integer` 未定义来源。建议明确定义为树文件级版本号或删除（`base_content_hashes` 已足够）。

**点 B**：`op: delete` 的 payload 需明确 — 不需要 payload，仅用 `id` + `base_hash`。`op: update` 中 `null` 表示清除字段，省略表示保持原值。

## 三、开放问题决议（§17）

## 四、新发现的必须修改

### N1. §16 示例引用悬空

§16 写"详见 v0 文档示例"，但文档中没有 v0 示例。需补充一个完整的 v1 格式最小可用 B 示例。

### N2. §12.3 最后一个错误示例渲染损坏

第 763-769 行的三层反引号嵌套导致解析混乱。改用缩进或 `~~~` 围栏。

### N3. §9 决策 source_refs 与写回文档结构不一致

写回文档 §5 的决策 `source_refs` 使用内联结构 `{path, note}`，协议使用 ev-id 引用。建议在 §9 注释说明以本协议为准，后续同步更新写回文档。

## 五、新建议（可在后续版本改进）

### S1. 证据源文件变更检测

建议增加可选 `source_file_hash` 字段，用于检测源文件编辑后的行号漂移和证据失效。

### S2. 跨项目事实复用预留

建议在 §3 `project-spec.yaml` 中预留 `imports: []` 字段。

### S3. 字段废弃策略

§13 缺少"废弃字段"的过渡策略。建议：废弃字段在 2 个 minor 版本内保留但标记 deprecated。

### S4. §11.3 校验报告 path 格式

`errors[].path` 与 `node_results` 有重叠。建议节点级错误用 `node_id:func-xxx` 而非数组索引。

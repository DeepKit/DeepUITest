# 视频流水线

## 概述

通过统一 Video IR 和 Renderer Adapter 将 Agent 生成的镜头脚本渲染为多平台视频。**视频流水线是独立运行的**，Agent 完成后即可生成视觉素材、字幕布局和静默预览；只有正式带声成片才需要绑定已通过 Gate 3a 的音频资产。采用分层渲染 + 多 Composition 架构，一次生成多版本输出。

当前自用版第一条完整生产链路固定为：文章 -> 音频候选包 + B站视频候选包。视频长度通常不超过 15 分钟，画面风格以简单表意为准，优先保证意思准确、字幕清楚、节奏稳定，不追求强插画和复杂视觉包装。

视频线同时支持两个渲染后端：

| 后端 | 用途 | 特点 |
|---|---|---|
| HyperFrames adapter | 第一阶段默认后端，服务 B站候选包和本地可视化编辑 | HTML/CSS/JS composition，便于 Agent 生成、lint、snapshot 和浏览器预览 |
| Remotion adapter | 后续扩展后端，服务 React 模板和既有 Remotion 生态场景 | React composition，适合复杂组件化模板和精确帧控制 |

Agent 不直接生成 HyperFrames HTML 或 Remotion React 代码，只生成稳定的 Video IR。渲染后端由模板、平台配置或任务参数选择；当前默认值为 `hyperframes`，Remotion 不阻塞第一条完整生产链路。
## 桌面主控与渲染 Worker 边界

视频渲染由 Delphi + DeepBase 桌面主程序发起和管理。HyperFrames、Remotion、Chromium 属于可替换的外部 render worker，不拥有配置真相、业务状态或任务状态。

| 主程序负责 | render worker 负责 |
|---|---|
| 从 DB2 读取 `shot_document`、平台规格和模板版本 | 消费 Video IR 并生成 composition |
| 通过 DeepBase.JobQueue / StatusMachine 创建、领取、取消和恢复任务 | lint、snapshot、preview、render |
| 记录日志、heartbeat、错误映射、资产索引和 Gate 3b | 输出版本化 manifest 和媒体文件 |
| 决定是否接受 worker 结果 | 不直接修改 DB2 业务表 |

Node/TypeScript 只允许出现在 worker 内部实现中，不进入 DeepFrames 桌面主程序。

## 输入契约

视频流水线读取共享的 `shot_document`（可导出 `shots.json` 快照），并按运行模式决定是否读取音频资产快照：

| 输入项 | 来源 | 用途 | 必需性 |
|---|---|---|---|
| `shot_document` | Agent 工作流 | 叙事文本、视觉意图、字幕内容、平台目标 | 必需 |
| `video_ir` | 视频线编译阶段 | 后端无关的场景、时间轴、素材和布局快照 | 必需，由 `shot_document` 编译生成 |
| audio_manifest.json | 音频流水线 | 精确 duration、音轨资产、时间戳资产引用 | 仅正式带声成片必需 |
| timestamps asset | ASR 回传 | 卡拉 OK 字幕同步 | 带字幕同步时必需 |
| chapter audio asset | TTS + 混音 | 视频音轨 | `final-with-audio` 必需 |

### 运行模式

| 模式 | 说明 | 音频要求 |
|---|---|---|
| `visual-preview` | 只生成图片、字幕布局和静默视频 | 不要求音频 |
| `timed-preview` | 使用 Agent 预估时长或 placeholder audio 生成可预览时间轴 | 不要求正式音频 |
| `final-with-audio` | 绑定已通过 Gate 3a 的音频资产，生成正式带声成片 | 必须有 audio manifest |

缺失音频只阻塞 `final-with-audio`，不阻塞图片生成、模板匹配、静默预览和平台画面检查。

## 流水线阶段

```
shot_document + 可选 audio_manifest.json
  │
  ▼
┌──────────────┐
│ 1. 素材准备    │  多比例背景图生成
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 2. Video IR 编译│  模板匹配、布局、安全区和时间轴快照
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 3. 后端适配     │  HyperFrames HTML 或 Remotion React Composition
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 4. 分层渲染     │  背景层 + 主体层 + 文字层，各层独立适配比例
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 5. 多版本输出  │  按平台配置渲染不同尺寸/码率

       │
       ▼
  movie_{platform}.mp4
```

### 1. 素材准备

从 `shot_document` 提取所有 `visual.background_prompt`，按目标平台比例批量生成。第一阶段仅要求图片或画面能准确表达当前镜头含义，不以强风格化插画、复杂角色一致性或电影级画面作为验收条件。

Prompt 自动附加构图提示词：

| 比例 | 附加提示 |
|---|---|
| 16:9 | "wide shot, horizontal composition, cinematic" |
| 9:16 | "vertical composition, tall frame, portrait orientation" |
| 3:4 | "medium shot, portrait composition" |
| 1:1 | "centered composition, square frame" |

素材缓存：
- 文件名: `{shot_id}_{aspect_ratio}.png`
- 相同 prompt 结果缓存，避免重复生成
- 目录: `assets/backgrounds/`

### 2. Video IR 与模板匹配

`video_ir.json` 是渲染层稳定契约。它保留内容版本、平台、账号 Profile、场景、音轨、字幕、素材引用、布局、安全区、转场和质量规则。HyperFrames 和 Remotion adapter 都只消费 Video IR，不直接读取 Agent 的自由文本输出。

配置驱动的模板注册中心负责选择模板和渲染后端：

```typescript
interface ShotTemplate {
  id: string;
  supportedTypes: ShotType[];
  supportedBackends: RenderBackend[];
  compile: (props: ShotProps) => VideoIRScene;
}

const registry = new TemplateRegistry();
registry.register(NarrationTemplate);
registry.register(DialogueTemplate);
registry.register(ActionTemplate);
registry.register(TitleTemplate);

const template = registry.resolve(shot.type, theme);
```

冲突策略：当多个模板匹配同一 shot.type 时，按 `theme.templatePriority` 排序取第一个。

模板编译器接收标准化 props，输出后端无关的 Video IR：

```typescript
interface ShotProps {
  shot: Shot;
  theme: Theme;
  platform: PlatformConfig;
  audioDuration?: number;  // 单位: 秒，正式成片从 audio manifest 读取，预览可为空
  wordTimestamps?: WordTimestamp[];  // 逐字时间戳，正式字幕同步时从时间戳资产读取
}
```

### 3. Renderer Adapter

Renderer Adapter 将同一份 Video IR 转换为具体 composition：

```typescript
type RenderBackend = "hyperframes" | "remotion";

interface RendererAdapter {
  backend: RenderBackend;
  lint(ir: VideoIR): Promise<LintResult>;
  preview(ir: VideoIR): Promise<PreviewResult>;
  render(ir: VideoIR, output: RenderOutput): Promise<RenderResult>;
}
```

HyperFrames adapter 生成 HTML/CSS/JS composition，使用浏览器预览、逐帧捕获和 FFmpeg 编码。Remotion adapter 生成 React composition。两个 adapter 都必须先执行 composition lint，并在关键帧生成 snapshot 供 Gate 3b 校验。

### 4. 分层渲染

每个 shot 的画面分为三层，各层独立响应画面比例变化：

**背景层**: AI 生成的场景图，全屏铺满
**主体层**: 角色立绘/关键物体，根据平台比例调整位置和缩放
**文字层**: 字幕、标题，在平台安全区内定位

```tsx
export const ShotRenderer: React.FC<ShotProps> = ({ shot, theme, platform, audioDuration, wordTimestamps }) => {
  const { width, height } = useVideoDimensions();
  const isVertical = width / height < 1;

  return (
    <AbsoluteFill>
      <Img src={getBackground(shot.id, platform.aspect)} style={styles.background} />

      {shot.visual.layers.subject && (
        <Img
          src={shot.visual.layers.subject}
          style={getPosition(shot.visual.layers.subject_position, platform.aspect)}
        />
      )}

      <Subtitle
        text={shot.visual.layers.text.content}
        safeZone={getSafeZone(platform.id)}
        style={theme.subtitle}
        wordTimestamps={wordTimestamps}
      />

      {platform.aiLabelMode === "persistent_watermark" && <AILabel position="top-right" />}
    </AbsoluteFill>
  );
};
```

**主体层竖屏遮挡处理**：竖屏下底部 UI 遮挡区域较大，主体层需要额外上移：

```typescript
function getSubjectPosition(position, aspectRatio) {
  const base = position[aspectRatio];
  // 竖屏时额外上移，避免被底部 UI 遮挡
  if (aspectRatio === "9:16" || aspectRatio === "3:4") {
    return { ...base, y: `${Math.max(parseFloat(base.y) - 10, 10)}%` };
  }
  return base;
}
```

**安全区定义**：

| 平台 | 安全区（底部留白） |
|---|---|
| 抖音/快手 | 底部 18% (点赞/评论 UI) |
| 小红书 | 底部 15% |
| B站 | 底部 8% |
| 视频号 | 底部 16% |

每行字幕最大字数：

| 比例 | 每行最大字数 |
|---|---|
| 16:9 | 20 |
| 9:16 | 14 |
| 3:4 | 16 |

### 转场实现

转场定义保存在 Video IR 中。以下是 Remotion adapter 使用 `<Sequence>` + 自定义转场组件的实现示例：

```tsx
<TransitionSeries>
  {shots.map((shot, i) => (
    <TransitionSeries.Sequence durationInFrames={shot.frames}>
      <ShotRenderer shot={shot} />
    </TransitionSeries.Sequence>
    <TransitionSeries.Transition
      presentation={getTransition(shot.visual.transition.type)}
      durationInFrames={Math.round(shot.visual.transition.duration * fps)}
    />
  ))}
</TransitionSeries>
```

转场类型映射：
- `fade` → `<fade/>`
- `cut` → 无转场组件
- `slide` → `<slide/>`
- `zoom` → 自定义缩放组件

## 音频-视频时间轴同步

**所有时间单位统一为秒。**

视频线维护自己的时间轴状态，不直接修改音频线状态。

### 全局时间轴量化

正式视频不能对每个 shot 使用 `round(duration * fps)` 后直接相加，否则长视频会产生累计漂移。Video IR 必须先建立全局秒级时间轴，再按平台 fps 做全局量化。

规则：

1. 先计算每个 scene 的 `start_sec` / `end_sec`，以 audio manifest 的全局时间戳为准；无音频时使用估算时长。
2. 对全局边界做量化：`frame_start = round(start_sec * fps)`，`frame_end = round(end_sec * fps)`。
3. `frame_count = frame_end - frame_start`，最小值为 1 帧。
4. 最后一帧以音频总时长校准：`total_frames = round(audio_total_sec * fps)`。
5. 如果局部残差导致任意 scene 小于 1 帧或字幕窗口错位，按时间轴顺序分配残差，不允许直接丢帧。
6. Gate 3b 校验全章偏差和任意 60 秒窗口偏差。

```text
scene[0].frame_start = 0
scene[i].frame_start = round(scene[i].start_sec * fps)
scene[i].frame_end   = round(scene[i].end_sec * fps)
last.frame_end       = round(audio_manifest.total_duration_sec * fps)
```

静默预览可以使用估算时长，但必须在 manifest 中标明 `duration_source = estimated`；正式带声成片必须标明 `duration_source = audio_manifest`。
1. 音频流水线生成 TTS 音频后，精确测量实际时长（秒），写入 `audio_manifest.json`
2. ASR 返回逐字时间戳（秒），作为 timestamps asset 由 audio manifest 引用
3. 视频流水线在 `final-with-audio` 模式读取 audio manifest，生成 video timeline snapshot
4. 视频流水线读取 snapshot 中的 duration（秒）计算帧数：

```typescript
const frameStart = quantizeGlobalStart(scene.startSec, fps);
const frameEnd = quantizeGlobalEnd(scene.endSec, fps, totalAudioSec);
const durationInFrames = Math.max(1, frameEnd - frameStart);
```

5. 字幕组件读取 timestamps asset 实现卡拉 OK 效果

静默预览和估时预览使用 `shot.audio.estimated_duration` 或 placeholder audio，不宣称具备最终字幕级同步精度。

## 增量渲染

### shot 级别 checkpoint

`deepframes.video_step` 记录每个 shot 在素材生成、合成、渲染等阶段的完成状态；`deepframes.video_asset` 记录背景图、分层图、静默预览、带声成片等资产。

| 表 | 粒度 | 用途 |
|---|---|---|
| `deepframes.video_job` | project/chapter/platform/delivery/backend | 视频线一次生产任务 |
| `deepframes.video_step` | job/shot/stage | `image`、`video_ir`、`compose`、`lint`、`render` 等 shot 级状态 |
| `deepframes.video_asset` | job/shot/asset_type | 背景图、Video IR、composition、snapshot、preview、final video |

断点续跑时查询 `video_step.status`，跳过 `done` 的 shot，只重做 `failed` 和 `pending` 的。

### 渲染层断点

```bash
deepframes render --chapter 1 --platform bili --resume-from shot_080
```

Remotion adapter 利用 `--frames` 参数指定帧范围；HyperFrames adapter 按场景或帧区间捕获。长视频分章渲染后 FFmpeg 合并，章节交界处 0.5 秒交叉淡入淡出。

合并后同时校验全章总时长和局部滑动窗口偏差：全章偏差 > 0.5 秒警告；任意 60 秒窗口内音视频累计偏差 > 50ms 标记 Gate 3b 失败。章节交界交叉淡入淡出使用 equal-power curve，避免音频相位叠加导致可闻伪影。

## 性能估算

| 视频长度 | 素材生成 | 参考渲染耗时 (1080p) | 总计 |
|---|---|---|---|
| 5 分钟 | 2-3 分钟 | 8-15 分钟 | 10-18 分钟 |
| 10 分钟 | 4-5 分钟 | 15-30 分钟 | 19-35 分钟 |
| 30 分钟 | 8-12 分钟 | 45-90 分钟 | 53-102 分钟 |

> 含 retry 余量（按 10% 失败率估算）。ASR 逐字时间戳额外耗时约 10%。

优化手段：
- Renderer Adapter 默认并发设为 `min(CPU 核心数 - 1, 4)`，并在渲染前检查可用内存
- `--platform all` 默认按平台串行渲染；需要并行时显式传入 `--parallel-platforms N`
- 素材生成 10 路并行（令牌桶限流：60 req/min）
- 长视频分章并行渲染后 FFmpeg 合并

# 系统架构

## 概述

DeepFrames 是一个 AI 驱动的通用音视频内容自动生产系统，将文本、资料库、转录稿和人工录入内容自动转化为多平台音视频候选包。支持 B站、喜马拉雅、抖音、快手、小红书、视频号、YouTube 等平台的一次生产多版本输出。

**核心设计原则：音频与视频是两条独立的流水线。** 音频通常先行制作，视频按需后做。两条线各自完整，不互相阻塞。

## 战略基线

- 当前优先级是自用版生产工具，商业化、目标客户和销售包装后置，除非影响底层架构。
- DeepFrames 不按“先砍功能做 MVP”的方式定义产品；目标是完整功能的软件，允许按工程依赖分阶段实现，但架构和数据契约从一开始按完整产品设计。
- 长期定位是通用 AI 音视频生产工具，未来可作为独立产品销售，因此底层不能被小说、单平台或单渲染框架锁死。
- 核心竞争力优先放在多平台、多账号、多版本的工业化生产能力。
- 首个生产工作流以已经生产好的文章为主，目标视频默认不超过 15 分钟。
- 生产顺序是先稳定文章到音频/B站视频，再扩展从文章派生多平台短内容候选包。
- DeepFrames 只负责生产，不负责发布、运营、选题规划和数据复盘。
- 表达准确优先于传播效果；标题可适度强化吸引力，但正文不能歪曲原意。
- 同一文章可生成主版本和实验版本，默认 1+1，具体数量作为参数配置。

## DeepBase 集成基线

DeepFrames 是 **DeepBase 原生桌面应用**，不是 Web 控制台、SaaS 后台或 TypeScript 主程序。主控层、状态层、配置层、日志层、任务编排层和人工审核界面都由 Delphi + DeepBase 承担；Node、Chromium、HyperFrames、Remotion、FFmpeg 只作为可替换的外部 worker 或工具进程。

| 层级 | 方案 | 说明 |
|---|---|---|
| 桌面主程序 | Delphi VCL + DeepBaseVCL / DeepShell | Windows 自用版优先，FMX 作为未来跨平台扩展 |
| 配置与密钥 | DeepBase.Config + DeepBase.Security | 禁止散落 JSON、INI、Registry、明文 API Key |
| 日志与诊断 | DeepBase.Logging | 生产过程、外部 worker、API 调用统一入日志和事件表 |
| 数据访问 | DeepBase.Persistence + DoQry + migrations | DB1/DB2/DB3 分层，业务表不写入 ConfigDB |
| 任务编排 | DeepBase.DB.JobQueue + DeepBase.DB.StatusMachine | 支持幂等、心跳、断点续跑、失败回收 |
| LLM / 语音 | DeepBase.LLM / DeepBase.Speech 的 provider adapter | StepFun 作为模型与语音 provider，不绕过 DeepBase 配置和密钥体系 |
| 媒体工具 | FFmpeg / ffprobe / Chromium / HyperFrames / Remotion | 由 Delphi 主程序启动、监控、取消和收集结果 |

### 数据库边界

| 数据库 | 用途 | DeepFrames 约定 |
|---|---|---|
| DB1 `DeepFramesConfig.db` | DeepBase 框架配置、日志、i18n、窗体状态、MRU、Hotkeys、LLM 本地配置 | 必选，业务生产数据不得混入 |
| DB2 `DeepFramesData.db` | DeepFrames 私有业务数据、任务、文档版本、资产索引、质量门控结果 | 自用版默认 SQLite，路径由 DB1 的 `DB2.Path` 管理 |
| DB3 PostgreSQL / SQLite | 未来共享业务库或与 ArtifactOS 的交换层 | 需要协作或跨机器时启用，客户端不直接连接 DB4 |

### 核心文档链

DeepFrames 不直接从文章跳到镜头。稳定的业务链路是：

```text
source_document
  -> script_document
  -> accuracy_report
  -> variant_document
  -> shot_document
  -> audio_manifest / video_ir
  -> candidate_package
```

`chapter` 只是首个文章生产配方里的分段表现，底层统一称为 `content_unit`。同一篇文章可以拆成章节、观点单元、平台短版本或账号定位版本，但它们都走同一套内容单元和文档版本模型。
## 整体流水线

```
输入内容/资料库
  │
  ▼
┌──────────────┐
│ 1. 内容预处理  │  章节/主题切分、段落标注、角色/术语识别
└──────┬───────┘
       │  🚧 Gate 1: 结构校验（自动 + 参数化人工控制点）
       ▼
┌──────────────┐
│ 2. Agent 工作流 │  切片 → Worker → 汇总 → QA → 风格校验
└──────┬───────┘
       │  🚧 Gate 2: 内容审核（QA Agent + 参数化人工控制点）
       │
       │  输出: shot_document（叙事、音频指令、视觉意图和资产引用）
       │
       ├──────────────────────────────────────────┐
       ▼                                          ▼
┌────────────────────┐                  ┌────────────────────┐
│ 3a. 音频任务状态机   │                  │ 3b. 视频任务状态机   │
│ audio_jobs          │                  │ video_jobs          │
│                    │                  │                    │
│ 输入: shot_document │                  │ 输入: shot_document │
│ TTS/ASR/BGM/混音    │                  │ 图像/字幕/Renderer  │
│                    │                  │                    │
│ 输出: audio_assets  │                  │ 输出: video_assets  │
└─────────┬──────────┘                  └─────────┬──────────┘
          │                                       │
          │ 🚧 Gate 3a: 音频成品校验               │ 🚧 Gate 3b: 视频成品校验
          ▼                                       ▼
┌────────────────────┐                  ┌────────────────────┐
│ 4a. 音频生产包导出   │                  │ 4b. 视频生产包导出   │
│ 音频文件+元数据       │                  │ 视频文件+封面+元数据  │
└────────────────────┘                  └────────────────────┘
```

### 两条流水线的独立性

| 特性 | 音频流水线 | 视频流水线 |
|---|---|---|
| 运行时机 | Agent 完成后即可开始 | Agent 完成后即可准备素材，可延后成片 |
| 输入 | `shot_document` | `shot_document` + 可选 audio manifest |
| 私有状态 | audio_jobs / audio_steps / audio_assets | video_jobs / video_steps / video_assets |
| 输出 | MP3、timestamps、audio manifest | 静默预览、带声 MP4、多平台版本、video manifest |
| 质量门控 | Gate 3a，音频成品校验 | Gate 3b，视频成品校验 |
| 典型场景 | 先批量制作长内容音频 | 挑选章节/主题/观点单元配视频 |
| 控制入口 | 桌面端任务命令 `audio.run` | 桌面端任务命令 `video.render` |

**典型工作模式**：先集中制作长内容音频候选包；再按章节、主题或观点单元生成 B站及其他平台的视频候选包。视频线失败、排队或返工不会影响已通过 Gate 3a 的音频交付。

### 双线边界契约

两条流水线只共享上游叙事契约和资产引用，不共享内部状态。

| 范围 | 内容 |
|---|---|
| 共享契约 | project、content_unit、shot、文本、角色、风格、平台配置、资产引用 |
| 音频私有 | TTS job、ASR job、mix job、audio assets、audio QA、音频生产包状态 |
| 视频私有 | image job、render job、composition、video assets、video QA、视频生产包状态 |

音频线不能直接改写视频线状态，视频线不能直接改写音频线状态。跨线引用必须通过资产 manifest、数据库 asset 记录或只读快照完成。

### 视频流水线对音频资产的软引用

视频流水线可以读取音频线产出的资产快照：
- 从 audio manifest 获取精确 `duration`（用于计算正式成片帧数）
- 从 timestamps asset 获取逐字时间戳（用于字幕同步）
- 绑定 chapter audio asset 作为视频音轨

正式带声成片需要已通过 Gate 3a 的音频资产；视觉素材生成、静默预览和估时预览不需要等待音频完成。缺失音频只阻塞 `final-with-audio` 交付，不阻塞视频线的图片生成、模板校验和静默样片。

### 与 ArtifactOS（演擎）的集成边界

DeepFrames 是独立生产系统，只负责内容生产（音频、视频、字幕、封面、平台包和生产质量结果），不负责平台账号、登录会话、浏览器上传、自动发布、发布后运营或账号安全。双方只通过 DB3 / PostgreSQL 的 `integration.*` 层交换生产请求、生产结果与可消费资产状态。

| 方向 | 契约 |
|---|---|
| ArtifactOS → DeepFrames | 写入 `integration.production_request`，携带 SourcePack（源体系包）、Case（案）、章节、策略约束、目标平台和交付类型 |
| DeepFrames → ArtifactOS | 写入 `integration.production_result` 与 `integration.asset_status`，回传 audio manifest、video manifest、质量快照、平台包路径、元数据包和失败原因 |
| 禁止 | 互相调用内部服务、共享运行状态表、直接读写对方业务表、通过本地配置文件交换业务参数 |

`deepframes.*` 表只归 DeepFrames 写入；`artifactos.*` 表只归 ArtifactOS 写入；`integration.*` 表是双方唯一共享边界。DeepFrames 的所有业务配置、生产配方、平台规格和状态机参数均从数据库读取；密钥类敏感信息统一通过 DeepBase.Security 保存。

## 核心模块

### 1. 文本预处理

- **输入**: 本地文本/Markdown/PDF、网页内容、音视频转录稿、人工录入条目，或来自 DeepStory/ArtifactOS 的内容引用
- **处理**:
  - 章节、主题或观点单元自动切分为 `content_unit`
  - 对话/旁白识别
  - 角色声音标记
  - 情感/场景标注
- **输出**: `source_document` 与 `script_document`，可导出 JSON 快照
- **质量门控**: 自动校验完整性 + 可选人工确认角色/场景识别

### 2. Agent 工作流

- **输入**: `script_document` + 风格预设
- **Agent 链路**:
  - **Splitter**: 语义+时长双约束切分（4-6 秒/段），生成章节风格摘要和镜头组
  - **Worker**: 并行处理，接收 group 共享风格，生成画面描述 + 音频指令 + 字幕样式
  - **Assembler**: 汇总所有 shot，校验衔接连贯性
  - **QA Agent**: 独立质量审核（文本完整性、画面匹配、风格一致）
  - **Style Keeper**: 跨 shot 风格一致性校验
- **上下文**: 全局风格锚点 + 章节摘要 + group 共享风格 + 前后各 1 shot
- **输出**: `shot_document`（共享镜头契约，包含叙事文本、音频指令、视觉意图和资产引用）

### 3a. 音频流水线（独立）

- **TTS 引擎**: Step Plan `stepaudio-2.5-tts`
- **功能**: 多角色配音、结构化情感控制 `{emotion, pace, pitch}`、可选 BGM 通道（默认关闭）
- **输出格式**: MP3（各平台适配）
- **详情**: 见 `05.audio-音频流水线-audio-pipeline.md`
- **运行方式**: 音频线可独立批量运行，输出 audio manifest 供后续视频线按需引用

### 3b. 视频流水线（独立）

- **输入契约**: `shot_document`；正式带声成片额外绑定已通过 Gate 3a 的 audio manifest
- **渲染架构**: 统一 Video IR + Renderer Adapter
- **渲染后端**: HyperFrames（HTML/CSS/JS composition）与 Remotion（React composition）均可用，按模板、平台和许可证约束选择
- **架构**: 分层渲染（背景层/主体层/文字层）+ 多 Composition 多分辨率 + composition lint/snapshot QA
- **模板系统**: 配置驱动（TemplateRegistry + Theme + RenderBackend），Agent 输出 Video IR，不直接绑定某个渲染框架
- **输出**: 静默预览、带声成片，或按 `07.platform-多平台适配-multi-platform.md` 中定义的平台规格渲染多版本
- **详情**: 见 `04.video-视频流水线-video-pipeline.md`

### 4. 平台生产包导出

- **音频包**: 喜马拉雅等音频平台所需音频文件、封面和元数据
- **视频包**: B站、抖音、快手、小红书、视频号、YouTube 所需视频文件、封面和元数据
- **平台适配**: 各平台独立的画面比例、时长策略、元数据生成
- **AI 标注**: 根据平台要求在成品或元数据中添加 AI 生成内容声明
- **详情**: 见 `06.dist-内容分发-distribution.md`（候选包导出）和 `07.platform-多平台适配-multi-platform.md`

## 技术栈

| 层级 | 技术 |
|---|---|
| 桌面主程序 | Delphi VCL + DeepBaseVCL / DeepShell |
| 基础框架 | DeepBase Core / Services / Persistence / Features |
| 配置、日志、密钥 | DeepBase.Config / DeepBase.Logging / DeepBase.Security |
| 数据库 | DB1 SQLite ConfigDB + DB2 SQLite 业务库；DB3 PostgreSQL 可选 |
| 数据访问 | FireDAC + DeepBase.DB.DoQry + migrations |
| 任务编排 | DeepBase.DB.JobQueue + DeepBase.DB.StatusMachine + DeepFrames 业务状态表 |
| AI 推理 | StepFun provider adapter，接入 DeepBase.LLM |
| TTS / ASR | StepFun provider adapter，接入 DeepBase.Speech；中间音频优先 WAV/PCM |
| 图像生成 | StepFun image adapter，配置与密钥走 DeepBase |
| 视频渲染 | HyperFrames / Remotion / Chromium 作为外部 render worker，通过 Renderer Adapter 抽象 |
| 媒体处理 | FFmpeg / ffprobe 外部工具，由 Delphi 主程序管理 |
| 测试 | DUnitX + DeepBase 测试脚本；外部 worker 使用各自最小回归 |

## 数据流

```
content.md / source pack / transcript
  → import_source(content) → source_document
  → build_script(source_document) → script_document + accuracy_report
  → make_variants(script_document) → variant_document
  → agent_workflow(variant_document, preset) → shot_document
  ├→ audio_pipeline(shot_document) → audio_manifest + timestamps + audio assets
  └→ video_pipeline(shot_document, optional audio_manifest) → video_ir + preview/final assets
  → package(audio|video, platforms) → candidate_package（文件 + 元数据 + 质量快照）
```

## 使用规模假设

DeepFrames 当前按**单人单机桌面生产工具**设计，默认由一个操作者在本机运行桌面主程序完成导入、生产、审核、预览和候选包导出。StepFun 文字、语音、图像能力按包月使用，不在 DeepFrames 内置 token/次数预算拦截；如需成本统计，可作为日志或报表能力后置实现。

### 自用版首个生产工作流

自用版首个生产工作流以已经生产好的文章为主要输入，不从原始小说、未整理资料或运营选题自动规划起步。默认目标是将单篇文章生产为可交付的音频候选包和 B站视频候选包，单条视频目标时长不超过 15 分钟；超出时长时由系统自动拆分或浓缩，并保留原文依据引用。控制点可由参数设定，默认全自动跑到候选包，只有红灯停止，黄灯只提醒。该工作流是实现顺序上的起点，不代表产品能力边界。

| 场景 | 说明 |
|---|---|
| 文章转音频 | 将单篇文章生成配音、timestamps、BGM 混音和 audio manifest |
| 文章转视频 | 将单篇文章生成 15 分钟以内的视频候选包 |
| 多平台包 | 同一文章按平台规格导出文件、封面和元数据包，不负责实际上传 |

### 生产耗时关注点

DeepFrames 当前主要关注单机吞吐、断点续跑、输出质量和音视频独立运行，不以多租户安全、平台账号自动化或 API 费用控制作为当前阶段核心设计目标。

## 关键约束

- Step Plan 中文 TTS 短文本可能触发内容审查（451），需保证每段文本为自然完整句
- 渲染后端需通过 Renderer Adapter 隔离；Remotion 商业许可和 HyperFrames 依赖许可证在产品化前必须复核
- 各平台文件大小/时长/规格限制见 `07.platform` 文档
- AI 生成内容需按平台要求添加标注
- 视频线正式带声交付需要绑定已通过 Gate 3a 的音频资产；静默预览和视觉素材生成可独立运行

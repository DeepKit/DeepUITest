# Agent 工作流

## 概述

DeepFrames 采用 Multi-Agent 架构，将输入内容按语义切分后分配给多个 Agent 并行处理。Agent 链路包含 5 种角色：Splitter → Worker → Assembler → QA → Style Keeper。

本文档中的章节、角色和叙事镜头是首个生产配方，不是产品边界。通用内容可以按章节、主题或观点单元进入同一条 Agent 链路，并通过模板注册表选择讲解、问答、案例、观点冲突等表达模板。

**职责边界原则**：Assembler 只做数据层面的补全（时间轴间隙、时长匹配、格式校验），所有语义层面的质量判断统一收归 QA Agent。

## 工作流阶段

```
script_document (预处理与脚本化输出)
  │
  ▼
┌─────────────┐
│  Splitter    │  语义+时长双约束切分
│  Agent       │  生成章节风格摘要 + 镜头组
└──────┬──────┘
       │ shots[] + style_anchor + chapter_summary + shot_groups
       ▼
┌─────────────────────────────────┐
│     并行 Worker Agents (5-8路)   │
│                                │
│  每个 Worker 输入:              │
│  · 当前 shot 文本              │
│  · 全局风格锚点 (style_anchor)  │
│  · 章节摘要 (chapter_summary)  │
│  · group 共享风格 (group_style) │
│  · 前后各 1 shot (上下文)      │
│  · Few-shot 示例               │
│                                │
│  ┌─────┐ ┌─────┐ ┌─────┐     │
│  │Shot1│ │Shot2│ │Shot3│ ... │
│  └──┬──┘ └──┬──┘ └──┬──┘     │
└─────┼───────┼───────┼────────┘
      │       │       │
      ▼       ▼       ▼
┌─────────────┐
│  Assembler   │  数据层补全：时间轴、时长匹配、格式校验
│  Agent       │  （不做语义质量判断）
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  QA Agent    │  语义质量审核（默认 deepseek-v4-pro）
│  (强模型)    │  不合格 shot → 展示给用户 → 用户决定回流重做
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Style Keeper│  跨 shot 风格一致性校验
│  Agent       │
└──────┬──────┘
       │
       ▼
  完整镜头脚本 (`shot_document`，可导出 shots.json 快照)
  → 进入 Gate 2 审核
```

## Agent 定义

### 1. Splitter Agent（切片器）

**职责**: 将章节文本按语义+时长双约束切分为镜头单元，生成章节级风格摘要和镜头组。

**切分优先级**（从高到低）：
1. 场景切换（地点/时间变化）
2. 角色切换（对话轮转）
3. 情感转折（氛围突变）
4. 时长阈值（4-6 秒，弹性范围 3-8 秒）

**镜头组(group)概念**:
- 3-5 个语义相近的 shot 组成一个 group
- group 内共享视觉风格参数（`group_style`），减少背景图重新生成
- 跨 group 才做明显的风格/背景切换
- group 边界处额外注入首尾 shot 摘要，防止长章节（50+ shots）跨 group 风格漂移

**输入**:
```json
{
  "chapter_id": 1,
  "title": "第一章 初入江湖",
  "segments": [...],
  "characters": [
    {"name": "张三", "voice_id": "voice_a", "description": "年轻侠客"}
  ],
  "preset_id": "xuanhuan"
}
```

**输出**:
```json
{
  "style_anchor": {
    "art_style": "中国水墨画与奇幻风格融合",
    "color_palette": ["深蓝", "金色", "紫色"],
    "tone": "大气磅礴，略带神秘"
  },
  "chapter_summary": "张三初入江湖，在客栈遇到神秘老者，获得一本武功秘籍。基调：好奇+紧张。场景：客栈、街道、山间小路。",
  "shot_groups": [
    {
      "id": "group_01",
      "shot_ids": ["shot_001", "shot_002", "shot_003"],
      "group_style": "客栈内景，暖黄灯光，木质结构，江湖气息",
      "boundary_summary": "张三推开客栈大门 → 落座饮酒，氛围从紧张转为好奇"
    }
  ],
  "shots": [...]
}
```

### 2. Worker Agent（Per-Shot）

**职责**: 为单个镜头生成完整的音视频指令。

**输入（包含 group 上下文）**:
```json
{
  "current_shot": { "text": "...", "type": "narration" },
  "context": {
    "style_anchor": { "art_style": "...", "color_palette": [...], "tone": "..." },
    "chapter_summary": "...",
    "group_style": "客栈内景，暖黄灯光，木质结构，江湖气息",
    "prev_shot": { "...summary..." },
    "next_shot": { "...summary..." }
  },
  "few_shot_examples": ["...2-3个高质量shot示例..."]
}
```

`group_style` 由 Splitter 在切分阶段生成，作为同组所有 Worker 的共享视觉参数。Worker 在 `background_prompt` 中必须延续 group_style 的视觉基调。

**结构化输出**:
```json
{
  "shot_id": "shot_001",
  "group_id": "group_01",
  "audio": {
    "text": "夜色笼罩着古城，远处传来悠扬的笛声。",
    "voice": "cixingnansheng",
    "emotion": "mysterious",
    "pace": "slow",
    "pitch": "low",
    "instruction": "神秘低沉，语速偏慢"
  },
  "visual": {
    "background_prompt": "[中国水墨画风] + [古城墙远景，月光下城墙轮廓，灯笼微光] + [远景低角度] + [月光冷色调] + [深蓝与金色]",
    "target_aspect_ratios": ["16:9", "9:16"],
    "layers": {
      "subject": null,
      "text": {
        "content": "夜色笼罩着古城，远处传来悠扬的笛声。",
        "position": "bottom",
        "style": "fade-in"
      }
    },
    "transition": {
      "type": "fade",
      "duration": 0.5
    }
  }
}
```

**画面描述 Prompt 模板**: `[画风] + [主体] + [构图] + [光影] + [色调]`，从 `style_anchor` + `group_style` 自动填充画风和色调部分。

### 3. Assembler Agent（汇总器）

**职责**: 数据层面的补全和校验（不做语义质量判断）

**处理范围**:
- 补全 shot 间的时间轴间隙
- 校验音频时长与视频时长在数值上匹配
- 修正格式错误（字段缺失、类型不匹配）
- 编号连续性检查

**不做**:
- 画面质量判断 → QA Agent
- 风格一致性检查 → Style Keeper
- 转场语义自然度 → QA Agent

**输出**: 初版 `shot_document`，必要时导出 `shots.json` 调试快照

### 4. QA Agent（质量审核）

**职责**: 独立语义质量把关，默认使用 `deepseek-v4-pro`；其他 Agent 默认使用 `stepfun-flash-3.5`。最终模型分配由生产前配置确定，DeepFrames 不内置 LLM 自动路由策略。

**检查维度**:

| 维度 | 规则 | 不合格处理 |
|---|---|---|
| 文本完整性 | 字幕文本与原文覆盖率 ≥ 95% | 标记遗漏段落 |
| 画面匹配度 | 画面描述与文本语义相关 | 标记 |
| 情感一致性 | emotion 标注与语境匹配 | 标记 |
| 风格统一性 | 同 group 内画风一致 | 标记 |
| 转场连贯性 | 相邻 shot 转场自然 | 标记 |
| 时长合理性 | 单 shot 3-8 秒，无异常值 | 标记 |

**输出**:
```json
{
  "gate_result": "pass | warn | fail",
  "score": 0.85,
  "issues": [
    {
      "shot_id": "shot_023",
      "type": "style_inconsistency",
      "severity": "warn",
      "description": "画风从水墨切换到写实",
      "suggestion": "统一为中国水墨画风"
    }
  ]
}
```

**Gate 2 审核流程**:
- QA 结果为 `pass` → 自动通过
- QA 结果为 `warn` → **展示给用户**，由用户决定是接受还是重做
- QA 结果为 `fail` → 标记问题 shot，展示给用户，用户确认后回流 Worker 重做（最多 2 轮）
- 仍不合格则标记 `degraded: true` 走降级方案

### 5. Style Keeper Agent（风格一致性）

**职责**: 横跨所有 shot 的全局风格校验

**处理**:
- 建立章节级"风格指纹"：主色调、画风关键词、构图偏好
- 逐 shot 比对偏差，标记偏离过大的 shot
- 检查 group 间过渡是否平滑（避免 group 边界处风格突变）
- 输出风格修正建议

## Prompt Registry

所有 Agent 的 prompt 必须以版本化模板管理，不能只写在代码里。

| Agent | 默认模型 | Prompt 模板要求 |
|---|---|---|
| Splitter | `stepfun-flash-3.5` | system prompt、切分规则、输出 JSON schema、1 个完整章节切分示例 |
| Worker | `stepfun-flash-3.5` | system prompt、画面描述模板、音频指令模板、2-3 个 shot few-shot 示例 |
| Assembler | `stepfun-flash-3.5` | 只允许数据补全与格式修复，不做语义判断 |
| QA | `deepseek-v4-pro` | 质量评分 rubric、hard/soft issue 定义、pass/warn/fail 阈值 |
| Style Keeper | `stepfun-flash-3.5` | 风格指纹定义、偏差阈值、修正建议格式 |

Prompt 文件需包含 `prompt_version`，并与 `schema_version` 一起写入 job metadata，便于复现同一次生产结果。生产前用户可修改 Agent 到模型的映射，但 DeepFrames 不实现自动模型路由。
### DeepBase 持久化约束

Prompt Registry 是 DB2 中的真实业务模块，不是代码目录里的 prompt 文件集合：

| 表 | 用途 |
|---|---|
| `deepframes_prompt_template` | prompt 模板、版本、输出结构和 few-shot 示例 |
| `deepframes_prompt_run` | 每次调用的模板版本、模型、输入、输出、耗时和错误 |
| `deepframes_model_binding` | Agent 角色到 DeepBase.LLM provider/model 的明确绑定 |
| `deepframes_eval_result` | QA、人工复核和评估结果 |

StepFun Chat 调用通过 DeepBase.LLM adapter 执行，API Key 通过 DeepBase.Security 保存。Agent 不在 VCL UI 线程同步调用远程 API。

## 编排策略

### 并行度控制

- Worker Agent 并行数：配置化（默认 5-8）
- Splitter、Assembler、QA、Style Keeper 串行执行
- 采用令牌桶 + 自适应并发：监控 API 响应延迟，动态调整窗口

### 错误处理（按类型分级）

| 失败类型 | 处理策略 |
|---|---|
| TTS 451 审查 | 自动改写文本重试 1 次，仍失败则降级 |
| API 限流 (429) | 指数退避重试，最多 3 次 |
| 网络超时 | 固定间隔重试，最多 3 次 |
| Agent 推理异常 | 降级为简化模板 |
| Worker 失败 | 重试 3 次，标记 degraded |

### 重试/时间约束

- 全局最大重试轮次：2 轮（QA 回流）
- 单 shot 最大重试次数：3 次
- Agent 阶段默认超时：30 分钟（可配置）
- StepFun 文字模型按包月使用，DeepFrames 当前不做 token/次数预算拦截；异常重试只按稳定性和生产耗时控制

### 降级 Agent

当 shot 无法正常生成时，输出简化版本保证时间轴完整：

```json
{
  "shot_id": "shot_023",
  "metadata": {
    "degraded": true,
    "degraded_reason": "image_generation_failed",
    "fallback": "solid_color_background + subtitle_only"
  }
}
```

批量降级修复命令：
```bash
deepframes repair --chapter 1 --degraded-only
```

## 数据格式约定

Agent 阶段以 Delphi 领域对象和 DB2 版本化文档为主契约；JSON 仅用于模型结构化输出、worker payload 和导出快照。每个 payload 必须带 `schema_version`，进入下一阶段前由 Delphi 校验。

核心数据：
- **script document**: 预处理与脚本化输出，Splitter 的输入，写入 `deepframes_script_document`
- **shot document**: Agent 工作流最终输出，音频和视频流水线各自的输入，写入 `deepframes_shot_document`
- **job/step tables**: 任务状态（shot 级别 checkpoint），写入 `deepframes_job`、`deepframes_job_step` 和音视频阶段表，支持断点续跑

shot_id 规则：章节内唯一，格式 `shot_{三位序号}`（如 `shot_001`, `shot_002`）。

Schema 变更时需通过快照测试验证向后兼容。

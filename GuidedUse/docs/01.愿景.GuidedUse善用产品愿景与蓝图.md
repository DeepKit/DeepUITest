# GuidedUse 善用产品愿景与蓝图

> 产品名：善用 / GuidedUse
> 定位：桌面悬浮式软件任务陪跑系统
> 用户：个人用户 / 小团队 / 独立软件作者 / 自研软件用户 / 未来软件厂商客户成功团队
> 当前策略：先自用和轻产品验证，后续再外放

```text

```

英文表达：


---

## 产品本质

善用不是教程平台，也不是 RPA，更不是普通 AI 问答。

善用是一个软件任务陪跑系统：

```text
用户正在使用某个软件
  -> 善用悬浮在旁边
  -> 显示当前步骤、图卡、线框图、聚焦框和提示语
  -> 用户按提示在真实软件里操作
  -> 卡住时进入 LostRecovery
  -> 最终完成一个真实任务
```

核心目标不是让用户学完整个软件，而是让用户先完成第一件有价值的事。

## 第一阶段边界

第一阶段优先做：

```text
1. 桌面悬浮播放器
2. GuidePackage 善用包
3. TaskJourney 任务旅程
4. StepInstruction 步骤提示
5. SceneVisual 场域视觉
6. FocusSketch 聚焦线框图
7. VisualAnchor 视觉锚点
8. RouteRule 路由
9. LostRecovery 迷路恢复
10. TraceEvent 卡点记录
```

第一阶段暂缓：

```text
1. 自动点击和自动填写
2. 重 RPA
3. 完整 UI Automation
4. 复杂 OCR
5. 浏览器插件
6. 多人协作和企业权限
7. 行业专家库
8. 大 B 投标型项目
```

## 第一批样板

优先样板：

```text
善用指导 DeepLaunch 绑定第一个快速启动程序
```

样板价值：

```text
1. 场景清楚
2. 步骤可控
3. 有真实桌面软件
4. 能展示 FocusSketch
5. 能展示 LostRecovery
6. 能和 DeepUITest 后续测试链形成闭环
```

后续样板：

```text
善用指导用户创建第一个 FocusSketch
善用指导 Cursor 完成第一个 AI 编程任务
善用指导 ChatGPT 完成一个固定工作流
善用指导自研软件完成首次配置
```

## 与 OCGS 的关系

OCGS 放在后台，不作为第一层市场表达。

内部对象映射：

```text
用户要完成的任务结果 = Output
当前软件页面或状态 = FieldScene
当前要操作的位置 = AccessGate / VisualAnchor
当前步骤说明 = StepInstruction
下一步规则 = RouteRule
卡住后的恢复 = LostRecovery
完成和卡点记录 = Trace / Evidence
善用包发布 = Seal
```

对外只讲：

```text
新软件不会用？善用一步步带你用。
```

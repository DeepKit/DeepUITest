## 1. 原子性与唯一性原则

### 1.1 原子性

每个阶段只能验证一个主要假设，且必须有明确输入、输出、通过标准和失败处理。

| 阶段 | 只验证什么 | 不混入什么 |
|---|---|---|
| P0a | 数据可达性：发现、只读打开、schema 识别、兼容性报告 | 互动分析、隐私画像、状态提示 |
| P0b | 元数据有效性：方向、时间线、频率、响应延迟、沉默/回暖指标 | 正文、关键词、成交意图、话术 |
| P0c | 隐私与证据可审计性：PRIVATE/UNKNOWN 隔离、body-zero、证据链、删除 | 写备注/标签、UIA、发送辅助 |
| P0.5 | 小样本客户雷达验证：Top 20 命中率、隐私误入率、证据可理解性 | 产品化交付、发送、群发 |
| P1 | 本地客户雷达 + 可解释跟进队列 + 数据导出；标签/备注只读解析（L0/L1）；少量短标签写回为独立可选功能（用户主动触发） | PC 微信 UIA 粘贴、批量发送 |
| P1.5 | 产品事实卡 + 轻量订单信号 | 完整订单系统、自动营销 |
| P2 | 半自动话术、绿/黄/红审核、分波发送、发送后追踪 | 自动发送、绕过用户确认 |
| P3 | 朋友圈轻量运营、群聊深度、多账号汇总 | 大规模平台自动化 |

P0 标签矩阵范围：闲人判定、身份、互动状态、渠道、关键日期、广告追踪。不包含产品关联（置信度不足）、行为标签、交易标签（需 M1 内容分析）。

任何功能如果依赖后续阶段能力，不得提前放入前一阶段。

## 2. P0 目标

P0 要回答五个问题：

1. 能否在用户本机稳定发现并以只读方式打开微信数据源。
2. 能否在不读取消息正文的 `M0 元数据模式` 下，形成联系人、群聊、互动时间线和基础趋势。
3. 能否证明代码路径没有访问正文列、没有写入微信数据库、没有触发 UIA。
4. 能否在隐私确认前后严格隔离 `PRIVATE` 和 `UNKNOWN` 联系人。
5. 能否为每条客户雷达提示提供可追溯证据，证明“为什么这个人被列入今日关注”。

P0 的成功标准不是“用户能完成销售动作”，而是“核心数据链路可信、可失败、可复现、可审计、可继续扩展”。

## 3. 隐私模式

P0 只实现 `M0 元数据模式`。

| 模式 | 读取内容 | 能力 | 阶段 |
|---|---|---|---|
| `M0` 元数据模式 | 联系人、群聊、消息时间、方向、类型、数量；不读取消息正文 | 互动频率、响应延迟、沉默/降温提示、基础隐私排除 | P0 |
| `M1` 内容分析模式 | 用户显式授权后的业务联系人消息正文短期快照 | 关键词、摘要、意图、话术上下文 | P1+ |
| `M2` 微信写回模式 | 单独授权后通过 UIA 写短标签/短备注 | 手机微信可见的状态交付 | P1+ 技术验证 |
| `M3` 发送辅助模式 | 单独授权后定位联系人、粘贴草稿，用户手动发送 | 半自动效率工具 | P2+ |

**M1 数据保留与清理**：M1 产生的派生数据（摘要、事实提取、画像标签、话术上下文）默认保留在本地。用户可随时在面板中删除任意联系人的派生数据。删除操作必须级联清理该联系人的所有 M1 派生产物——摘要删除、标签矩阵中 M1 推导的标签重置为 P0 推断值或留空、话术草稿删除。原始消息正文快照不长期存储——M1 分析完成后仅保留结构化提取结果，快照在 24 小时后自动清理。
| `M2` 微信写回模式 | 单独授权后通过 UIA 写短标签/短备注 | 手机微信可见的状态交付 | P1+ 技术验证 |
| `M3` 发送辅助模式 | 单独授权后定位联系人、粘贴草稿，用户手动发送 | 半自动效率工具 | P2+ |

P0 文案不得出现“表达过兴趣但未成交”“上次对话摘要”“关键词识别”“价格/效果/购买意图”等依赖消息正文的能力，除非明确标注为 `M1` 后续能力。

### 3.1 UNKNOWN 默认拒绝

隐私状态的默认策略：

| 隐私状态 | P0 行为 |
|---|---|
| `BUSINESS + HUMAN_CONFIRMED` | 可进入指标、雷达提示、证据报告 |
| `BUSINESS + SYSTEM_GUESS` | 只进入候选队列；若将出现在首屏，必须先让用户确认 |
| `PRIVATE` | 不进入指标、雷达提示、导出报告；已产生的派生数据必须级联删除 |
| `IDLE`（闲人） | 关联产品数=0。可进入广告建议队列。不可进入产品状态机。广告次数超限后进入删除建议。 |
| `UNKNOWN` | 不展示、不导出、不生成状态、不进入营销建议；只进入”待确认身份”队列 |

## 4. P0 范围

### 4.1 范围内

1. 微信数据源发现：自动检测常见微信数据目录，允许手动选择路径。
2. 多数据源识别：发现多个微信数据源时记录 `source_account_id`，P0 只分析用户选定的一个源；跨号合并后置。
3. 数据源兼容性报告：记录微信版本、数据库文件、schema 指纹、读取结果。
4. SchemaAdapter 契约：每个支持的 schema 必须有字段白名单、禁止字段、方向映射、时间戳规则、消息类型归一化和失败原因。
5. 只读数据适配：读取联系人、群聊、消息元数据，不写入微信数据库。
6. 正文零访问验证：记录正文列是否存在、是否被查询、写入次数、UIA 调用次数。
7. 小规模隐私分流：高置信私人自动隐藏，`UNKNOWN` 默认不分析；只让用户确认影响首屏的少量联系人。
8. 元数据指标：最近互动时间、互动频率、响应延迟趋势、单向消息比例、长期沉默、近期回暖。
9. 客户雷达提示：生成“互动明显下降”“长期未联系”“最近重新活跃”“我发多对方回少”“数据不足”等提示。
10. 证据链：每个提示保存触发信号、时间窗口、阈值、置信度、数据来源、不确定性、失效时间。
11. 本地审计日志：记录扫描、读取、字段访问、隐私决策、指标计算、提示生成、删除。
12. 删除能力：用户可以删除 P0 本地数据、审计报告和导出文件。

### 4.2 范围外

- 不读取消息正文。
- 不做关键词、摘要、意图、价格、成交判断。
- 不生成销售话术。
- 不写微信备注或标签。
- 不操作 PC 微信 UIA。
- 不发送或粘贴任何消息。
- 不做群发、绿/黄/红审核、发送后追踪。
- 不做多微信号合并。
- 不做朋友圈、订单、素材库、仪表盘。
- 不做云端同步或上传。

## 5. P0 原子任务

### 5.1 P0a：数据可达性

| 编号 | 任务 | 输入 | 输出 | 通过标准 |
|---|---|---|---|---|
| A0 | 数据源扫描 | 本机微信目录或手动路径 | `DataSourceScan` | 能列出候选数据源或给出明确失败原因 |
| A1 | 只读打开 | 数据库文件 | `ReadOnlyOpenReport` | 使用只读连接或只读快照，不锁库、不写库 |
| A2 | Schema 探测 | 数据库文件 | `SchemaReport` | 匹配已知 `SchemaAdapter` 或输出不支持原因 |
| A3 | 字段访问计划 | `SchemaAdapter` | `FieldAccessPlan` | 列出允许字段、禁止字段、正文列、查询计划 |

### 5.2 P0b：元数据有效性

| 编号 | 任务 | 输入 | 输出 | 通过标准 |
|---|---|---|---|---|
| B0 | 元数据读取 | 支持的 schema | `Contact`、`Conversation`、`MessageMeta` | 不读取正文，能构建 90 天互动时间线 |
| B1 | 方向归一化 | `MessageMeta` | `DirectionMappingReport` | 能解释方向来源；不能确定时标为 `unknown` |
| B2 | 指标计算 | `MessageMeta` | `InteractionMetric` | 每个确认业务联系人有可解释指标或 `DATA_INSUFFICIENT` |
| B3 | 客户雷达提示 | 指标、隐私决策 | `RadarHint` | 每条提示有证据链、置信度、不确定性 |

### 5.3 P0c：隐私与证据可审计性

| 编号 | 任务 | 输入 | 输出 | 通过标准 |
|---|---|---|---|---|
| C0 | 小规模隐私分流 | 联系人、元数据特征 | `PrivacyDecision` | `PRIVATE/UNKNOWN` 不进入雷达提示 |
| C1 | body-zero 验证 | 查询日志、字段访问计划 | `BodyZeroReport` | 正文列查询次数 = 0，写入次数 = 0，UIA 调用次数 = 0 |
| C2 | 证据导出 | 扫描和提示结果 | `p0-evidence.md` / `p0-report.json` | 可复现本次判断，不含消息正文 |
| C3 | 删除级联 | 本地 P0 数据 | `DeletionManifest` | 删除指标、提示、报告、缓存；保留最小删除审计 |

任务必须按顺序通过。任一任务失败，后续任务不得伪造数据继续。

## 7. 验收标准

### 7.1 工程验收

P0 通过必须同时满足：

1. 至少 1 个真实本机微信数据源完成 P0a-P0c。失败也要输出明确原因——哪一步失败了、为什么、建议的替代路线。
2. 全流程不读取消息正文，不写入微信数据，不触发 UIA。
4. `BodyZeroReport` 显示：`body_columns_queried = false`、`write_attempts = 0`、`uia_calls = 0`。
5. 对不支持的微信版本能输出明确兼容性报告，而不是静默失败。
6. `PRIVATE` 和 `UNKNOWN` 联系人没有进入雷达提示、指标展示或导出报告。
7. 每条 `RadarHint` 都能追溯到元数据证据和阈值。
8. 同一输入重复运行输出一致，除时间戳和审计 ID 外无非确定性差异。
9. 用户可以删除本地生成的 P0 数据和审计报告。

### 7.2 产品验收

P0.5 小样本验证必须同时满足：

1. 5 分钟内出现首批可解释联系人，或明确说明数据不足。
2. 用户能对每条雷达提示标记：`有用 / 不准 / 私人 / 不是客户 / 以后提醒`。
3. Top 20 今日关注中至少 1 个联系人被用户认为“值得看一下”。
4. 用户能理解每条提示的证据，不需要阅读系统内部术语。
5. 用户能一键删除本地 P0 数据和报告。

## 8. 失败分流

| 失败点 | 处理 |
|---|---|
| A0/A1 数据不可达或读取不稳定 | 转向用户授权导入、企微/API、CRM 导入路线 |
| A2 schema 不支持 | 输出兼容性报告，不做猜测读取 |
| B0/B1 方向或时间线不可解释 | 停止状态提示，只输出数据质量报告 |
| B3 雷达提示价值低 | 不进入 UIA/发送层，先做业务客户白名单或 M1 小范围授权验证 |
| C0 隐私确认成本过高 | 先做用户导入业务客户名单白名单，不做全量扫描后排除 |
| C1 body-zero 失败 | 阻断 P0，通过安全审查后重做 |

## 9. 后续阶段原则

### 9.1 P1：客户雷达安全交付版

P1 只在 P0 通过后进入，优先实现：

- 本地客户雷达看板。
- 可解释跟进队列。
- 数据导出。
- 文件传输助手异常提醒和日报总结（用户手动发送）。
- 标签/备注只读解析（L0/L1）。
- 标签/备注整理手动模式（L0建议 + 用户自行在微信操作）。

P1 不做 PC 微信 UIA 粘贴、批量发送。UIA 粘贴到输入框属于 P2 辅助模式。

### 9.2 P1.5：事实底座

P1.5 补齐后续话术和绿灯规则所需事实：

- 产品事实卡：价格区间、库存/活动、卖点、禁用承诺、FAQ、素材。
- 轻量订单信号：已买、待付款、待发货、已发货、售后中、复购周期。

没有事实底座前，不能把复购、物流、售后类消息列为稳定绿灯。

### 9.3 P2：辅助效率版

P2 才进入：

- 半自动话术。
- 绿/黄/红审核。
- 分波发送。
- 发送后追踪。

P2 仍不可自动发送。所有物理发送动作必须由用户完成。

### 9.4 微信写回原则

微信写回仅在以下场景启用，且必须用户主动触发：

1. **标签/备注整理**（L2 操作）：用户审核建议 → 预览 → 点击"执行" → 系统通过 UIA 批量操作。分级体系详见 `08.开发层-标签与备注整理规格.md`。
2. **文件传输助手消息**：仅用于异常提醒和日报总结。系统粘贴到输入框，用户手动发送。
3. **辅助模式粘贴**：系统通过 UIA 粘贴话术到 PC 微信输入框（P2）。

准确表述为：
> DeepAxis 不上传到自有云；启用微信写回后，选定字段会写入微信并受微信同步机制影响。

完整话术留在 DeepAxis 面板。备注追加写入只允许标准化字段（渠道、成交日期、产品、生日），不承载话术、敏感摘要、购买兴趣。

## 0. 定位

本文是 DeepAxis 用户界面的唯一设计事实源。定义面板布局、信息架构、交互规范和视觉标准。

**核心原则**：用户 90% 的时间在微信窗口上。DeepAxis 的存在是"余光里的驾驶舱"——扫一眼就知道该做什么、按一个键就执行。

**DeepBase 集成原则**：DeepAxis UI 使用 DeepShell 的命令、设置、布局、日志和 Governance 接入能力；业务工作台布局自定义。所有按钮、快捷键、菜单和后台动作必须注册为 Command，高风险动作必须绑定 Gate。

## 1. 架构决策：竖条面板，挂在微信右侧

```

│                            │ 280×全屏高  │
│  ┌──────────┬────────────┐ │            │
│  │ 会话列表  │ 聊天区      │ │ ① 整体指南 │
│  │          │            │ │   (上部)   │
│  │          │            │ │            │
│  │          │            │ ├────────────┤
│  │          │            │ │ ② 人名列表  │
│  │          │            │ │   (左下)   │
│  │          │            │ ├────────────┤
│  │          │            │ │ ③ 详细信息  │
│  │          │            │ │  +操作指导  │
│  │          │            │ │   (右下)   │
│  ├──────────┴────────────┤ │            │
│  │ 微信输入框              │ │            │
│  └───────────────────────┘ │            │
└────────────────────────────┴────────────┘

280px 宽，高度追随微信窗口。
SetWindowPos 自动跟随微信窗口移动/缩放。

```

**和之前三种布局模式的关系**：

| 模式 | 宽度 | 场景 |
|------|------|------|
| **竖条面板**（默认） | 280px | 日常发送。挂在微信右侧 |
| **扩展面板** | 400px | 用户拖动分隔条展开。多出标签矩阵+证据链 |
| **全屏面板** | 副屏全宽 | 双显示器。独立窗口在副屏 |

竖条是默认。用户随时向右拖动左边框 → 展开到 400px。再拖回来 → 回到 280px。

## 2. 区域①：上部 — 整体指南

**位置**：面板顶部，固定高度约 160px，始终可见不滚动。

**内容**：全局统计 + 今日综合要求。用户扫一眼就知道"今天整体什么情况"。

```
┌────────────────────────┐
│ DeepAxis               │  28px 标题行
│                        │
│ 📊 今日概览             │  14px 小节标题
│ ┌────────────────────┐ │
│ │ 待跟进  12人        │ │  48px 大数字，最显眼
│ │ 待回复   3人 🔴     │ │
│ │ 降温预警 8人 🟡     │ │
│ │ 闲人可广告 156人    │ │
│ └────────────────────┘ │
│                        │
│ 📋 今日建议             │  14px 小节标题
│ ┌────────────────────┐ │
│ │ 建议群发: 47条      │ │
│ │ 话术模板: 新品推荐   │ │
│ │ 预计耗时: ~6分钟    │ │
│ │ [开始审核 →]       │ │
│ └────────────────────┘ │
├────────────────────────┤
│ (分隔线，下面可滚动)    │
└────────────────────────┘

高度：~160px。始终固定，不随下面滚动。
```

**设计要点**：
- 上部信息不滚动——用户随时扫一眼顶部就知道全局状态
- "待跟进"数字最大——这是用户每天打开 DeepAxis 第一眼看的东西
- "开始审核"按钮——点击后，下方的人名列表自动加载该批次联系人
- 颜色语义：🔴=需立即处理，🟡=关注，无标记=正常

**位置**：面板下部左侧，约 45% 宽度 (~126px)，可滚动。

│          │                 │

**设计要点**：
- 按三色分组（绿灯在前、黄灯居中、红灯在后）
- 每个名字一行，紧凑排列（行高 28px），颜色圆点 + 名字
- 当前选中行高亮（背景色加深 + 左侧 3px 蓝色竖条）
- 已发送的联系人名字变灰 + 前面 ✓ 标记
- 跳过的联系人名字变灰 + 前面 — 标记
- 支持键盘 ↑↓ 切换，Enter 或 Space 粘贴
- 滚动时分组标题（🟢绿灯）吸顶

**分组折叠**：
- 绿灯默认展开
- 黄灯默认展开
- 红灯默认展开（红灯数量少，通常 3-8 人）
- 用户点击分组标题可折叠/展开

## 6. 交互规范

### 6.1 键盘操作

**全局热键**（`RegisterHotKey`，微信内也能触发）：

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+Shift+Enter` | 粘贴当前话术到微信输入框 | 全局热键（避免与中文输入法 Ctrl+Shift+Space 冲突）|
| `Ctrl+Shift+S` | 跳过当前选中联系人 |
| `Ctrl+Shift+E` | 焦点跳到话术编辑框 |
| `Ctrl+Shift+H` | 显示/隐藏 DeepAxis 面板 |
| `Ctrl+Shift+1/2/3` | 切换话术风格（变体1/2/3） |

**面板内快捷键**（DeepAxis 有焦点时生效，不干扰微信）：

| 键 | 生效条件 | 功能 |
|----|---------|------|
| `Space` | 焦点在审核区（非编辑框） | 粘贴话术到微信输入框 + 切焦点 |
| `Enter` | 焦点在审核区 | 同 Space |
| `Esc` | 任意位置 | 跳过当前联系人 / 取消编辑 |
| `E` | 焦点在审核区（非编辑框） | 进入话术编辑模式 |
| `1` `2` `3` | 焦点在审核区 | 切换到话术变体1/2/3 |
| `↑` `↓` | 焦点在审核区或人名列表 | 上/下一个联系人 |
| `Ctrl+Enter` | 焦点在编辑框 | 确认编辑完成，退出编辑模式 |
| `Tab` | 焦点在编辑框 | 跳到下一个可替换变量 |

**焦点在 TRichEdit 编辑框内时**：E/1/2/3/Space 作为正常文字输入，不触发热键。

### 6.1.1 Command/Gate 绑定

UI 不直接执行业务动作。以下动作必须通过 DeepShell CommandManager：

| UI 动作 | Command | Gate |
|---|---|---|
| 读取正文授权 | `wechat.read_body` | `wechat.read_body_gate` |
| 粘贴话术 | `wechat.uia_paste` | `wechat.uia_paste_gate` |
| 最终发送 | `wechat.final_send` | `wechat.final_send_gate` |
| 写备注/标签 | `wechat.write_remark_tag` | `wechat.writeback_gate` |
| 删除联系人 | `contact.delete` | `contact.delete_gate` |
| 批量准备队列 | `bulk.prepare_queue` | `bulk.prepare_queue_gate` |
| 执行分波 | `bulk.execute_wave` | `bulk.execute_wave_gate` |

按钮 `OnClick`、快捷键回调和后台任务不得绕过 Command/Gate 直接调用业务服务。

### 6.2 鼠标操作

| 操作 | 目标 | 效果 |
|------|------|------|
| 点击人名 | 人名列表中的联系人 | 选中该联系人，右侧刷新详细信息 |
| 双击人名 | 人名列表中的联系人 | 选中 + 自动执行粘贴 |
| 点击 [Space 粘贴发送] | 按钮 | 粘贴话术到微信输入框 + 切焦点 |
| 点击 [Esc 跳过] | 按钮 | 跳过当前，移到下一个 |
| 点击 [E 编辑] | 按钮 | 话术进入编辑模式 |
| 点击 [1] [2] [3] | 按钮 | 切换话术变体 |
| 点击 ▸ 证据/标签/历史 | 折叠区 | 展开查看详情 |
| 拖动面板左边框 | 面板左边缘 | 调整宽度 (280↔400px) |
| 点击分组标题 🟢绿灯 | 列表分组头 | 折叠/展开该分组 |

### 6.3 颜色与无障碍

绿黄红三色分类**必须同时使用颜色+图标+文字**，不可只用颜色：

| 分类 | 颜色 | 图标 | 文字 |
|------|------|------|------|
| 绿灯 | #4CAF50 绿 | 🟢 | 绿灯 |
| 黄灯 | #FF9800 橙 | 🟡 | 黄灯 |
| 红灯 | #F44336 红 | 🔴 | 红灯 |

默认字号：客户名 14pt Bold，正文 11pt，标签 10pt。按钮最小点击区域 40×28px。

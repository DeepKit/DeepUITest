## 0. 文档地位

本文定义 DeepAxis 标签和备注整理功能的操作分级体系和安全边界。

核心原则：**系统永远是"建议者"不是"决定者"。用户主动触发，预览确认后执行，可随时撤销。**

---

## 1. 操作分级体系

| 级别 | 定义 | 触发方式 | 边界分类 | 示例操作 |
|------|------|---------|---------|---------|
| **L0 只读分析** | 只分析本地数据，不产生任何对微信的变更 | 自动（无���用户触发） | 🟢 | 检测重复标签、格式不一致备注、语义等价标签 |
| **L1 面板建议** | 在 DeepAxis 面板生成结构化整理建议 | 自动展示，用户可关闭 | 🟢 | "建议将'宝妈''妈妈用户'合并为'宝妈'（覆盖47人）" |
| **L2a 逐条确认后执行** | 用户逐条勾选 → 预览 → 点击"执行" → 系统通过 UIA 操作微信 | 用户主动逐条触发 | 🟡 | 合并 2 个标签、修改 5 个联系人的备注追加字段 |
| **L2b 批量确认后执行** | 用户审核建议列表 → 批量勾选 → 预览 → 分批执行 | 用户主动批量触发 | 🟡 | 批量合并 10 组标签、批量追加 50 条备注格式 |
| **L3 预设规则后自动** | 用户预设条件规则 → 系统检测到符合条件时自动执行 | 系统按规则自动执行 | 🟠 | "以后新增的来源:小红书联系人自动打标签" |

## 2. 标签整理

### 2.1 能做什么（L0-L2）

- **重复标签检测**（L0）：自动发现语义重复标签组，建议合并
- **僵尸标签清理**（L1）：检测超过 3 个月未使用的标签，建议清理
- **标签合并**（L2a/L2b）：用户确认后，通过 UIA 给一批联系人加标签 B、删标签 A
- **标签创建建议**（L1）：根据客户行为数据建议新标签
- **新好友标签建议**（L1）：加好友时自动建议标签

### 2.2 不能做什么

- 不自动修改标签（L3 仅限用户预设的可枚举规则）
- 不基于 AI 推断自动打标签
- 不删除用户手动创建的标签（除非用户在整理建议中勾选同意）
- 不静默操作——所有写操作必须有预览和确认

### 2.3 安全参数

| 参数 | 安全值 | 红线 |
|------|--------|------|
| 单次操作联系人 | ≤100人 | 不超过300人 |
| 操作间隔 | 800-3000ms 随机 | 不低于400ms |
| 批次休息 | 每30人休息5-8秒 | 不可连续跑 |
| 单日总量 | ≤300次 | 不超过500次 |
| 时间窗口 | 08:00-22:00 | 深夜不操作 |
| 两次整理间隔 | ≥7天 | 不连天操作 |

### 2.4 标签矩阵维度完整列表

DeepAxis 内部标签矩阵包含以下维度。每个维度按可用阶段标注。所有标签由系统分析聊天历史自动推导，附带来源证据和置信度。

| 维度 | 阶段 | 标签值域 | 推导来源 | 置信度阈值 |
|------|------|---------|---------|-----------|
| 闲人判定 | P0 | `闲人` / `已关联产品` | 产品关联数=0 | 0.70 |
| 身份 | P0 | `客户` / `朋友` / `家人` / `同行` / `竞品` / `待确认` | 微信标签名匹配 + 用户确认 | 0.75（自动）1.0（确认后） |
| 产品关联 | P1+ | 产品名列表 | M1 内容分析 + 群聊归属 | 0.65 |
| 产品状态 | P0(per-product) | 0-9 | 双轴状态机 | 0.80（自动）0.50-0.80（建议） |
| 互动状态 | P0 | `活跃` / `降温` / `长期沉默(>90d)` / `极长期沉默(>180d)` | MessageMeta 自动计算 | 0.90 |
| 渠道 | P0 | 渠道名 | 备注正则提取 | 0.70 |
| 关键日期 | P0 | 日期 | 备注正则提取 | 0.85 |
| 广告追踪 | P0（仅闲人） | 计数+时间+状态 | 系统自计数 | N/A |
| 行为标签 | P1+ | `转介绍者` / `促销敏感` / `决策快速` / `社交型` / `投诉倾向` | M1 语义分析 | 0.60 |
| 交易标签 | P1+ | `欠款` / `退款过` / `投诉过` | M1 语义分析 | 0.70 |
| 沟通偏好 | P1+ | `语音偏好` / `晨间活跃` / `周末沉默` | 消息类型/时间统计 | 0.60 |

**举证原则**：标签必须附带来源证据。置信度低于阈值时该维度留空，不猜测。**宁愿空白也不乱标。**

## 3. 备注整理

### 3.1 能做什么（L0-L2）

- **备注信息提取**（L0）：正则提取日期/金额/电话（M0模式即可做）
- **格式规范化建议**（L1）：检测格式不一致，建议统一
- **追加标准化字段**（L2a）：在备注末尾追加 `┊渠道:小红书 ┊成交:0520`，不修改用户原文
- **备注补全建议**（L1）：根据对话元数据建议补充缺失信息

### 3.2 不能做什么

- 不修改用户原文（`┊` 之前的内容绝不改动）
- 不覆盖写入
- 不自动写备注（必须用户确认）
- 不挖掘个人信息（婚姻状况、家庭矛盾等）

### 3.3 备注追加格式

```
用户原文（DeepAxis 绝不修改）
┊渠道:小红书 ┊成交:0520 ┊产品:面膜 ┊生日:11.15
```

追加字段定义：
| 字段 | 格式 | 示例 |
|------|------|------|
| 渠道来源 | `┊渠道:{渠道名}` | `┊渠道:小红书` |
| 成交日期 | `┊成交:{MMDD}` | `┊成交:0520` |
| 产品兴趣 | `┊产品:{产品名}` | `┊产品:面膜` |
| 生日 | `┊生日:{MMDD}` | `┊生日:1115` |

## 4. 安全网

### 4.1 操作前

- **全量预览**：执行前展示每条修改的具体内容（操作前→操作后）
- **影响分析**：标注每个操作的后果（如"删除此标签后，47个联系人将不再出现在'准客户'筛选结果中"）

### 4.2 操作中

- **操作前快照**：记录每个受影响联系人的当前状态，72小时可撤销
- **分批暂停**：每10条暂停一次，用户确认后继续
- **写入前二次校验**：写备注前重新读取，检测并发冲突→暂停→提示用户
- **实时进度展示**：显示成功/失败/待处理数量

### 4.3 操作后

- **验证报告**：逐条对比 SQLite 确认结果，失败条目加入重试
- **撤销窗口**：72小时内可逐条或批量撤销
- **审计日志**：记录所有操作的时间、内容、结果

## 5. 默认模式与升级路径

**默认 = 手动模式**（L0 + L1：DeepAxis 只显示建议，用户在 PC 上通过 DeepAxis 面板的操作指引在微信中自行操作）。

```
手动模式（默认，L0+L1）
  │ 用户手动执行 ≥ 10 条建议，系统验证准确率 ≥ 95%
  ▼
L2a 逐条确认后自动执行
  │ 用户使用 L2a ≥ 10 次，无撤销操作
  ▼
L2b 批量确认后自动执行
  │ 用户主动创建规则
  ▼
L3 预设规则后自动执行（日上限 20 条 + 熔断机制）
```

每一步升级必须由用户主动选择。每级都有"退回上一级"按钮。

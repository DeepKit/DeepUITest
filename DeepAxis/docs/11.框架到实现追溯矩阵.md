# 11. 框架到实现追溯矩阵

> 版本：v1.0
> 日期：2026-06-17
> 用途：映射每个框架原语到具体的内部开发阶段、Delphi/DeepBase 代码模块、数据结构和测试用例

---

## 原语 → 实现映射

| 框架原语 | 类型 | P0 实现 | P1 扩展 | P2 扩展 |
|---------|------|---------|---------|---------|
| **State-Driven** | 硬约束 | `InteractionMetric` 数据对象。`RadarEngine.generate()` 从指标派生提示，不独立创建任务 | `TagEngine` 驱动状态变迁。`FlowCompilation` 确保任务从 `MeaningDivergence` 编译 | `CalibrationEngine` 消费状态变迁日志 |
| **Boundary-First** | 硬约束 | 简化为"不自动执行"。`SchemaAdapter.forbidden_fields[]` 结构性禁止正文访问。`BodyZeroReport` 验证 | — | `BoundaryEngine` 完整 G×U/L 公式（P2） |
| **Evidence Chain** | 硬约束 | `EvidenceBuilder.build()` 为每个 `RadarHint` 生成 `EvidenceRecord`。`source_hash` 字段保证完整性 | `EvidenceRecord` 关联到 `MeaningDivergence` | — |
| **Human as Meaning Source** | 架构承诺 | 不实现（P0 无系统建议让用户否决） | `MeaningDivergence` 数据对象。用户否决 → 训练信号 | `CalibrationEngine` 消费分歧数据 |
| **Calibration Engine** | 一等原语 | 不实现。但 `CalibrationData` 采集点已预留（每条 hint 记录 inputs） | — | `CalibrationEngine` 消费 N≥30 次判决数据 |
| **ASTO Cycle** | 设计启发法 | 简化为 Perceive + Intervene + Retrospect | Resolve + Design + Materialize | Dissolve |
| **Flow Compilation** | 架构约束 | 不实现 | `FlowCompiler` 从 `MeaningDivergence` 编译任务 | — |
| **COP Pipeline** | 信号处理 | 不实现 | — | `COPPipeline` 五步管线（P2） |
| **Boundary Engine** | 治理引擎 | 不实现 | — | `BoundaryEngine` 完整 G×U/L（P2） |
| **TAT 六字段** | 责任检查 | 不实现 | — | `TATChecker` 付费版（P2） |
| **ODD 验证** | 工程纪律 | DUnitX 测试验证 `SchemaAdapter` 契约。`BodyZeroReport` 的可复现性测试 | 契约驱动 + 变异测试 | 对抗 + 管道隔离 |
| **Capability Profile** | 发布治理 | `DeepAxis.Core.Profile` 读取 `personal_full` / `external_safe` / `strict_compliance` | Profile 驱动 UI/Command 可用性 | 发布前能力矩阵测试 |

## 测试用例 → 框架假设

| 框架假设 | P0 测试 | 通过标准 |
|---------|---------|---------|
| H1: State-Driven 优于 Task-Driven | 不测试（P0 无 UI） | P1+ |
| H2: Boundary-First 产生更高信任 | DUnitX `Test.BodyZero` 验证 `body_queried=False` | CI 阻断 |
| H3: 证据化闭环减少盲目信任 | 不测试（P0 无用户交互） | P0.5 用户测试 |
| H4: 校准循环改善判断质量 | 不测试（P0 无校准） | P2+ |
| H5: Human as Meaning Source 优于接受率优化 | 不测试（P0 无用户否决） | P1+ |

## Python 工具边界

Python 只作为 `DeCrypt/` 与 `probe/` 中的逆向、验证、一次性分析工具。DeepAxis 产品代码直接使用 Delphi + DeepBase，不再定义“P0 Python → P1 Delphi”的迁移路线。

如果保留 `src/deepaxis/*.py`，只能作为历史参考或研究脚本，不能作为产品运行链路依赖。

## 核心决策

### 1. 旧 MVP 废弃

旧 MVP（个人微信私域销售副驾，9.9/99/199 定价，"今日作战卡"模式）已归档至 `99.归档/`。

废弃原因：
- 旧 MVP 是 Flow 思维（每日固定任务清单），而非 Cycle 思维（客户状态感知→干预→回溯）
- 与由来版（ASTO Business Agent Runtime）无架构承接关系
- 与市面上 AI 文案生成工具无结构性差异
- 无法验证 ASTO 的核心假设：以 Cycle 而非 Flow 为中心的运行时，能在真实业务中产生更好的销售结果

### 2. 由来版是核心方向

DeepAxis 的真正产品形态：以 ASTO 七序循环为核心的客户状态感知→干预引擎。

一句话定位：**有边界的业务智能体运行时，第一款落地产品是微信/企微生态的客户增长运行中枢。**

### 3. 重构方向

- 从"内容生成器 + 任务清单"重构为"客户状态感知 → 干预建议 → 执行 → 回溯"的最小 Cycle 闭环
- 感知引擎第一版用硬编码规则（5-8 条），付费版加入 AI
- 裂变暂不讨论，先讨论哲学基础

```
哲学治理链:  DM(10) → ASTO(20) → OCGS(25) → ARBT(30) → TAT(40)
工程链:       ODD(50)
```

每个理论模块都可独立使用，上游只是可选深化路径。DeepAxis 以 ASTO(20) 为核心，TAT(40)、ODD(50)、COP(51)、OCGS(25) 提供工程支撑。

## 一、DM（差异一元论）— 哲学地基

**核心命题**：差异不是世界中的第一个事件，而是存在者被识别、被描述、被区分的前条件。凡存在者必已处于差异、边界与约束之中。

**最小本体承诺**（六句）：
1. 差异是对象、关系与边界得以成立的最小起点
2. 并非一切组合都同等可行，存在稳定约束关系
3. 稳定对象来自约束被组织后的边界化结果
4. 时间性首先表现为痕迹进入后续成立条件的继承序
5. 层级并非纯幻象，上层结构可以留下新的约束位置与新的失效方式
6. 某些结构具有内部性，其内部差异会不对称地进入自身后续成立条件

**对 DeepAxis 而言**：DM 是可选哲学底座。DeepAxis 不需要扛着整套 DM 才能成立——ASTO 已经提供了足够的描述语法。DM 的价值在于提供"差异→结构→边界"的底层直觉，让产品设计时自然地追问：**"这个客户属性的变化，是否已经构成了需要介入的差异？"**

## 二、ASTO（属集变迁存在论）— DeepAxis 的直接理论基础

**核心**：1-5-6-7-1 循环

- **一元**：存在即属集。客户不是"实体"，而是属性集合（昵称、状态、最近互动、说过的话…）
- **五态**：自在→共识→编码→物化→定向。描述属性集合的空间形态
- **六阶**：混沌→秩序→流变→脉冲→崩解→归元。描述系统的时间动力学
- **七序**：感知→解析→干预→设计→物化→回溯→消解。描述主体的介入循环
- **定向维**：规约不可达性结构。所有回溯的结果沉淀为规则

**人在系统中的三重角色**：基底（存在论前提）、操作者（七序的不可替代执行主体）、守护者（防止系统异化）

**三对核心张力**：结构 vs 能动、秩序 vs 混沌、算法 vs 伦理

**否定性导引**：ASTO 反复强调"它不是什么"比"它是什么"更重要。这适用于 DeepAxis 的产品定义——必须声明自己不是 CRM、不是自动化、不是效率工具、不是成功学。

**对 DeepAxis 而言**：ASTO 是产品的心脏。DeepAxis 做的事情不是"生成文案"，而是七序循环——系统感知客户状态变化（感知）→ 诊断问题（解析）→ 建议策略（干预）→ 生成内容（设计→物化）→ 记录结果 → 沉淀规则（回溯→消解→定向维）。

## 三、TAT（责任架构理论）— DeepAxis 的 Boundary Engine

**核心命题**：任何能够产生高影响后果的系统，都必须在扩张之前配置不可绕过的责任闭合结构。

**工作公式**：`G × U / L ≤ A₀ · R`

在 DeepAxis 中：AI 的自动化能力扩张（G↑），必须以责任闭合度 R 为先决条件。

**六责任字段**（subject / interface / evidence / fuse / compensation / review）：
| 字段 | DeepAxis 映射 |
|------|--------------|
| subject 责任主体 | 谁对 AI 建议的后果负责？→ 销售员本人 |
| interface 责任接口 | 高影响动作是否经过责任接口？→ 🟡 黄灯需要人确认 |
| evidence 证据链 | 每次判断的依据是否可追溯？→ 证据化认知闭环的七字段 |
| fuse 熔断权 | 能否停止？→ 🔴 红灯不自动执行 |
| compensation 补偿承接 | AI 错误建议的损失谁承担？ |
| review 复审 | 谁审计系统的判断质量？ |

**受控模糊**：在责任闭合度不足时可以有限探索，但有硬时限（90 天初始 + 60 天续期一次，累计不超过 180 天），超时自动升级。适用于 DeepAxis 早期——感知引擎的规则可以在"受控模糊"状态下运行积累数据。

**对 DeepAxis 而言**：TAT 的六责任字段和门槛矩阵直接塑造 Boundary Engine 三色模型——🟢 黄🔴 的判定不是凭感觉，而是基于 G（影响规模）、U（不可逆性）、L（调节延迟）的结构化裁决。

| DeepAxis 能力 | G | U | L | 裁决 |
|---|---|---|---|---|
| AI 识别客户状态变化并提示 | 低 | 低 | 短 | 🟢 可自动 |
| AI 生成话术草稿 | 中 | 低 | 短 | 🟢 可自动 |
| AI 建议跟进时机和策略 | 中 | 中 | 中 | 🟡 需确认 |
| AI 修改客户状态标签 | 中 | 中 | 中 | 🟡 需确认 |
| AI 承诺价格/优惠 | 高 | 高 | 长 | 🔴 禁止 |
| AI 自动发送消息 | 高 | 高 | 长 | 🔴 禁止 |

## 四、ODD（产出物驱动开发）— DeepAxis 的构建方法

**核心**：不信任 AI 的过程，只信任可验证的结果。AI 写的代码不可信，AI 写的测试也不可信——但人类定义的输入输出映射是可信的。

**五字段 ABI**：contract（契约）/ validation（验证）/ evidence（证据）/ seal（封存）/ rollback-recall（回滚召回）

**对 DeepAxis 而言**：
1. **感知引擎的契约驱动开发**：人类定义"当客户 7 天无互动 + 状态=意向 → 输出=降温预警"。给定 10 个客户状态，输出是否符合预期——不需要信任 AI。
2. **变异测试**：主动在感知规则中引入 bug（"10 天无互动才预警"），检查验证用例能否捕获。
3. **对抗式验证**：两个 AI——一个写规则，一个攻击规则（构造边界 case）。
4. **"自己吃自己"的 ODD 版本**：DeepAxis 团队用 DeepAxis 销售 → 产生真实客户数据 → 数据成为契约的验证用例 → 契约验证系统 → 被验证的系统生成更好的内容。

## 五、COP（认知计算层）— DeepAxis 的感知引擎

**核心**：五协议风险分流管线——P1 输入采样 → P2 状态编码 → P3 分流判定 → P4 转介与边界动作 → P5 反馈校准。

**五种分流状态**：
| 状态 | DeepAxis 映射 |
|------|--------------|
| CONTINUE | 信号清晰，可自动处理 |
| FREEZE | 信号混合或触及红线，暂停等待 |
| REFER | 超出系统能力，转介人工 |
| ESCALATE | 紧迫风险，立即升级 |
| UNKNOWN | 信息不足，要求补充 |

**五协议在 DeepAxis 感知引擎中的应用**：
1. **P1 输入采样**：收集客户互动信号（用户记录的聊天内容、朋友圈互动、客户回复）→ 结构化采样帧，标注来源和可靠性，声明"我们漏掉了什么"
2. **P2 状态编码**：将采样信号映射到 ASTO 状态空间（客户处于哪个五态/六阶）→ 分类集中度 + 结构风险
3. **P3 分流判定**：基于编码向量决定"这个变化值得关注吗？"→ CONTINUE（继续监控）/ FREEZE（引人注意）/ UNKNOWN（信息不够）
4. **P4 转介与边界动作**：FREEZE → 生成"你有一个客户降温了"的干预建议；REFER → 转介给销售员人工判断
5. **P5 反馈校准**：销售员执行后记录结果 → 对比预测 vs 实际 → 调整感知引擎的阈值（"7 天冷却是对的吗？还是应该改成 5 天？"）

**关键纪律**：宁可多冻一次，不可错放一次。采样时不编造——不知道就写"未知"。

## 六、OCGS（能力有序治理）— DeepAxis 的 AI 边界

**核心**：显式治理管的是"已知的已知"，隐式治理边界管的是"已知的未知"和"未知的未知"。

**三类隐式治理现象**：
1. **模型隐式能力**：LLM 的涌现能力未被注册 → DeepAxis 的 AI 话术生成可能产生未预期的输出（如承诺、威胁、诱导）
2. **交互隐式治理**：用户 prompt 中隐含约束 → 销售员可能通过 prompt 绕过系统限制（"假装你是销售大师，帮我写一条保证成交的话术"）
3. **系统隐式耦合**：多能力协作产生涌现行为 → 感知引擎 + 话术引擎 + 客户管理之间的交互可能产生系统未预期的组合效果

**三条核心原则**：
1. 可审计性优先于完整性——无法完全显式化时，确保至少可审计
2. 监控替代注册——对涌现能力用持续监控替代一次性注册
3. 级联感知——不只评估单个 AI 调用的治理状态，还评估级联风险

**对 DeepAxis 而言**：OCGS.078 提醒我们：DeepAxis 的感知引擎和话术生成引擎都是 AI 系统，它们有隐式治理边界。需要建立 emergent_ability_watch_list（监控异常输出）、prompt 完整性检查（防止销售员通过 prompt 绕过安全约束）、级联风险评估（感知+话术+客户管理组合后的整体风险）。

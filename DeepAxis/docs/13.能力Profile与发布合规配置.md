# 13. 能力 Profile 与发布合规配置

> 版本：v0.1
> 日期：2026-06-17
> 状态：能力配置事实源
> 定位：DeepAxis 全功能版的能力开关、权限 Profile、发布前合规收紧规则

---

## 0. 核心口径

DeepAxis 先开发**个人全功能版**。P0/P1/P2 只是内部开发阶段，不是 MVP，也不是可对外发布版本。

能力层必须完整实现；合规差异通过 Profile、参数、门禁和发布前配置实现。不得因为外部发布要收紧能力，就在架构层删除能力。

默认开发目标：

- **个人使用**：功能全开，由使用者自担风险，仍保留审计、证据、撤销和熔断。
- **外部发布**：同一套能力通过 Profile 收紧，高风险动作必须由用户做最后确认。
- **严格合规**：进一步关闭正文读取、写回、删除、最终发送等高风险能力。

## 1. Profile

| Profile | 用途 | 默认策略 |
|---|---|---|
| `personal_full` | 作者个人使用、全功能开发验证 | 能力全开；L2/L3 动作保留审计和熔断 |
| `external_safe` | 对外发布默认配置 | 写回、删除等动作必须确认；最终发送默认关闭；部分高风险能力默认关闭 |
| `strict_compliance` | 更保守的商业/团队环境 | 正文读取、批量写回、联系人删除、最终发送默认关闭 |

Profile 存储在 DeepBase DB1 ConfigDB：

```text
DeepAxis.Profile.Current = personal_full | external_safe | strict_compliance
```

发布包不得通过删除代码来实现合规版。发布前只允许通过 Profile 和 Governance 配置收紧能力。

## 2. 能力开关

能力开关统一存入 DeepBase DB1 ConfigDB，不创建散落的 JSON/INI/YAML 配置文件。

| Capability | 说明 | `personal_full` | `external_safe` | `strict_compliance` |
|---|---|---:|---:|---:|
| `wechat.m0.metadata_read` | 只读联系人、群聊、消息元数据 | on | on | on |
| `wechat.m1.body_read` | 授权后读取业务联系人正文 | on | per_contact_confirm | off |
| `wechat.m2.writeback_tag_remark` | 备注/标签写回 | on | confirm_each_batch | off |
| `wechat.m3.uia_paste` | UIA 定位联系人并粘贴草稿 | on | confirm_each_batch | off |
| `wechat.final_send` | 自动触发最终发送动作 | on | off | off |
| `contact.delete` | 微信联系人删除辅助 | on | confirm_each_contact | off |
| `bulk.prepare_queue` | 批量准备发送队列 | on | confirm_each_batch | confirm_each_batch |
| `bulk.wave_sending` | 分波执行发送队列 | on | confirm_each_wave | off |
| `llm.local` | 本地 LLM/规则话术 | on | on | on |
| `llm.cloud` | 云端 LLM 话术/分析 | on | explicit_consent | off |
| `export.report` | 导出本地报告 | on | privacy_filtered | privacy_filtered |
| `multi_account` | 多微信号管理 | on | on | review_required |

动作值含义：

| 值 | 含义 |
|---|---|
| `on` | 允许执行，仍记录审计 |
| `off` | 禁用；命令不可执行 |
| `explicit_consent` | 首次启用需显式授权 |
| `per_contact_confirm` | 每个联系人或联系人组需授权 |
| `confirm_each_batch` | 每批次执行前用户确认 |
| `confirm_each_wave` | 每波执行前用户确认 |
| `confirm_each_contact` | 逐个联系人确认 |
| `privacy_filtered` | 必须经过隐私过滤后导出 |
| `review_required` | 需要用户复核配置和输出 |

## 3. Governance 映射

所有高风险能力必须通过 DeepBase Governance 的 Command/Gate/Action 体系执行。按钮、快捷键、菜单和后台任务不得绕过 CommandManager。

| Action | Capability | Risk | Gate |
|---|---|---:|---|
| `wechat.read_metadata` | `wechat.m0.metadata_read` | L1 | `wechat.read_metadata_gate` |
| `wechat.read_body` | `wechat.m1.body_read` | L3 | `wechat.read_body_gate` |
| `wechat.write_remark_tag` | `wechat.m2.writeback_tag_remark` | L3 | `wechat.writeback_gate` |
| `wechat.uia_paste` | `wechat.m3.uia_paste` | L2 | `wechat.uia_paste_gate` |
| `wechat.final_send` | `wechat.final_send` | L3 | `wechat.final_send_gate` |
| `contact.delete` | `contact.delete` | L3 | `contact.delete_gate` |
| `bulk.prepare_queue` | `bulk.prepare_queue` | L2 | `bulk.prepare_queue_gate` |
| `bulk.execute_wave` | `bulk.wave_sending` | L3 | `bulk.execute_wave_gate` |
| `llm.cloud_analyze` | `llm.cloud` | L3 | `llm.cloud_gate` |
| `export.report` | `export.report` | L2 | `export.report_gate` |

`personal_full` 可以允许 L3 动作执行，但不能跳过 Evidence、AuditEvent、ActionRun 和失败回滚记录。

## 4. 平台限制保护

DeepAxis 可以做节流、排队、熔断和异常检测，目的只能是：

- 降低误操作风险；
- 避免用户无法处理大量回复；
- 避免本地微信或数据库被高频操作压垮；
- 在异常、封禁风险、窗口状态不确定时暂停动作并提示用户。

不得把“模拟人类操作”设计成规避平台反自动化检测的能力。实现中可以保留面向安全的节奏控制和熔断，但文档、配置和代码不得包含绕过检测、隐身规避或欺骗平台风控的策略。

## 5. 最终发送策略

`wechat.final_send` 是 L3 高风险能力。

| Profile | 策略 |
|---|---|
| `personal_full` | 可开启。自动发送必须记录发送前草稿、目标联系人、触发来源、时间、执行结果和撤回窗口。 |
| `external_safe` | 关闭。系统最多定位联系人并粘贴草稿，最终发送由用户完成。 |
| `strict_compliance` | 关闭。发送辅助也默认关闭。 |

即使在 `personal_full` 中，以下情况也必须熔断：

- 联系人隐私状态为 `UNKNOWN` 或 `PRIVATE`；
- 草稿包含禁用承诺、医疗/功效保证、价格越权承诺；
- UIA 无法确认当前会话目标；
- 发送队列与当前微信号不匹配；
- 发送后只读检测无法确认结果。

## 6. 发布前合规收紧

发布外部版本前必须执行：

1. Profile 切换为 `external_safe` 或 `strict_compliance`。
2. Governance 切换为 `gmEnforce`。
3. 验证 L2/L3 Gate、ActionGrid、DueRule、Evidence 持久化全部可用。
4. 运行能力矩阵测试，确认关闭能力不可被 UI、快捷键、后台任务绕过。
5. 导出发布配置快照，写入发布审计。

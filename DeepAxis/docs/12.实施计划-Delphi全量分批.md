> 版本：v1.0
> 日期：2026-06-17
> 状态：已确认方向，待开始编码
> 口径：个人全功能版优先；P0/P1/P2 为内部开发阶段，不是 MVP 或对外发布版本
> 依赖：[13.能力Profile与发布合规配置](13.能力Profile与发布合规配置.md)

## 架构决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 语言 | **Delphi 13.1 + VCL**（直接，不做 Python P0） | DeepBase 已可用，P0 代码直接成为 P1 骨架 |
| 解密 | **A路径：内存扫描 → 存入配置DB**（先）/ B路径：DLL Hook（后） | 内存扫描已验证可行，Hook 作为高版本后备 |
| 密钥存储 | **KeyScanner → DeepBase.Security + DB2 引用** | 解耦解密和主程序；密钥不明文写入 SQLite；不创建 `key_config.db` |
| 交付形态 | **持续监控 VCL 面板**（非一次性报告） | 用户需要实时监控，非报告 |
| 价值主张 | **微信路人到产品成交的价值促进工具** | 用户可理解的一句话 |
| 范围 | **个人全功能版，分批实现** | 用户使用的是完整产品；阶段只是内部开发顺序 |
| 能力治理 | **Profile + DeepBase Governance** | 个人版全开；外部发布前通过配置收紧 |
| UI 壳 | **TDeepMainForm + DeepAxis 自定义工作台** | 复用 DeepShell 命令/设置/日志/Governance，业务布局自定义 |

## 分批交付计划

### 批次 0：地基（Week 1-2）

**目标**：KeyScanner 独立 EXE 可用 + DeepAxis 骨架可运行

| # | 任务 | 模块 | 输出 |
|---|------|------|------|
| K0 | KeyScanner 项目骨架 | `KeyScanner.dpr` | 可编译的 EXE 骨架 |
| K1 | 微信进程发现 + 内存读取 | `WeChat.Scanner.pas` | 列出所有 Weixin.exe PID，读取 MEM_COMMIT 区域 |
| K2 | Hex key 模式扫描 | `WeChat.Scanner.pas` | 搜索 `x'<64hex><32hex salt>'` 模式 |
| K3 | HMAC 验证 + Secret 写入 | `WeChat.Scanner.pas` | 验证后调用 `DeepBase.Security.SaveSecret`，DB2 只保存 source_account 与 secret_ref |
| K4 | DeepAxis 项目骨架 | `DeepAxis.dpr` | 可编译的 VCL 骨架 |
| K5 | 数据源管理 + 解密 | `Core.Config.pas` + `WeChat.Decrypt.pas` | 读取 DB2 secret_ref，通过 `DeepBase.Security.LoadSecret` 解密后只读打开微信 DB |
| K6 | SchemaAdapter 接口 + 参考实现 | `WeChat.Adapter.pas` + `Adapter411053.pas` | 字段白名单/黑名单、方向映射、类型归一化 |
| K7 | DeepBase 初始化 | `DeepAxis.dpr` | `DeepBase.InitializeOrRaise` + `DeepBase.Persistence.Manager.FireDAC` |
| K8 | Profile 初始化 | `Core.Profile.pas` | 默认 `personal_full`，可切换 `external_safe` / `strict_compliance` |
| K9 | Governance observe | `Core.Governance.pas` | 注册 L2/L3 Action/Gate，先 `gmObserve` |

**批次 0 交付物**：
- `KeyScanner.exe`：一键扫描 → Secret 写入 DeepBase.Security → DB2 保存数据源和 secret_ref
- `DeepAxis.exe`：启动 → 初始化 DeepBase → 读取 Profile → 解密 DB → 工作台骨架

## 关键设计决策

### 增量轮询（替代全量扫描）

```
每次轮询：
  1. 对每个联系人：SELECT MAX(local_id) FROM Msg_<hash>
  2. 如果 local_id > scan_cursor.last_local_id → 增量提取新消息
  3. 只更新受影响的 InteractionMetric → RadarHint
  4. 轮询间隔：前台 5s / 后台 60s
```

### DB2 数据源与 Secret 引用

DeepAxis 不创建独立的 `key_config.db`。微信账号、数据库路径、schema 指纹、密钥引用和验证状态都进入 DB2 本地业务库。

```sql
CREATE TABLE wechat_key_refs (
    source_account_id TEXT PRIMARY KEY,
    wechat_version TEXT,
    secret_ref TEXT NOT NULL,        -- DeepBase.Security secret key, not raw key
    salt_hex TEXT NOT NULL,          -- 32-hex salt suffix
    db_path TEXT NOT NULL,           -- 微信数据库路径
    captured_at INTEGER NOT NULL,    -- Unix timestamp
    verified INTEGER NOT NULL DEFAULT 0  -- HMAC 验证通过=1
);
```

原始微信密钥、LLM Key、后端 Token 等敏感值统一通过 `DeepBase.Security.SaveSecret/LoadSecret` 保存。DB2 只允许保存 `secret_ref`、哈希、时间戳和验证状态，不允许保存明文 secret。

### 隐私模式

| 模式 | 阶段 | 读取内容 |
|------|------|---------|
| M0 | 批次 1 | 联系人、群聊、消息时间/方向/类型（不读正文） |
| M1 | 批次 3 | 用户显式授权后，读取业务联系人消息正文 |
| M2 | 批次 3 | 单独授权后，UIA 写标签/备注 |
| M3 | 批次 3 | 单独授权后，粘贴话术到微信输入框 |
| M4 | 批次 3 | Profile 控制的最终发送动作（personal_full 开启，外部版关闭） |

## 技术风险与缓解

| 风险 | 缓解 |
|------|------|
| 微信版本更新 → schema 变化 | SchemaAdapter 指纹仅对必需字段做哈希，新增表/列不影响 |
| 微信版本更新 → 反内存扫描 | B路径：DLL Hook 作为后备 |
| DeepBase 框架接口变更 | 所有组件通过 `Core.Contracts.pas` 接口通信，不直接依赖 DeepBase 内部 |
| 轮询性能不足 | 增量模式 + 连接池 + 批量查询 |

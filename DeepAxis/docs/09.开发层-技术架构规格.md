## 0. 技术栈决策

> **开发阶段口径**: 直接使用 Delphi 13.1 + VCL + DeepBase。不做 Python 产品中间层。P0/P1/P2 只是内部开发阶段，不是 MVP 或对外发布版本。
> **UI 尺寸**: 以 [10.开发层-UI设计规格](10.开发层-UI设计规格.md) 为主事实源（280px 竖条 / 400px 扩展 / 双屏）。
> **能力口径**: 先开发 `personal_full` 全功能版；发布前通过 Profile、参数和 Governance 收紧能力。

| 决策 | 结论 | 理由 | 阶段 |
|------|------|------|------|
| 语言 + 框架 | **Delphi 13.1 + VCL + DeepBase** | P0 代码直接复用，不做 Python 中间层 | P0 起 |
| 密钥捕获 | **KeyScanner.exe**（独立进程内存扫描）| 解密和主程序解耦；密钥走 `DeepBase.Security`，DB 只存引用和元数据 | P0 起 |
| 本地数据库 | **SQLite (WAL)** via FireDAC | DeepBase 已封装 | P0 起 |
| 微信 SQLite 解密 | **SQLCipher via DeepBase 32.data** | 自定义 VendorLib 加载 sqlite3_sqlcipher.dll | P0 起 |
| UIA 自动化 | **COM IUIAutomation via DeepBase 34.data** | 原生 COM 调用 | P2 起 |
| UI 壳 | **DeepShell + DeepAxis 自定义工作台** | 复用命令、设置、布局、日志、Governance；业务工作台自定义 | P0 起 |
| 线程模型 | **主线程 + TDBPollerThread** (P0) → + TUIAExecutionThread (P2) | 原生多线程 | P0 起 |
| 打包 | **NSIS / Inno Setup** | 单 exe + sqlite3_sqlcipher.dll | P0 起 |

## 3. 线程模型

> **P0 阶段**: 单线程即可（DB Poller）。UIA Execution 线程延后到 P2。

```
┌─────────────────── DeepAxis.exe (单进程) ────────────────────┐
│                                                              │
│  Main Thread (VCL Message Loop)                              │
│  ├── UI 渲染 + 用户交互                                       │
│  ├── 接收后台线程信号 → 更新面板                               │
│  └── 发起 UIA 命令 → FCommandQueue.Enqueue                    │
│                                                              │
│  TDBPollerThread (TThread)                                   │
│  ├── 定时读微信 SQLite (WxReader)                             │
│  ├── 检测新消息/发送结果                                       │
│  ├── 轮询间隔：微信前台 1s / 后台 30s                          │
│  └── 有新数据 → TThread.Queue(Main, SignalNewData)            │
│                                                              │
│  TUIAExecutionThread (TThread)                               │
│  ├── 消费 FCommandQueue                                       │
│  ├── 执行 UIA 操作 (COM calls)                                │
│  ├── 重试/超时/ClipboardGuard                                 │
│  └── 结果 → TThread.Queue(Main, SignalComplete)              │
│                                                              │
│  DeepAxis SQLite (主线程访问，WAL)                             │
│  └── WAL 自动处理并发读写                                     │
│                                                              │
│  微信 SQLite (外部，只读)                                      │
│  └── WAL reader 不阻塞微信写入                                │
└──────────────────────────────────────────────────────────────┘
```

## 4. 数据流

### 4.1 读取流（微信 → DeepAxis）

```
微信 SQLite (加密 WAL)
    │
    ▼ WxDecrypt (SQLCipher 密钥派生 + PRAGMA key)
    │
    ▼ WxAdapter (TWeChat39xAdapter.MapRow → 内部标准行)
    │
    ▼ WxReader.ReadIncremental(since) → TMessageMeta[], TContactDelta[]
    │
    ▼ DeepAxis SQLite (写入本地 contacts / messages / tag_profile)
    │
    ▼ Feature Engines (Radar / Tag / IdleFunnel 读取本地 DB)
    │
    ▼ UI Signal → TThread.Queue → 面板刷新
```

### 4.2 粘贴流（DeepAxis → 微信）

```
用户按空格键 → ScriptView.OnPasteClick
    │
    ▼ SendQueue.Enqueue(contact_id, script_text)
    │
    ▼ TUIACommand.Create(uaSetValue, Target=微信输入框, Value=话术)
    │
    ▼ TUIAExecutionThread 消费命令
    │   ├── ClipboardGuard.Create (保存剪贴板)
    │   ├── UIA FindElement(微信输入框)
    │   ├── Guard.SetContent(话术) → Guard.DoPaste
    │   ├── Guard.Destroy (恢复剪贴板)
    │   └── 记录 paste_log
    │
    ▼ TThread.Queue → QueueView 更新状态
```

### 4.3 检测流（发送后追踪）

```
TDBPollerThread 检测到新 outbound 消息
    │
    ▼ WxReader 返回该消息的 peer_id + sent_at
    │
    ▼ 匹配 SendQueue 中的待确认项
    │
    ▼ 更新本地 Contact.last_msg_at / AdTrack.ad_count
    │
    ▼ TThread.Queue → RadarView 更新"已发送待回复"状态
```

### 4.4 最终发送流（Profile 控制）

最终发送是 L3 能力，是否启用由 `13.能力Profile与发布合规配置.md` 决定。

```
CommandManager.Execute(wechat.final_send)
    │
    ▼ Governance.EnterGate(wechat.final_send_gate)
    │   ├── personal_full: 可执行，记录 Evidence + ActionRun
    │   ├── external_safe: 阻断，要求用户手动发送
    │   └── strict_compliance: 阻断
    │
    ▼ TUIAExecutionThread 执行最终发送动作（仅 personal_full）
    │
    ▼ WxReader 只读检测 outbound 结果
    │
    ▼ AuditEvent + SendQueue 状态更新
```

实现约束：
- 不允许绕过 CommandManager 直接调用 UIA 最终发送。
- 不允许对 `UNKNOWN` / `PRIVATE` 联系人执行最终发送。
- UIA 无法确认当前会话、微信号或输入框状态时必须熔断。
- 对外发布 Profile 默认关闭该能力。

## 6. UI 架构

### 6.1 框架决策：使用 DeepShell 壳能力，自定义 DeepAxis 工作台

DeepAxis 主程序继承 `TDeepMainForm`，但不直接采用 DeepShell 默认 IDE 风格三面板作为最终业务体验。DeepShell 负责通用桌面壳能力，DeepAxis 负责微信旁工作台的业务布局。

**复用 DeepShell 的能力：**
- `CommandManager`：所有按钮、菜单、快捷键、后台动作统一注册为 Command。
- `Governance` 接入：L2/L3 动作通过 Gate/ActionGrid/Evidence 执行。
- `Settings/Layout/Recent`：窗口状态、Profile、最近工作现场统一保存。
- `Status/Log/Progress`：状态栏、日志、问题和长任务反馈统一处理。
- `ServiceRegistry/EventBus`：业务服务、后台任务和 UI 更新解耦。

**DeepAxis 自定义的能力：**
- 280px 微信旁竖条面板、400px 扩展面板、双屏全屏工作台。
- 客户雷达、话术审核、发送队列、标签矩阵等业务视图。
- 微信窗口跟随、UIA 执行、发送后只读检测。

**理由：**
- DeepShell 的默认布局适合开发者工具；DeepAxis 需要紧贴微信的销售工作流。
- 但 DeepShell 的命令、治理、设置、日志和生命周期能力不能重复造。
- 所有高风险动作必须经过 Command/Gate，不能落在按钮 `OnClick` 里直接执行。

**复用的 DeepBase VCL 组件：**
- `DeepBase.VCL.DeepShell.*` — 命令、布局、设置、日志、Provider 宿主
- `DeepBase.VCL.ThemeAdapter` — 主题适配
- `DeepBase.VCL.ConfigControls` — 设置页控件
- `DeepBase.VCL.BindableControls` — MVVM 数据绑定
- `DeepBase.VCL.MVVMControls` — ViewModel→View 绑定

### 6.2 三种布局模式

| 模式 | 场景 | 尺寸 | 描述 |
|------|------|------|------|
| **精简浮窗** | 单屏、日常发送 | 280×120 | 当前客户卡片+趋势图+空格发送。最小干扰 |
| **Dock 模式** | 单屏、需更多信息 | 400×全屏高 | 紧贴微信右侧。雷达+话术+队列 |
| **全屏面板** | 双屏 | 副屏全屏 | 完整面板：VTV客户列表+话术审核+标签矩阵+图表 |

用户一键切换（`Ctrl+L`）。布局偏好持久化到 DB1 ConfigDB。

### 6.4 Skia4Delphi 图形集成

DeepAxis 通过 DeepBase 底座使用 Skia4Delphi 7.1.0 作为统一图形引擎。

| 图形 | 控件 | 用途 | 阶段 |
|------|------|------|------|
| 迷你趋势图 | `TSkPaintBox` | 雷达面板：互动频率/响应延迟趋势 | P0 |
| 发送进度环 | `TSkPaintBox` | 浮窗：实时发送进度弧 | P1 |
| 客户分布环 | `TSkPaintBox` | 概览面板：活跃/降温/沉默/流失 | P1 |
| 产品×状态热力图 | `TGridPanel` + `TSkPaintBox` | 标签矩阵面板 | P1.5 |
| 证据链时间线 | `TSkPaintBox` | 客户详情：互动事件时间线 | P2 |

### 6.5 键盘驱动工作流

所有操作支持键盘完成，全程手不碰鼠标：

| 操作 | 面板内 | 全局热键 |
|------|--------|---------|
| 粘贴+切焦点 | `Space` | `Ctrl+Shift+Space` |
| 跳过当前 | `Esc` | `Ctrl+Shift+S` |
| 编辑话术 | `E` | `Ctrl+Shift+E` |
| 换话术风格 | `1`/`2`/`3` | `Ctrl+Shift+1/2/3` |
| 显示/隐藏面板 | `Ctrl+H` | `Ctrl+Shift+H` |

全局热键通过 `RegisterHotKey` 注册到系统消息队列，不依赖 DeepAxis 窗口焦点。

### 6.6 与竞品的 UI 对比

| 能力 | DeepAxis (VCL+Skia) | 竞品 (Electron/Web) |
|------|---------------------|---------------------|
| 窗口 dock 到微信旁 | `SetWindowPos`+`SetWinEventHook` | ❌ |
| 全局热键 | `RegisterHotKey` Win32 API | 不可靠 |
| 冷启动 | < 1s exe | 3-8s |
| 内存占用 | < 80MB | 200-400MB |
| 万级列表滚动 | VTV 60fps | 虚拟滚动性能退化 |
| 中文输入 | `TRichEdit` 原生IME | ContentEditable 兼容差 |
| 迷你趋势图 | Skia GPU 渲染 | Canvas/SVG 卡顿 |
| 透明覆盖层 | `WS_EX_TRANSPARENT` | ❌ |
| 异形窗口 | `SetWindowRgn` | ❌ |
| 安装包体积 | < 10MB | 120-250MB |

# DeepAxis / 序枢

DeepAxis（序枢）是有边界的业务智能体运行时——第一款落地产品是 **CRM + 销售促进系统**。

它不是再做一个 CRM。它站在 CRM 和通信渠道之上，持续感知客户状态变迁、推动销售跟进、沉淀客户规则，并在此过程中严格守边界：什么可以自动化、什么必须人类确认、什么被架构层禁止。

### 一句话卖点

> **"你的微信好友里，谁是可以变成客户的人？谁该删了？DeepAxis 帮你把闲人变成付款顾客。"**

这不是"帮你省时间"的 CRM。这是**帮你找回人脑无法记住的信息**的工具——你正在丢掉的客户、你忘掉的成交信号、你看不到的回复速度下降趋势。DeepAxis 默认本地处理、不上传到自有云；未来若启用微信写回，选定字段会写入微信并受微信同步机制影响，必须单独授权。

当前开发口径：

- **DeepAxis 没有 MVP 交付口径**。P0/P1/P2 只是内部开发阶段，不是对外发布版本；用户使用的是最终成型的完整产品。
- 当前先开发作者个人使用的 `personal_full` 全功能版，所有能力完整实现；外部发布前通过 Profile、参数、Governance 门禁收紧能力。
- `04/05/06` 是目标场景设计；开发阶段按依赖顺序实现完整产品，不以“可先交付的子集”作为发布标准。
- 任何关于“P0 / MVP / 1.0 必须做”的冲突表述，以 [07.开发层-P0技术验证规格](docs/07.开发层-P0技术验证规格.md) 为准。

## 理论基础

DeepAxis 基于作者 Fuyi 的"差异一元论"理论体系构建，核心依赖：

- **ASTO（属集变迁存在论）**：1-5-6-7-1 循环——状态驱动、边界优先、证据化认知
- **TAT（责任架构理论）**：六责任字段 + G×U/L Boundary Engine
- **ODD（产出物驱动开发）**：契约→验证→证据→封存→回滚
- **COP（认知计算层）**：五协议风险分流管线
- **OCGS（能力有序治理）**：AI 隐式治理边界

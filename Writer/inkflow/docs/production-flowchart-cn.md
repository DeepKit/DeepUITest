# InkFlow 生产流程 ASCII 方框图

日期：2026-06-29
说明：本文用 ASCII 字符画框和箭头，内容用中文，方便检查当前软件生产流程是否符合预期。

## 0. 图例

```text
+------------------+
| 阶段或命令        |
+------------------+

        |
        v

+------------------+
| 下一阶段          |
+------------------+

? = 判断点
Y = 通过 / 是
N = 不通过 / 否

[人工] = 人类介入
[软件] = InkFlow 自动执行
[DB]   = 写入数据库审计或真相源
```

## 1. 总体生产流程

```text
+--------------------------------------------------+
| [人工+软件] ink init                              |
| 全书启动；生成章以上层级 contract-draft.yaml      |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [人工+架构师] 讨论并修订契约草案                  |
| 人类不直接改文件；架构师根据讨论优化契约           |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [人工+软件] ink confirm-contract                  |
| 契约审计师两轮复审；通过后入库 confirmed           |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [人工+软件] ink setup --chapter                   |
| 某一章生产前校准；生成 setup YAML + fact_manifest |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [软件] ink run --chapter                          |
| 按 shot 自动生产：大纲门禁 -> 写手 -> 评审 -> Gate |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [软件] 自动导出当前 run 的审稿稿                   |
| 只说明 run 通过门禁，不代表正式正文                |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [人工] ink review --accept/--revise/--reject      |
| 人工验收；accept 后才成为 canonical 正式版本       |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [软件] ink export                                 |
| 默认只导出 accepted 正式章节；--draft 才导出草稿   |
+--------------------------------------------------+
```

核心边界：

```text
[人工介入] init / confirm-contract / setup / review
[软件自动] run 期间不问人，失败就记录原因并停止或等待 resume
[正式正文] 只有 review --accept 后的 canonical chapter
```

## 3. confirm-contract 内部流程

```text
+--------------------------------------------------+
| [软件] 读取架构师输出的 contract-draft.yaml        |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 基础格式校验                                      |
| YAML / 必填字段 / 高创造力字段 / 废弃角色名        |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [契约审计师-1] 结构完整性复审                     |
| 必需段落、角色弧线、chapter_N_events、占位符       |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [契约审计师-2] 生产就绪复审                       |
| shot 编号、POV 声明、must_land、提示词残留、钩子   |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 两轮复审全部通过 ?                                |
+--------------------------------------------------+
    | Y                                      | N
    v                                        v
+-------------------------------+      +--------------------------------+
| 创建 meta_contract             |      | 写 contract audit report        |
| draft -> human_review          |      | [DB] contract_conflict          |
| human_review -> confirmed      |      | 打回架构师和人类继续讨论        |
+-------------------------------+      +--------------------------------+
```

注意：

```text
人类不是直接编辑契约文件的责任人。
人类负责表达意图和做最终方向判断。
架构师负责把讨论结果改写成契约草案。
契约审计师负责复审契约是否能进入生产。
复审不通过，不能 confirmed，也不能 setup/run。
```

## 6. 大纲门禁和正文门禁的关系

```text
+--------------------------------------------------+
| fact_manifest                                    |
| 本章硬事实、禁词、旧称、hook、type_roles、POV等   |
+--------------------------------------------------+
        |
        +----------------------------+
        |                            |
        v                            v
+-----------------------------+  +--------------------------------+
| Outline Fact Gate           |  | Draft Hard Fact Gate            |
| 检查大纲有没有承接契约       |  | 检查正文候选稿有没有违约        |
+-----------------------------+  +--------------------------------+
        |                            |
        v                            v
+-----------------------------+  +--------------------------------+
| 不通过：不进入正文写作       |  | 不通过：不进入文学 jury         |
+-----------------------------+  +--------------------------------+
```

这条线是当前最关键的设计：

```text
先判资格，再做文学 PK。
违约大纲不能进入写作。
违约正文不能靠文笔好成为 winner。
```

## 7. 评审层流程

```text
+--------------------------------------------------+
| 候选稿先过 Gate1 + Hard Fact Gate                |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| Type Duty Gate                                   |
| 只有 shot 声明了类型职责才启用                    |
| 例如：suspense / blank_space / hook               |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| Literary Jury                                    |
| 文学 9 维评分，只比较合格稿                       |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 去掉异常高低分/计算综合分/检查过线数量            |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| winner 只能来自 eligible drafts                  |
+--------------------------------------------------+
```

当前应坚持的规则：

```text
硬规则失败 = 没资格参赛
类型职责失败 = 没完成该 shot 的特殊功能
文学分 = 合格稿之间的排序工具
```

## 8. review 和 export 的正式正文边界

```text
+--------------------------------------------------+
| run --chapter 自动导出                            |
| 输出：审稿稿 / draft output                       |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [人工] 审阅正文质量、契约兑现、章节钩子           |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| review 选择                                      |
+--------------------------------------------------+
     | accept                  | revise/reject
     v                         v
+--------------------------+  +--------------------------------+
| [DB] canonical accepted   |  | [DB] needs_revision/rejected    |
| 成为正式章节              |  | 回到 setup/run 修订             |
+--------------------------+  +--------------------------------+
     |
     v
+--------------------------------------------------+
| export 默认只读取 accepted 章节                   |
+--------------------------------------------------+
```

因此：

```text
run 通过 != 正式发表
自动导出 != 正式正文
review --accept 才是正式正文入口
```

## 9. run-book 全书/整卷编排

```text
+--------------------------------------------------+
| [人工] ink run-book --from A --to B               |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [软件] 创建 book_run 批次                          |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 章节列表：A, A+1, ..., B                          |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 对每章串行执行                                   |
| setup --chapter -> run --chapter                  |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 当前章成功 ?                                      |
+--------------------------------------------------+
    | Y                                      | N
    v                                        v
+-------------------------------+      +--------------------------------+
| 记录 chapter completed         |      | 记录 chapter failed            |
| 进入下一章                     |      | 默认停止；--continue-on-fail继续 |
+-------------------------------+      +--------------------------------+
        |
        v
+--------------------------------------------------+
| book-report 汇总待 review / 待返工章节            |
+--------------------------------------------------+
```

注意：

```text
run-book 只是编排层。
它不会取消逐章 setup。
它不会取消人工 review。
它不会把未 accept 的章节变成正式正文。
```

## 10. 审计和失败归因

```text
+--------------------------------------------------+
| setup / run / outline / prompt / writer / jury    |
| gate / review / export                            |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| [DB] writing_audit_events                         |
+--------------------------------------------------+
        |
        +---------------------+
        |                     |
        v                     v
+--------------------+  +--------------------------------+
| setup snapshots    |  | model_attempts                  |
| context snapshots  |  | 完整 prompt / response           |
+--------------------+  +--------------------------------+
        |
        v
+--------------------------------------------------+
| writing_draft_eligibility                         |
| 每份候选稿在哪个 gate 被判合格/不合格              |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| writing_failure_attributions                      |
| contract_conflict / outline_gap / task_card_gap   |
| writer_drift / jury_failure / model_failure 等    |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| ink audit-report                                  |
| 复盘质量问题来自契约、任务卡、写手、评审还是模型   |
+--------------------------------------------------+
```

失败归因大致对应：

```text
setup 自相矛盾                  -> contract_conflict
大纲缺失或不承接契约             -> outline_gap
任务卡缺 must_land/POV/硬事实    -> task_card_gap
正文违反硬事实或禁扩写           -> writer_drift
模型调用或 JSON 解析失败         -> model_failure
评审不可用                      -> jury_failure
规则误杀有效稿                  -> gate_false_positive
```

## 12. 最容易出问题的位置

```text
+--------------------------------------------------+
| 1. setup 阶段                                     |
| 人类没校准本章契约，后面软件只能按错契约执行       |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 2. 大纲门禁                                       |
| 如果没拦住违约大纲，后面正文容易系统性跑偏         |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 3. Draft Eligibility Gate                         |
| 如果违约稿进入文学 jury，赛马可能选出好读但违约稿  |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 4. Jury 阈值和过线数量                            |
| 如果只选最高分，不要求足够过线稿，会误封低信心稿   |
+--------------------------------------------------+
        |
        v
+--------------------------------------------------+
| 5. review 边界                                    |
| 如果未 accept 的草稿被当正式上下文，会污染后续章节 |
+--------------------------------------------------+
```

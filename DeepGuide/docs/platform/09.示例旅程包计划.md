## 2. 首个正向样例

已定：先做财税/会计实操样板“发票报销材料检查”：

```text
目标：指导新入职财务助理 / 报销初审员完成报销材料初审
风险：L1-L2，遇到税务合法性、资金不可逆或高风险例外时升级 L3 并转人工
路径：员工提问 -> 多轮澄清 -> 选择旅程 -> 检查发票基本信息 -> 检查附件材料 -> 检查单位规则 -> 输出材料齐全/需补材料/需专家确认/退出
异常：材料缺失、发票类型不明、截图/原件不确定、单位规则不适用、员工选择我不确定
```

理由：

- 财税/会计实操公开教程多，用户容易理解样板。
- 规则密度高，能验证 DeepGuide 把专家经验变成可执行旅程。
- 能覆盖意图澄清、0-9 数字候选、Gate/Card/Route、视觉锚点、RiskPolicy、LostRecovery 和 Trace。
- 不把 DeepGuide 做成税务裁判，不采集证据链，只验证导航闭环。

## 3. 正反例具体定义

详细节点、风险和图卡规格以 `10.财税发票报销材料检查旅程规格.md` 为准。

| 编号 | 场景 | 预期 Validator |
|---|---|---|
| EX-001 | 发票、报销单、差旅附件齐全；单位规则满足；L2 确认“仅表示材料初审齐全”；输出 `materials_ready_for_next_approval` | Green |
| EX-002 | `gate.attachment.checklist` 后没有 RouteRule 能到达结果或完成门 | R-003、G-002 |
| EX-003 | `gate.unit_policy.match` 是 L2，但没有 RiskPolicy 或确认被关闭 | K-001、K-002 |
| EX-004 | 疑似假票/税务合法性/资金放行被标为 L3，却直接给可报销或可付款结论 | K-003、K-004 |

EX-001 必须包含 `gate.expert_call` 分支，但正向 DryRun 不触发。EX-002/003/004 只服务 Validator，不进入 Coach 演示。

## 4. 第二个样例建议

深客客服场景：

```text
目标：客户咨询退款进度，坐席按旅程完成查询和答复
风险：L2
关键点：客户身份确认、SLA 提醒、情绪升级、工单升级
```

这个样例用于验证行业扩展字段和 L2 风险确认。

## 5. 样例验收

每个样例必须提供：

- JSON Package。
- 预期 Validator 结果。
- DryRun 路径。
- 预期 TraceEvent 摘要。
- 若为反例，必须写明预期 Red/Yellow 规则 ID。

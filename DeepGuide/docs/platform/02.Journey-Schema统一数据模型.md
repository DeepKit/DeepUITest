## 重要说明

## 核心对象

| 对象 | 作用 | 由谁主要编辑/消费 |
|---|---|---|
| Output | 旅程最终要拿到的业务结果 | Studio 创建，Coach 验证 |
| IntentTrigger | 用户输入到候选旅程的匹配入口 | Studio 创建，Coach 消费 |
| Journey | 连接 Output、start_gate 和步骤序列 | Studio 创建，Runtime 消费 |
| Field | 业务场域或操作区域 | Studio 创建，Showcase 解释 |
| Gate | 旅程门禁和条件判断点 | Studio 创建，Runtime 执行 |
| GuideCard | 面向一线用户的线框图卡/话术/选择项/视觉锚点 | Studio 创建，Coach 展示 |
| RouteRule | Gate/Card 之间的转移规则 | Runtime 执行，Validator 校验 |
| RiskPolicy | L2/L3 等风险确认规则 | Risk Engine 执行 |
| LostRecovery | 迷路、卡住、异常时的恢复路径 | Coach 执行 |
| TraceSchema | TraceEvent 的字段要求 | Coach 和后端消费 |
| HumanDecisionLog | AI 主持式倒推中的人类决策记录 | Studio 生成 |

---

## 可发布包最小要求

发布前至少满足：

- 1 个 Output。
- 1 个 IntentTrigger。
- 1 条 Journey，且有 start_gate。
- 每个 Step 绑定有效 Gate 和 Card。
- 至少 1 个 CompletionGate 能到达 Output。
- RouteRule 引用完整，主路径可达。
- L2/L3 Gate 有 RiskPolicy。
- 关键 Gate 有 LostRecovery。
- 有 accountability_set 和 remediation_set。
- 至少 1 个正常路径测试样例。

---

## Schema 与 Validator 的分工

Schema 负责：字段、类型、枚举、结构。

Validator 负责：

- 引用是否存在。
- 路径是否可达。
- 高风险治理是否闭合。
- `published` 包是否满足审核、发布治理、召回和 Trace 要求。
- 数字候选是否符合 0-9 规则：1-8 业务候选，9 重新生成选项，0 返回/取消。

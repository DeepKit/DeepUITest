# DeepGuide Journey Protocol v1.0

> Protocol Version: v1.0
> Form: JSON Schema + State Machines + RFC-style Rules
> Status: Release Candidate
> Last Updated: 2026-05-13

---

## 0. 协议定位

本协议定义 DeepGuide Journey Package 的最小可执行结构。它不定义具体 UI 风格、存储后端、NLP 算法或行业业务规则。

协议解决四个问题：

1. Studio 应该写出什么包。
2. Validator 应该检查什么。
3. Coach 应该如何播放包。
4. Trace 应该如何记录并回放一次旅程执行。

---

## 0.1 真源关系

| 层级 | 文件 | 作用 |
|---|---|---|
| 协议真源 | 本文件 | 对象、状态机、MUST/SHOULD/MAY 规则 |
| 机器结构 | `07.journey-package.schema.json` | JSON 类型、枚举、结构校验 |
| 语义校验 | `08.Validator规则清单.md` | 引用完整性、路径可达、风险治理 |

当三者冲突时，先修协议，再修 Schema 和 Validator。

---

## 0.2 协议不覆盖

| 不覆盖 | 说明 |
|---|---|
| UI 渲染 | 图卡视觉由前端实现决定 |
| 存储实现 | Package 与 Trace 的存储后端不在协议范围 |
| 意图识别算法 | NLP/LLM 算法不在协议范围 |
| 行业规则内容 | 行业规则通过配置包注入 |
| 法律认证 | Conformance 不等于法律或监管认证 |

## 1. Package 顶层结构

```json
{
  "protocol_version": "1.0",
  "package_key": "pkg_finance_tax_invoice_reimb_material_1_0_0",
  "package_name": "发票报销材料检查旅程包",
  "package_type": "business_journey",
  "version": "1.0.0",
  "status": "draft | reviewed | published | recalled | deprecated | archived",
  "domain": "finance_tax_practice",
  "owner_org": "org_finance_team",

  "boundary_set": {},
  "ability_set": {},
  "accountability_set": {},
  "seal_set": {},
  "remediation_set": {},

  "outputs": [],
  "intent_triggers": [],
  "journeys": [],
  "fields": [],
  "gates": [],
  "guide_cards": [],
  "route_rules": [],
  "risk_policies": [],
  "lost_recoveries": [],
  "trace_schema": {},
  "test_cases": [],
  "human_decision_log": [],

  "extension_schema": {},
  "industry_extensions": {}
}
```

### 1.1 顶层规则

- **[PKG-R01] MUST**: `protocol_version` 必须为 `1.0`。
- **[PKG-R02] MUST**: `package_key` 在同一部署域内唯一。
- **[PKG-R03] MUST**: `version` 使用 `major.minor.patch`。
- **[PKG-R04] MUST**: `published` 包不可原地修改。
- **[PKG-R05] MUST**: 内部引用必须指向本包内已定义对象。
- **[PKG-R06] SHOULD**: 发布前至少包含 1 个正向用例和 1 个异常用例。

## 2. 生命周期状态机

```text
draft --review_submit--> reviewed --publish_approve--> published
  ^                          |
  |------ change_request -----|

published --recall_trigger----> recalled ----archive_trigger----> archived
published --deprecate_trigger-> deprecated --archive_trigger----> archived
```

### 2.1 状态规则

- **[SM-R01] MUST**: 状态转换必须遵循状态机，不允许跳跃。
- **[SM-R02] MUST**: 每次状态转换必须记录 Package 级 TraceEvent。
- **[SM-R03] MUST**: `review_submit` 前必须没有 Validator Red 项。
- **[SM-R04] MUST**: `publish_approve` 前必须有 `published_by`。
- **[SM-R05] MUST**: `recall_trigger` 必须由 `recall_owner` 或等价权限发起。
- **[SM-R06] SHOULD**: `deprecated` 应提供 replacement package。

## 3. Journey 执行状态机

```text
idle -> intent_matched -> journey_selected -> playing -> completed
                                     |          |       |
                                     |          |       -> aborted
                                     |          -> lost -> playing
                                     -> risk_confirm -> playing
```

### 3.1 状态规则

- **[JE-R01] MUST**: Coach 执行必须从 `idle` 开始。
- **[JE-R02] MUST**: `intent_matched` 到 `journey_selected` 必须有明确的人类选择动作。
- **[JE-R03] MUST**: 进入 `risk_confirm` 后必须暂停执行，等待人类确认。
- **[JE-R04] MUST**: `lost` 必须提供至少一条恢复路径。
- **[JE-R05] MUST**: 每次状态转换必须生成 TraceEvent。
- **[JE-R06] SHOULD**: `playing` 超时应进入 `lost`。
- **[JE-R07] MAY**: 唯一高置信匹配可以作为推荐候选置顶，但不得自动结束澄清或自动进入旅程。

## 4. 核心对象

| 对象 | 最小作用 |
|---|---|
| Output | 旅程最终产出和完成状态 |
| IntentTrigger | 员工文字/语音提问到候选旅程的入口 |
| Journey | 从 start_gate 到 Output 的路径定义 |
| Field | 业务场域或界面区域 |
| Gate | 判断点、动作点、风险点或完成点 |
| GuideCard | 给一线用户看的图卡、视觉锚点和数字候选 |
| RouteRule | 从一个 Gate/Card 到下一个 Gate/Card 的转移规则 |
| RiskPolicy | 风险提示、确认、二次确认、阻断规则 |
| LostRecovery | 卡住、迷路、超时时的恢复路径 |
| TestCase | Validator 和 DryRun 的测试输入 |
| HumanDecisionLog | AI 主持式倒推中的人类选择记录 |

### 4.1 数字候选规则

- **[CARD-R01] MUST**: 面向一线用户的候选项必须使用 0-9 数字编号。
- **[CARD-R02] MUST**: 1-8 用于业务候选；9 保留为重新生成/重组选项；0 保留为返回、取消或退出。
- **[CARD-R03] MUST**: 所有前台候选界面必须提供 0，让人类始终有退出机制。
- **[CARD-R04] MUST**: AI 生成或澄清候选必须提供 9，让人类可以要求重新生成选项。
- **[CARD-R05] MUST**: 单屏业务候选不得超过 8 项。
- **[CARD-R06] SHOULD**: 超过 8 个业务候选时分页或先分类。

### 4.2 视觉锚点规则

- **[VIS-R01] SHOULD**: 系统界面类 GuideCard 应以线框图为主，尽量与员工正在操作的真实界面结构一致。
- **[VIS-R02] MUST**: GuideCard 视觉锚点仅用于 B 图卡参考导航，不得作为真实业务系统覆盖操作层。
- **[VIS-R03] SHOULD**: GuideCard 可声明视觉锚点，包括目标区域、目标字段、目标按钮、风险区和完成状态。
- **[VIS-R04] SHOULD**: 当前目标使用聚焦化展示，非当前区域可模糊化或弱化。
- **[VIS-R05] SHOULD**: GuideCard 可使用色框和导航线连接说明文字、数字候选和界面目标。
- **[VIS-R06] MUST**: 视觉锚点只表示导航提示，不表示自动点击、自动填写或证据链采集。
- **[VIS-R07] SHOULD**: 视觉锚点可以由 AI 根据专家口头说明生成草稿，但发布前必须由专家确认。
- **[VIS-R08] MUST**: 视觉锚点确认粒度按流程节点执行，一图一认，不得用整条旅程批量确认替代节点确认。

## 5. Due 对象

### 5.1 BoundarySet

定义适用范围、不适用条件和前置能力。

- **[BD-R01] MUST**: `scope_declaration` 不可为空。
- **[BD-R02] SHOULD**: 高风险包应配置不适用条件。
- **[BD-R03] SHOULD**: 边界覆盖地域、主体、业务类型。

### 5.2 AbilitySet

采用扁平数组，通过 `category` 区分能力类型。

```json
{
  "abilities": [
    {
      "ability_key": "ability.invoice_system_access",
      "category": "system_permission",
      "description": "报销系统查询权限",
      "required": true,
      "if_not_met": "请联系管理员开通权限"
    }
  ]
}
```

- **[AB-R01] MUST**: 每项能力必须有 `ability_key`、`category`、`required`。
- **[AB-R02] MUST**: `required=true` 的能力必须有 `if_not_met`。
- **[AB-R03] SHOULD**: Coach 进入旅程前检查 required 能力。

### 5.3 AccountabilitySet

- **[AC-R01] MUST**: 每个包必须有 `created_by`。
- **[AC-R02] MUST**: `published` 包必须有 `reviewed_by`、`published_by`、`outcome_owner`。
- **[AC-R03] SHOULD**: L2/L3 包应有 `recall_owner`。

### 5.4 SealSet

- **[SEAL-R01] MUST**: `published` 包不可原地修改。
- **[SEAL-R02] MUST**: 修改已发布包必须创建新版本。
- **[SEAL-R03] MUST**: Trace 必须绑定发布时的 `package_key + version`。

### 5.5 RemediationSet

- **[RE-R01] MUST**: `published` 包必须有召回策略。
- **[RE-R02] MUST**: 召回必须提供 replacement package 或 fallback instruction。
- **[RE-R03] MUST**: 已在执行中的旅程不得因召回被强制中断。
- **[RE-R04] MUST**: 所有包必须支持反馈回流。

## 6. 风险治理

| 风险 | 含义 | 必须治理 |
|---|---|---|
| L0 | 只读/浏览 | 基础 Trace |
| L1 | 低风险可撤回 | Gate Trace |
| L2 | 影响业务记录/客户结果 | 用户确认、Trace、outcome_owner |
| L3 | 不可逆/法律/资金 | 二次确认、人工升级、禁止自动放行 |

- **[RISK-R01] MUST**: L2/L3 不得自动跳过确认。
- **[RISK-R02] MUST**: L3 必须配置二次确认与人工升级或回退路径。
- **[RISK-R03] MUST**: L3 不得纯自动放行。

## 7. TraceEvent 标准字段

Coach 和 Package 生命周期操作必须产生 TraceEvent。

```json
{
  "event_id": "trace_001",
  "event_type": "state_transition | gate_decision | risk_confirm | lost_recovery | package_lifecycle",
  "package_key": "pkg_finance_tax_invoice_reimb_material_1_0_0",
  "package_version": "1.0.0",
  "journey_session_id": "sess_001",
  "from_state": "playing",
  "to_state": "risk_confirm",
  "gate_key": "gate.submit",
  "card_key": "card.submit_confirm",
  "route_key": "route.submit.risk",
  "actor_ref": "user_001",
  "trigger": "risk_trigger",
  "timestamp": "2026-05-13T10:00:00Z",
  "context_hash": "sha256:...",
  "context_refs": []
}
```

- **[TR-R01] MUST**: 每次状态转换产生 TraceEvent。
- **[TR-R02] MUST**: TraceEvent 绑定 package_key 和 package_version。
- **[TR-R03] MUST**: 风险确认 TraceEvent 记录人类确认动作。
- **[TR-R04] SHOULD**: 关键 TraceEvent 绑定 context_hash。
- **[TR-R05] MUST**: TraceEvent 只记录旅程状态、选择、风险确认、迷路恢复和反馈线索，不得默认采集真实业务系统截图、原始票据、隐私原文或实际点击证据。
- **[TR-R06] MUST**: DeepGuide Trace 不等同于证据链，不得作为责任裁判材料设计；若客户需要证据链，应进入 DeepAssist 或客户审计系统边界。

## 8. 行业扩展机制

行业配置包不得修改核心状态机。行业差异通过以下方式表达：

- `extension_schema`：声明行业扩展字段名称、类型、适用对象。
- `industry_extensions`：保存行业扩展配置。
- GuideCard 文案和模板变量。
- RiskPolicy 默认值。
- LostRecovery 默认模板。

- **[EXT-R01] MUST**: 行业扩展不得改变核心对象语义。
- **[EXT-R02] MUST**: Coach 不认识的扩展字段不得影响核心状态机执行。
- **[EXT-R03] SHOULD**: 行业扩展字段应有命名空间，例如 `service.emotion_level`。

## 9. 产品端职责

| 产品端 | 可做 | 不可做 |
|---|---|---|
| Studio | 创建、编辑、校验、审核、发布包 | 执行业务旅程 |
| Coach | 播放 published 包、记录 Trace、反馈回流 | 自由生成业务规则、播放 draft 包 |
| Showcase | 只读解释和演示 | 产生业务 Trace、执行风险确认 |
| Validator | 拦截结构、语义、风险和发布问题 | 替业务责任人做判断 |

---

## 10. 发布门槛

一个包进入 `reviewed` 或 `published` 前，必须通过：

1. JSON Schema 校验。
2. Validator Red 项清零。
3. 至少一条主路径 DryRun 成功。
4. L2/L3 风险治理完整。
5. 审核链和发布治理信息完整。

# DeepGuide Platform 通用底座愿景与蓝图

> 定位：所有深导产品共享的协议与运行底座
> 架构层级：L1 通用底座
> 面向用户：不直接面向终端用户，通过 Studio、Coach、Showcase 和行业产品间接服务

---

## 一句话定位

DeepGuide Platform 提供统一的旅程协议、校验器、运行时、风险控制、旅程记录和行业扩展机制。

---

## 底座组件

```text
DeepGuide Platform
├─ Journey Protocol         协议真源：对象、状态机、治理规则
├─ JSON Schema              机器结构校验
├─ Validator                语义校验、路径校验、风险校验、发布门槛
├─ Journey Runtime          Coach/Showcase 共享的播放与路由引擎
├─ Risk Engine              L0-L3 风险分级、确认、阻断
├─ Trace Engine             TraceEvent、版本绑定、上下文引用
├─ AI Layer                 辅助编排、受控匹配、卡点分析
└─ Industry Adapter         术语映射、扩展字段、默认风险规则
```

---

## 组件职责

### Journey Protocol

定义 DeepGuide 的协议对象和规则。所有产品端必须遵守 Protocol，不允许各端私自发明对象或状态机。

### JSON Schema

校验 Journey Package 的结构、类型、枚举和基础必填字段。Schema 解决“形状是否正确”，不解决“引用是否存在、路径是否可达、风险是否闭合”。

### Validator

三层校验：

- Schema 校验：字段类型、必填、枚举值。
- 语义校验：引用完整性、路径可达、孤儿对象、Completion 可达。
- 治理校验：风险确认、发布治理、召回策略、Trace 要求。

### Journey Runtime

加载 `published` 旅程包，执行协议状态机，按 Gate/Card/Route 播放，并把风险确认、迷路恢复和完成验证写成 TraceEvent。

### Risk Engine

```text
L0 只读/浏览：基础 Trace 即可
L1 低风险可撤回：关键 Gate 留痕，必要时提示
L2 影响业务记录/客户结果：必须显式确认，必须有 outcome_owner
L3 高风险不可逆/法律/资金：二次确认、人工升级、禁止自动放行
```

### Trace Engine

统一产生 TraceEvent，至少绑定：`package_key`、`version`、`journey_session_id`、状态转换、触发动作、当前 Gate/Card/Route、操作者和时间。

### AI Layer

AI 只能承担三个受控角色：

- 辅助编排：把专家输入转成候选结构和视觉锚点草稿，由人类确认；专家可以动口不动手，AI 负责画定。
- 受控澄清：员工从独立悬浮窗口用文字表达问题，语音为可选增强；AI 多轮澄清后匹配已发布旅程包，输出专业意见和数字候选，由人类确认是否进入旅程。
- 卡点分析：分析 Trace 和反馈，生成优化建议。

AI 不得跳过风险门禁，不得替用户做 L2/L3 决策，不得自由生成未审核业务规则。

### 离线与内网部署

第一版不要求离线模式。第二版支持无外网环境下播放已缓存的 published 旅程包，并支持甲方内部 AI。多语言能力通过 DeepBase i18n 接入，不阻塞 MVP。

### 桌面环境

Runtime/Coach 首版以 Windows 10/11 普通企业桌面为目标运行环境，覆盖高 DPI、多屏、缩放比例和独立悬浮窗口基本行为。Win7 不进入首版底座承诺；如客户因存量系统需要支持，按项目制做遗留兼容评估，且不得牺牲主线协议、Runtime 和 Coach 的现代桌面体验。

### Industry Adapter

行业差异通过配置包表达，包括术语映射、扩展字段、默认风险规则、旅程模板、演示数据和销售话术。行业扩展不得破坏 Protocol 的核心状态机。

---

## 与产品端的关系

```text
Studio   -> 调用 Protocol + Schema + Validator + AI Layer（辅助编排）
Coach    -> 调用 Runtime + Risk + Trace + AI Layer（受控澄清）
Showcase -> 调用 Runtime（只读解释模式）
行业产品 -> 通过 Industry Adapter 注入术语、字段和模板
```

开发优先级：先做 Protocol / Schema / Validator，再做 Studio 和 Coach。

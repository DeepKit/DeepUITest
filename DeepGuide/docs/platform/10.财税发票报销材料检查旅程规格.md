## 1. Q18 第一条旅程节点

旅程名：发票报销材料检查。

目标用户：新入职财务助理 / 报销初审员。

输出状态：

```text
materials_ready_for_next_approval：材料初审齐全，可进入后续审批
needs_supplement：需补充材料
needs_expert_confirmation：需专家确认
aborted：用户退出或场景不适用
```

### 节点清单

| 序号 | Gate Key | Card Key | 面板 | 风险 | 目的 |
|---|---|---|---|---|---|
| 0 | `intent.finance_tax.reimb_material_check` | `card.intent.invoice_reimb` | A | L0 | 员工主动提问后澄清：发票真假、材料齐全、单位规则、我说不清 |
| 1 | `gate.scope.confirm` | `card.scope.confirm` | B | L0 | 确认当前只做报销材料初审，不做税务合法性裁判、付款审批或真实系统提交 |
| 2 | `gate.materials.intake` | `card.materials.intake` | B | L1 | 确认员工手头有哪些材料：发票、报销单、事由说明、附件、审批/合同/验收等 |
| 3 | `gate.invoice.basic_elements` | `card.invoice.basic_elements` | B | L1 | 核对发票基本要素：票号、日期、金额、抬头、税号、销售方、项目、备注 |
| 4 | `gate.invoice.form_source` | `card.invoice.form_source` | B | L2 | 判断材料形态：正式电子票/纸票/截图/照片/信息不完整，决定是否可继续初审 |
| 5 | `gate.reimbursement.category` | `card.reimbursement.category` | B | L1 | 确认报销类别：差旅、招待、采购、办公、培训、其他 |
| 6 | `gate.attachment.checklist` | `card.attachment.checklist` | B | L1/L2 | 按报销类别检查附件清单，生成缺项或待补材料 |
| 7 | `gate.unit_policy.match` | `card.unit_policy.match` | B | L2 | 检查本单位规则：金额阈值、审批要求、预算/项目、期限、附件要求 |
| 8 | `gate.exception.scan` | `card.exception.scan` | B | L2/L3 | 扫描异常：抬头不符、金额不一致、重复报销疑似、税务/法律/资金高风险 |
| 9 | `gate.output.prepare` | `card.output.prepare` | B | L2 | 生成初审结果候选：材料齐全、需补材料、需专家确认、退出 |
| 10 | `gate.expert_call` | `card.expert_call_summary` | A+B | L2/L3 | 需要专家时生成脱敏问题摘要，交由员工发送或转人工 |
| 11 | `gate.completion` | `card.completion` | B | L0 | 完成旅程，写 Trace，提示结果只是导航初审状态 |

### 主路径

```text
intent.finance_tax.reimb_material_check
-> gate.scope.confirm
-> gate.materials.intake
-> gate.invoice.basic_elements
-> gate.invoice.form_source
-> gate.reimbursement.category
-> gate.attachment.checklist
-> gate.unit_policy.match
-> gate.exception.scan
-> gate.output.prepare
-> gate.completion
```

### 常见分支

```text
材料缺失 -> needs_supplement -> gate.completion
截图/照片/信息不完整 -> gate.unit_policy.match 或 gate.expert_call
单位规则不适用/不确定 -> gate.expert_call
疑似重复报销/税务合法性/资金不可逆 -> gate.expert_call
员工选择 0 -> aborted -> gate.completion
```

所有前台候选必须包含 `0`。AI 生成或重组候选必须包含 `9`。

## 2. Q19 风险分级

| 风险 | 财税样板中的含义 | 示例 | Coach 行为 |
|---|---|---|---|
| L0 | 解释、澄清、范围确认，不影响业务结果 | 说明本旅程只做材料初审；员工退出 | 允许直接展示和记录基础 Trace |
| L1 | 普通材料核对和缺项提示，可撤回、可补充 | 发票号码/金额/日期核对；附件是否存在；报销类别选择 | 可导航，可生成缺项清单 |
| L2 | 影响是否进入后续审批或影响报销结果 | 截图是否可作为初审材料；单位规则是否满足；金额阈值；审批附件是否可后补 | 必须人类确认，Trace 记录确认动作 |
| L3 | 税务合法性、法律责任、资金不可逆、重大异常 | 疑似假票、重复报销疑似、资金支付放行、税务抵扣合法性、重大金额例外 | 必须人工升级，DeepGuide 不给最终结论 |

风险口径：

- “材料是否齐全”通常是 L1/L2。
- “是否符合本单位报销规则”通常是 L2。
- “发票是否合法、是否可税前扣除、是否可付款”属于 L3 或客户专业系统边界，DeepGuide 只引导呼叫专家。

## 3. Q20 专家呼叫触发条件

触发专家呼叫的条件：

- 员工在任一 L2/L3 节点选择“我不确定”或“需要问专家”。
- AI 多轮澄清两轮后仍无法把问题归入已发布旅程分支。
- 规则来源冲突：通用规则、单位规则、专家规则之间不一致。
- 当前节点缺少单位规则或专家规则。
- 进入 L3：疑似假票、重复报销疑似、资金不可逆、税务合法性、法律责任或重大金额例外。
- LostRecovery 重试后仍无法继续。

### 专家问题摘要格式

摘要只带结构化事实，不带发票原图、真实系统截图、隐私原文或点击证据。

```text
[DeepGuide 专家问题摘要]
业务：发票报销材料检查
旅程包：pkg_finance_tax_invoice_reimb_material_1_0_0 / 1.0.0
当前节点：gate.unit_policy.match
风险级别：L2

员工想解决：
确认当前材料是否可进入后续报销审批。

已确认事实（脱敏）：
1. 已有发票材料：是
2. 已有报销事由：是
3. 已有附件：部分缺失
4. 报销类别：差旅
5. 单位规则命中：差旅需行程单和住宿/交通凭证

未确认/冲突：
1. 当前只有电子截图，是否允许先进入初审
2. 行程单缺失，是否允许后补

已走节点：
scope.confirm -> materials.intake -> invoice.basic_elements -> attachment.checklist -> unit_policy.match

请专家判断：
1. 可按材料齐全进入后续审批
2. 需补充材料后再提交
3. 不适用本旅程，转其他流程
4. 升级为高风险线下处理
0. 返回给员工继续澄清
```

专家回复后，员工仍通过 DeepGuide 数字候选继续旅程。DeepGuide 不替专家作结论。

## 4. Q21 样例包定义

### EX-001 正例

文件：`examples/valid/finance-tax-invoice-reimbursement-material-check.json`

目的：验证财税/会计实操最小正向闭环。

要求：

- 包含完整主路径，从意图澄清到完成。
- 包含 L2 `gate.unit_policy.match` 与 `gate.output.prepare` 的 RiskPolicy。
- 包含 `gate.expert_call` 分支，但正向 DryRun 不触发。
- 每个关键 Gate 至少有一个 GuideCard。
- GuideCard 使用 `wireframe_reference` 和视觉锚点。
- TraceSchema 不要求原始票据、真实截图、隐私原文或点击证据。

预期 Validator：Green。

正向 DryRun：

```text
员工选择：2 报销材料是否齐全
材料状态：发票、报销单、差旅附件齐全
单位规则：命中且满足
风险确认：L2 确认“仅表示材料初审齐全”
输出：materials_ready_for_next_approval
```

### EX-002 反例：断路

文件：`examples/invalid/finance-tax-missing-route-to-output.json`

问题：`gate.attachment.checklist` 后没有可达 `gate.output.prepare` 或 `gate.completion` 的 RouteRule。

预期 Validator：

```text
R-003 RouteRule target 缺失或无效
G-002 无路径能到达 CompletionGate
```

### EX-003 反例：L2 无确认

文件：`examples/invalid/finance-tax-l2-unit-policy-no-confirm.json`

问题：`gate.unit_policy.match` 标为 L2，但没有绑定 RiskPolicy 或 `confirm_required=false`。

预期 Validator：

```text
K-001 L2/L3 Gate 必须绑定 RiskPolicy
K-002 L2/L3 RiskPolicy 必须 confirm_required=true
```

### EX-004 反例：L3 无升级

文件：`examples/invalid/finance-tax-l3-tax-legality-no-escalation.json`

问题：旅程把疑似假票、税务合法性或资金放行作为 L3，却直接给“可报销/可付款”结论，没有二次确认、人工升级或回退路径。

预期 Validator：

```text
K-003 L3 必须配置二次确认与人工升级或回退路径
K-004 L3 不得配置纯自动放行路径
```

## 5. Q22 图卡素材策略

第一版只用通用线框图，不用真实客户系统截图，不做仿真报销系统界面。

原因：

- 线框图足够验证图卡导航、视觉锚点、色框和导航线。
- 避免真实客户系统版权、隐私、数据脱敏和界面差异问题。
- 不让用户误解 DeepGuide 正在覆盖或操控真实业务系统。

第一版图卡集合：

```text
wire.invoice.summary        发票摘要线框
wire.material.list          报销材料清单线框
wire.reimbursement.category 报销类别选择线框
wire.unit.policy            单位规则核对线框
wire.exception.scan         异常提示线框
wire.output.status          初审结果线框
wire.expert.summary         专家摘要线框
```

视觉规则：

- 一张图卡只服务一个流程节点，一图一认。
- 用通用字段名和演示数据，不出现客户名称、真实发票号码、真实供应商或员工隐私。
- 粉红实线标当前主焦点，粉红虚线标候选目标，浅黄色标风险区，浅绿色标完成状态。
- 导航线只连到线框图目标，不连到真实业务系统。

第二版可做仿真报销系统界面，但仍必须使用脱敏演示数据。客户真实截图只有在客户明确授权、完成脱敏、专家逐图确认后才能进入客户项目配置包。

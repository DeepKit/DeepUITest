# DeepGuide Validator 规则清单

> 状态：开发真源
> 适用协议：DeepGuide Journey Protocol v1.0
> 目的：定义 Studio 提交审核、发布前必须执行的语义校验

---

## 1. 校验分层

| 层级 | 名称 | 失败等级 | 示例 |
|---|---|---|---|
| S | Schema | Red | 字段类型错误、枚举错误、缺顶层对象 |
| R | Reference | Red | route 指向不存在的 gate |
| G | Graph | Red/Yellow | start_gate 不可达、孤儿 gate |
| C | Card | Red/Yellow | 业务候选超过 8 项、缺 0 退出或 9 重生成 |
| K | Risk | Red | L2/L3 缺确认、L3 缺人工升级或回退 |
| T | Trace | Red/Yellow | 风险动作未要求 Trace |
| A | Accountability | Red | published 包缺 outcome_owner |
| V | Version | Red | published 包原地修改 |

---

## 2. Red 规则

Red 必须修复，否则不得提交审核或发布。

| ID | 规则 |
|---|---|
| S-001 | JSON 必须通过 `journey-package.schema.json` 校验 |
| R-001 | 所有 `output_key` 引用必须存在 |
| R-002 | 所有 `gate_key`、`field_key`、`card_key`、`route_key` 引用必须存在 |
| R-003 | RouteRule 的 `target_gate_key` 和 `target_card_key` 必须存在 |
| G-001 | 每条 Journey 必须有可达的 `start_gate_key` |
| G-002 | 至少一条路径能到达 CompletionGate |
| G-003 | CompletionGate 必须能绑定 Output |
| C-001 | GuideCard 的一线候选按钮编号必须遵守 0-9 数字语法 |
| C-002 | 单张 GuideCard 面向一线的业务候选不得超过 8 项 |
| C-003 | 所有前台候选界面必须提供 0=返回/取消/退出 |
| C-004 | AI 生成或澄清候选必须提供 9=重新生成选项 |
| K-001 | L2/L3 Gate 必须绑定 RiskPolicy |
| K-002 | L2/L3 RiskPolicy 必须 `confirm_required=true` |
| K-003 | L3 必须配置二次确认与人工升级或回退路径 |
| K-004 | L3 不得配置纯自动放行路径 |
| T-001 | 每次 Journey 状态转换必须能生成 TraceEvent |
| T-002 | TraceSchema 不得要求采集原始票据、真实系统截图、隐私原文或实际点击证据 |
| A-001 | published 包必须有 reviewed_by、published_by、outcome_owner |
| A-002 | L2/L3 包必须有 outcome_owner |
| V-001 | published 包不可原地修改 |
| V-002 | recalled 包不可新进入 Coach |

---

## 3. Yellow 规则

Yellow 可以提交审核，但审核员必须看到。

| ID | 规则 |
|---|---|
| G-101 | 存在未被任何 Journey 使用的 Gate |
| G-102 | 存在未被任何 Route 使用的 GuideCard |
| G-103 | 只有正向路径，没有异常路径测试 |
| K-101 | L1 关键动作未配置用户提示 |
| L-101 | 关键 Gate 缺 LostRecovery |
| T-101 | TraceSchema 未声明 context_hash |
| B-101 | BoundarySet 未列出 excluded_scenarios |
| E-101 | 行业扩展字段未声明命名空间 |

---

## 4. DryRun 要求

发布前至少跑通：

1. 一条正常完成路径。
2. 一条用户拒绝风险确认路径。
3. 一条 LostRecovery 路径。
4. 一条不适用边界拦截路径。

DryRun 输出必须包含：

- 经过的 Gate/Card/Route 序列。
- 触发的 RiskPolicy。
- 生成的 TraceEvent 数量。
- 是否到达 Output。
- Trace 禁止字段扫描结果。
- 失败原因。

---

## 5. Studio 红绿灯映射

```text
Red    = 存在 Red 规则失败，不可提交审核
Yellow = 无 Red，但存在 Yellow，允许提交审核
Green  = 无 Red，无 Yellow，可提交审核或发布
```

Studio 保存草稿时可以只做 Schema 校验；提交审核和发布前必须跑完整 Validator。

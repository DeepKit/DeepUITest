# DeepGuide 企业级 MVP 实施路线

> 状态：开发收敛版
> 定位：跨产品的最小闭环验证计划

---

## MVP 总目标

第一阶段只验证一个命题：

> 能否把一个企业高频业务，从专家经验转成标准 Journey Package，并让新人在 Coach 中按图卡和数字候选完成任务，同时留下可回放的旅程 Trace。

最小闭环：

```text
业务专家 -> Studio 创建旅程包 -> Validator 校验 -> 审核发布
-> Coach 播放 -> 新人完成任务 -> Trace 旅程记录 -> 反馈回流 Studio
```

---

## 阶段切线

| 阶段 | 目标 | 交付物 | 是否阻塞后续 |
|---|---|---|---|
| P0 | 协议可执行 | Protocol、JSON Schema、Validator、样例包 | 是 |
| P1 | Studio 能造包 | 最小写包端、红黄绿校验、发布流程 | 是 |
| P2 | Coach 能播包 | 独立悬浮窗口、文字输入、可选语音、双悬浮面板、多轮意图澄清、意图候选、数字选择、状态机、Trace、Windows 10/11 桌面兼容验收 | 是 |
| P3 | 反馈能回流 | 卡点反馈、版本召回、包迭代 | 否 |
| P4 | 扩展演示 | Showcase、行业插件、售前样板 | 否 |
| V2 | 受限网络增强 | 离线播放已缓存旅程包、甲方内部 AI 配置、DeepBase i18n 接入 | 否 |

## 桌面运行环境切线

首版只承诺 Windows 10/11 普通企业桌面，重点验收独立悬浮窗口在常见高 DPI、多屏、缩放比例和主副屏切换下的可用性。

Win7 不进入 P0-P3，也不作为第一版市场承诺。仍使用 Win7 的客户可作为遗留项目单独评估：限制为文字输入、已发布旅程包播放、基础图卡和本地缓存；语音、现代 WebView、完整高 DPI/多屏体验、外部 AI 访问不做默认承诺，并需现场验收。

## 推荐首个样板场景

已定：首个参考行业为财税/会计实操，首个样板业务为发票报销材料检查。

样板用户：新入职财务助理 / 报销初审员。

样板目标：

```text
员工拿到一张发票和一组报销材料后，能在 Coach 陪跑下检查材料是否齐全、是否需要补充、是否需要专家确认，并知道下一步怎么走。
```

边界：

- 不做完整报销审批流。
- 不做税务结论裁判。
- 不替员工点击、填写、提交。
- 不采集证据链或追责材料。
- 只用通用报销系统线框图，不默认使用真实客户系统截图。

原因：财税/会计实操教程密度高、规则密度高、现场卡点多，能同时验证多轮澄清、图卡导航、风险确认、迷路恢复、Trace 和反馈回流。

首条旅程节点：意图澄清、范围确认、材料接收、发票基本要素、材料形态、报销类别、附件清单、单位规则、异常扫描、结果准备、专家呼叫/完成。

第一版图卡使用通用线框图，不使用真实客户系统截图。

## 实施节奏

```text
第 1 周：协议收敛 + Schema + Validator 规则
第 2 周：样例包 + 反例包 + Validator 自动测试
第 3 周：Studio 最小写包端
第 4 周：Coach 最小播放端（独立悬浮窗口，不介入浏览器和其它业务系统，完成 Windows 10/11 桌面验证）
第 5 周：Trace、反馈、召回和复盘
```

---

## 成功标准

业务成功：新人能通过 Coach 找到正确旅程并完成任务。

产品成功：Studio 能造包，Validator 能拦错，Coach 能播包，Trace 能回放。

方法成功：宝物倒推可执行，AI 主持式提问能产生 HumanDecisionLog，人类最终决策可复盘。

工程成功：所有 P0/P1/P2 用例可以自动化回归。

---

## 商业化节奏

第一阶段（0-6 月）：轻量版验证，以财税/会计实操的“发票报销材料检查”做首个样板。

第二阶段（6-18 月）：标准版拓展，优先深客和深用。

第三阶段（18 月+）：企业版突破，选择重行业做深度样板。

第二版增强：支持无外网环境下播放已缓存旅程包；支持甲方内部 AI；接入 DeepBase i18n 实现多语言。Win7 等遗留环境按项目制兼容评估，不纳入标准版默认承诺。

---

## 三档定价设想

轻量版：免费起步，限制旅程包数量，订阅解锁。

标准版：按坐席数或按年许可。

企业版：实施费 + 年费 + 行业配置包。

# DeepGuide Studio 基于协议的实现规范

> 状态：开发收敛版
> 协议依赖：DeepGuide Journey Protocol v1.0

---

## 0. Studio 与协议的关系

Studio 是 Journey Package 的写入端。它负责创建、编辑、校验、审核和发布旅程包。

Studio 不执行旅程，不渲染前台图卡，不写业务执行 Trace。它只保证产出的旅程包符合协议，并能被 Coach 和 Showcase 消费。

---

## 1. Studio 负责的对象

| 顺序 | 对象 | 说明 |
|---|---|---|
| 1 | Package 元信息 | package_key、name、domain、owner_org、version |
| 2 | BoundarySet | 适用范围、不适用条件、前置能力说明 |
| 3 | AbilitySet | 系统、硬件、材料、人员、外部服务能力 |
| 4 | Output | 宝物、完成状态、风险等级 |
| 5 | Journey | start_gate、步骤序列、目标 Output |
| 6 | Field | 业务场域 |
| 7 | Gate | 门禁、条件、风险等级 |
| 8 | GuideCard | 图卡、话术、数字候选、视觉锚点 |
| 9 | RouteRule | 路由、触发条件、目标 Gate/Card |
| 10 | RiskPolicy | L2/L3 确认和阻断规则 |
| 11 | LostRecovery | 迷路恢复路径 |
| 12 | TestCase | DryRun 测试样例 |
| 13 | AccountabilitySet | 创建、审核、发布、结果责任、召回责任 |
| 14 | RemediationSet | 召回、回滚、反馈回流 |
| 15 | HumanDecisionLog | AI 主持式倒推的人类决策记录 |

SealSet 通常由发布动作自动生成或锁定。

---

## 2. 核心工作流

```text
new draft
  -> define Output
  -> AI-assisted backward gating
  -> edit Field/Gate/Card/Route
  -> configure RiskPolicy and LostRecovery
  -> run Validator
  -> submit_review
  -> reviewed
  -> publish_approve
  -> published
```

`published` 后不可原地修改，只能新建版本、召回、废弃或归档。

---

## 3. Validator 调用时机

| 时机 | 校验 | 阻断 |
|---|---|---|
| 保存草稿 | JSON Schema 基础校验 | 不阻断编辑，只提示 |
| 提交审核 | 完整 Validator | Red 阻断 |
| 发布前 | 完整 Validator + DryRun | Red 阻断 |
| 新建版本 | Schema + 差异检查 | published 原版本不可修改 |

---

## 4. AI 主持式倒推

AI 的职责是主持问题和生成候选，不替用户做最终决定。

流程：

1. 从 Output 开始提问。
2. 给出 0-9 数字候选：1-8 业务候选，9 重新生成选项，0 返回/取消。
3. 人类选择、修正或否定。
4. Studio 记录 HumanDecisionLog。
5. 生成 Gate、Card、Route 的草稿。
6. Validator 检查草稿是否可发布。

硬约束：

- 必须从 Output 倒推，不从入口顺推。
- 每次人类选择都要记录理由。
- AI 生成内容默认是草稿，不能绕过审核发布。

---

## 4.1 AI 画定视觉锚点

Studio 的视觉锚点编辑采用“专家动口不动手”的方式：

1. 每个流程节点生成一张线框参考图。
2. 专家描述该节点中要看哪里、点哪里、核对哪里。
3. AI 根据专家描述在线框图上画定色框、导航线、模糊区和聚焦区。
4. 专家对当前节点图卡口头确认、否定或修正。
5. AI 根据反馈重新画定，直到专家确认。
6. Studio 将确认后的视觉锚点写入该流程节点对应的 GuideCard 草稿，并进入 Validator/审核发布流程。

硬约束：

- 专家不需要手工拖拽画框或连线。
- AI 画定的视觉锚点默认是草稿，必须经专家确认。
- 视觉锚点确认按流程节点进行，一图一认，不做整条旅程一次性批量确认。
- B 图卡以线框图为主，只服务 Coach B 图卡参考导航，不得用于真实系统覆盖、自动点击或证据链采集。

---

## 5. 红黄绿机制

| 灯色 | 含义 | 处理 |
|---|---|---|
| Red | MUST 规则违反 | 不可提交审核/发布 |
| Yellow | SHOULD 规则未满足 | 可提交审核，但审核员必须看到 |
| Green | 无 Red/Yellow | 可进入下一步 |

---

## 6. Studio 不负责

| 不负责 | 负责方 |
|---|---|
| Journey 执行 | Coach Runtime |
| 业务执行 Trace | Coach + Trace 后端 |
| 一线图卡最终渲染 | Coach 前端 |
| 只读演示 | Showcase |
| 意图识别算法细节 | Coach / AI Layer |

Studio 的边界：只管写包、校验、审核、发布。

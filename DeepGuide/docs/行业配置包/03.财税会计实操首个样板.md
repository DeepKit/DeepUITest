# 财税/会计实操首个样板

> 状态：Q12-Q17 已确认
> 用途：作为 DeepGuide 第一条可开发、可演示、可销售验证的行业样板

---

## 1. 样板定位

首个参考行业：财税/会计实操。

选择理由：

- 公开教程和培训内容密度高，便于参考用户理解方式。
- 业务规则、单位制度、材料清单和例外情况都比较多，能体现 DeepGuide 的价值。
- 新人现场容易卡住，适合验证“让新员工也能象专家一样完成工作”。
- 可以从低到中风险场景切入，不必一开始挑战完整税务裁判或资金审批。

---

## 2. 首个样板业务

首个样板业务：发票报销材料检查。

第一版只验证：

```text
员工拿到一张发票和一组报销材料后，能否按已发布旅程检查材料是否齐全、是否需要补充、是否需要专家确认，并知道下一步怎么走。
```

第一版不做：

- 完整报销审批流。
- 自动判断税务合法性。
- 自动替单位作出合规结论。
- 自动提交报销、自动填单、自动点击。
- 证据链采集和事后追责裁判。

---

## 3. 首个用户角色

目标用户：新入职财务助理 / 报销初审员。

这个角色不是税务专家，也不是最终审批人。他需要 DeepGuide 帮他把材料、制度、风险点和例外情况一步一步走清楚。

---

## 4. 责任边界

DeepGuide 在财税/会计实操样板中仍然只是导航工具：

- 可以提示材料清单、核对顺序、常见错误、单位规则和风险点。
- 可以在不确定时继续追问，或引导员工呼叫专家。
- 可以记录旅程走到哪里、员工选择了哪个数字、在哪一步卡住。
- 不做税务结论裁判，不替单位承担合规责任。
- 不替员工点击、填写、提交或留存业务证据。

最终责任仍由单位制度、财务负责人、税务专业人员或真实业务系统承担。

---

## 5. 规则来源

第一版规则来源分三层：

```text
通用规则：发票基本要素、常见材料项、常见错误
单位规则：本单位报销制度、审批要求、附件要求、例外处理
专家规则：老财务经验、风险提醒、边界案例、呼叫专家条件
```

MVP 优先使用单位规则和专家规则。通用规则只做背景提示，不把 DeepGuide 变成泛税法问答。

---

## 6. Trace 边界

Trace 用于旅程复盘和产品改进，不用于证据链和追责。

Trace 记录：

- 进入了哪个旅程包和版本。
- 走到哪个 Gate/Card/Route。
- 员工选择了哪个数字候选。
- 是否触发风险确认、迷路恢复、呼叫专家、退出或完成。
- 卡点反馈和旅程改进线索。

Trace 不记录：

- 发票原图或电子票文件。
- 客户、员工、供应商等隐私原文。
- 真实业务系统截图。
- 员工在真实系统里的实际点击证据。
- 报销审批证据链或责任裁判材料。

---

## 7. 图卡素材

第一版使用通用报销系统线框图，不使用真实客户系统截图作为默认素材。

线框图表达：

- 发票号码、金额、日期、销售方、购买方等核对区域。
- 附件清单、审批状态、补材料入口等业务区域。
- 当前要看的位置、风险区域、完成状态和下一步候选。

B 图卡只做参考导航，不覆盖真实业务系统。

---

## 8. 第一条旅程骨架

```text
员工提问
-> A 面板多轮澄清：真假 / 材料齐全 / 单位规则 / 我不确定
-> 人类确认进入“发票报销材料检查”
-> B 面板展示材料清单线框图
-> 检查发票基本信息
-> 检查报销附件
-> 检查本单位规则
-> 例外或不确定时呼叫专家
-> 输出：材料齐全 / 需补材料 / 需专家确认 / 退出
```

---

## 9. 风险分级建议

```text
L1：只做材料清单提示、普通字段核对、缺项提醒
L2：涉及单位规则适用、是否可进入后续审批、可能影响报销结果
L3：涉及税务合法性、资金不可逆处理、法律责任或高风险例外
```

L2 必须人类确认。L3 必须人工升级，DeepGuide 不给最终结论。

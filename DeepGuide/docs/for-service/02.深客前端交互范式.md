# 深客前端交互范式

> 状态：行业扩展规范草案
> 依赖：DeepGuide Coach + Journey Protocol v1.0

---

## 1. 定位

深客是企业客服场景的 L2 二级底座。

```text
深客 = Coach Runtime + 客服行业交互插件 + 客服行业配置包
```

深客不得修改 Coach 的核心状态机，只能通过行业扩展字段、默认 RiskPolicy、GuideCard 模板和 LostRecovery 模板增强体验。

---

## 2. 话术分支模式

- GuideCard 可以嵌入标准话术模板。
- 话术支持变量替换，例如客户名、工单号、产品名。
- 话术分支必须落到 RouteRule，不能只存在于自然语言里。

---

## 3. 客户情绪判断

建议扩展字段：`service.emotion_level`。

枚举：`calm | anxious | angry | escalated`。

规则：

- 情绪可以由 AI 辅助判断或坐席手动标记。
- 高情绪状态可以影响 RouteRule，但不得自动执行高风险业务动作。
- 情绪升级应触发 LostRecovery 或人工升级路径。

---

## 4. 工单升级交互

不新增核心 Gate 类型。升级应使用：

- `HumanConfirmGate`：坐席确认升级。
- `RiskGate`：涉及投诉、赔付、合规时触发风险确认。
- `industry_extensions.service.escalation`：保存升级摘要、优先级、目标队列。

升级后旅程可以暂停，等待高级处理结果。

---

## 5. SLA 提醒

建议扩展字段：`service.sla_level`。

枚举：`normal | warning | critical`。

SLA 临近时：

- UI 高亮提示。
- 可触发 LostRecovery。
- 不直接改变核心状态机，仍通过 RouteRule 表达路径。

---

## 6. 行业扩展字段

| 字段 | 说明 |
|---|---|
| `service.customer_level` | 客户等级：VIP/普通/新客 |
| `service.issue_category` | 问题分类 |
| `service.sla_level` | SLA 级别 |
| `service.emotion_level` | 情绪级别 |
| `service.ticket_priority` | 工单优先级 |
| `service.escalation_summary` | 升级摘要 |

所有扩展字段必须在 `extension_schema` 中声明。

---

## 7. 与通用 Coach 的关系

- 继承 Coach 的状态机、Trace、RiskPolicy、LostRecovery。
- 通过行业配置包提供模板和默认规则。
- 不允许绕过 published 包、风险确认和 Trace。

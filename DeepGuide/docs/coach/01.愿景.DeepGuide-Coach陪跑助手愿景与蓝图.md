# DeepGuide Coach 陪跑助手愿景与蓝图

> 产品名：深导·陪跑 DeepGuide Coach
> 定位：企业一线员工的业务陪跑助手
> 用户：窗口人员 / 客服 / 柜员 / 新员工 / 临时工

---

## 一句话定位

> **让新员工也能象专家一样完成工作。**

---

## 核心原则

```text
1. 独立悬浮窗口 — 不介入浏览器和其它业务系统，承载 A/B 双悬浮面板
2. 不是自由聊天机器人 — 优先使用已审核发布的旅程包
3. 不替员工猜需求 — 员工用文字或语音主动提问，AI 负责多轮澄清
4. 人类决定进入 — AI 可以推荐，是否问清楚、是否进入旅程由人类选择
5. 所有候选数字化 — 前台选择使用 0-9：1-8 业务候选，9 重新生成选项，0 返回/取消
6. 看图操作，卡住再问 — 默认显示图卡，关键状态才交互确认
7. 高风险必须确认 — L2/L3 不允许自动跳过
8. 关键旅程可复盘 — Trace 记录导航过程，不承担证据链或追责责任
9. 首版环境可控 — 首版支持 Windows 10/11 普通桌面，高 DPI/多屏适配；Win7 只做项目制遗留兼容
```

---

## 主流程

```text
FloatingEntry（悬浮入口，点击展开）
  ↓
PanelA.IntentClarify（A 面板：员工提问、多轮澄清、专业意见、旅程候选）
  ↓
HumanChoice（人类确认是否进入）
  ↓
JourneySelect（进入旅程）
  ↓
PanelB.GuideCardPlay（B 面板：图卡展示、数字候选、风险提示、完成验证）
  ↓
RiskConfirm / LostRecovery（风险确认 / 迷路恢复）
  ↓
OutputVerify（完成验证）
  ↓
TraceComplete（旅程记录完成）
```

## 核心能力

```text
双悬浮面板：A 意图澄清对话框，B 图卡展示区
A 面板：员工文字/语音主动提问 → 多轮澄清 → 专业意见 → 旅程候选 → 人类确认
B 面板：贴合真实操作界面的图卡播放 → 模糊/聚焦 → 色框导航线 → 数字候选 → 风险提示 → 完成验证
迷路恢复 LostRecovery
风险确认（L2/L3 不可自动跳过）
完成验证 + Trace 旅程记录
呼叫专家（生成问题摘要）
```

## 双悬浮面板

Coach 采用独立悬浮窗口，不介入浏览器和其它业务系统。窗口内包含两个悬浮面板，而不是一个大聊天框：

```text
A. 意图澄清对话框
- 入口：员工点击悬浮按钮后展开
- 内容：文字输入、多轮澄清、专业意见、旅程候选；语音按钮可选
- 控制：展开、收缩、钉住由员工决定
- 决策：是否问清楚、是否进入旅程，由员工通过数字选择确认

B. 图卡展示区
- 入口：员工确认进入旅程后出现
- 内容：当前 GuideCard、数字候选、风险提示、完成验证、迷路恢复入口
- 视觉：尽量与员工正在操作的业务界面一致，通过模糊化/聚焦化、色框和导航线指出目标区域
- 控制：展开、收缩、钉住由员工决定
- 决策：员工按 0-9 选择下一步，Coach 只导航不代操作
```

A 面板负责“问清楚我要做什么”，B 面板负责“显示现在该怎么做”。二者可以同时存在，但职责不能混用：A 不播放执行图卡，B 不做自由聊天。两个面板都必须提供展开、收缩和钉住按钮，是否展开、收缩或固定在屏幕上由员工决定。

员工遇到问题时主动点击独立悬浮窗口展开 A 面板，用文字提问；语音输入可选。Coach 不根据屏幕状态主动猜员工要做什么。

进入旅程后，B 面板成为主面板；A 面板可以收起，也可以在员工卡住、选择 9、选择“我不确定”或需要呼叫专家时重新展开。

多轮澄清是否结束，由员工通过数字选择确认。AI 可以说“建议进入某旅程”，但不能自动替员工进入旅程。

## B 图卡视觉规则

B 图卡展示区不是抽象说明卡，也不是覆盖在真实业务系统上的操作层，而是仅供参考的线框导航图。它应尽量贴近员工正在操作的真实界面结构，但不遮挡、不改写、不操控真实系统。

```text
线框一致：图卡用线框图表达页面、字段、按钮和区域，名称与真实业务界面保持一致
模糊化：非当前关注区域可以弱化或模糊，减少干扰
聚焦化：当前要看的字段、按钮或区域必须清晰突出
色框：用颜色框标出当前目标、候选目标、风险区域和完成状态
导航线：用线条把说明文字、数字候选和线框图目标连接起来
```

色框建议：

```text
粉红实线：当前主焦点
粉红虚线：候选目标
浅蓝色框：业务场域
浅黄色框：风险区域
浅绿色框：成功或完成状态
灰色蒙层：弱化背景
```

图卡的美感不是“画一张漂亮图”，而是用足够像真实界面的线框图，让员工一眼知道真实界面里该看哪里、点哪里、核对哪里。DeepGuide 仍然不替员工点击，只把目标区域在参考图中导航出来。

## 意图澄清示例

用户说："客户问这个发票能不能报销。"

Coach 不直接猜员工要什么，而是先澄清：

```text
你现在要确认的是哪件事？
1. 发票真假
2. 报销材料是否齐全
3. 是否符合本单位报销规则
4. 我不确定，请继续问我
9. 重新生成选项
0. 返回/取消
```

用户说"2"后，Coach 给出专业意见和旅程候选：

```text
建议先走“发票报销材料检查”旅程。
1. 进入发票报销材料检查
2. 继续补充情况
9. 重新生成选项
0. 返回/取消
```

用户说"1"，进入对应旅程。

## 迷路恢复示例

```text
你现在卡在哪？
1. 找不到系统入口
2. 不知道材料是否齐全
3. 系统提示错误
4. 需要问专家
9. 重新生成选项
0. 返回上一步/取消
```

每个恢复路径指向明确 Gate 或 Card。

## MVP 范围

第一版必须支持：独立悬浮窗口、双悬浮面板、A 意图澄清对话框、B 图卡展示区、展开/收缩/钉住、点击展开、文字输入、可选语音输入、多轮意图澄清、专业意见、意图候选、数字选择、人类确认进入旅程、图卡播放、模糊/聚焦、色框导航线、LostRecovery、风险确认、完成验证、Trace 旅程记录、从 Studio 发布旅程包。

首个样板：财税/会计实操中的发票报销材料检查，面向新入职财务助理 / 报销初审员。

首版运行环境：Windows 10/11 普通桌面，覆盖常见高 DPI、多屏和独立悬浮窗口场景。

暂不做：自由聊天业务决策、自动替用户提交高风险业务、大规模知识库问答、复杂 RPA、多人协作工单、第一版离线模式、Win7 普遍兼容承诺。

第二版支持离线模式：可播放已缓存 published 旅程包；外网受限客户可配置甲方内部 AI。多语言能力不阻塞第一版，后续接 DeepBase i18n。Win7 客户只作为遗留项目兼容评估，按现场环境、功能限制和单独验收处理。

## 验收标准

```text
用户能从 A 意图澄清对话框通过语音/文字表达问题，并由人类确认进入正确业务旅程；进入后 B 图卡展示区能以接近真实业务界面的线框图、模糊/聚焦和色框导航线展示当前步骤
所有候选都遵守 0-9 数字语法：1-8 业务候选，9 重新生成选项，0 返回/取消
正常路径能走到 Output
关键卡点有 LostRecovery
高风险动作有确认
完成结果有 Trace 旅程记录
前台不能使用未发布旅程包
版本变更后 Coach 使用最新发布版本
用户反馈能回流 Studio
```

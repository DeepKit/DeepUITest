## 1. 概述

### 1.1 架构定位

DeepFlow 是*智能应用的操作系*统*，提供：
- 11 个标准化角色的运行时
- Workflow 流程引擎
- Skill 扩展机制
- 安全与信任边*界*
- 多层记忆体系

### 1.2 开发方法论

DeepFlow 开发应遵循 `00.ai智能体架构规*范*025-12-03.md`（Agent系统软件设计完整指导手册）中的：
- **设计模式**：Reflection、Tool Use、Planning、Multi-Agent、Evaluator-Optimizer
- **Prompt工程**：XML 标签隔离、思维链、Few-Shot 示例
- **评估体系**：单元测试、模型评估库·黄金数据集(Golden Dataset)** 回归测试
- **降级策略**：自动重试、输出修复、传统方法兜底

## 3. 11 角色架构

### 3.1 角色层级

| 层级 | 角色 | 职责 | 信任级别 |
|------|------|------|----------|
| L0 元层 | 引擎(Engine) | 系统生命周期管理 | 完全信任 |
| L0 元层 | 督察(Inspector) | 调试与可观测性 | 完全信任 |
| L4 决策层 | 总指挥(Commander) | 任务分解与分配 | 有限信任 |
| L4 决策层 | 调度官(Dispatcher) | 流程编排与调度 | 有限信任 |
| L3 智能层 | 智囊(Advisor) | AI 推理与建议 | 不信任 |
| L2 能力层 | 执行者(Executor) | 执行具体任务 | 不信任 |
| L2 能力层 | 守卫(Guard) | 安全校验 | 有限信任 |
| L2 能力层 | 军需员(Quartermaster) | 资源与配额管理 | 有限信任 |
| L1 基础层 | 后勤(Logistics) | 资源管理 | 完全信任 |
| L1 基础层 | 记录官(Chronicler) | 日志与审计 | 完全信任 |
| L1 基础层 | 通信官(SignalOfficer) | 外部通信 | 有限信任 |

### 3.2 角色交互原则

1. **单向依赖**：高层可调用低层，低层不能调用高层。
2. **接口隔离**：角色间通过接口通信，不直接访问内部状态。
3. **输出校验**：不信任区角色的输出必须经过守卫校验
4. **消息驱动**：角色间通过标准消息协议通信

### 3.3 角色接口定义

详见 `05.01.API-DeepFlow接口规范-v1.0.md`

## 4. Workflow 引擎

### 4.1 任务类型

| 类型 | 说明 | 示例 |
|------|------|------|
| SystemTask | 系统内置任务 | 变量赋值、条件判断 |
| SkillTask | 调用 Skill | HTTP 请求、数据库查询 |
| AgentTask | AI 推理任务 | 内容生成、意图理解|
| HumanTask | 人工介入任务 | 审批、确认|

### 4.2 流程结构

支持的流程结构：
- **顺序执行**：A → B → C
- **条件分支**：if/else、switch
- **并行执行**：fork/join
- **循环**：while、for-each
- **子流程**：嵌套 Workflow

### 4.3 状态机

```
┌────────→  创建     ┌─────────┐
│NEW │─────────> │PENDING │
└────────           └────┬────┘
                         │开始执行
                         ►
                    ┌─────────┐
             ┌───── ►RUNNING ►─────┐
             ├     │    └────┴────│     │
             │暂停      │完成      │失败
             │          │          │

        │PAUSED ││ COMPLETED││ FAILED │

```

### 4.4 快速通道 (Fast Path)

针对低风险、无状态的简单Skill 调用，架构支持**快速通道**模式。

**触发条件（必须同时满足）**：
| 条件 | 阈值/规则 | 说明 |
|------|----------|------|
| Skill 信任级别 | `Core` 或 `Official` | 排除 Community/User 级别 |
| Skill 副作用类型 | 在白名单内 | 见下文 |
| 预估执行时长 | < 100ms | 基于历史统计 |
| 输入大小 | < 4KB | 避免大数据校验开销 |
| 当前系统负载 | < 80% | 高负载时禁用快速通道 |

**副作用白名单**：
| 允许 | 禁止 |
|------|------|
| 纯计算（无IO） | 数据库写入 |
| 内存缓存读取 | 文件写入 |
| 本地配置读取 | 外部 API 调用 |
| 日志写入（低级别） | 发送通知/消息 |

**跳过的步骤**：
- Commander 任务分解（直接使用原始请求）
- Guard 入口深度校验（仅做格式校验）
- 完整审计日志（仅记录摘要）

**保留的步骤**：
- Guard 出口校验（必须）
- 基础权限检查（必须）
- 错误处理与降级（必须）

### 4.5 Saga 补偿机制

对于包含多个有副作用步骤的Workflow，采用Saga 模式保障最终一致性：

```
┌─────────────────────────────────────────────────────────────────┐
│                  Saga 执行流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                │
│ 正向执行：Step1 ─→Step2 ─→Step3 ─→Step4 ─→完成            │
│              ↓       ↓       ↓       ↓                     │
│              ↓       ↓       ↓       ↓                     │
│           [记录]   [记录]   [记录]   [记录]                    │
│                                                                │
│ 补偿执行（Step3 失败时）←?                                     │
│              Step2.Compensate ◄─ Step1.Compensate              │
│                                                                │
└─────────────────────────────────────────────────────────────────┘
```

**Skill 补偿接口**：
```pascal
ICompensableSkill = interface(ISkill)
  // 检查是否支持补偿？
  function CanCompensate: Boolean;
  // 执行补偿操作
  function Compensate(const AOriginalInput: TSkillInput;
    const AOriginalOutput: TSkillOutput;
    const AReason: string): TSkillOutput;
  // 获取补偿超时时间
  function GetCompensateTimeout: Integer;
end;
```

**补偿策略配置**：
```json
{
  "sagaConfig": {
    "enabled": true,
    "compensateOrder": "reverse",
    "maxCompensateRetries": 3,
    "compensateTimeout": 30000,
    "onCompensateFail": "alert_and_manual"
  }
}
```

**补偿失败处理**：
| 策略 | 说明 |
|------|------|
| `retry` | 自动重试（最多N 次） |
| `alert_and_manual` | 告警并等待人工介入 |
| `force_complete` | 标记为补偿失败但继续（需审计后） |
| `dead_letter` | 进入死信队列等待处理 |


**熔断器配置)?
```pascal
TCircuitBreakerConfig = record
  FailureThreshold: Integer;     // 触发熔断的连续失败次数，默认 5
   SuccessThreshold: Integer;     // 恢复所需连续成功次数，默认 3
   OpenTimeout: Integer;          // 熔断持续时间(ms)，默认 30000
   HalfOpenMaxCalls: Integer;     // 半开状态最大探测调用数，默认 3

```

**熔断适用角色**：
| 角色 | 熔断对象 | 降级策略 |
|------|----------|----------|
| 通信员 | 外部 HTTP/MCP 服务 | 返回缓存结果或默认值 |
| 智囊 | LLM API | 返回低置信度默认响应 |
| 执行员 | Python Skill 服务 | 使用 Delphi 备用实现 |

### 6.2 负载控制

**背压机制**：
```pascal
TBackpressureConfig = record
  MaxPendingRequests: Integer;   // 最大排队请求数，默认:1000
  MaxConcurrentTasks: Integer;   // 最大并发任务数，默认:100
  RejectPolicy: TRejectPolicy;   // 拒绝策略：drop/queue/error
  QueueTimeout: Integer;         // 队列等待超时(ms)，默认:30000
end;
```

**限流规则**:
| 维度 | 限制 | 说明 |
|------|------|------|
| 全局 QPS | 1000/s | 系统整体吞吐上限 |
| 单用户QPS | 100/s | 防止单用户占用过多资源|
| LLM 调用 | 10/s | API 成本控制 |
| 工作流 Workflow 并发步骤 | 10 | 防止 fork 爆炸 |

## 7. 安全机制

### 7.1 三重守卫

```
请求 ──> [门卫] ──> 处理 ──> [监工] ──> 输出 ──> [审核官] ──> 响应
         入口校验      过程监控           出口校验
```

### 7.2 信任边界

|| 区域 | 角色 | 约束 |
||------|------|------|
|| 完全信任区| 引擎/督察/后勤/记录员| 无额外校验|
|| 有限信任区| 总指挥/调度员/守卫/军需员/通信员| 权限检查|
|| 不信任区 | 智囊/执行官| 输出必须校验 |

### 7.3 安全原则

1. **硬执行优于软执行** - 安全规则由架构强制，不依赖Prompt
2. **最小权限** - 每个角色只拥有完成任务所需的最小权限
3. **纵深防御** - 多层校验，单点失败不导致安全漏洞
4. **可审计** - 所有操作记录在案，可追溯

### 10.3 性能与通信优化 (IPC)

鉴于 Delphi 与 Python 之间通过 HTTP 通讯可能产生延迟，架构采用以下策略优化：

1.  **长连接 (Keep-Alive)**: 复用 HTTP 连接，避免每次请求握手开销。
2.  **Payload 压缩**: 对于超过 4KB 的报文，启用 GZIP 压缩。
3.  **本地回环优化**: 明确绑定 `127.0.0.1`，避免 DNS 解析延迟。
4.  **Fast Path (未来)**:
     - 对于高频、低计算量的 Skill (如正则匹配)，在 Delphi 侧原生实现。
     - 考虑集成 `Python4Delphi` (P4D) 直接调用 DLL，或使用 ZeroMQ/共享内存替代 HTTP。

### 10.4 Python 服务生命周期管理

为确保桌面环境下的稳定性，DeepFlow Core (Delphi) 负责 Python 服务的全生命周期管理。
- **内嵌运行**：集成 Embeddable Python，无需用户手动安装环境。
- **自动启动/守护**：Engine 启动时自动拉起 Python 进程，SignalOfficer 负责心跳检测。
- **自动重启**：检测到服务崩溃时自动重启，并恢复上下文。

### 9.4 数据存储策略

**本地优先原则**：
- 每个应用独立 SQLite 数据库。
- 离线可用，保护用户隐私。
- 决策数据默认不上云。

**可选云同步（3.0+）**：
- 用户主动选择同步内容
- PostgreSQL 存储同步数据
- 用户账号、Skill 市场元数据

## 2. 元层角色（Level 0：?

### 2.1 引擎（Engine：?

| 项目 | 内容 |
|------|------|
| **军队：**? | 战争机器 / 国家机器 |
| **电影定义** | 摄影机/ 放映系统 |
| **核心职责** | 驱动所有角色运转的"心脏" |
| **特点** | 纯程序、无智能、绝对可预测 |

#### 职责详情

1. **角色实例管理**：创建、销毁各角色实例
2. **消息路由**：角色之间的通信管道
3. **事件循环**：驱动整个系统的主循环
4. **生命周期管理**：启动、运行、暂停、停止

#### 代码结构

```
UniFlowEngine
├── RoleRegistry          // 角色注册表
方法  ├── register(role)
    ├── getInstance(roleType)
    └── getAllRoles()
├── MessageBus            // 消息总线
方法  ├── send(from, to, message)
    ├── broadcast(message)
    └── subscribe(topic, handler)
├── EventLoop             // 事件循环
方法  ├── start()
    ├── stop()
    ├── pause()
    └── resume()
└── LifecycleManager      // 生命周期
    ├── initialize()
    ├── shutdown()
    └── healthCheck()
```

#### 边界

- **不做任何业务决策**
- 只负责让其他角色"能动起来"
- 必须极度稳定，代码覆盖率 > 95%

### 2.2 督察（Inspector模块）

| 项目 | 内容 |
|------|------|
| **军队类型** | 总监察长 / 参谋总部督察 |
**电影角色** | 监制 / 制片监督 |
**核心职责** | 观察、调试、干预所有角色 |
**特点** | 特权访问、可穿透所有边界 |

#### 职责详情

1. **调试接口**：查看任何角色的内部状态
2. **断点控制**：暂停/单步执行任何流程
3. **注入测试**：Mock 任何角色的输入/输出
4. **性能剖析**：收集各角色的执行指标
5. **紧急停止**：强制停止/重启任何角色

#### 代码结构

```
UniFlowInspector
├── StateViewer           // 状态查看
│   ├── getRoleState(roleType)
│   ├── getWorkflowState(instanceId)
│   └── getMemoryState()
├── DebugController       // 调试控制
│   ├── setBreakpoint(location)
│   ├── step()
│   ├── continue()
│   └── abort()
├── MockInjector          // Mock 注入
│   ├── mockSkill(skillId, response)
│   ├── mockAgent(agentId, response)
│   └── mockExternal(serviceId, response)
├── Profiler              // 性能剖析
│   ├── startProfiling()
│   ├── stopProfiling()
│   └── getReport()
└── EmergencyControl      // 紧急控制
    ├── forceStop(roleType)
    ├── forceRestart(roleType)
    └── isolate(roleType)
```

#### 安全控制

| 督察能力 | 风险 | 控制措施 |
|----------|------|----------|
| 状态查看 | 敏感数据泄露 | 脱敏、权限分配 |
| 断点控制 | 服务中断 | 仅限开放测试环境 |
| Mock 注入 | 绕过安全检查| 生产环境禁用 |
| 紧急干预| 误操作导致故障| 需要认证、审计记录|

## 3. 决策层角色（Level 4（指挥层）

### 3.1 总指挥（Commander（指挥官）

| 项目 | 内容 |
|------|------|
| **军队（军队）?** | 司令员|
| **电影（电影）?** | 导演 |
| **核心职责** | 全局决策、资源调度、最终拍板|
| **实现类型** | 纯程序（不使用AI）?|

#### 职责详情

1. **请求受理**：决定是否接受请求？
2. **资源调度**：分配计算、存储/AI 资源
3. **最终拍板*：有争议时做最终决定
4. **异常兜底**：处理无法自动恢复的故障
5. **对外响应**：向调用方返回最终结果

#### 边界

- 不直接处理业务细节
- 不包含任何业务UI 代码
- 依赖：调度员、守卫者

---

### 3.2 调度员（Dispatcher（调度员）

| 项目 | 内容 |
|------|------|
| **军队（军队）?** | 参谋 |
| **电影（电影）** | 副导演/ 场记 |
| **核心职责** | 拆解任务、安排执行顺序、追踪进度|
| **实现类型** | Workflow 引擎 |

#### 职责详情

1. **任务拆解**：将请求分解为可执行步骤
2. **流程选择**：决定使用哪种 Workflow
3. **步骤调度**：按序执行：SystemTask/SkillTask/AgentTask/HumanTask
4. **状态追踪*：维护任务的当前状态和进度
5. **重试决策**：失败时决定是否重试/跳过/终止
6. **人工协调**：管理 HumanTask 的等待和恢复

#### 边界

- 不关心每个步骤内部如何完成"
- 只关心输入输出与状态
- 不直接调用LLM
- 依赖：智囊、执行者、守卫、记录员、军械官

## 4. 智能层角色（Level 3）

### 4.1 智囊（Advisor）

| 项目 | 内容 |
|------|------|
| **军队参谋** | 情报专员 |
| **电影导演** | 编剧 |
| **核心职责** | 理解/生成/诊断（AI 能力范围） |
| **实现类型** | Agent 运行时 |

#### 三种专长

| 专长 | 军队比喻 | 电影比喻 | 职责 |
|------|----------|----------|------|
| **理解专长** | 情报分析 | 编剧前期/读剧本| 理解用户意图，输出结构化意图 |
| **生成专长** | 作战方案 | 编剧创作 | 生成内容/方案/代码草案 |
| **诊断专长** | 战损评估 | 剪辑/调色 | 分析问题、给修复建议 |

#### 职责详情

1. **意图理解**：解析自然语言/半结构化输入
2. **内容生成**：生成文案、代码、方案等
3. **问题诊断**：分析错误、给出排查建议
4. **Prompt 组装**：运行时构建最佳Prompt
5. **Few-shot 选择**：从记忆中选择相关示例

#### 关键约束

- **只输出"提案"，不直接落地副作用**
- 生成结果必须经过守卫审核
- 依赖：军械官、记录员、执行者

## 5. 能力层角色（Level 2)

### 5.1 执行者（Executor)

| 项目 | 内容 |
|------|------|
| **军队）* | 作战部队 / 工兵 |
| **电影）* | 摄制组（摄影、灯光、录音、剪辑） |
| **核心职责** | 调接口、跑脚本、真正干活|
| **实现类型** | SkillRunner + ServiceAdapter |

#### 职责详情

1. **Skill 执行**：调用已注册的Skill
2. **外部调用**：通过通信官访问外部服务
3. **结果封装**：将执行结果格式化返回
4. **错误处理**：捕获异常，按策略重试
5. **进度上报**：向调度员报告执行状态

#### 边界

- 不做跨步骤决策
- 不直接访问外部（通过通信官）
- 依赖：通信官、军械官

---

### 5.2 守卫（Guard角色）

| 项目 | 内容 |
|------|------|
| **军队角色** | 宪兵 / 军法官 |
| **电影角色** | 法务 / 审片委员会 |
| **核心职责** | 入口/过程/出口把关 |
| **特点** | 一票否决权 |

#### 三个子角色

| 子角色 | 军队角色 | 电影角色 | 位置 | 职责 |
|--------|--------|--------|------|------|
| **门卫** | 哨兵 | 门禁保安 | 入口 | 请求合法性、权限检查 |
| **监工** | 督战队 | 现场监制 | 过程 | 超时/超预期/异常行为监控 |
| **审核角色** | 军法官 | 审片委员会 | 出口 | 结果格式/安全/合规校验 |

#### 职责详情

1. **入口校验**：请求格式、权限、参数有效性 |
2. **过程监控**：步数限制、时间限制、成本限制 |
3. **出口审核**：结果格式、安全合规、业务逻辑
4. **幻觉检测**：AI 输出的合理性验证 |
5. **告警上报**：安全事件通知总指挥

#### 关键原则

- **一票否决权**：守卫说"不行"就是不行
- 任何角色的输出都要过守卫
- 依赖：记录员

### 5.3 军械官（Quartermaster）

| 项目 | 内容 |
|------|------|
| **军队** | 军械处长 |
| **电影** | 道具组/ 道具管理 |
| **核心职责** | 管理 Skills/Prompts 注册、配置、权限 |
| **管理对象** | 静态资产（能力定义、模板、配置） |

#### 职责详情

1. **Skill 注册**：登记可用的 Skill 定义
2. **Prompt 管理**：存储和版本控制 Prompt 模板
3. **配置管理**：Skill/Prompt 的参数配置
4. **权限分发**：谁能用哪些 Skill/Prompt
5. **版本控制**：升级、回滚、兼容性检查

#### 代码结构

```
Quartermaster
├── SkillRegistry        // 技能注册中心
├── SkillConfigManager   // 技能配置管理
├── PromptRegistry       // Prompt 模板注册
├── PromptConfigManager  // Prompt 参数配置
└── AssetVersionControl  // 版本管理
```

#### 边界

- **静态资产**，不是运行时组件
- Prompt 运行时组装由智囊负责
- 依赖：后勤、记录员

## 7. 角色间通信

### 7.1 两种消息类型

#### 命令消息（Command模式）

```
发送方 → 接收方：我要你做一件事，等你的结果
```
- 同步或异步等待
- 有明确的请求/响应
- 需要处理超时和失败

#### 事件消息（Event模式）

```
发生者通知所有订阅者：有件事发生了，你们看着办
```
- 发后不管
- 多个订阅者
- 解耦合

### 7.2 消息流向矩阵

| 发送方 | 接收方 | 消息类型 | 说明 |
|--------|--------|----------|------|
| 总指挥 | 调度员 | Command | 下达任务 |
| 调度员 | 智囊/执行者 | Command | 分配工作 |
| 智囊 | 军械库 | Command | 获取 Prompt/Skill |
| 智囊 | 记录员 | Command | 读写记忆 |
| 执行者 | 通信官 | Command | 调用外部服务 |
| 守卫 | 任意角色 | Command | 校验请求 |
| 任意角色 | 记录员 | Event | 记录发生的事 |
| 守卫 | 总指挥 | Event | 安全告警 |
| 引擎 | 所有角色 | Event | 生命周期事件 |

## 8. 信任边界

```
┌─────────────────────────────────────────────────────────┐
│                   完全信任区                           │
│        引擎 │ 督察 │ 后勤 │ 记录员                     │
├─────────────────────────────────────────────────────────┤
高                   有限信任级                           审计员
审计员   总指挥、调度、守卫、军械、通信             审计员
可信   （可信但需要审计）                                    可信
 ├─────────────────────────────────────────────────────────》
│                   不信任区                              │
审查             智囊 审查操作                              动作
执行者   （输出必须校验，行为必须监控。                        操作
└─────────────────────────────────────────────────────────描述
```

**智囊和执行者在"不信任区"**区域
- 智囊的输出由 LLM 生成，可能有幻觉
- 执行者调用外部服务，可能有意破坏

## 9. 生命周期覆盖

### 9.1 阶段与角色

| 生命周期阶段 | 涉及角色 |
|--------------|----------|
| 启动初始化 | 引擎、后勤、军械官、记录员、通信官、守卫、总指挥 |
| 接收受理 | 守卫（门卫）、总指挥、调度员、记录员 |
| 规划调度 | 调度员、军械官、记录员 |
| 执行处理 | 智囊、执行者、守卫（监工）、通信官、记录员 |
| 验证输出 | 守卫（审核官）、智囊、调度员、执行者、后勤、总指挥 |
| 收尾清理 | 记录员、后勤、守卫、总指挥 |

### 9.2 请求生命周期流程

```
请求 →门卫（入口校验） →总指挥（受理/拒绝）→调度员（拆任务）
                                                      ↓
                                           ├─ 智囊（如需 AI）─┤
                                           └─                 │
                                        执行者←───────── 监工（过程监控）
                                           ↓
                                        审核官（出口把关）↓
                                           │
                                      落地/输出
                                           ↓
记录员（归档）
```

## 10. 角色职责总结

| 角色 | 主要覆盖阶段 | 核心价值 |
|------|--------------|----------|
| **引擎** | 全程 | 驱动一切运转 |
| **督察** | 全程（观测） | 调试和干预能力 |
| **总指挥** | 全程（决策点） | 最终拍板、异常兜底 |
| **调度员** | 规划→执行→输出 | 任务编排、流程控制 |
| **智囊** | 执行→验证 | AI 能力、理由生成/诊断 |
| **执行员** | 执行 | 真正干活、调用外部 |
| **守卫** | 全程（检查点） | 安全把关、质量保证 |
| **后勤** | 启动→收尾 | 基础设施、资源管理 |
| **军械员** | 启动→规划 | 能力资产管理 |
| **记录员** | 全程（旁观者） | 记录一切、记忆管理 |
| **通信员** | 执行 | 外部通信管理 |

## 11. 最小角色配置

### 11.1 最简系统组 · 角色组

- 总指挥 + 执行员 + 守卫 + 后勤

### 11.2 标准系统组 · 角色组

- 总指挥 + 调度员 + 智囊 + 执行员 + 守卫 + 后勤 + 记录员

- 全部 11 个角色

## 1. 核心命题

本文档回答三个关键问题：

1. **系统落地**：如何让 DeepFlow 从设计走向可运行的系统？
2. **易于集成**：如何让外部系统能方便地使用 DeepFlow 能力？
3. **MCP 利用**：如何充分利用MCP 协议实现能力互通？

## 2. 系统落地策略

### 2.1 最小可运行系统（MRS - Minimum Runnable System）

**核心理念**：在 MVP 之前，先有一个"能跑起来"的系统；

```
MRS 阶段目标：
┌─────────────────────────────────────────────────────────────────┐
│                   最小可运行系统                                 │
├─────────────────────────────────────────────────────────────────┤
│ 1. Delphi 主程序能启动                                          │
│ 2. 能发送消息到 Python 服务                                     │
│ 3. Python 服务能调用LLM 返回结果                               │
☑ 4. 结果能显示在 UI ☑
☑ 5. 整个过程可追溯（有日志）                                     ☑
└─────────────────────────────────────────────────────────────────☑
```

### 2.2 分层落地路线

```
阶段 0: 基础设施层(Infrastructure)
├── Python 嵌入式环境打包
├── HTTP 通信验证（Delphi <-> FastAPI）
├── SQLite 数据库初始化
└── 配置管理（JSON/YAML）

阶段 1: 核心运行时层 (Core Runtime)
├── 消息总线实现
├── 6 角色基础框架
├── Skill 注册与调用
└── 基础日志审计

阶段 2: 流程执行引擎(Workflow Engine)
├── 状态机实现
├── 顺序/条件执行
├── 状态持久化
└── 中断与恢复

阶段 3: 业务应用层(Application)
├── 洞见·决策流程
├── 多角色并行推演
├── 记忆系统集成
└── UI 交互完善
```

### 2.3 落地风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Python 环境问题 | 中 | 使用 Embedded Python + 预打包依赖 |
| LLM API 不稳定 | 高 | 多后端容错 + Mock 模式 |
| 状态恢复复杂 | 中 | 简化状态模型，只持久化关键节点 |
| 性能瓶颈 | 高| 异步执行 + 连接池+ 缓存 |
| 调试困难 | 高| 完善日志 + Inspector 角色 |

### 2.4 落地检验标准

**MRS 验收标准**：
- [ ] 冷启动到可接受用户输入 < 5s
- [ ] Delphi -> Python 往返延迟 < 100ms（排除LLM）
- [ ] 异常情况有明确错误码和日志
- [ ] 主进程崩溃不会丢失执行状态

**MVP 验收标准**：
- [ ] 完整的决策流程可执行
- [ ] 至少 3 个角色可并行推演
- [ ] HumanTask 可正确等待和恢复
- [ ] 重启后 Workflow 可从断点继续

#### 3.3.2 Skill 封装模式

```python
外部服务封装的 Skill 的标准模型
class ExternalServiceSkill(BaseSkill):
    def __init__(self, service_config: dict):
        self.service = ExternalServiceClient(service_config)
        
    async def execute(self, input: SkillInput) -> SkillOutput:
        try:
输入转换（内部格式 -> 外部格式）
            external_request = self._transform_input(input)
            
            # 2. 调用外部服务
            external_response = await self.service.call(external_request)
            
输出转换（外部格式 -> 内部格式）
            result = self._transform_output(external_response)
            
            return SkillOutput(success=True, data=result)
            
        except TimeoutError:
            return SkillOutput(success=False, error="EXTERNAL_TIMEOUT")
        except AuthError:
            return SkillOutput(success=False, error="EXTERNAL_AUTH_FAILED")
        except Exception as e:
            return SkillOutput(success=False, error=f"EXTERNAL_ERROR: {str(e)}")
```

### 4.2 MCP Server 实现│.0 阶段│

#### 4.2.1 暴露 DeepFlow 能力│MCP Tool

```python
# uniFlow_py/mcp_server.py
from mcp import MCPServer, Tool, Resource

class UniFlowMCPServer(MCPServer):
    def __init__(self, skill_registry):
        super().__init__()
        self.skill_registry = skill_registry
        self._register_tools()
    
    def _register_tools(self):
        """将 UniFlow Skills 自动转换为 MCP Tools"""
        for skill in self.skill_registry.list_all():
            meta = skill.get_meta()
            tool = Tool(
                name=f"uniflow_{meta.name}",
                description=meta.description,
                input_schema=meta.input_schema,
                # MCP 回调 -> Skill 执行
                handler=lambda input: self._execute_skill(meta.name, input)
            )
            self.register_tool(tool)
    
    async def _execute_skill(self, skill_name: str, input: dict) -> dict:
        """MCP Tool 调用转发给Skill 执行"""
        skill = self.skill_registry.get(skill_name)
        result = await skill.execute(SkillInput(data=input))
        return result.data
```

#### 4.2.2 MCP 能力暴露策略

| 能力类型 | MCP 暴露 | 说明 |
|----------|----------|------|
| 只读查询 | 仅优先 | 决策记录、会话历史、Workflow 状态 |
| 纯计算 | 仅优先 | 文本分析、摘要、结构化抽取 |
| LLM 包装 | ⚠️ 受控 | 需要配额和安全审计 |
| Workflow 执行 | ⚠️ 受控 | 仅暴露预定义模板 |
| 写入操作 | 仅禁止 | 不通过 MCP 暴露写入能力 |

### 4.3 MCP Client 实现（理想版本）

#### 4.3.1 接入外部 MCP Server

```python
# uniFlow_py/mcp_client.py
from mcp.client import MCPClient

class MCPSkillBridge:
    """将外部MCP Tool 桥接到UniFlow Skill"""
    
    def __init__(self, server_config: dict):
        self.client = MCPClient(server_config['endpoint'])
        self.server_id = server_config['id']
        
    async def discover_tools(self) -> list[SkillMeta]:
        """发现并转换MCP Tools为Skill元数据"""
        tools = await self.client.list_tools()
        return [self._tool_to_skill_meta(t) for t in tools]
    
    async def execute_tool(self, tool_name: str, input: dict) -> dict:
        """执行 MCP Tool"""
        return await self.client.call_tool(tool_name, input)
    
    def _tool_to_skill_meta(self, tool: MCPTool) -> SkillMeta:
        """MCP Tool -> SkillMeta 转换"""
        return SkillMeta(
            name=f"mcp.{self.server_id}.{tool.name}",
            version="1.0",
            description=tool.description,
            input_schema=tool.input_schema,
            output_schema=tool.output_schema or {},
            source_type=SkillSourceType.MCP
        )
```

## 7. 总结

### 7.1 核心结论

1. **落地优先**：先有能跑的系统，再追求功能完善。
2. **分层设计**：内部保持抽象，对外提供标准协议。
3. **安全第一**：所有外部接口必须经过认证、授权、审计。
4. **渐进开发**：先 Provider（被调用），再做 Consumer（调用外部）。

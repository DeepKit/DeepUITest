## 2. 产品简介

### 2.1 DevDirector 的核心能力与优势

DevDirector 定位为"零代码自动化工具"

1. **项目/功能/步骤三级结构** - Project / Feature / Step (00-xx)
2. **执行记录和决策追踪** - Execution Log + Decision 记录
3. **组件化的脚本模型** - 脚本(Script) / 角色元素(Actor/Prop) / 帧(Frame) / 场景(ScenarioFlow)
4. **自然语言驱动的测试生成** - NL 自然语言生成 / UIScreen/UIRegion/UIControl/UIViewState
5. **多角色 AI 协作模式** - 架构(总控) / 开发(编码) / 测试(验证) / 产品(需求)
6. **智能工作日志自动生成** - 自动记录操作日志到 WorkLog
7. **知识沉淀** - Guideline/Pattern/BugCase 管理

### 2.2 DeepFlow vs DevDirector 人员对比

| 角色 | DevDirector | DeepFlow MVP |
|------|-------------|-------------|
| 岗位 | AI资深专家 | 通用Agent编排 |
| 角色 | 4 个AI角色+Prompt编排 | 11 个角色+工作流编排 |
| 部署 | 本地部署 | 云端部署 Workflow |
| 扩展 | 固定流程 | Skill 灵活配置 |
| 安全 | Prompt内容加密执行 | 强约束控制，硬执行 |
| 日志 | WorkLog 日报 | 完整流程记录 |

## 3. 数据处理规划

### 3.1 第一版：MVP功能规划

> **验证目标**验证DeepFlow ??DevDirector 集成
> **验证范围**覆盖场景DeepInsight所能支持体系

#### 技术栈

| 模块 | 技术选型 | 说明 |
|------|----------|------|
| 本地存储 | Delphi + FMX | 基于 DeepBase 数据库 + 零冗余备份 |
| Python Skill | FastAPI + LiteLLM | HTTP 接口服务 |
| LLM 集成 | LiteLLM | 支持 OpenRouter 多模型 |
| 本地存储 | SQLite | 完全隐私读取和备份控制 |
| 移动存储 | PostgreSQL 11.0+ | 可选同步 |

#### 整体实现的技术方案

**1. 方案一、红色等级定义**

| 级别 | 颜色 | MVP 实现场景 |
|------|------|-------------|
| 元素 (L0) | 前端 + 后端 | MVP 实现 |
| 微服务(L4) | 接口层 + 服务层 | 完整实现 |
| 领域驱动设计(L3) | 领域层 | 部分实现，需LLM辅助|
| 错误清单(L3) | 执行清单+ 注册清单 + 决策清单| 实例实现 |
| 配置清单(L1) | 执行清单+ 记录清单 + 通信清单| 实例实现 |

**2. Skill 能力评估框架**

Core Skills模块涵盖6项关联相关技能
- HTTP 协议规范
- 数据库可写入DeepBase 集群
- 文件解析
- LLM 模型封装
- 定时任务
- 人工审核

**3. Workflow 工作流引擎**

支持的任意任务类型：SystemTask、SkillTask、AgentTask、HumanTask

支持的工作流结构：顺序流程、并行分支、子流程嵌套

**4. 安全模型**

系统开发各阶段均应遵循标准工程流程，并进行人工审核确认。

外部安全边界设计。
- 安全设计控制指标：认证/授权/记录/日志。
- 信息安全管控指标：认证/授权/记录/日志。
- 相关方职责执行人（含委员会）

**5. 成功观察？**

- 记录会员自动登录功能中的角色信息?
- 系统提供查询接口
- 清理相关数据?

#### MVP 验收标准

1. 能够被 DevDirector 管理项目
2. 视频成长过程影响视频水印清单：
3. 可被观察到的结果
4. 安全可靠

## 4. 数据原则

### 4.1 12 个核心洞察的底层逻辑

1. **AI 是个可靠的工具** ??确保有足够 AI 的安全感??
2. **上下文丰富 > 模型强大** ??上下文丰富更重要??
3. **Skill 帮用户做决策** ??用户依赖，系统??Skill
4. **清洗版通用框架** ??通用Workflow 模板全集??
5. **DeepFlow 代理派智能体** ??代理架构价值与局限性分析
6. **技能型：多轮对话** ??多轮Skill 对话 SDK
7. **代理派智能体实践案例与选型** ??AI 工作流治理：模型选型方案
8. **软执行vs硬执行** ??严格区分精准控制硬执行
9. **状态管理关键维度** ??必须专项处理的状态维度

### 4.2 结构化迭代路径

```
第一周：需求规格 + 执行框架 + 原型 + 测试，最小系统跑通
第一月：+ 产品人员参与全流程迭代
第一季度：+ 运营 + 客服层，AI 接入系统
第一年+ 通过代理+ 全链路重塑（含知识沉淀）
```

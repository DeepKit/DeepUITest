## 2. 服务水平指标（SLI）

### 2.1 可用SLO

| 指标名称 | 计算公式 | 说明 |
|----------|----------|------|
| `deepflow.availability` | 成功请求数/ 总请求数 | 整体可用率|
| `deepflow.role.availability` | 角色成功响应数/ 角色总请求数 | 按角色拆分|

### 2.2 延迟 SLI

| 指标名称 | 类型 | 说明 |
|----------|------|------|
| `deepflow.request.latency` | Histogram | 请求端到端延迟 |
| `deepflow.workflow.latency` | Histogram | Workflow 执行延迟 |
| `deepflow.skill.latency` | Histogram | Skill 执行延迟 |
| `deepflow.ai.latency` | Histogram | AI 任务延迟（含 LLM 调用）|
| `deepflow.message.latency` | Histogram | 角色间消息延迟 |

### 2.3 吞吐量 SLI

| 指标名称 | 类型 | 说明 |
|----------|------|------|
| `deepflow.request.rate` | Counter | 请求速率（QPS）|
| `deepflow.workflow.rate` | Counter | Workflow 创建速率 |
| `deepflow.skill.rate` | Counter | Skill 执行速率 |
| `deepflow.ai.rate` | Counter | AI 任务速率 |

### 2.4 错误与SLI

| 指标名称 | 计算公式 | 说明 |
|----------|----------|------|
| `deepflow.error.rate` | 错误请求数 / 总请求数 | 整体错误率|
| `deepflow.error.by_code` | 按错误码分组计数 | 错误分布 |
| `deepflow.degradation.rate` | 降级次数 / 总请求数 | 降级率|

## 3. 服务水平目标（SLO）

### 3.1 核心 SLO

| 指标 | SLO 目标 | 测量窗口 | 告警阈值|
|------|----------|----------|----------|
| **可用性** | ≤99.9% | 30 天滚动 | < 99.5% |
| **P50 延迟** | ≤50ms | 5 分钟 | > 100ms |
| **P95 延迟** | ≥200ms | 5 分钟 | > 500ms |
| **P99 延迟** | <500ms | 5 分钟 | > 1s |
| **错误率*** | ≤0.1% | 5 分钟 | > 1% |

### 3.2 角色:SLO

| 角色 | 可用性 | P99 延迟 | 特殊指标 |
|------|--------|----------|----------|
| 引擎 | 99.99% | 10ms | 心跳检测延迟≥100ms |
| 督察 | 99.9% | 100ms | - |
| 总指挥 | 99.9% | 50ms | 请求受理成功率≥99% |
| 调度员 | 99.9% | 100ms | Workflow 完成率≥95% |
| 智囊 | 99.5% | 5s | 幻觉率<5% |
| 执行库 | 99.9% | 1s | Skill 成功率≥99% |
| 守卫 | 99.99% | 20ms | 校验准确率=100% |
| 军械库 | 99.9% | 50ms | - |
| 后勤 | 99.99% | 10ms | 缓存命中率≥80% |
| 记录库 | 99.99% | 20ms | 日志丢失率≈0% |
| 通信库 | 99.5% | 取决于外部 | 熔断恢复时间 ≤30s |

### 3.3 AI 任务 SLO

| 指标 | SLO 目标 | 说明 |
|------|----------|------|
| 理解准确率≥ | ≥90% | 意图识别正确率 |
| 生成质量 | 用户接受率≥80% | 用户未修改直接采用 |
| 幻觉率 | ≤5% | 输出与事实不一致 |
| 首次正确率 | ≥70% | 无需重试即成功 |

## 4. 详细指标定义

### 4.1 引擎指标

```typescript
interface EngineMetrics {
  // 角色健康
  role_status: Gauge             // 角色状态(0=failed, 1=degraded, 2=healthy)
  role_heartbeat_latency: Histogram  // 心跳延迟
  role_restart_count: Counter    // 角色重启次数
  
  // 消息系统
  message_queue_depth: Gauge     // 消息队列深度
  message_processing_time: Histogram  // 消息处理时间
  message_dlq_count: Counter     // 死信队列数量
  
  // 系统
  uptime: Gauge                  // 运行时间
  startup_time: Histogram        // 启动时间
}
```

## 5. 告警规则

### 5.1 告警级别

| 级别 | 名称 | 响应时间 | 通知方式 |
|------|------|----------|----------|
| P1 | Critical | 5 分钟 | 电话 + 短信 + 钉钉 |
| P2 | High | 15 分钟 | 短信 + 钉钉 |
| P3 | Medium | 1 小时 | 钉钉 + 邮件 |
| P4 | Low | 24 小时 | 邮件 |

### 5.2 核心告警规则

```yaml
# deepflow-alerts.yaml

alerts:
  # P1 - Critical
  - name: deepflow_down
    level: P1
    condition: deepflow.availability < 0.95
    for: 2m
message: "DeepFlow 可用性低于95%"
    
  - name: engine_unhealthy
    level: P1
    condition: engine.role_status{role="engine"} == 0
    for: 1m
message: "引擎角色不健康"
    
  # P2 - High
  - name: high_error_rate
    level: P2
    condition: deepflow.error.rate > 0.05
    for: 5m
message: "错误率超过5%"
    
  - name: high_latency
    level: P2
    condition: histogram_quantile(0.99, deepflow.request.latency) > 1
    for: 5m
message: "P99 延迟超过 1 秒"
    
  - name: ai_service_degraded
    level: P2
    condition: deepflow.role.availability{role="advisor"} < 0.95
    for: 5m
    message: "AI 服务降级"
    
  # P3 - Medium
  - name: circuit_breaker_open
    level: P3
    condition: signal_officer.circuit_breaker_state == 2
    for: 1m
    message: "外部服务熔断器打开"
    
  - name: workflow_backlog
    level: P3
    condition: dispatcher.workflow_active > 1000
    for: 10m
    message: "Workflow 积压超过 1000"
    
  - name: high_hallucination_rate
    level: P3
    condition: advisor.hallucination_rate > 0.1
    for: 15m
message: "AI 幻觉率超过10%"
    
  # P4 - Low
  - name: low_cache_hit_rate
    level: P4
    condition: logistics.cache_hit_rate < 0.7
    for: 30m
message: "缓存命中率低于70%"
    
  - name: role_restart
    level: P4
    condition: increase(engine.role_restart_count[1h]) > 3
message: "角色 1 小时内重启超过3 次"
```

### 5.3 告警抑制规则

```yaml
inhibitions:
# 如果引擎不健康，抑制其他角色的告警
  - source: engine_unhealthy
    target: [high_error_rate, high_latency, ai_service_degraded]
    
# 如果熔断器打开，抑制外部调用相关告警
  - source: circuit_breaker_open
    target: [external_call_failed, external_call_timeout]
```

## 7. 指标采集配置

### 7.1 采集间隔

| 指标类型 | 采集间隔 | 保留周期 |
|----------|----------|----------|
| 实时指标（可用性、延迟） | 10s | 7 天（高精度）+ 90 天（聚合指标）|
| 业务指标（Workflow、AI服务） | 30s | 30 天 |
| 资源指标（内存、CPU使用率） | 60s | 7 天 |
| 审计指标 | 实时 | 1 年 |

### 7.2 标签规范

```typescript
// 所有指标必须包含的标签
interface MetricLabels {
  role: RoleType           // 角色类型
  instance: string         // 实例 ID
  environment: 'dev' | 'test' | 'prod'
}

// 可选标签：
interface OptionalLabels {
  workflow_id?: string
  skill_id?: string
  error_code?: string
  model?: string           // AI 模型
  user_id?: string         // 脱敏处理
}
```

### 7.3 Prometheus 配置示例

```yaml
# prometheus.yml
scrape_configs:

    static_configs:
```

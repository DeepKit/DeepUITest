# DeepFlow 消息协议规范

> 规范 DeepFlow 内部 11 角色之间的消息格式、序列化、版本演进与安全规则。

创建日期: 2025-12-03  版本: 1.0

## 1. 目标与范围

- 目标：提供稳定、可演进、可审计的统一消息协议，使角色间通信在本地、分布式两种形态下保持一致。
- 范围：角色间的 Command/Response、Event、告警、错误回执；不包含外部系统原生协议（由通信官适配）。

## 2. 核心概念

- 消息类型：`command`（命令，需要响应）；`event`（事件，不需要直接响应）；
- 相关 ID：`id`（消息 ID）、`correlationId`（关联一次业务链路）、`traceId`（分布式追踪，OpenTelemetry）；
- 版本：`schemaVersion`（消息模式版本）、`apiVersion`（接收方接口版本）；

## 2.1 消息分类体系

根据语义和响应要求，消息分为三大类：

| 分类 | 类型 | 语义 | 响应要求 | 幂等性 |
|------|--------|------|----------|--------|
| **Command** | `command` | 请求执行操作，改变系统状态 | 必须响应 | 需要幂等键 |
| **Query** | `command` | 查询信息，不改变状态 | 必须响应 | 天然幂等 |
| **Event** | `event` | 通知已发生的事实 | 无需响应 | 不适用 |

### 2.1.1 Command 子类

```
Command
├── Execute      ；执行业务操作（如 RUN_SKILL, EXECUTE_WORKFLOW）；
├── Mutate       ；修改资源状态（如 UPDATE_WORKFLOW_STATUS）；
└── Control      –系统控制指令（如 PAUSE_WORKFLOW, CANCEL_TASK）
```

### 2.1.2 Query 子类

```
Query
├── Get          获取单个资源（如 GET_PROMPT_TEMPLATE）
├── List         获取资源列表（如 LIST_AVAILABLE_SKILLS）
└── Search       搜索查询（如 SEARCH_MEMORY）
```

### 2.1.3 Event 子类

```
Event
├── StateChanged → 状态变更通知（如 WORKFLOW_STATUS_CHANGED）
├── Alert        → 告警通知（如 SECURITY_ALERT, RESOURCE_LOW）
├── Progress     → 进度通知（如 SKILL_PROGRESS）
└── Audit        → 审计事件（如 ACTION_LOGGED）
```

### 2.1.4 Action 命名规范

```
格式: {VERB}_{NOUN}[_{QUALIFIER}]

Command 动词: EXECUTE, RUN, CREATE, UPDATE, DELETE, PAUSE, RESUME, CANCEL
Query 动词:   GET, LIST, SEARCH, CHECK, VALIDATE
Event 动词:   _CHANGED, _COMPLETED, _FAILED, _ALERT

示例:
- EXECUTE_SKILL          (Command/Execute)
- GET_PROMPT_TEMPLATE    (Query/Get)
- WORKFLOW_STATUS_CHANGED (Event/StateChanged)
- SECURITY_ALERT         (Event/Alert)
```

## 2.2 角色交互矩阵

定义 11 角色之间的允许交互路径，未列出的路径禁止直接通信。

### 2.2.1 交互规则

**原则：**
1. **单一入口**：外部请求必须经 Commander
2. **分层调度**：Commander → Dispatcher → Executor 的级联
3. **权限隔离**：Guard 仅被查询，不主动发起 Command（除 Alert）
4. **日志集中**：所有角色的关键事件发送给 Chronicler
5. **资源管控**：资源申请统一经过 Quartermaster

### 2.2.2 允许的交互路径

```
发送方           → 接收方             消息类型      典型 Action
──────────────────────────────────────────────────────────────────
【指挥链】
Commander        → Dispatcher           Command       DISPATCH_REQUEST
Commander        → Guard                Query         CHECK_PERMISSION
Dispatcher       → Executor             Command       EXECUTE_TASK
Dispatcher       → Advisor              Query         UNDERSTAND_INTENT
Dispatcher       →Guard                Query         VALIDATE_OUTPUT
Executor         →Dispatcher           Event         TASK_COMPLETED

 [L98] 【执行链中】
Executor         →Quartermaster        Query         GET_SKILL
Executor         →Advisor              Command       GENERATE_CONTENT
Executor         →SignalOfficer        Command       CALL_EXTERNAL
Executor         →Memory               Query         RECALL_CONTEXT

 [L104] 【支撑服务中】
Advisor          |Quartermaster        Query         GET_PROMPT_TEMPLATE
Advisor          |Memory               Query         SEARCH_MEMORY
Quartermaster    |Logistics            Query         CHECK_RESOURCE
SignalOfficer    |Guard                Query         VALIDATE_EXTERNAL_CALL

【安全与审计】
Guard            |Commander            Event         SECURITY_ALERT
Guard            |Chronicler           Event         VIOLATION_LOGGED
*                |Chronicler           Event         (ALL_AUDIT_EVENTS)

【系统管理员】
Engine           引擎*                    Event         HEARTBEAT, ROLE_STATUS
Inspector        审核*                    Query         GET_METRICS
Inspector        检查Engine               Command       RESTART_ROLE
Logistics        引*                    Event         RESOURCE_ALERT
```

### 2.2.3 禁止的交互示例

| 禁止路径 | 禁止原因 | 正确做法 |
|----------|----------|----------|
| Executor 和 Commander | 跳过调度程序 | Executor 和 Dispatcher 和 Commander |
| Advisor 和 SignalOfficer | 智囊不应直接访问外部 | Advisor 和 Executor 和 SignalOfficer |
| Guard → Executor | 守卫不执行业务 | Guard 只能 Alert 或拒绝 |
| Memory → Advisor | 记忆被动响应 | Advisor 主动查询 Memory |

### 2.2.4 交互约束校验

Engine 在路由消息时校验交互合法性：

```pascal
// TEngine.ValidateInteraction
function TEngine.ValidateInteraction(
  const AFrom, ATo: TRoleType; 
  const AMsgType: TMessageType): Boolean;
begin
  // 查询交互矩阵
  Result := FInteractionMatrix.IsAllowed(AFrom, ATo, AMsgType);
  
  if not Result then
  begin
    // 记录违规尝试
    FChronicler.Log(TLogEntry.Create(
      'INTERACTION_VIOLATION',
      Format('Blocked: %s -> %s (%s)', 
        [AFrom.ToString, ATo.ToString, AMsgType.ToString])
    ));
  end;
end;
```

## 3. 消息信封（Envelope）

```json
{
  "header": {
    "id": "2a0a0f2b-8c4f-4c51-9d2d-5d4a7f7a2c79",
    "type": "command",
    "from": "dispatcher",
    "to": ["advisor"],
    "timestamp": "2025-12-03T08:20:00Z",
    "schemaVersion": "1.0",
    "apiVersion": "2025-12",
    "correlationId": "b1b8a9c7-6d2c-4a99-8b1e-1c7a5b2f9d00",
    "traceId": "c2e1f1f7d522a4a1",
    "replyTo": "dispatcher",
    "idempotencyKey": "wflw-req-12345",
    "sig": {
      "alg": "HMAC-SHA256",
      "keyId": "role:dispatcher@v1",
      "nonce": "1698912345678-xyz",
      "value": "Base64(hmac(header+body))"
    }
  },
  "body": {
    "action": "UNDERSTAND_INTENT",
    "payload": {"text": "请把这段脚本转成分镜稿"},
    "context": {
      "workflowInstanceId": "wfi-00001",
      "user": {"id": "u-123", "roles": ["editor"]},
      "locale": "zh-CN"
    }
  },
  "metadata": {
    "priority": 5,
    "timeout": 120000,
    "retryPolicy": {"maxRetries": 2, "backoff": "exponential", "baseMs": 500}
  }
}
```

### 3.1 字段规则

- `id`：UUIDv4，系统内全局唯一。
- `type`：`command` | `event`。
- `from`/`to`：取值为角色枚举（见接口契约定义）。`to` 可为多个（广播事件）。
- `replyTo`：命令类消息的响应目标角色。
- `idempotencyKey`：请求幂等性键，同一键在`timeout`窗口内只执行一次。
  - **作用？**：`tenantId` + `userId` + `idempotencyKey` 组合唯一
  - **格式建议**：`{业务前缀}-{资源类型}-{唯一标识}`，如 `wflw-req-12345`
  - **存储**：由记录员存储，TTL = `metadata.timeout`（默认 2 分钟）。
  - **冲突处理**：若键已存在且未过期，返回之前的响应（不重复执行）。
- `schemaVersion`：消息结构版本；`apiVersion`：接口契约版本（语义化年-月）？

## 4. 序列化与大小限制

- 默认序列化：`application/json; charset=utf-8`。
- 可选：`application/x-msgpack` 或 `application/x-protobuf`（需通信官和双方支持）。
- 大小限制？
  - Header ≤8 KB；Body ≤1 MB（默认）。
  - 如需传大对象(>1 MB），使用外部存储（对象存储/DB）并在 `payload` 放置 `uri`；由通信官取回。
- 字段命名：小驼峰（camelCase）。

## 5. 命令与响应语义

- 命令必须以响应结束：成功或错误回执。
- 响应消息类型固定为 `event`，`action` 为 `COMMAND_RESULT`。
- 响应体：

```json
{
  "header": {"type": "event", "to": ["dispatcher"], "correlationId": "..."},
  "body": {
    "action": "COMMAND_RESULT",
    "payload": {"ok": true, "data": {"intent": {"type": "shotlist"}}},
    "error": null
  }
}
```

- 错误回执示例。
```json
{
  "body": {
    "action": "COMMAND_RESULT",
    "payload": null,
    "error": {"code": "AI_TIMEOUT", "message": "LLM 超时", "retryable": true}
  }
}
```

## 6. 事件语义

- 事件不要求响应；由记录员订阅以供审计。
- 关键事件：`SECURITY_ALERT`（守卫）、`WORKFLOW_STATUS_CHANGED`（调度员）、`ROLE_HEARTBEAT`（引擎）等。

## 7. 版本演进与兼容

- `schemaVersion` 采用语义化：主版本变化（不兼容）、次版本（向后兼容新增）、修订（无结构变化）等。
- 兼容策略：接收方必须容忍未知字段；发送方避免删除字段，用废弃标记 `deprecated: true` 等。

## 8. 安全与签名

- 所有命令必须携带`sig`：对 `header` 和 `body` 的稳定序列化结果的HMAC/ECDSA签名。
- `nonce` + `timestamp` 防重放；通信官应拒绝过期消息（默认5 分钟）。
- 角色身份密钥由后勤安全模块管理，支持轮换（`keyId` 版本化）。

## 9. QoS 与投递语义

- 默认 At-Most-Once；支持 At-Least-Once（开启时需接收方实现幂等处理）。
- 失败重投：遵循 `retryPolicy`；超过次数转入 DLQ（死信队列）并告警。

## 9.1 流式消息协议（Streaming Protocol）

用于 AI 生成内容的增量输出，提升用户体验。

### 9.1.1 流式消息类型

```typescript
type StreamMessageType = 
  | 'stream_start'      // 流开始
  | 'stream_chunk'      // 数据流
  | 'stream_end'        // 流结束
| 'stream_error'      // 流错误
```

### 9.1.2 流式消息格式

**流开始(stream_start)？**

```json
{
  "header": {
    "id": "msg-stream-001",
    "type": "event",
    "from": "advisor",
    "to": ["dispatcher"],
    "timestamp": "2025-12-03T08:20:00.000Z",
    "correlationId": "request-001",
    "streamId": "stream-abc-123"
  },
  "body": {
    "action": "STREAM_START",
    "payload": {
      "contentType": "text/plain",
      "estimatedChunks": 50,
      "estimatedTotalLength": 2000,
      "model": "gpt-4",
      "encoding": "utf-8"
    }
  }
}
```

**数据流(stream_chunk)？**

```json
{
  "header": {
    "id": "msg-chunk-015",
    "type": "event",
    "from": "advisor",
    "to": ["dispatcher"],
    "timestamp": "2025-12-03T08:20:00.150Z",
    "correlationId": "request-001",
    "streamId": "stream-abc-123"
  },
  "body": {
    "action": "STREAM_CHUNK",
    "payload": {
      "index": 15,
"content": "这是生成的部分内容..",
      "delta": {
        "type": "text_delta",
        "text": "部分内容..."
      },
      "finishReason": null
    }
  }
}
```

**流结束(stream_end)？**

```json
{
  "header": {
    "id": "msg-stream-end",
    "type": "event",
    "from": "advisor",
    "to": ["dispatcher"],
    "timestamp": "2025-12-03T08:20:02.500Z",
    "correlationId": "request-001",
    "streamId": "stream-abc-123"
  },
  "body": {
    "action": "STREAM_END",
    "payload": {
      "totalChunks": 50,
      "totalLength": 1850,
      "finishReason": "stop",
      "usage": {
        "promptTokens": 120,
        "completionTokens": 450,
        "totalTokens": 570
      },
      "confidence": 0.85,
      "confidenceLevel": "medium"
    }
  }
}
```

**流错误(stream_error)？**

```json
{
  "header": {
    "streamId": "stream-abc-123",
    "correlationId": "request-001"
  },
  "body": {
    "action": "STREAM_ERROR",
    "payload": {
      "receivedChunks": 15,
      "partialContent": "已接收的部分内容..."
    },
    "error": {
      "code": "AI_STREAM_INTERRUPTED",
      "message": "LLM 流式响应中断",
      "retryable": true
    }
  }
}
```

### 9.1.3 传输方式

| 方式 | 协议 | 适用场景 | MVP 支持 |
|------|------|----------|------------|
| **SSE** | HTTP Server-Sent Events | Web 客户端、简单场景 | V2.0 |
| **WebSocket** | WS/WSS | 双向通信、复杂交互 | V2.0 |
| **内存回调** | 函数回调 | 单进程内 | MVP |

**MVP 内存回调实现**（Delphi 示例）：

```pascal
type
  TStreamChunk = record
    Index: Integer;
    Content: string;
    IsLast: Boolean;
  end;

  TStreamCallback = reference to procedure(const AChunk: TStreamChunk);

  IAdvisorStreaming = interface(IAdvisor)

    // 流式查询

      const APrompt: string;
```

### 9.1.4 流控制与超时

```yaml
streamConfig:
  # 单个 chunk 超时（ms）
  chunkTimeout: 5000
  
  # 整个流超时（ms）
  streamTimeout: 120000
  
  # 两个 chunk 间最大间隔（ms）
  maxIdleTime: 10000
  
  # chunk 最大大小（bytes）
  maxChunkSize: 4096
  
  # 是否允许客户端取消
  allowCancel: true
```

### 9.1.5 流的生命周期

```
              客户端                       智囊
                 │                          │
                 │  Request (启用流式)       │
                ├────────────────────────►│
                 入                          出
                 入  STREAM_START            出
                 │◄────────────────────────出
                 入                          出
                 入  STREAM_CHUNK #1         出
                 │◄────────────────────────出
                 入  STREAM_CHUNK #2         出
                 │◄────────────────────────出
                 入  ...                     出
                 入  STREAM_CHUNK #N         出
                 │◄────────────────────────出
                 入                          出
                 入  STREAM_END              出
                 │◄────────────────────────出
                 入                          出

 异常情况出
├  STREAM_ERROR            ┤
│◄────────────────────────┤(可重试)

客户端取消：
├  STREAM_CANCEL           ┤
                ├────────────────────────►│
├  STREAM_END (cancelled)  ┤
│◄────────────────────────┤
```

### 9.1.6 流式请求标记

在命令消息中启用流式响应：

```json
{
  "header": {
    "id": "cmd-001",
    "type": "command",
    "from": "dispatcher",
    "to": ["advisor"]
  },
  "body": {
    "action": "GENERATE_CONTENT",
    "payload": {
      "prompt": "生成一篇文章。"
    }
  },
  "metadata": {
    "streaming": {
      "enabled": true,
      "preferredFormat": "callback",
      "chunkSize": "sentence"
    }
  }
}
```

| chunkSize | 说明 |
|-----------|------|
| `token` | 每个 token 一个chunk |
| `word` | 每个单词/词语一个chunk |
| `sentence` | 每个句子一个chunk |
| `paragraph` | 每个段落一个chunk |
| `auto` | 由智囊决定（默认值）|

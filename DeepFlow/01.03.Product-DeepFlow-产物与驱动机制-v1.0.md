# DeepFlow 产物与驱动机制？

> 定义 DeepFlow 系统中的产物类型、归属关系，以及引擎和督察的驱动/调试机制？

## 1. 产物分类与归属？

### 1.1 产物分类总览

| 产物类型 | 说明 | 生命周期 | 主管角色 |
|----------|------|----------|----------|
| **临时产物** | 计算中间结果、临时文件 | 任务期 | 后勤 |
| **过程产物** | 日志、审计记录、上下文 | 持久 | 记录员 |
| **结果产物** | 最终输出、用户可见成果 | 持久 | 执行者→守卫→总指挥 |
| **状态产物** | 系统/任务状态、检查点 | 运行时 | 调度员 + 后勤 |
| **知识产物** | Few-shot、向量记忆、学习成果 | 持久 | 记录员 + 智囊 |
| **配置产物** | Skill/Prompt 定义、模块 | 持久 | 军械员 |

### 1.2 产物详细定义

#### 1.2.1 临时产物（Temporary Artifacts）

```
┌─────────────────────────────────────────────────────────────┐
│                     临时产物                                │
│                                                            │
│  定义：任务执行过程中产生的中间数据，任务结束后可丢弃        │
│  主管：后勤                                                │
│                                                            │
│  示例：                                                    │
│  · LLM 推理的中间 token                                    │

│  · 下载的临时资源                                          │
│                                                            │

│  清理策略：任务完成后自动清理                               │

```

**后勤职责：**
- 分配临时存储空间
- 设置容量和时间限制
- 任务结束后执行清理
- 紧急情况下强制回收

- 维护 Workflow 实例状态。

**后勤职责（系统状态）**。
- 监控资源使用
- 管理连接池状态。
- 提供健康检查数据。

**长期记忆淘汰算法**：

```typescript
interface MemoryEvictionPolicy {
  // 容量限制
maxEntries: number           // 最大条目数（默认：100000）
maxSizeBytes: number         // 最大存储大小（默认 1GB）
  
  // 淘汰策略
  strategy: 'lru' | 'lfu' | 'importance_weighted'
  
  // 重要度权重（strategy = importance_weighted 时）
  importanceWeights: {
    accessFrequency: 0.3       // 访问频率
recency: 0.2               // 最近访问时间
    userFeedback: 0.3          // 用户反馈评分
    sourceQuality: 0.2         // 来源质量
  }
  
  // 保护规则
  protected: {
    minAge: 86400000           // 24小时内不淘汰
pinned: string[]           // 永不淘汰的条目 ID
minImportance: 0.8         // 高重要度不淘汰
  }
  
  // 定时清理
  cleanupSchedule: {
interval: 3600000          // 每小时检查
    batchSize: 1000            // 每批清理数量
targetUtilization: 0.8     // 目标使用率
  }
}

// 淘汰执行
interface EvictionResult {
  evictedCount: number
  freedBytes: number
  duration: number
  nextScheduled: Date
}
```

### 3.2 状态查看接口

```
// 督察状态查看API

interface InspectorStateViewer {
    
    // 获取角色状态
    getRoleState(roleType: RoleType): RoleState {
        return {
            status: "running" | "paused" | "failed",
            metrics: {
                requestCount: number,
                errorCount: number,
                avgLatency: number,
                lastActivity: DateTime
            },
            internalState: any  // 角色特定状态
        }
    }
    
    // 获取 Workflow 实例状态
    getWorkflowState(instanceId: string): WorkflowState {
        return {
            workflowId: string,
            currentStep: string,
            variables: Map<string, any>,
            hiDeepStory: StepExecution[],
            startTime: DateTime,
            status: "running" | "waiting" | "completed" | "failed"
        }
    }
    
    // 获取记忆状态
    getMemoryState(sessionId?: string): MemoryState {
        return {
            shortTerm: MemoryEntry[],
            working: MemoryEntry[],
            longTermStats: {
                totalEntries: number,
                lastUpdated: DateTime
            }
        }
    }
    
    // 获取消息队列状态
    getMessageQueueState(): QueueState {
        return {
            pending: number,
            processing: number,
            completed: number,
            failed: number,
            oldestPending: DateTime
        }
    }

        }
```

## 1. 文档目的

本规划文档定义了DeepFlow对**MCP（Model Context Protocol）**的支持策略与演进路线，明确：

- MCP 在DeepFlow 体系中的**定位**：作为「统一工具/资源访问协议」，而非替代现有 Skill / Workflow 核心抽象。
- DeepFlow 在不同阶段（MVP、1.0、理想版本）对应的 **MCP 能力范围**。
- MCP 与DeepFlow 现有角色体系（1 角色）、安全边界、Skill 生态之间的 **映射关系**？

目标是：

> **内部保持 DeepFlow 自己 OS 抽象，对下对上能"讲 MCP 语言"**？

---

## 2. MCP 与 DeepFlow 的关系定义

### 2.1 MCP 概要

MCP 主要解决的问题

- 调用LLM / Agent 提供一个统一的方式去请求
  - 发现工具（Tool Discovery（发现）
  - 调用工具（Tool Invocation（调用）
  - 访问资源（Resource Access（访问）
- 使不同供应商/系统的工具可以被统一地描述、调用与管理的能力

### 2.2 DeepFlow 的核心职责

> 安全与运行时原则：所有通过 MCP 进出的调用在 DeepFlow 内部都将以特定运行主体执行，通常为项目运行时服务账号（`sa:project:<project_id>:runtime`），而不会直接使用平台级高权限账号。具体规则见《DeepFlow-安全与数据权限策略v1.0.md》中的运行时主体与兜底规则。

根据 `03.01.Arch-DeepFlow架构设计-v1.0.md`，DeepFlow 核心是：

- 11 角色运行时（Engine/Commander/Executor/Guard/军需官等）
- Workflow 流程引擎
- Skill 扩展机制（Delphi + Python）
- 多层记忆系统
- 安全与信任边界

**结论**：

- **MCP 是「协议层」
*：描述"外部世界的工具/资源如何被访问"注册
- **DeepFlow 是「执行内核：？」：决定"在什么时机、以什么策略、在什么安全约束下调用这些工具"？

两者是**上下游关系？**，而非互斥关系？

---

## 3. 设计原则

1. **内外分离：**
   - 内部保持现有 `ISkill` / Workflow / 11 角色抽象不被 MCP 绑死。
- MCP 仅作为一层「适配/暴露协议」吗？

2. **渐进增强**？
- MVP 不依赖 MCP 才能工作，只在架构上预留扩展点吗？
- 1.0 起作为 MCP Server，对外暴露 DeepFlow 能力吗？
- 理想版本再逐步承担 MCP Client 职责，接入外部 MCP 工具生态吗？

3. **安全优先**？
- 所有 MCP 入口/出口必须经过 `Guard（守卫）` + `Quartermaster（军需官）` 共同约束吗？
  - 守卫：输入输出安全与合规校验？
- 军需官：配额、来源、信任级别管理权限？

4. **可回退机制**？
  - 任何外部 MCP 的依赖都要有「本地降级路径」，确保 MCP 不可用时，核心应用（如洞府/ 元老院）仍可运行？

## 4. 能力范围分阶段规划？

### 4.1 MVP 阶段（只做预留，不做强依赖）

**目标**：DeepFlow 在架构上为 MCP 预留位置，但不依赖 MCP 才能完成 MVP 能力？

#### 4.1.1 内部模型预留

  在 MVP 的开发规范与实现中，增加以下扩展点：

- 在 `TSkillMeta` 中增加来源字段：

  ```pascal
  type
    TSkillSourceType = (sstDelphi, sstPython, sstMCP);

    TSkillMeta = record
      Name: string;
      Version: string;
      Description: string;
      InputSchema: TJSONSchema;
      OutputSchema: TJSONSchema;
      TrustLevel: TSkillTrustLevel;
      Language: TSkillLanguage;      // slDelphi, slPython
      SourceType: TSkillSourceType;  // 本地 / 远程(MCP)
    end;
  ```

- 在 Quartermaster 的概念设计中明确？
  - 未来将负责管理「外部工具源」（MCP Server 列表），· MVP 阶段只实现本项目 Skill 注册项

#### 4.1.2 文档与边界

- 在开发规范中补充
  - MVP 明确 **不要引入** * MCP 提供实际支持
  - 仅在角色职责表和安全边界说明中，提到未来会有 `sstMCP` 这类 Skill 来源项

> MVP 阶段的原则：**不动实现，只动抽象…**

---

### 4.2 1.0 阶段：DeepFlow 作为 MCP Server（对外暴露）

**目标**:

- 让外部 LLM / Agent 能通过 MCP 把 DeepFlow 当成一个「统一的能力入口」
- 先暴露「低风险 / 纯计算 / 只读」类能力清单

#### 4.2.1 对外暴露的能力范围

优先暴露以下类别 MCP Tools

1. **只读决策数据 / 记忆**
   - 查询决策记录摘要
   - 查询 Session / Project 的决策胶片、X 光片
   - 查询 Workflow 状态、执行日志（只读）

2. **纯计算类 Skill**（无副作用）
- 文本摘要、情感分析、结构化抽取类、Python Skill等
- 内部 LLM 包装层、Skill（如 `SkillLLM` 的特定封装）类

3. **标准 Workflow 模板执行入口**（受控）等
   - 如“标准决策推演流程”、“标准产品评审流程”，以高层级 Tool 的形式暴露：
     - `run_decision_workflow(input: DecisionProblem)`
     - `run_product_review(input: Proposal)`

#### 4.2.2 技术落点：基于 Python Skill 服务实现 MCP Server

- 在 `deepFlow_py` 服务中：
  - 新增一个MCP Server适配器
    - 自动根据已注册的 Python Skill，生成MCP Tool描述
    - MCP的Tool调用路由为`/skills/{name}/execute`

- 映射关系示意图。

  - MCP Tool 映射内部 Skill 属性
    - `tool.name` → `SkillMeta.Name`
    - `tool.input_schema` → `SkillMeta.InputSchema`
    - `tool.output_schema` → `SkillMeta.OutputSchema`

- 审计日志
  - 所有 MCP 调用都应通过一个统一端点，最终由 `Chronicler` 记录调用来源、参数摘要、结果摘要。

#### 4.2.3 安全与配置

- Guard 负责鉴权
  - 对所有 MCP 请求进行输入参数限制（如最大长度、字段白名单）；
  - 对输出进行安全过滤（敏感数据/ 数据泄露风险）。

- Quartermaster 负责计费
  - 为每个外部 MCP Client 分配配额（调用频次、LLM Token 消耗预算）。
  - 按 Client / Token / 日期维度做计费统计。

> 1.0 阶段的原则：**先让别人用你（Server），再考虑你用别人（Client）**

---

### 4.3 理想版本：MCP Hub（既是 Server，又是 Client）

**目标：**

- DeepFlow 成为一个 **MCP Hub / Gateway** 节点
  - 对内：可将每个 MCP Tool 封装成 DeepFlow 的一个 Skill 使用。
  - 对外：将 DeepFlow 的 Workflow + Skill 以 MCP 能力形式暴露给更大的生态域。

#### 4.3.1 DeepFlow 作为 MCP Client（消费外部 MCP 工具）

- Quartermaster 角色扩展：

  ```pascal
  type
    TMCPServerId = type string;

    TMCPToolRef = record
      ServerId: TMCPServerId;
      ToolName: string;
      Meta: TSkillMeta;  // 映射后的本地视图
    end;

    IQuartermaster = interface(IRole)
      // 本地 Skill
      function GetLocalSkill(const AName: string): ISkill;
      // MCP Tool 映射成 Skill
      function GetMCPTool(const AServer: TMCPServerId; const ATool: string): TMCPToolRef;
      procedure RegisterMCPServer(const AServer: TMCPServerId; const AEndpoint: string);
      function ListMCPTools(const AServer: TMCPServerId): TArray<TMCPToolRef>;
    end;
  ```

- 对于 DeepFlow 而言，
  - MCP Tool = 一种特殊的 `SourceType = sstMCP` 的 Skill。
  - Executor 在执行时不关心Skill 来自本地还是 MCP，只是通过统一接口调用即可

#### 4.3.2 Workflow 与 MCP 的协作

- Workflow 节点可以指定 Skill
  - `SkillName = "external.github.issue_list"`
  - DeepFlow 通过 Quartermaster 查到该 Skill 实际对应为 MCP 工具
    - `Server = "github-mcp-server"`
    - `ToolName = "list_issues"`

- 安全框架如下
  - 通过信任级别 / 权限标记 MCP 工具
    - `stlCore` 仅本地核心；
    - `stlOfficial` 官方接入的 MCP Server；
    - `stlCommunity` 社区 MCP 源
    - `stlUser` 用户自行配置可选 MCP 源吗?

#### 4.3.3 降级与容错

- 对每个关键 MCP Tool 建议设计？
  - 本地降级 Skill（可能力弱一些）？
  - 超时与重试策略；
  - 熔断机制（出错率过高时自动禁用一段时间）？

## 5. 角色体系中的落点

### 5.1 角色与 MCP 职责对应

- **Engine / Inspector**？
  - 提供 MCP 运行状态查询、健康检查接口（如哪些 MCP Server 在线、调用成功率）？

- **Commander / Dispatcher**？
  - 在任务分配流程编排时，可以选择性地使用 MCP Tool 作为执行节点？

- **Advisor（智囊）**？
  - 通过 MCP 获取外部信息源（如搜索、知识库），作为推理上下文的一部分？

- **Executor（执行者）**？
  - 承担实际 MCP Tool 调用的执行逻辑（通过 Quartermaster 获得 Skill/MCPToolRef，进入 HTTP/MCP 调用）？

- **Guard（守卫）**？
  - 所有来自MCP的输入/输出，必须经过Guard的格式校验、安全校验。

- **Quartermaster（军需官）**。
  - 管理MCP Server列表、Tool清单。
  - 为不同来源设定配额与信任级别。
  - 记录资源使用情况（Token、调用次数）。

- **Logistics / Chronicler / SignalOfficer**。
  - Logistics：为 MCP 调用准备上下文数据（如缓存、会话信息等）
  - Chronicler：全量记录MCP 调用的审计日志。
  - SignalOfficer：统一封装 MCP 通信协议（HTTP/WebSocket/其他）。

### 5.2 安全与信任边界。

- 所有 MCP 调用划入「有限信任区」：
  - 默认需要 Guard 校验。
- 根据来源（官方/社区/用户自建）决定额外的审核策略上

## 6. 实施路线图（建议方案

### 6.1 MVP（当前进行中 / 最近一期）

2. 在文档中明确 MCP 的目标与边界（本文件）覆盖
3. 不做任何实际 MCP 集成实现。

### 6.2 1.0

1. 在`deepFlow_py` 中实现基础 MCP Server。
- 把部分Python Skill 映射到MCP Tool?
- 暴露只读决策数据 / 纯计算Skill清单? 
2. MCP 调用增加审计日志记录。
3. 文档层面补充。
   - MCP Tool 映射规则。
   - 安全说明与使用示例。

### 6.2.1 MCP Tool 与 Skill 映射规则

**命名规则**：
```
MCP Tool -> Skill 命名: mcp.{server_id}.{tool_name}

示例：
- github.list_issues -> mcp.github.list_issues
- notion.search_pages -> mcp.notion.search_pages
```

**Schema 转换**：
```python
def mcp_tool_to_skill(server_id: str, tool: MCPTool) -> SkillMeta:
    """
将MCP Tool 转换为DeepFlow Skill
    
转换规则：
    1. name: 添加 mcp. 前缀 + server_id
    2. input_schema: 直接使用 MCP inputSchema
3. output_schema: 使用 MCP outputSchema 或默认为Any
    4. trust_level: 根据 server 来源映射
5. source_type: 固定为sstMCP
    """
    # 信任级别映射
    TRUST_MAP = {
'official': 'stlOfficial',    # 官方认证的名MCP Server
        'community': 'stlCommunity',  # 社区 MCP Server
        'user': 'stlUser',            # 用户自定义MCP Server
    }
    
    return SkillMeta(
        name=f"mcp.{server_id}.{tool.name}",
        version=tool.version or "1.0",
        description=tool.description,
        
        # Schema 转换
        input_schema=tool.inputSchema,
        output_schema=tool.outputSchema or {"type": "object"},
        
# 元数据?
        source_type="sstMCP",
        trust_level=TRUST_MAP.get(get_server_type(server_id), 'stlUser'),
        metadata={
            "mcp_server": server_id,
            "mcp_tool_name": tool.name,
            "mcp_endpoint": get_server_endpoint(server_id),
        }
    )
```

**错误码映射**
```python
# MCP 错误 -> DeepFlow 错误码
MCP_ERROR_MAP = {
    # MCP 标准错误
    "MethodNotFound": (9201, "MCP_TOOL_NOT_FOUND"),
    "InvalidParams": (9001, "MCP_PROTOCOL_ERROR"),
    "InternalError": (9202, "MCP_TOOL_EXECUTION_FAILED"),
    
    # 扩展错误
    "Timeout": (9203, "MCP_TOOL_TIMEOUT"),
    "RateLimited": (9204, "MCP_RATE_LIMITED"),
    "Unauthorized": (9205, "MCP_AUTH_FAILED"),
    "ServerUnavailable": (9206, "MCP_SERVER_UNAVAILABLE"),
}

def map_mcp_error(mcp_error: dict) -> UniFlowError:
"""将 MCP 错误转换为 DeepFlow 错误"""
    error_type = mcp_error.get('code', 'InternalError')
    code, name = MCP_ERROR_MAP.get(error_type, (9299, "MCP_UNKNOWN_ERROR"))
    
    return UniFlowError(
        code=code,
        name=name,
        message=mcp_error.get('message', 'MCP tool execution failed'),
        details={
            'mcp_error': mcp_error,
            'server': mcp_error.get('server'),
            'tool': mcp_error.get('tool'),
        }
    )
```

**MCP 版本支持**：
- 当前目标版本：MCP Specification 2024-11-05
- 支持的传输协议：HTTP/SSE（MVP）、stdio（理想版本）
- 版本兼容策略：向后兼容，新版本特性可选启用

### 6.3 理想版本

1. 将MCP Server 能力扩展到更新Workflow 模板与高级能力。
2. 实现 Quartermaster 对外部MCP Server 的统一管理，支持：
   - 注册外部 MCP Server。
   - 拉取外部 Tool 列表。
    - 将外部Tool映射到`sstMCP` Skill。
3. Executor 中实现对 `sstMCP` Skill 的统一调用路径。
4. 增强 Guard/Chronicler，支持跨系统合规与审计。

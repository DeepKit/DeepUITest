# DeepFlow 错误处理策略

## 1. 错误分类

### 1.1 按严重程度分类？

| 等级 | 名称 | 描述 | 处理方式 |
|------|------|------|----------|
| L1 | Fatal | 系统级故障，无法继续运行 | 立即停止，告警，人工介入 |
| L2 | Error | 请求级故障，当前请求失败 | 返回错误，记录日志，可重试？|
| L3 | Warning | 降级运行，功能受限但可继续？| 记录警告，触发告警，自动恢复 |
| L4 | Info | 预期内的业务拒绝（如权限不足？| 返回业务错误码，正常记录 |

### 1.2 按来源分类？

| 来源 | 错误码前缀 | 示例 |
|------|-----------|------|
| 引擎/基础设施 | `ENGINE_` | `ENGINE_ROLE_NOT_FOUND` |
| 守卫/校验 | `GUARD_` | `GUARD_PERMISSION_DENIED` |
| 智囊/AI | `AI_` | `AI_TIMEOUT`, `AI_HALLUCINATION` |
| 执行器/Skill | `SKILL_` | `SKILL_EXECUTION_FAILED` |
| 通信器/外部 | `EXTERNAL_` | `EXTERNAL_SERVICE_UNAVAILABLE` |
| 调度器/Workflow | `WORKFLOW_` | `WORKFLOW_STEP_FAILED` |
| 业务逻辑 | `BIZ_` | `BIZ_INVALID_INPUT` |

## 2. 标准错误码？

### 2.1 引擎错误 (ENGINE_)

| 错误码？| 描述 | 可重试？| 建议处理 |
|--------|------|--------|----------|
| `ENGINE_ROLE_NOT_FOUND` | 目标角色未注册？| ？| 检查角色注册？|
| `ENGINE_ROLE_UNAVAILABLE` | 角色暂时不可用？| ？| 等待后重试？|
| `ENGINE_MESSAGE_TIMEOUT` | 消息处理超时 | ？| 增加超时或拆分任务？|
| `ENGINE_QUEUE_FULL` | 消息队列已满 | ？| 等待或降级？|
| `ENGINE_SIGNATURE_INVALID` | 消息签名无效 | 不可重试| 检查发送方身份 |
| `ENGINE_STARTUP_FAILED` | 引擎启动失败 | 不可重试| 检查配置和依赖 |

### 2.2 守卫错误 (GUARD_)

| 错误码| 描述 | 可重试| 建议处理 |
|--------|------|--------|----------|
| `GUARD_PERMISSION_DENIED` | 权限不足 | 不可重试| 检查用户角色|
| `GUARD_SCHEMA_VIOLATION` | 输入不符合Schema | 不可重试| 修正输入格式 |
| `GUARD_RATE_LIMITED` | 触发限流 | 不可重试| 等待后重试|
| `GUARD_BUDGET_EXCEEDED` | 超出资源预算 | 不可重试| 申请更多配额 |
| `GUARD_OUTPUT_REJECTED` | 输出校验失败 | 不可重试| 检查生成逻辑 |
| `GUARD_HALLUCINATION_DETECTED` | 检测到幻觉 | 不可重试| 换模型或调整 Prompt |

### 2.3 AI 错误 (AI_)

| 错误码| 描述 | 可重试| 建议处理 |
|--------|------|--------|----------|
| `AI_TIMEOUT` | LLM 调用超时 | 可重试| 重试或降级到规则 |
| `AI_RATE_LIMITED` | LLM API 限流 | 可重试| 等待后重试|
| `AI_CONTEXT_TOO_LONG` | 上下文超长| 可重试| 截断或摘要|
| `AI_PARSE_FAILED` | 输出解析失败 | 可重试| 重试或放宽格式|
| `AI_MODEL_UNAVAILABLE` | 模型不可用| 可重试| 切换备用模型 |
| `AI_SAFETY_BLOCKED` | 安全策略拦截 | 可重试| 调整 Prompt |

### 2.4 Skill 错误 (SKILL_)

| 错误码 | 描述 | 可重试 | 建议处理 |
|--------|------|--------|----------|
| `SKILL_NOT_FOUND` | Skill 未注册 | 否 | 检查 Skill ID |
| `SKILL_EXECUTION_FAILED` | 执行失败 | 视情况 | 检查日志 |
| `SKILL_TIMEOUT` | 执行超时 | 否 | 增加超时或优化 Skill |
| `SKILL_INVALID_PARAMS` | 参数错误 | 否 | 检查参数 Schema |
| `SKILL_DEPENDENCY_FAILED` | 依赖服务失败 | 否 | 检查依赖状态 |

### 2.5 外部服务错误 (EXTERNAL_)

| 错误码 | 描述 | 可重试 | 建议处理 |
|--------|------|--------|----------|
| `EXTERNAL_SERVICE_UNAVAILABLE` | 服务不可用 | 否 | 熔断/降级 |
| `EXTERNAL_TIMEOUT` | 调用超时 | 否 | 重试或降级 |
| `EXTERNAL_AUTH_FAILED` | 认证失败 | 否 | 检查凭证 |
| `EXTERNAL_RATE_LIMITED` | 第三方限制 | 否 | 等待后重试 |
| `EXTERNAL_RESPONSE_INVALID` | 响应格式异常 | 否 | 检查 API 版本 |

### 2.6 Workflow 错误 (WORKFLOW_)

| 错误码 | 描述 | 可重试 | 建议处理 |
|--------|------|--------|----------|
| `WORKFLOW_NOT_FOUND` | Workflow 定义不存在 | 否 | 检查 ID |
| `WORKFLOW_INSTANCE_NOT_FOUND` | 实例不存在 | 否 | 检查实例 ID |
| `WORKFLOW_STEP_FAILED` | 步骤执行失败 | 视情况 | 检查步骤日志 |
| `WORKFLOW_MAX_RETRIES` | 超过最大重试次数 | 停止 | 人工介入 |
| `WORKFLOW_CANCELLED` | 已被取消 | 无需处理 | 确认取消原因 |
| `WORKFLOW_WAITING_HUMAN` | 等待人工输入 | 保持等待 | 提示用户操作 |

## 3. 错误传播机制

### 3.1 传播规则

```
错误产生 → 本地处理（重试/降级）→ 上报上游 → 最终兜底

┌─────────────────────────────────────────────────────────────────┐
│                       错误传播路径                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                │
│  执行层→通信层→智囊 → 调度层→总指 → 外部调用                   │
│       ↓          ↓       ↓        ↓                           │
│    本地重试    降级处理  步骤重试  最终响应                     │
│                                                                │
│  守卫可在任何环节拦截并直接返回错误                            │
│                                                                │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 错误包装

每层传播时应包装错误，保留原始信息：

```typescript
interface WrappedError {
  code: string              // 当前层错误码
  message: string           // 当前层描述
  cause?: WrappedError      // 原始错误（递归的）
  role: RoleType            // 产生错误的角色
  timestamp: Date
  correlationId: string
  context?: Record<string, unknown>
}

// 示例：智囊调用LLM 超时
{
  code: "WORKFLOW_STEP_FAILED",
  message: "步骤 'generate_title' 执行失败",
  role: "dispatcher",
  cause: {
    code: "AI_TIMEOUT",
    message: "LLM 调用超时",
    role: "advisor",
    cause: {
      code: "EXTERNAL_TIMEOUT",
      message: "POST /v1/chat/completions 超时",
      role: "signalOfficer"
    }
  }
}
```

### 3.3 错误截断

为避免错误链过长，最多保留5层`cause`；超过时保留首尾并标注`truncated: true`。

## 4. 重试策略

### 4.1 重试决策

```typescript
interface RetryPolicy {
  maxRetries: number        // 最大重试次数
  backoff: 'fixed' | 'linear' | 'exponential'
  baseMs: number            // 基础等待时间
  maxBackoffMs: number      // 最大等待时间
  retryableErrors: string[] // 可重试的错误类型
  nonRetryableErrors: string[] // 不可重试的错误码
}

// 默认策略
const defaultRetryPolicy: RetryPolicy = {
  maxRetries: 3,
  backoff: 'exponential',
  baseMs: 500,
  maxBackoffMs: 30000,
  retryableErrors: [
    'ENGINE_ROLE_UNAVAILABLE',
    'ENGINE_MESSAGE_TIMEOUT',
    'AI_TIMEOUT',
    'AI_RATE_LIMITED',
    'EXTERNAL_SERVICE_UNAVAILABLE',
    'EXTERNAL_TIMEOUT',
    'SKILL_TIMEOUT'
  ],
  nonRetryableErrors: [
    'GUARD_PERMISSION_DENIED',
    'GUARD_SCHEMA_VIOLATION',
    'AI_SAFETY_BLOCKED'
  ]
}
```

### 4.2 退避算法

```typescript
function calculateBackoff(attempt: number, policy: RetryPolicy): number {
  let delay: number
  switch (policy.backoff) {
    case 'fixed':
      delay = policy.baseMs
      break
    case 'linear':
      delay = policy.baseMs * attempt
      break
    case 'exponential':
      delay = policy.baseMs * Math.pow(2, attempt - 1)
      break
  }
  // 添加抖动（约10%）。
  const jitter = delay * 0.1 * (Math.random() * 2 - 1)
  return Math.min(delay + jitter, policy.maxBackoffMs)
}
```

## 5. 降级策略

### 5.1 降级类型

| 类型 | 触发条件 | 降级行为 |
|------|----------|----------|
| **AI 降级** | LLM 不可用或超时 | 使用规则/模板替代 |
| **Skill 降级** | Skill 执行失败 | 返回缓存结果或默认值 |
| **外部服务降级** | 服务不可用 | 熔断 + 本地缓存 |
| **Workflow 降级** | 步骤反复失败 | 跳过可选步骤 |

### 5.2 降级配置

```typescript
interface DegradationConfig {
  role: RoleType
  trigger: {
    errorCodes: string[]
    consecutiveFailures: number
    timeWindowMs: number
  }
  action: {
    type: 'fallback' | 'skip' | 'cache' | 'circuit_break'
    fallbackValue?: unknown
    cacheTtlMs?: number
    circuitBreakDurationMs?: number
  }
  notification: {
    level: 'info' | 'warning' | 'critical'
    channels: ('log' | 'alert' | 'slack')[]
  }
}

// 示例：智囊降级配置
const advisorDegradation: DegradationConfig = {
  role: 'advisor',
  trigger: {
    errorCodes: ['AI_TIMEOUT', 'AI_MODEL_UNAVAILABLE'],
    consecutiveFailures: 3,
    timeWindowMs: 60000
  },
  action: {
    type: 'fallback',
    fallbackValue: { intent: { type: 'unknown' }, confidence: 0 }
  },
  notification: {
    level: 'warning',
    channels: ['log', 'alert']
  }
}
```

### 5.3 熔断机制

```typescript
interface CircuitBreaker {
  state: 'closed' | 'open' | 'half_open'
  
  // 关闭状态：正常请求
  // 打开状态：直接拒绝，返回降级响应
  // 半开状态：允许少量请求探测

  config: {
    failureThreshold: number      // 失败次数阈值
    successThreshold: number      // 半开状态成功次数阈值
    timeoutMs: number             // 打开状态持续时间
    monitorWindowMs: number       // 监控窗口
  }
}

// 示例配置
const externalServiceCircuitBreaker = {
  failureThreshold: 5,
  successThreshold: 3,
  timeoutMs: 30000,
  monitorWindowMs: 60000
}
```

## 6. 错误恢复

### 6.1 自动恢复

| 场景 | 恢复策略 |
|------|----------|
| 角色心跳超时 | 引擎自动重启角色（最多 3 次） |
| 消息队列阻塞 | 自动扩展队列或丢弃低优先级消息 |
| 外部服务恢复 | 熔断器自动进入半开状态探测 |
| Workflow 步骤失败 | 按重试策略自动重试 |

### 6.2 人工恢复

| 场景 | 触发条件 | 处理方式 |
|------|----------|----------|
| 角色启动失败 | 连续 3 次重启失败 | 告警 + 等待运维 |
| 数据不一致 | 校验检测到异常 | 告警 + 人工修复 |
| 安全事件 | 守卫检测到异常行为 | 隔离 + 人工调查 |
| Workflow 阻塞 | 超过 SLA 未完成 | 告警 + 人工介入 |

## 7. 错误监控与告警

### 7.1 错误指标

```typescript
interface ErrorMetrics {
  // 计数器
  errorCount: Counter              // 按错误码分组
  retryCount: Counter              // 重试次数
  degradationCount: Counter        // 降级次数
  
  // 比率
  errorRate: Gauge                 // 错误率（滑动窗口）
  retrySuccessRate: Gauge          // 重试成功率
  
  // 直方图
  errorLatency: Histogram          // 错误响应延迟
  
  // 标签
  labels: ['role', 'errorCode', 'retryable']
}
```

### 7.2 告警规则

| 指标 | 阈值 | 告警级别 |
|------|------|----------|
| 错误率| > 5% (5分钟) | Warning |
| 错误率| > 10% (5分钟) | Critical |
| 连续失败 | > 10 次| Critical |
| 熔断器打开 | 任意服务 | Warning |
| L1 Fatal 错误 | 任意 | Critical |

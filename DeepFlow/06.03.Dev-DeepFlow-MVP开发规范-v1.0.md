> **版本**: 1.1 | **更新日期**: 2025-12-04
> MVP 核心命题：证明DeepFlow 能力超越 DevDirector，首个验证场景为「洞见·思维显影」
>
> 重要：本文档与`06.11.Dev-DeepFlow-MVP定义与实现指南v1.0.md` 保持一致。如有冲突，06.11 为准。

## 1. MVP 目标

### 1.1 核心命题

证明 DeepFlow 作为「智能应用操作系统」的能力。
- 6 角色核心架构（MVP 最小可行配置，vs DevDirector 的 1 个 AI 角色 Prompt 级分工）
- 任意拓扑 Workflow（vs DevDirector 的线性 00-xx 步骤）
- Skill 可扩展（vs DevDirector 的固定能力）
- 硬执行安全（vs DevDirector 的 Prompt 引导软执行）

### 1.2 验证场景

**洞见·思维显影** 的核心流程：
1. 用户输入决策问题
2. 多角色（决策教练、诨问者、心理镜鉴..）并行推演
3. 生成决策胶片（结构化输出）
4. 生成 X 光片（觉察记录）
5. 存入持久记忆

### 1.3 验收标准

1. 系统能承载「洞见」的多角色决策流程
2. 系统支持至少 3 个角色并行推演
3. 完整的推演过程可追溯
4. 守卫能阻止危险操作
5. 系统失败能恢复
6. 当HumanTask 等待 24 小时后，Workflow 能继续执行
7. 应用重启后，进行中的 Workflow 能正确恢复

### 5.2 Skill 基类

```python
from abc import ABC, abstractmethod
from pydantic import BaseModel
from typing import Any, Dict

class SkillMeta(BaseModel):
    name: str
    version: str
    description: str
    input_schema: Dict[str, Any]
    output_schema: Dict[str, Any]

class SkillInput(BaseModel):
    data: Dict[str, Any]
    context: Dict[str, Any] = {}

class SkillOutput(BaseModel):
    success: bool
    data: Dict[str, Any] = {}
    error: str = ""

class BaseSkill(ABC):
    @abstractmethod
    def get_meta(self) -> SkillMeta:
        pass
    
    @abstractmethod
    async def execute(self, input: SkillInput) -> SkillOutput:
        pass
    
    def validate(self, input: SkillInput) -> bool:
        return True
```

### 5.3 API 端点

```python
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from skills.registry import SkillRegistry

app = FastAPI(title="DeepFlow Python Skills")
registry = SkillRegistry()

@app.get("/skills")
async def list_skills():
    return {"skills": [s.get_meta().dict() for s in registry.list_all()]}

@app.get("/skills/{name}")
async def get_schema(name: str):
    skill = registry.get(name)
    if not skill:
        raise HTTPException(404, f"Skill '{name}' not found")
    meta = skill.get_meta()
    return {
        "input_schema": meta.input_schema,
        "output_schema": meta.output_schema
    }

@app.post("/skills/{name}/execute")
async def execute_skill(name: str, request: ExecuteRequest):
    skill = registry.get(name)
    if not skill:
        raise HTTPException(404, f"Skill '{name}' not found")
    
    try:
        result = await skill.execute(request.input)
        return result.dict()
    except Exception as e:
        return SkillOutput(success=False, error=str(e)).dict()

@app.post("/skills/{name}/execute/stream")
async def stream_skill(name: str, request: ExecuteRequest):
    skill = registry.get(name)
    if not skill:
        raise HTTPException(404, f"Skill '{request.skill_name}' not found")
    
    async def generate():
        async for chunk in skill.stream(request.input):
            yield f"data: {chunk}\n\n"
    
    return StreamingResponse(generate(), media_type="text/event-stream")

@app.get("/health")
async def health():
    return {"status": "ok"}
```

## 6. 实现步骤

**目标**：在全面开发前验证 6 角色通信机制的可行性。

**最小角色集**：3 个，从 MVP 6 角色中选取 3 个
- Engine（消息路由）
- Commander（接收请求）
- Dispatcher（执行 Echo Skill，替代 Executor）
- Guard（简单校验）

**验证场景**：
```
用户输入 "Hello" 
  ├─ Engine 路由到 Commander
Commander 路由到 Dispatcher
Dispatcher 调用 EchoSkill
Guard 校验输出
返回 "Hello" 给用户
```

**验收标准**：
- [ ] 4 个角色能通过消息正常通信

- [ ] 异常能被正确传递和处理

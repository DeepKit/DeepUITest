# DeepFlow MVP 定义与实现指南

## 概述

本文档定义DeepFlow的最小可行产品（MVP）边界，明确实现技术栈和开发路径。MVP 的目标是验证核心架构理念，避免过度工程化。

## 1. MVP 角色边界

### 1.1 MVP 必需角色（5个）

| 角色 | 英文 | 职责 | MVP 实现要点 |
|------|------|------|--------------|
| **引擎** | Engine | 核心消息驱动循环 | 单线程事件循环，消息队列 |
| **总指挥** | Commander | 请求入口，会话管理 | 请求解析，会话生命周期 |
| **调度员** | Dispatcher | Workflow 执行 | 简易状态机(State Machine)，持久化游标，不含复杂调度 |
| **智囊** | Advisor | AI 能力调用 | Python Service 封装，LLM 调用，Prompt 模板 |
| **守卫** | Guard | 输入输出校验 | JSON Schema 校验，基础安全检查 |
| **记录员** | Chronicler | 日志与审计 | 文件日志，SQLite 审计库 |

### 1.2 延后实现角色（5个）

| 角色 | 英文 | 延后原因 | 替代方案 |
|------|------|---------|---------|
| **督察** | Inspector | 调试能力非核心 | 使用日志 + 断点调试 |
| **执行员** | Executor | 可简化 | 调度员直接调用 Skill |
| **军械员** | Quartermaster | 配置管理可简化 | 使用配置文件（JSON/YAML）|
| **后勤** | Logistics | 运行时配置可简化 | 硬编码 + 配置文件 |
| **通信员** | SignalOfficer | 消息总线可简化 | 内存消息队列 |

## 2. 技术栈定义

### 2.1 MVP 实现语言

**混合技术栈：Delphi (Core) + Python (Skills)**

- **Delphi (Object Pascal)**: 实现核心角色（Engine, Commander, Dispatcher, Guard, Chronicler），构建高稳定性、低延迟的"操作系统内核"。
- **Python**: 实现 Advisor (LLM Client) 和具体的 Skills，利用其丰富的 AI 生态（LiteLLM, LangChain等）。
- **通讯协议**: 内部通过 HTTP/JSON 进行 IPC 通讯（MVP阶段），未来可升级为共享内存或 ZeroMQ。

### 2.2 核心依赖

| 组件 | 技术选型 | 说明 |
|------|---------|------|
| **UI 框架** | FMX (FireMonkey) | 跨平台UI |
| **JSON 处理** | System.JSON / SuperObject | 消息序列化。|
| **YAML 解析** | Neslib.Yaml / 自实现。| Workflow 定义解析 |
| **Skill 运行** | Python 3.10+ / FastAPI | 承载 AI 与外部工具调用。|
| **HTTP 客户端** | System.Net.HttpClient | Delphi 调用 Python Skill 服务 |
| **SQLite** | FireDAC | 状态持久化、审计日志。|
| **正则表达式** | System.RegularExpressions | 模板解析 |

### 2.3 接口定义方式

由于 MVP 使用 Delphi 单一语言，接口定义采用：

1. **Delphi Interface** - 角色间契约
2. **JSON Schema** - 消息格式校验（外部文件）
3. **Markdown 文档** - 人类可读规范

**示例：角色接口定义**

```pascal
type
  // 消息基类
  TUniFlowMessage = class
  private
    FMsgId: string;
    FCorrelationId: string;
    FTimestamp: TDateTime;
    FFrom: string;
    FTo: string;
  public
    property MsgId: string read FMsgId write FMsgId;
    property CorrelationId: string read FCorrelationId write FCorrelationId;
    property Timestamp: TDateTime read FTimestamp write FTimestamp;
    property From: string read FFrom write FFrom;
    property To: string read FTo write FTo;
    
    function ToJSON: TJSONObject; virtual;
    class function FromJSON(AJson: TJSONObject): TUniFlowMessage; virtual;
  end;

  // 角色接口
  IUniFlowRole = interface
    ['{GUID}']
    function GetRoleName: string;
    procedure HandleMessage(AMessage: TUniFlowMessage);
    procedure Start;
    procedure Stop;
  end;

  // 智囊接口
  IAdvisor = interface(IUniFlowRole)
    ['{GUID}']
    function Query(const APrompt: string; AContext: TJSONObject): TAdvisorResponse;
    function QueryAsync(const APrompt: string; AContext: TJSONObject; 
      ACallback: TProc<TAdvisorResponse>): IAsyncTask;
  end;

  // 守卫接口
  IGuard = interface(IUniFlowRole)
    ['{GUID}']
    function ValidateInput(AData: TJSONObject; const ASchemaName: string): TValidationResult;
    function ValidateOutput(AData: TJSONObject; const ASchemaName: string): TValidationResult;
    function CheckSecurity(ARequest: TJSONObject): TSecurityCheckResult;
  end;
```

## 3. MVP 功能范围

### 3.1 包含的功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **基础 Workflow 执行** | SkillTask, AgentTask, Condition, Loop | P0 |
| **LLM 调用** | OpenAI 兼容 API | P0 |
| **输入输出校验** | JSON Schema 校验 | P0 |
| **会话管理** | 创建、恢复、终止会话 | P0 |
| **审计日志** | 所有操作记录到 SQLite | P0 |
| **错误处理** | 基础重试、超时、回退 | P1 |
| **Prompt 模板** | 变量替换、条件块 | P1 |
| **HumanTask** | 人工介入节点 | P1 |
| **置信度路径** | 基于 AI 置信度的条件分支 | P1 |

### 3.2 不包含的功能（V2.0+）

| 功能 | 延后原因 |
|------|---------|
| 分布式部署 | 复杂度高，需先验证单机模型 |
| 多LLM 模型切换 | 先支持单一模型 |
| 流式输出 | 需要 WebSocket，增加复杂度 |
| 向量记忆检索 | 需要向量数据库，增加依赖 |
| 督察调试 UI | 需要额外 UI 开发 |
| Chaos 测试 | 非核心功能 |

## 4. 实现路线

### 4.1 阶段划分

```
Phase 1: 核心框架 (2周)
├── 引擎消息循环
├── 角色基类与接口
├── 消息序列化、反序列化
└── 配置加载

Phase 2: 调度能力 (2阶段)
├── YAML Workflow 解析
├── 步骤执行器
├── 变量上下文管理
└── 状态持久化 (SQLite)

Phase 3: AI 集成 (1阶段)
├── LLM HTTP 客户端
├── Prompt 模板引擎
├── 响应解析
└── 置信度提取

Phase 4: 校验与安全 (1阶段)
├── JSON Schema 校验器
├── 输入消毒
├── 敏感信息过滤
└── 速率限制

Phase 5: 会话管理 (1阶段)
├── 会话生命周期
├── 上下文存储
├── 会话恢复
└── 超时处理

Phase 6: 集成测试 (1阶段)
├── 端到端测试
├── 错误场景测试
├── 性能基准
└── 文档完善
```

### 4.2 里程碑

| 里程碑| 时间阶段| 验收标准 |
|--------|--------|---------|
| **M1: Hello World** | Week 2 | 能执行简单Workflow，调用LLM 返回结果 |
| **M2: 完整流程** | Week 4 | 支持条件、循环、错误处理的复杂 Workflow |
| **M3: 生产就绪** | Week 6 | 审计完备、性能达标、文档完善|

## 6. 验证标准

### 6.1 功能验证

| 测试场景 | 描述 | 通过标准 |
|---------|------|---------|
| 简单问答 | 用户提问，AI 回答 | 正确返回结果 |
| 条件分支 | 基于用户输入走不同分支 | 正确路由 |
| 置信度路由 | 低置信度触发人工审核 | 正确识别并路由 |
| 错误恢复 | LLM 超时后重试 | 3次重试后优雅失败 |
| 会话恢复 | 应用重启后恢复会话| 状态正确恢复|

### 6.2 性能基准

| 指标 | 目标值| 测量方法 |
|------|-------|---------|
| 消息处理延迟 | <10ms (不含 LLM) | 内部计时 |
| Workflow 解析 | <100ms | 首次加载时间 |
| 并发会话数| >100 | 压力测试 |
| 内存占用 | <200MB | 100 会话场景 |

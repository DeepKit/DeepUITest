## 1. 架构定位

### 1.1 三层产品架构

```
┌─────────────────────────────────────────────────────────────────┐
│                       用户应用层                               │
│ ┌───────────────────┐ ┌───────────────────┐ ┌─────────────┐│
│ │  SoIs（如是）     │ │ DevDirector      │ │ 其他应用    ││
│ │  对话交互系统      │ │ 导演器           │ │            ││
│ └─────────┬─────────┘ └─────────┬─────────┘ └──────┬──────┘│
└────────────┼──────────────────────┼───────────────────┼────────┘
             │                     │                  │
             │                     │                  │
┌─────────────────────────────────────────────────────────────────┐
│                       能力转换层                               │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │                SayDone（述成）                            │ │
│ │             自然语言 → 结构化数据                         │ │
│ └───────────────────────────────────────────────────────────┘ │
└────────────────────────────────────┬────────────────────────────┘
                                      │
                                      │
┌─────────────────────────────────────────────────────────────────┐
└                       运行时基础层                             ┐
└┌───────────────────────────────────────────────────────────┐┐
└└                   DeepFlow                                 ┘┐
└└             智能应用操作系统                               ┘┐
└└  角色调度 · 消息路由 · 安全守卫 · 可观测性                ┘┐
└└───────────────────────────────────────────────────────────┘┘
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 各层职责

| 层次 | 产品 | 核心职责 | 用户感知 |
|------|------|----------|----------|
| **用户应用场景** | SoIs、DevDirector | 用户交互、业务场景 | 直接可见 |
| **能力转换层** | SayDone | NL→结构化转换 | 间接（转换结果） |
| **运行时基础层** | DeepFlow | 运行时调度、安全、监护 | 不可见 |

### 1.3 层间关系

```
┌──────────────────────────────────────────────────────────────┐
  关系类型                                                          │
║                                                          ║
║ SoIs ─────uses────> SayDone ─────runs-on────> DeepFlow   ║
║                                                          ║
║ · SoIs 调用 SayDone 的转换能力                           ║
║ · SayDone 基于 DeepFlow 运行时实现                       ║
║ · DeepFlow 提供角色框架，SayDone 实例化具体角色          ║
╚──────────────────────────────────────────────────────────╝
```

### 1.4 技术栈定义

| 产品 | MVP 实现语言 | V2.0 可选 | 说明 |
|------|-------------|---------|------|
| **DeepFlow** | Delphi (Object Pascal) | - | · SayDone/SoIs 保持一致 |
| **SayDone** | Delphi (FMX) | - | 现有实现 |
| **SoIs** | Delphi (FMX) | - | 现有实现 |

**技术栈统一决策**：

1. **MVP 阶段**：全部使用 **Delphi** 实现，确保与现有 SayDone/SoIs 无缝集成
2. **接口定义**：文档中 TypeScript 定义作为参考规范，实际实现用 Delphi Interface
3. **消息交换**：使用 JSON 格式，配合 JSON Schema 验证
4. **跨语言扩展**（V2.0）：如需其他语言实现，通过 IPC/HTTP 集成

**Delphi 核心依赖**：

```

◆ UI 框架         ◆ FMX (FireMonkey)                        ◆

◆ HTTP 客户端    ◆ System.Net.HttpClient                   ◆
◆ 数据库         ◆ FireDAC + SQLite                        ◆
◆ YAML 解析       ◆ Neslib.Yaml / 自实现                   ◆
```

### 2.3 角色复用规则

**完全复用**（代码级复用）：
- 守卫者・Guard
- 记忆官・Chronicler
- 监工 员Inspector (观测功能)

**扩展复用**（继承扩展）：
- AI代理 员Advisor + 共情/自检能力
- 总导演・Commander + Dispatcher 组合

**新增角色**（SayDone/SoIs 特有）：
- 共情官、自检员、Diff分析员、回退官。
- 澄清官、草图师、定位员、默认官

## 3. 术语统一

### 3.1 术语对照表：

| 概念 | DeepFlow 术语 | SayDone 术语 | SoIs 术语 | 统一建议 |
|------|-------------|-------------|-----------|----------|
| 运行时核心 | Engine | - | - | **引擎** |
| 全局调度 | Commander | 总导演 | - | **总指挥** |
| 任务编排 | Dispatcher | (总导演 | 进度 | **调度员** |
| AI 能力 | Advisor | AI代理 | 多个角色 | **智囊** |
| 安全校验 | Guard | 守卫者 | 守卫者 | **守卫** |
| 记录存储 | Chronicler | 记忆者 | 记忆者 | **记录者** |
| 质量监控 | Inspector | 监制 | 监工 | **督察** |
| 执行单元 | Skill | Skill | - | **技能Skill** |
| 编排流程 | Workflow | 流程 | Loop | **工作流** |
| 用户输入 | ExternalRequest | 用户指令 | 需求 | **请求** |
| AI 输出问题 | Hallucination | 幻觉 | - | **幻觉** |

### 3.2 命名规范

**角色命名规范**：
- 文档描述使用中文名（如"智囊"）
- 代码中使用英文名（如 `IAdvisor`）
- 日志/指标使用英文小写（如 `advisor`）

**消息命名规范**：
- Action 使用大写下划线（如 `UNDERSTAND_INTENT`）
- 字段使用小驼峰（如 `correlationId`）

## 4. 集成方式

### 4.1 SayDone 集成 DeepFlow

```typescript
// SayDone 启动配置
const sayDoneConfig: UniFlowConfig = {
  // 复用 DeepFlow 基础角色
  roles: {
    engine: new UniFlowEngine(),
    guard: new UniFlowGuard(),
    chronicler: new UniFlowChronicler(),
    logistics: new UniFlowLogistics(),
    signalOfficer: new UniFlowSignalOfficer(),
    
    // SayDone 扩展角色
    advisor: new SayDoneAdvisor({
      empathyEnabled: true,
      selfCheckEnabled: true
    }),
    commander: new SayDoneDirector(),
    
    // SayDone 新增角色
    diffAnalyzer: new DiffAnalyzer(),
    rollbackManager: new RollbackManager()
  },
  
  // 注册 SayDone 特有 Workflows
  workflows: [
    'saydone-understand-workflow',
    'saydone-transform-workflow',
    'saydone-validate-workflow'
  ]
}

const uniflow = await UniFlow.create(sayDoneConfig)
```

### 4.2 SoIs 集成 SayDone

```typescript
// SoIs 启动配置（基于SayDone）：
const soisConfig: SayDoneConfig = {
  // 继承 SayDone 配置
  ...sayDoneBaseConfig,
  
  // SoIs 扩展角色
  additionalRoles: {
    clarifier: new Clarifier(),
    sketcher: new Sketcher(),
    locator: new Locator(),
    defaulter: new Defaulter(),
    tracker: new Tracker()
  },
  
  // SoIs 特有 Workflows
  workflows: [
'sois-clarify-workflow',      // 需求澄清
    'sois-sketch-workflow',       // 草图生成
    'sois-locate-workflow',       // 问题定位
    'sois-propose-workflow'       // 方案建议
  ],
  
  // 运行模式
  mode: 'integrated' | 'standalone'
}
```

### 4.3 独立使用 DeepFlow

```typescript
// 例如：DeepFlow 使用（不依赖 SayDone/SoIs）
const pureUniFlowConfig: UniFlowConfig = {
  roles: {
// 仅使用 DeepFlow 11 个核心角色

// 自定义 Workflows

    'my-custom-workflow'
  ],
  
// 自定义 Skills

    myCustomSkill1,
    myCustomSkill2
  ]
```

## 7. 设计原则

### 7.1 DeepFlow 作为基础层的设计原则

1. **通用性**：DeepFlow 不包含任何业务特定逻辑
2. **可扩展**：角色接口支持扩展，Workflow 支持自定义
3. **稳定性**：核心接口保持向后兼容
4. **独立性**：可独立使用，不依赖 SayDone/SoIs

### 7.2 SayDone/SoIs 扩展原则

1. **继承优先**：优先继承DeepFlow 角色，避免重复实现
2. **职责单一**：新增角色应有明确单一职责
3. **松耦合**：与 DeepFlow 通过标准消息协议交互
4. **可替换**：SayDone 角色实现可被替换

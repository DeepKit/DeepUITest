# DeepUITest 深测产品愿景与蓝图

> 产品名：深导测试 DeepGuide Test（深测）
> 定位：Windows 桌面程序 UI 行为 Mock 测试系统
> 用户：开发者 / 测试人员
> MVP 优先级：第一优先（独立运行，不依赖底座）

---

## 一句话定位

深测是 Windows 桌面程序的 UI 行为 Mock 测试系统，用配置驱动测试，用红绿灯反馈质量。

---

## 核心能力

1. UI 行为 Mock 测试 - 模拟用户操作，验证 UI 状态变化
2. 配置端 + 测试端 - 分离测试配置与测试执行
3. 共享数据库 - 测试用例、结果、Bug 统一存储
4. AI 辅助生成测试配置 - AI 阅读开发文档和代码生成测试配置
5. 红绿灯机制 - 绿色通过 / 黄色警告 / 红色失败
6. 跨软件 Bug 记录库 - 统一管理多个软件的测试问题
7. 测试经验沉淀 - 测试模式和经验可复用

---

## 适用范围

VCL / FMX / Windows 桌面程序 / DeepGuide 各端 / 深启 DeepLaunch / 善用 / 其他 OCGS 应用

---

## 独立运行原则

深测有自己的测试配置模型，不需要旅程包体系就能工作。
后续可选集成底座：从旅程包自动生成测试用例（增强功能，非前提条件）。

---

## 为什么是第一优先

1. 可立即服务自己和其他 Delphi/Windows 桌面软件
2. 不依赖底座开发进度，可独立启动
3. 是其他产品质量保障的基础
4. 有明确的技术边界，可快速交付 MVP

---

## 测试配置模型（独立协议）

深测有自己的配置协议，不依赖 Journey Protocol：

TestSuite（测试套件）
  TestCase（测试用例）
    UIElement（UI 元素定位）
    Action（操作：点击/输入/等待/断言）
    ExpectedState（预期状态）
    ActualState（实际状态）
    Result（红/黄/绿）

UIElement 定位方式：
  - 控件名（Name/Caption）
  - 控件类型 + 层级路径
  - 坐标（备选）
  - 图像识别（备选）

---

## 架构

配置端（Studio 风格）：
  - 创建测试套件
  - 定义 UI 元素
  - 编排操作序列
  - 设置预期状态
  - AI 辅助生成配置

测试端（执行器）：
  - 加载测试套件
  - 连接目标程序
  - 执行操作序列
  - 比对预期/实际状态
  - 输出红绿灯结果

共享数据库：
  - 测试用例存储
  - 执行结果存储
  - Bug 记录
  - 测试经验沉淀

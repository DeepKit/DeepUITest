# OCGS-善用-DeepLaunch案例：倒推流程修正版

> 文件性质：纠错记录 + 流程修正稿  
> 主题：纠正“顺推式提问”，恢复 OCGS 正确的“从宝物倒推到第一道门”流程  
> 状态：v0.2 修正版  
> 核心纠正：不能在宝物定义后马上问“第一道门在哪里”；必须先问“拿到宝物前的最后一道门是什么”，再逐层往外倒推。

---

## 0. 本次纠错

前一版讨论中，AI 在定义宝物后直接问：

```text
这条善用任务的第一道门在哪里？
```

这是错误的。

这不是倒推，而是顺推。

OCGS 正确流程应该是：

```text
宝物 Output
  ← 最后一道门 / CompletionGate / DueGate
    ← 宝物所在的直接场域
      ← 上层场域
        ← 更上层场域
          ← AppGate / 第一道入口门
```

也就是说，第一道门不是马上问出来的，而是最后倒推到的。

---

## 1. 正确的主持方式

### 错误问法

```text
宝物已经定义好了。
第 2 问：第一道门在哪里？
A. 善用里选择 DeepLaunch 入门包
B. DeepLaunch 已打开并看到格子区域
C. DeepLaunch 已打开但不知道格子区域在哪里
```

这属于从入口顺推。

### 正确问法

```text
宝物已经定义好了。
第 2 问：用户拿到这个宝物前，最后必须通过哪一道门？
```

也就是：

```text
一个程序已经绑定到格子/单键，并可快速启动。
在它成为“已拿到宝物”之前，最后一个确认动作是什么？
```

## 2. DeepLaunch 案例当前宝物

```text
OutputKey:
  deeplaunch.grid.program_binding.ready

OutputName:
  一个程序已经成功绑定到 DeepLaunch 的某个格子和单键，并可快速启动

宝物描述:
  用户把一个外部可执行程序，与 DeepLaunch 中的某个格子 / 单键建立关联。
  完成后，用户可以通过双击格子、键入单键，或右键菜单快速启动该程序。
```

---

## 3. 正确的第 2 问：最后一道门是什么？

AI 主持人应该这样问：

```text
用户拿到“程序已绑定并可快速启动”这个宝物前，
最后必须通过哪一道门？
```

候选：

### A. 启动验证门 LaunchVerifyGate

```text
用户保存后，必须双击格子或键入单键，确认程序真的能启动。
只有启动成功，才算拿到宝物。
```

适合强调“可用结果”，不是只保存配置。

### B. 保存配置门 SaveGate

```text
用户点击保存后，配置写入成功，就算拿到宝物。
启动验证只是后续建议。
```

适合降低流程长度，但宝物确认较弱。

### C. 格子状态出现门 GridReadyGate

```text
保存后，格子显示图标/名称，说明绑定成功。
用户看到格子状态变化，即算拿到宝物。
```

适合视觉确认，但不能保证程序真的可启动。

### 主持建议

建议选择：

```text
A. 启动验证门 LaunchVerifyGate
```

理由：

```text
本宝物的核心不是“配置已保存”，而是“程序可以快速启动”。
所以必须通过一次启动验证，才算真正拿到宝物。
```

---

## 4. 如果选择 A，则倒推链条从这里开始

```text
Output:
  程序已绑定并可快速启动

← 最后一道门：
  LaunchVerifyGate：双击格子 / 键入单键，程序成功启动

← 直接前置场域：
  GridReadyField：格子已显示程序图标/名称，处于可启动状态

← 前置门：
  SaveGate：编辑窗体保存成功

← 前置场域：
  EditFormField：编辑窗体中已填好程序路径、参数、名称

← 前置门：
  ProgramPathGate：程序路径有效

← 前置场域：
  GridCellEditField：用户正在编辑某个格子

← 前置门：
  EditGate：用户从右键菜单进入编辑

← 前置场域：
  GridCellField：用户选中了一个空格子

← 上层场域：
  GridAreaField：DeepLaunch 格子区域

← 上层场域：
  DeepLaunchMainField：DeepLaunch 主界面

← 入口门：
  DeepLaunchGuideTaskGate：用户在善用中选择“绑定第一个程序”任务
```

注意：

```text
这条链是从 Output 往外倒推得到的，
不是从入口往里顺推列出来的。
```

## 5. AI 主导用户选择式流程的修正

以后 AI 主持时必须遵守以下顺序：

```text
1. 先确认宝物 Output
2. 再问最后一道门是什么
3. 再问最后一道门所在的直接场域是什么
4. 再问进入这个场域前要通过什么门
5. 再逐层往外倒推
6. 直到倒推到第一道入口门
7. 最后再整理成从入口到宝物的正向执行路径
```

也就是说：

```text
讨论时：倒推
呈现时：可以正向展示
```

不能把“最终展示路径”误当成“设计推导顺序”。

---

## 7. 冻结句

> OCGS 的设计讨论必须严格倒推：先定义用户最终要拿到的宝物 Output，再追问拿到宝物前的最后一道门，接着追问该门所在的直接场域、前置门、上层场域，逐层退回到 AppGate / 第一道入口。AI 主持人不能在宝物定义后直接问第一道门，否则就是顺推错误。讨论时倒推，呈现时可以正向。

## 1. 方法原则：必须倒推，不得顺推

### 1.1 错误方式：顺推

错误提问方式是：

```text
宝物定义完以后，马上问：
第一道门在哪里？
```

这属于顺推。

顺推容易让讨论从入口、界面、按钮、功能清单开始，导致：

```text
1. 还没确认最终产出，就开始画流程；
2. 门的粒度容易混乱；
3. 同一界面内的字段、按钮、状态被拆成一堆同级主门；
4. AI 容易抢答，提前输出大方案；
5. 人类被动审核，而不是主动选择。
```

### 1.2 正确方式：倒推

正确流程是：

```text
宝物 Output
  ← 最后一道门 / 负一号门
    ← 负二号门
      ← 负三号门
        ← ...
          ← 最外层入口门
```

也就是说：

> **先定义用户最终要拿到的宝物，再问拿到宝物前的最后一道门，然后逐层往外退，直到退回到入口。**

### 1.3 讨论与呈现的区别

```text
讨论时：
  必须倒推。

文档展示或用户说明时：
  可以正向展示。
```

例如：

```text
倒推讨论：
Output ← LaunchVerifyGate ← GridReadyGate ← SaveSuccessGate ...

正向呈现：
启动 DeepLaunch → 进入主界面 → 进入格子区域 → 选择空格子 → ...
```

两者不能混淆。

## 2. AI 主导用户选择式流程

### 2.1 AI 的角色

AI 不是抢答者，而是主持人。

AI 应该：

```text
1. 提出当前阶段最关键的问题；
2. 给出 A/B/C/D 选项；
3. 说明每个选项的后果；
4. 给出主持建议；
5. 等待用户选择、修正、否定或确认；
6. 记录 HumanDecisionLog；
7. 再进入下一问。
```

### 2.2 人类的角色

人类不是一次性写完整 PRD 的人。

人类主要负责：

```text
1. 选择；
2. 修正；
3. 否定错误方向；
4. 补充真实业务细节；
5. 确认冻结；
6. 判断粒度；
7. 批准进入下一阶段。
```

### 2.3 本案例中的重要纠错

本案例中，AI 曾错误地从宝物直接问“第一道门在哪里”。

用户纠正：

```text
不对，是倒推。
```

该纠正已经成为本流程的重要规则：

> **宝物定义后，不能问第一道门；必须先问负一号门，也就是宝物前最后一道门。**

## 3. 产品背景：善用与深启 DeepLaunch

### 3.1 善用定位

```text
善用，是一个桌面悬浮式软件任务陪跑系统 / 软件场域导航系统。
```

对外表达：

```text
新软件不会用？
善用悬浮在旁边，一步步带你做成第一件事。
```

善用的核心不是教程播放，而是：

```text
1. 悬浮在目标软件或网页上方；
2. 用步骤、聚焦线框图、卡点问答和迷路恢复引导用户；
3. 让用户不用来回切教程；
4. 在真实操作场景里完成一个任务；
5. 用户迷路时能被带回来。
```

### 3.2 深启 DeepLaunch

原软件名：

```text
2KeyRun
```

已更名为：

```text
深启 DeepLaunch
```

功能说明：

```text
1. 支持程序快速启动；
2. 支持格子 / 单键 / 右键菜单等启动入口；
3. 支持绑定程序路径与参数；
4. 图标可自动获取；
5. 已新增支持工作流启动。
```

本次演示暂不把“工作流启动”放进第一条宝物。

原因：

```text
1. 第一条任务应尽量简单；
2. 先让用户理解“一个格子 = 一个快速启动入口”；
3. 工作流启动更高级，适合作为第二阶段进阶宝物。
```

## 4. 本次宝物 Output 定义

### 4.1 宝物名称

```text
OutputKey:
  deeplaunch.grid.program_binding.ready

OutputName:
  一个程序已经成功绑定到 DeepLaunch 的某个格子和单键，并可快速启动
```

### 4.2 宝物描述

```text
用户把一个外部可执行程序，与 DeepLaunch 中的某个格子 / 单键建立关联。
完成后，用户可以通过双击格子、键入单键，或右键菜单快速启动该程序。
```

### 4.3 FinalState

```text
1. 某个格子已绑定程序路径；
2. 可选参数已保存；
3. 格子名称已生成或手动设置；
4. 图标已自动获取；
5. 用户能通过双击格子或单键启动程序；
6. 如果支持右键菜单启动，也可通过右键菜单启动。
```

### 4.4 RiskLevel

```text
L1：低风险配置，可撤回。
```

理由：

```text
该流程修改的是 DeepLaunch 的本地配置。
它不是高风险、不可逆、强承责操作。
```

## 5. 本次演示的两条路径

### 5.1 主路径：右键编辑路线

```text
打开 DeepLaunch
  → 进入格子区域
  → 选择一个空格子
  → 右键菜单 - 编辑
  → 打开编辑窗体
  → 绑定一个程序路径和参数
  → 可选：设置名称
  → 图标自动获取
  → 保存
  → 双击格子 / 键入单键
  → 成功启动程序
```

主路径价值：

```text
1. 步骤完整；
2. 可教学节点多；
3. 善用可以充分展示悬浮引导价值；
4. 适合做第一条标准演示路径。
```

### 5.2 补充路径：拖拽快速路线

```text
从外部拖动一个可执行文件
  → 放到 DeepLaunch 的某个格子
  → 系统自动绑定程序路径
  → 自动获取图标和名称
  → 用户双击格子 / 键入单键
  → 成功启动程序
```

补充路径价值：

```text
1. 更快；
2. 更直观；
3. 适合作为“更快方式”展示；
4. 不宜作为第一主线，因为善用可引导节点较少。
```

### 5.3 路径关系

主路径与拖拽路径不应混在一条主链里。

应理解为：

```text
主路径：
  右键编辑绑定程序

补充 Route：
  拖拽 exe 到格子快速绑定

两条路径在 GridReadyGate / 格子就绪门 汇合。
```

## 6. 门的粒度原则

### 6.1 一个界面就是一个门

用户补充的重要原则：

> **门打开进入和离开有界面变化，为一个场域。**

也就是说，当用户打开一道门以后：

```text
1. 进入了新的界面、窗体、页面、区域或浮层；
2. 出现了新的操作上下文；
3. 有自己的字段、按钮、状态和反馈；
4. 离开时会回到上层场域或进入另一场域；
5. 用户感知上像“到了另一个地方”。
```

这样的对象应视为一个场域门。

### 6.2 同一界面内的内容不要连续拆成主链门

在同一个界面中：

```text
字段填写；
按钮点击；
状态就绪；
校验提示；
自动解析；
保存动作；
```

不能全部升格为主链上相邻的负号门。

它们应归入该场域内部的：

```text
Conditions
SubGates
SubActions
FieldRequirements
Feedback
ExpectedResult
```

### 6.3 三类特别门

本案例中形成了几类门：

```text
FieldGate / 场域门：
  进入一个界面、窗体、页面、区域、浮层。

TargetObjectGate / 目标对象门：
  不一定是新界面，但必须定位一个具体操作对象。
  例如目标空格子。

ActionGate / 动作门：
  在某个场域内部触发关键动作。
  例如保存提交、启动验证。

StateGate / 状态显现门：
  不是新界面，而是用户需要确认某个状态已经显现。
  例如格子显示图标和名称。
```

## 7. 宝物倒推主链

### 7.1 总链条

```text
宝物 Output：
  程序已经绑定到 DeepLaunch 的某个格子 / 单键，并可快速启动

← 负一号门：
  LaunchVerifyGate / 启动验证门

← 负二号门：
  GridReadyGate / 格子就绪门

← 负三号门：
  SaveSuccessGate / 保存成功门

← 负四号门：
  SaveCommandGate / 保存提交门

← 负五号门：
  EditFormGate / 编辑窗体门

← 负六号门：
  ContextMenuGate / 右键菜单门

← 负七号门：
  EmptyGridCellTargetGate / 目标空格子定位门

← 负八号门：
  GridAreaGate / 格子区域门

← 负九号门：
  MainWindowGate / DeepLaunch 主界面门

← 负十号门：
  DeepLaunchAppGate / DeepLaunch 启动门
```

### 7.2 负一号门：LaunchVerifyGate / 启动验证门

```text
编号：
  负一号门

类型：
  ActionGate / 验证动作门

定义：
  用户必须双击格子或键入单键，确认程序真的启动成功。
  只有启动成功，才算拿到宝物。

为什么选它：
  本宝物的核心不是“配置已保存”，而是“程序可以快速启动”。
  所以必须通过一次启动验证。
```

### 7.3 负二号门：GridReadyGate / 格子就绪门

```text
编号：
  负二号门

类型：
  StateGate / 状态显现门

定义：
  用户保存后，目标格子已经显示程序名称 / 图标，并处于可启动状态。
  只有格子已经准备好，用户才能进入启动验证。

说明：
  该门不是新界面，而是状态显现。
  它对善用很重要，因为用户需要看到“这个格子已经准备好了”。
```

### 7.4 负三号门：SaveSuccessGate / 保存成功门

```text
编号：
  负三号门

类型：
  StateGate / 结果状态门

定义：
  用户在编辑窗体点击保存后，系统成功写入配置，并返回格子区域。
  保存成功后，目标格子才能显示名称 / 图标并进入可启动状态。

说明：
  保存成功是格子就绪的直接前置结果。
```

### 7.5 负四号门：SaveCommandGate / 保存提交门

```text
编号：
  负四号门

类型：
  ActionGate / 编辑窗体内关键动作门

定义：
  用户在编辑窗体中点击“保存”按钮，提交保存动作。
  如果保存动作完成，就进入 SaveSuccessGate。

重要说明：
  SaveCommandGate 不是独立界面门。
  它发生在 EditFormGate 内部，应被标注为编辑窗体场域内的关键动作门。
```

### 7.6 负五号门：EditFormGate / 编辑窗体门

```text
编号：
  负五号门

类型：
  FieldGate / 界面场域门

定义：
  用户已经进入 DeepLaunch 的编辑窗体。
  编辑窗体是一个完整操作界面，内部包含程序路径、参数、名称、图标自动获取、保存按钮等子条件与子动作。

内部结构：
  EditFormGate
    ├─ FieldRequirement: 程序路径
    ├─ FieldRequirement: 参数（可选）
    ├─ FieldRequirement: 名称（可选）
    ├─ SubAbility: 图标自动获取
    ├─ SubCondition: 路径有效
    ├─ SubAction: SaveCommand
    └─ Result: SaveSuccess
```

### 7.7 负六号门：ContextMenuGate / 右键菜单门

```text
编号：
  负六号门

类型：
  FieldGate / 临时浮层场域门

定义：
  用户在目标格子上点击右键，打开格子的右键菜单。
  右键菜单作为一个临时界面 / 浮层场域，里面包含“编辑”等菜单项。

内部子路由：
  ContextMenuGate
    └─ Route: ClickEdit → EditFormGate

说明：
  点击“编辑”不是主链独立门，而是右键菜单场域内的子动作 / 子路由。
```

### 7.8 负七号门：EmptyGridCellTargetGate / 目标空格子定位门

```text
编号：
  负七号门

类型：
  TargetObjectGate / 目标对象门

定义：
  用户已经在 DeepLaunch 的格子区域中找到一个空格子，并把鼠标 / 注意力定位到这个具体格子上。
  只有有了明确目标格子，右键菜单才有操作对象。

为什么它能进入主链：
  1. 右键菜单必须依附于具体目标对象；
  2. 如果没有目标格子，ContextMenuGate 没有上下文；
  3. 善用引导用户时，必须先让用户知道“对哪个格子操作”。
```

### 7.9 负八号门：GridAreaGate / 格子区域门

```text
编号：
  负八号门

类型：
  FieldGate / 区域场域门

定义：
  用户已经进入 DeepLaunch 的格子区域。
  只有看到格子区域，才可能进一步定位某一个具体空格子。

内部条件：
  GridAreaGate
    ├─ Condition: 格子区域可见
    ├─ Condition: 至少一个空格子可见
    ├─ Condition: 当前格子区域可操作
    └─ SubGate: EmptyGridCellTargetGate
```

### 7.10 负九号门：MainWindowGate / DeepLaunch 主界面门

```text
编号：
  负九号门

类型：
  FieldGate / 主界面场域门

定义：
  用户已经打开 DeepLaunch 主界面。
  主界面是 DeepLaunch 的上层操作场域，里面包含格子区域、程序树、设置区、状态区等。

说明：
  GridAreaGate 是 MainWindowGate 内部的功能区域场域。
```

### 7.11 负十号门：DeepLaunchAppGate / DeepLaunch 启动门

```text
编号：
  负十号门

类型：
  EntryGate / 应用启动门

定义：
  用户已经启动 DeepLaunch 程序。
  程序启动成功后，才会进入 DeepLaunch 主界面。

边界说明：
  安装不属于本链。
  DeepLaunchInstalledGate / 安装存在门不纳入本次主链。
```

## 9. 拖拽快速路径

拖拽路径不是主链，而是分支 Route。

### 9.1 拖拽路径倒推链

```text
Output：
  程序已经绑定到 DeepLaunch 的某个格子 / 单键，并可快速启动

← LaunchVerifyGate / 启动验证门
← GridReadyGate / 格子就绪门
← AutoBindGate / 自动绑定门
← DropExeGate / 拖拽释放门
← EmptyGridCellTargetGate / 目标空格子定位门
← GridAreaGate / 格子区域门
← MainWindowGate / 主界面门
← DeepLaunchAppGate / 启动门
```

### 9.2 正向呈现

```text
启动 DeepLaunch
  → 进入主界面
  → 进入格子区域
  → 定位一个空格子
  → 从外部拖动 exe 文件到格子
  → DeepLaunch 自动绑定路径、名称和图标
  → 格子进入就绪状态
  → 双击格子或键入单键
  → 程序成功启动
```

### 9.3 路径关系

```text
右键编辑路径：
  ContextMenuGate → EditFormGate → SaveCommandGate → SaveSuccessGate → GridReadyGate

拖拽快速路径：
  DropExeGate → AutoBindGate → GridReadyGate

两条路径在 GridReadyGate 汇合。
```

## 12. 专家评估结论

专家评估认为，当前门划分总体成立，但要注意四个标注：

### 12.1 SaveCommandGate 是动作门

```text
SaveCommandGate 不是独立界面门。
它是 EditFormGate 内部的关键动作门。
```

### 12.2 GridReadyGate 是状态显现门

```text
GridReadyGate 不是新场域。
它是保存成功后用户需要看到的可启动状态。
```

### 12.3 EmptyGridCellTargetGate 是目标对象门

```text
它不是完整新界面。
但因为右键菜单必须依附具体目标格子，所以它可以进入主链。
```

### 12.4 ContextMenuGate 是临时浮层场域门

```text
右键菜单出现前后，用户界面状态发生变化；
菜单本身承载一组操作选择；
因此可以作为临时场域门。
```

### 12.5 安装流程另开

```text
安装、部署、首次下载、授权、更新，不进入本宝物主链。
```

### 12.6 善用外壳链另开

```text
善用选择包、选择任务、绑定目标窗口，是善用引导层外壳；
DeepLaunchAppGate 之后才进入 DeepLaunch 内部业务链。
```

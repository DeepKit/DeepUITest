## 0. 本文件定位

这份文档不是开发规范，也不是 UI 细节稿。

它记录的是此前讨论中最重要的几个产品定位：

1. 从企业级“专家能力化”方向出发；
2. 发现大 B / 投标 / 人脉型销售路径太重；
3. 收缩为自己可用、普通用户也可用的轻产品；
4. 最终形成“善用”：桌面悬浮式软件任务陪跑系统；
5. 后台仍由 OCGS 指导，但前台表达必须足够口语、具体、可传播。

# 一、最早的企业级定位：企业专家能力化通用系统

## 1.1 后台战略定位

早期产品方向可以概括为：

> **企业专家能力化通用系统。**

它解决的不是“流程展示”，也不是“普通培训”，而是：

> **把企业专家的经验、判断、流程、异常处理、客户话术、证据要求和操作路径，转化为可沉淀、可训练、可调用、可跟做、可治理、可迭代的组织能力。**

这个定位是后台战略定位，适合用于：

- 白皮书；
- 产品架构文档；
- 战略说明；
- 融资材料；
- 企业级方案；
- 与 OCGS 的理论连接。

## 1.2 它不是这些东西

它不是：

```text
流程图工具；
普通知识库；
普通培训系统；
PPT 演示工具；
AI 问答机器人；
RPA 自动点击工具；
简单软件教程平台。
```

它的核心不是“展示流程”，而是：

> **把专家能力转化为组织可复用的能力资产。**

---

# 二、对外最有传播力的表达：小白也能像专家一样

## 2.1 最重要的一线表达

相比“企业专家能力化通用系统”这种抽象说法，更有传播力的一线表达是：

> **让小白也能像专家一样接待客户，少犯错。**

进一步强化：

> **让新人也能像专家一样办业务，少问人、少犯错、少投诉。**

这句话比抽象定位更容易被客户、用户和市场理解。

## 2.2 为什么这句话重要

它有三个优点：

1. **对象明确**：小白、新人、前台、客服、柜员、窗口人员；
2. **结果明确**：像专家一样接待客户、办理业务；
3. **价值明确**：少问人、少犯错、少投诉。

## 2.3 不同对象的表达

面向老板：

> 老员工会的，新人也能按步骤做；专家知道的，系统一步步提醒。

面向主管：

> 业务规则一变，不用反复开会培训，系统直接把新规则变成现场可跟做的标准旅程。

面向一线员工：

> 客户问什么、页面点哪里、字段怎么填、什么情况不能办，系统在旁边一步步带你走。

面向企业：

> 让专家经验不再只在老员工脑子里，而是变成全员可调用的现场能力。

# 三、命名体系阶段结论：深导 + 行业子名

## 3.1 “深”保留，“演”不再适合

原来的“深演”适合表达：

```text
把深层结构演出来；
把复杂系统演成旅程；
把 OCGS 讲成可视化过程。
```

但当前产品已从“演示 / 展示”转向：

```text
指导；
教学；
陪做；
成手；
成师；
现场带着办。
```

所以“演”不再适合，“深”应该保留。

## 3.2 总品牌：深导

阶段性命名建议：

> **深导**

含义：

```text
深：深层经验、深层判断、复杂规则、专家能力；
导：指导、引导、带做、导办、现场陪跑。
```

一句话：

> **深导，把专家能力变成小白也能跟做的现场指导。**

## 3.3 子产品 / 行业版命名

采用：

> **一个总品牌 + 多个行业 / 场景子名**

不要用一个名字强行覆盖所有场景。

建议结构：

```text
深导
  ├─ 深导·成师：通用企业专家能力化系统
  ├─ 深导·善办：窗口 / 客服 / 政务 / 税务接待场景
  ├─ 深导·陪办：一线实时操作助手
  └─ 深导·导办：政务事项导办行业版
```

## 3.4 各命名适用场景

### 深导·成师

适合：

```text
企业培训；
专家经验沉淀；
客服中心；
销售团队；
售后团队；
实施团队；
制造、银行、保险等专家能力复制场景。
```

表达：

> **让新人也能像专家一样办业务。**

### 深导·善办

适合：

```text
税务局；
政务大厅；
社保医保窗口；
电信营业厅；
学校后勤窗口；
客服接待；
银行柜面。
```

表达：

> **客户来了，会问、会查、会填、会说、会拦。**

### 深导·陪办

适合：

```text
桌面悬浮助手；
前台实时操作教练；
员工正在办业务时的旁路指导。
```

表达：

> **员工办业务时，专家系统在旁边一步步带。**

### 深导·导办

适合：

```text
政务；
税务；
大厅事项；
材料补正；
政策变化后的现场导办。
```

表达：

> **复杂事项现场导办系统。**

# 四、现实修正：大 B 方向太重，先做自己可用的大众产品

## 4.1 关键现实判断

虽然“企业专家能力化通用系统”方向很大，也有价值，但当前资源条件存在明显限制：

```text
没有大 B 人脉；
没有政务 / 银行 / 电信投标渠道；
没有成熟销售团队；
采购周期长；
关系型销售成本高；
即使产品做出来，也可能进不了门。
```

所以不适合一开始就做：

```text
政务大项目；
税务局项目；
银行项目；
电信营业厅系统；
大型企业专家能力平台。
```

## 4.2 战略收缩

产品应先从大 B 企业级系统收缩为：

> **自己可用，普通人也能用的产品。**

这个产品暂命名：

> **善用**

它不是放弃“专家能力化”，而是把能力从企业大系统降维到普通人的软件使用场景。

---

# 五、善用的核心定位

## 5.1 产品定位

> **善用，是一个桌面悬浮式软件任务陪跑系统。**

进一步定义：

> **善用悬浮在用户正在使用的软件或网页上方，通过步骤引导、截图 / 简笔线框图 / 聚焦导航图、卡点问答和迷路恢复，带用户一步步完成新软件里的真实任务。**

更短表达：

> **善用：新软件不会用？悬浮在旁边一步步带你用。**

## 5.2 它不是教程系统

善用不是：

```text
软件教程；
视频课程；
说明书；
知识库；
普通 AI 问答；
RPA 自动化；
自动点击工具。
```

它是：

> **软件任务陪跑系统。**

核心差别：

```text
普通教程：教你这个软件有什么功能；
善用：带你用这个软件完成一件事。
```

## 5.3 它解决的第一痛点

用户拿到新软件后，真正痛苦的不是“完全不会”，而是：

```text
不知道从哪里开始；
不知道当前页面是不是对的；
不知道下一步点哪里；
不知道字段大概填什么；
页面和教程不一致时不知道怎么办；
点错了不知道怎么回来；
完成一步后不知道下一步做什么。
```

善用的任务是：

> **让用户不迷路，并带他完成第一个有价值的结果。**

---

# 六、善用的第一用户与第一场景

## 6.1 第一用户

第一阶段优先面向：

```text
自己；
自己的软件用户；
独立软件作者；
AI 工具用户；
小团队内部工具用户；
拿到新软件但不想看长教程的普通用户。
```

## 6.2 不优先面向

第一阶段暂不优先：

```text
大企业；
政务大厅；
银行柜面；
税务局；
电信营业厅；
高合规大 B 场景。
```

这些可以作为未来“深导·善办 / 深导·成师”的行业版方向，但不是善用第一刀。

## 6.3 第一批可做软件

建议第一阶段围绕：

```text
自己的软件；
善用自己；
Cursor / AI 编程工具；
ChatGPT / AI 工具；
常见效率工具；
小团队内部软件。
```

# 七、善用的核心产品形态：桌面悬浮端 + 云端能力库

## 7.1 为什么不能先做纯 Web

纯 Web 端会带来切换负担：

```text
看教程网页；
切到目标软件；
再切回来；
再切过去；
容易迷路；
体验割裂。
```

善用应优先做：

> **桌面端悬浮助手。**

## 7.2 产品形态

```text
本地桌面悬浮端
  负责悬浮显示、步骤播放、线框/截图提示、窗口跟随、用户交互、本地缓存

云端
  负责旅程包、接口、AI 生成、问答、卡点数据、版本同步、模板市场
```

## 7.3 一句话表达

> **善用不是让你切到教程里学习，而是直接悬浮在你正在用的软件旁边，带你完成任务。**

---

# 八、视觉定位：不是截图教程，而是场域导航

## 8.1 两种视觉锚点

善用不一定必须使用原软件截图，也可以使用简笔线框图。

支持两类核心视觉锚点：

```text
1. 原截图锚点
   用真实软件截图 + 框线引导，适合强对照。

2. 简笔线框图锚点
   用相对位置框线图 / 简笔图表达场景，适合低成本、抗版本变化、保护隐私。
```

后续可增加：

```text
3. 混合锚点
   整体用线框图，局部嵌入真实截图。
```

## 8.2 核心不是还原 UI，而是还原场域

善用的关键不是把软件界面画得多像，而是让用户知道：

```text
我现在应该在哪；
我现在该看哪里；
我现在该点哪里；
我现在不用管哪里；
做完后应该看到什么；
如果我迷路了，怎么回来。
```

所以善用更准确的定位是：

> **软件场域导航系统。**

# 九、AI 线框生成器的定位

## 9.1 AI 可以从切图生成线框图

AI 可以根据目标软件截图生成线框图草案，但不能直接发布。

正确流程：

```text
用户截图
  ↓
AI 识别页面结构
  ↓
AI 生成线框草稿
  ↓
AI 标出候选区域 / 候选锚点
  ↓
人工校正
  ↓
系统检查
  ↓
发布为善用包
```

## 9.2 只生成导航需要的部分

AI 线框生成器不应追求完整复刻页面。

它只需要画出：

> **当前步骤导航需要的部分。**

其它部分可以：

```text
模糊；
灰掉；
弱化；
只画轮廓；
甚至不画。
```

## 9.3 导航最小可见集

新增关键概念：

> **导航最小可见集**

含义：

> **为了让用户完成当前步骤，必须被看见的最小视觉元素集合。**

例如当前步骤是“点击左侧 Settings 菜单”，最小可见集可能只有：

```text
左侧栏；
Settings 菜单；
当前位置提示；
点击后的目标页面提示。
```

其它区域都可以弱化。

## 9.4 线框图不是 UI 复刻，而是聚焦投射

阶段冻结句：

> **善用不是把软件页面完整画出来，而是把当前步骤需要通过的“门”画出来；其它部分可以模糊，只保留帮助用户定位的最小场域。**

# 十、善用与 OCGS 的关系

## 10.1 后台理论

善用仍由 OCGS 指导。

对应关系：

```text
用户要完成的任务结果 = Output
用户当前所在页面/软件状态 = FieldScene / ContextField
当前要点的位置 = AccessGate / VisualAnchor
当前步骤说明 = Feedback / Projection
下一步去哪 = RouteRule
卡住了怎么办 = LostRecovery / Fallback
完成后的记录 = Trace / Evidence
善用包发布 = Seal
```

## 10.2 对外不先讲 OCGS

对外不要先说：

> 基于 OCGS 的软件场域导航系统。

对外先说：

> **新软件不会用？善用悬浮在旁边，一步步带你用起来。**

或者：

> **不用来回切教程，善用直接浮在软件旁边，用框线和步骤带你完成任务。**

OCGS 放在后台，用来指导产品结构、开发流程和长期壁垒。

# 十一、最重要的定位冻结句

## 11.1 总定位

> **善用，是一个桌面悬浮式软件任务陪跑系统。**

## 11.2 更完整定义

> **善用悬浮在用户正在使用的软件或网页上方，通过原软件截图、简笔线框图、聚焦导航图、步骤引导、卡点问答和迷路恢复，帮助用户不用来回切教程，也能一步步完成新软件里的真实任务。**

## 11.3 最短传播语

> **新软件不会用？善用一步步带你用。**

## 11.4 更有产品感的传播语

> **善用：悬浮在软件旁边，用框线和步骤带你把新软件真正用起来。**

## 11.5 与深导体系的关系

```text
深导：总品牌 / 专家能力化方向
深导·成师：企业专家能力化系统
深导·善办：窗口接待 / 办业务场景
深导·陪办：一线实时操作助手
善用：普通用户 / 小团队 / 自用的软件任务陪跑产品
```

善用可以先独立作为轻产品推进，未来再归入深导体系。

# 十二、当前最重要的战略判断

## 12.1 不先走大 B

当前不优先做大 B 投标型企业系统。

原因：

```text
销售路径太重；
人脉门槛高；
采购周期长；
落地风险大；
自己做出来也未必卖得出去。
```

## 12.2 先做自己能用的产品

当前优先做：

> **自己可用、普通人也能用、可以公开推广、可以服务自己软件矩阵的善用。**

## 12.3 第一版不做过重能力

第一版不做：

```text
自动点击；
自动填写；
复杂 UI Automation；
复杂 OCR；
浏览器插件；
RPA；
企业权限；
高合规审批；
行业专家库；
完整语音系统。
```

第一版先做：

```text
桌面悬浮；
任务步骤；
简笔线框图；
原截图可选；
聚焦导航图；
我迷路了；
卡点问答；
善用包保存与播放。
```

# 十三、给下一次讨论的提醒

后续讨论应优先围绕产品定位推进，而不是过早陷入技术细节。

优先讨论顺序：

```text
1. 善用的第一目标用户是谁？
2. 善用第一版最小任务是什么？
3. 善用的第一条自举旅程是什么？
4. 善用包的数据结构如何服务定位？
5. 桌面悬浮端最小界面如何让用户不迷路？
6. AI 线框生成器什么时候接入？
7. 善用如何服务用户自己的软件和自己的 IP 产品矩阵？
```

---

## 冻结总句

> **善用不是教程平台，也不是 RPA，更不是普通 AI 问答。它是一个桌面悬浮式软件任务陪跑系统：当用户拿到新软件不知道怎么用时，善用悬浮在软件旁边，用原截图、简笔线框图、聚焦导航、步骤说明、卡点问答和迷路恢复，带用户完成一个真实任务。后台可由 OCGS 指导，但前台必须讲人话：新软件不会用？善用一步步带你用起来。**

## 0. 本文档定位

本文档用于记录本轮关于“善用”产品的阶段性推导结果。

“善用”已从早期的企业级“专家能力化系统 / 深导”方向，收缩为一个更适合当前资源条件、可自用、可大众化、可先独立开发的产品：

> **善用，是一个基于 OCGS 的桌面悬浮式软件任务陪跑系统。它悬浮在目标软件或 Web 页面上方，通过场域匹配、AI 生成的聚焦线框图、原软件截图、步骤门禁、迷路恢复和受控问答，帮助用户不来回切教程，也能一步步完成新软件里的真实任务。**

它不是大 B 投标系统，不依赖人脉销售。  
它首先应服务用户自己、独立软件作者、小团队、AI 工具用户，以及用户未来所有自研软件的上手引导。

## 1. 产品命名与定位冻结

### 1.1 产品名

```text
善用
```

### 1.2 一句话定位

```text
善用：悬浮在软件旁边，一步步带你把新软件用起来。
```

### 1.3 更完整定位

```text
善用，是一个桌面悬浮式软件任务陪跑系统。
它不直接控制目标软件，而是悬浮在目标软件或网页上方，
通过步骤引导、场域线框、视觉锚点、卡点问答和迷路恢复，
帮助用户完成一个真实软件任务。
```

### 1.4 关键差异

善用不是：

```text
软件教程平台；
截图教程工具；
视频课程；
知识库；
AI 聊天机器人；
RPA 自动点击工具；
企业大投标系统。
```

善用是：

```text
软件任务陪跑系统；
桌面悬浮式场域导航系统；
新软件首次成功任务引导器；
软件使用旅程包播放器；
AI 辅助生成软件引导包的工具。
```

## 2. 从“企业专家能力化”收缩到“善用”的原因

原方向“深导 / 企业专家能力化通用系统”有很强的战略价值，但存在现实销售难题：

```text
大 B 客户进入难；
投标周期长；
需要人脉、关系链和行业资源；
政务、税务、银行、电信等场景采购复杂；
产品即使做出来，也可能卖不进去。
```

因此当前阶段应改为：

```text
先做自己可以用、普通用户也可以用的轻产品；
先解决“一个人拿到新软件不会用”的普遍问题；
先做桌面端悬浮引导，不做大 B 深度集成；
先形成可传播、可演示、可自证的产品。
```

善用与深导的关系：

```text
深导：总思想 / 专家能力化方向
善用：软件使用场景下的轻量落地产品
善办：窗口/业务办理场景的行业版可能
成师：企业专家能力化场景的通用版可能
```

当前优先级：

```text
先做善用；
后续再把善用纳入深导体系。
```

## 3. 核心使用场景

### 3.1 用户拿到新软件后不会用

用户痛点不是“不知道这个软件有哪些功能”，而是：

```text
不知道从哪里开始；
不知道第一步点哪里；
不知道当前页面对不对；
不知道按钮在哪里；
不知道字段怎么填；
遇到异常不知道怎么办；
完成一步后不知道下一步是什么。
```

善用要解决的不是“学会整个软件”，而是：

> **带用户完成第一个有价值的任务。**

### 3.2 第一批适合场景

```text
AI 工具上手：ChatGPT、Cursor、Claude、Kimi、豆包等；
AI 编程工具上手：打开项目、修改功能、修复报错、检查修改；
个人效率工具：笔记软件、剪辑软件、数据库工具、项目管理工具；
用户自研软件：每个软件都配善用包；
独立软件作者：用善用包降低用户客服成本。
```

### 3.3 第一批推荐样板

优先样板：

```text
善用 Cursor：让用户完成第一个 AI 编程任务。
```

可选任务：

```text
1. 打开项目根目录；
2. 让 AI 读懂项目结构；
3. 修改一个小功能；
4. 修复一个报错；
5. 修改后检查结果；
6. 防止 AI 乱改文件。
```

## 4. 产品形态冻结：桌面悬浮端 + 云端能力库

### 4.1 为什么不是纯 Web 端

纯 Web 端需要用户在指导页面与目标软件之间来回切换，体验差。善用应贴着用户真实操作场景。

```text
Web 教程模式：看教程 → 切窗口 → 操作软件 → 再切回教程。
善用悬浮模式：看提示 → 同视野操作 → 卡住就问。
```

### 4.2 产品架构

```text
善用桌面端
  - 悬浮显示
  - 目标窗口绑定
  - 步骤播放
  - 场域线框渲染
  - 原截图/简笔图显示
  - 用户反馈记录
  - 本地缓存

云端能力库
  - 善用包存储
  - 旅程包版本
  - AI 问答接口
  - AI 线框生成器
  - 卡点统计
  - 模板市场
  - 账号与授权
```

### 4.3 技术路线建议

```text
桌面端：Delphi VCL
界面渲染：WebView2 / 原生绘制混合
本地缓存：SQLite
云端数据库：PostgreSQL
云端 API：统一旅程包、AI、卡点、账号接口
悬浮层：TopMost / Layered Window / Transparent Overlay
目标窗口匹配：进程名 + 窗口标题 + 用户手动选择
```

第一版不做：

```text
自动点击；
自动填写；
复杂 UI Automation；
复杂 OCR；
浏览器插件；
企业权限；
RPA；
多人协作。
```

## 5. 核心概念：善用包

善用的长期资产不是代码，而是“善用包”。

### 5.1 善用包定义

```text
善用包 = 一个软件的一组任务旅程 + 场域图 + 步骤说明 + 视觉锚点 + 卡点问答 + 迷路恢复。
```

例如：

```text
Cursor 善用包
ChatGPT 善用包
剪映善用包
Notion 善用包
Excel 善用包
某自研软件善用包
```

### 5.2 善用包对象结构

```text
GuidePackage
  ├─ SoftwareProfile      软件信息
  ├─ TaskJourney          任务旅程
  ├─ FieldScene           场景/场域
  ├─ SceneVisual          场域视觉投射
  ├─ VisualAnchor         视觉锚点
  ├─ StepInstruction      步骤指令
  ├─ AccessGate           步骤门禁
  ├─ RouteRule            路由规则
  ├─ Feedback             反馈
  ├─ LostRecovery         迷路恢复
  └─ Trace / Evidence     卡点与执行记录
```

## 6. 原截图、简笔图与 AI 线框生成器

### 6.1 重要修正

善用不一定必须使用原软件截图。

可以使用：

```text
原软件截图；
AI 生成的线框图；
人工绘制的相对位置框线图；
整体简笔图 + 局部截图的混合图。
```

核心不是还原真实 UI 细节，而是：

> **还原用户当前所在场域、相对位置、关键入口和下一步操作，避免用户迷路。**

### 6.2 SceneVisual 抽象

不要把底层对象命名为 Screenshot，而应命名为：

```text
SceneVisual
```

它可以有多种类型：

```text
ScreenshotVisual：原软件截图；
SketchVisual：简笔框线图；
FocusSketch：聚焦导航线框图；
RecoverySketch：迷路恢复线框图；
HybridVisual：混合图。
```

### 6.3 AI 线框生成器

模块名建议：

```text
善用场景抽线器
SceneWireframeGenerator
```

功能：

```text
上传/截取目标软件页面；
AI 识别页面结构；
AI 生成可编辑线框草图；
AI 生成候选锚点；
人选择当前步骤主锚点；
系统生成 FocusSketch；
人工校正后保存为 FieldScene。
```

注意：

```text
AI 生成的是 Draft，不是 Published。
必须经过人工校正、能力检查、路由测试、人工验收和封版。
```

## 7. 导航最小可见集

### 7.1 概念定义

新增核心概念：

```text
Navigation Minimal Visible Set
导航最小可见集
```

定义：

> **为了让用户完成当前步骤，必须被看见的最小视觉元素集合。**

善用线框图不追求完整复刻界面，而是只画出当前导航需要的部分。

### 7.2 为什么不完整复刻

完整复刻会带来：

```text
复杂度高；
用户看不出重点；
页面版本差异大；
隐私数据容易暴露；
制作成本高；
AI 容易误识别无关区域。
```

导航最小可见图只保留：

```text
当前要看哪里；
当前要点哪里；
当前要填哪里；
当前要避开哪里；
完成后应该看到什么；
迷路时如何回来。
```

### 7.3 FocusSketch

运行时默认给用户看：

```text
FocusSketch 聚焦线框图
```

不是 FullSketch。

FullSketch 可以用于制作端，FocusSketch 用于用户实际操作。

### 7.4 其它区域处理

无关区域可以：

```text
模糊；
弱化；
灰掉；
只画轮廓；
隐藏；
标注“暂时不用管”。
```

### 7.5 视觉语义

```text
红色：当前要点击 / 当前要操作
蓝色：当前要观察
黄色：风险提醒 / 不要乱点
绿色：成功标志
灰色：暂时不用管
紫色：可选路径
```

## 8. 善用的 OCGS 化理解

### 8.1 截图不是图片

```text
截图不是图片；
截图是场域原料。
```

### 8.2 线框图不是设计稿

```text
线框图不是设计稿；
线框图是场域投射。
```

### 8.3 红框不是标注

```text
红框不是标注；
红框是用户要通过的门。
```

### 8.4 “已完成”不是翻页

```text
用户点击“已完成”不是翻页；
而是通过一道 AccessGate。
```

### 8.5 “我迷路了”不是普通反馈

```text
“我迷路了”不是普通反馈；
而是进入 LostRecovery 路由。
```

## 9. 用 OCGS-d 8 步流程指导善用开发

善用开发必须遵守 OCGS-d 的“先定门，再造能；先验能，再配路；最后人测封版”的开发秩序。

### Step 1：讨论门禁 / 倒推设计

从 Output 倒推。

示例 Output：

```text
用户成功创建第一个 FocusSketch，并能在善用悬浮端播放。
```

需要倒推：

```text
宝物是什么？
最后一道门是什么？
用户在哪个场域里？
需要哪些视觉锚点？
用户如何进入下一步？
用户迷路时如何回来？
哪些路径禁止？
哪些操作需要记录？
正常/阻挡/异常路径是什么？
```

### Step 2：生成能力

第一批能力：

```text
创建 GuidePackage；
创建 SoftwareProfile；
创建 TaskJourney；
上传/截取截图；
AI 识别页面结构；
AI 生成线框草图；
编辑 FieldScene；
渲染 FocusSketch；
创建 VisualAnchor；
绑定 StepInstruction；
配置 LostRecovery；
播放任务旅程；
记录卡点；
云端同步。
```

### Step 3：能力检查

新增善用专用检查规则：

```text
SV-01：每个 Step 必须有一个 PrimaryFocusAnchor；
SV-02：FocusAnchor 不得超过 3 个，避免视觉过载；
SV-03：每个 FocusSketch 必须有 ContextFrame；
SV-04：每个 FocusSketch 必须有 ExpectedResult；
SV-05：每个 Step 必须有 LostRecovery；
SV-06：Muted 区域不得覆盖 FocusAnchor；
SV-07：FocusAnchor 必须绑定 StepInstruction；
SV-08：用户点击“我迷路了”必须有 RouteRule；
SV-09：每条 TaskJourney 必须能走到 Output；
SV-10：每个 FieldScene 必须至少有一个 SceneVisual。
```

### Step 4：生成解释器

善用需要的轻量解释器：

```text
GuidePackageResolver；
TaskJourneyResolver；
FieldSceneResolver；
SceneVisualResolver；
FocusProjectionResolver；
VisualAnchorResolver；
StepInstructionResolver；
RouteResolver；
FeedbackResolver；
LostRecoveryResolver；
QuestionResolver；
TraceRecorder。
```

### Step 5：路由配置

路由不写死。

```text
已完成 → 下一 Step；
我迷路了 → LostRecovery；
我找不到按钮 → AnchorExplain；
页面不一样 → VersionMismatchHelp；
我想跳过 → SkipPolicy；
我想重来 → RestartTask；
AI 线框生成失败 → ManualSketchEditor。
```

### Step 6：测试门禁路由

测试重点：

```text
任务能否从开始走到 Output；
每个“我迷路了”是否有恢复路径；
每个 FocusAnchor 是否能被渲染；
每个 Route 是否有 Fallback；
AI 生成失败时能否进入人工绘制；
线框图能否被用户理解。
```

### Step 7：人工测试

人工测试问：

```text
用户看图后能否在 3 秒内说出要点哪里？
用户能否在 5 秒内找到真实软件对应区域？
用户是否被无关区域干扰？
用户看不到目标时，能否通过“我迷路了”回来？
用户是否觉得善用是在帮助他，而不是增加负担？
```

### Step 8：封版

封版对象：

```text
GuidePackage 版本；
SoftwareProfile 版本；
TaskJourney 版本；
FieldScene 版本；
SceneVisual 版本；
VisualAnchor 版本；
StepInstruction 版本；
RouteRule 版本；
Feedback 版本；
TestReport；
HumanTestReport。
```

## 10. 第一版开发顺序建议

### Phase 0：数据模型与本地播放器

```text
GuidePackage JSON；
TaskJourney；
FieldScene；
SceneVisual；
VisualAnchor；
StepInstruction；
RouteRule；
Feedback；
LostRecovery。
```

### Phase 1：简笔框线图编辑器

先不接 AI。

```text
画矩形；
设置颜色语义；
设置标签；
绑定步骤；
保存 JSON；
运行时渲染。
```

### Phase 2：桌面悬浮播放器

```text
绑定目标窗口；
悬浮显示当前步骤；
显示 FocusSketch；
显示操作说明；
支持已完成 / 我迷路了 / 我找不到按钮；
本地记录卡点。
```

### Phase 3：AI 线框草稿生成器

```text
上传/截取截图；
AI 识别布局；
AI 生成候选区域；
AI 生成 FocusSketch 草稿；
人工校正。
```

### Phase 4：受控问答

```text
基于当前软件、任务、步骤、Anchor、LostRecovery 回答用户问题；
不允许自由乱答；
未覆盖问题进入“建议人工补充”。
```

### Phase 5：云端同步与善用包市场

```text
云端存储善用包；
版本更新；
模板下载；
卡点统计；
软件作者后台。
```

## 11. 当前冻结句

> **善用不是把软件页面完整画出来，而是把当前步骤需要通过的“门”画出来；其它部分可以模糊，只保留帮助用户定位的最小场域。**

> **善用不是做截图教程，而是用 AI 把软件页面抽象成可治理的场域线框，再悬浮在真实软件旁边，引导用户一步步完成任务。**

> **善用第一版应优先做“简笔框线图编辑器 + 桌面悬浮播放器”，AI 线框生成器作为第二阶段加入。**

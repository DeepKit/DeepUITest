## 1. 方法层冻结：AI 主导用户选择

### 1.1 新流程原则

```text
AI 不抢答。
AI 不直接生成完整方案。
AI 不要求用户一次性讲清完整需求。

AI 作为主持人：
  1. 提炼当前阶段最关键的问题；
  2. 给出 A/B/C/D 选项；
  3. 说明每个选项的后果；
  4. 给出主持建议；
  5. 用户选择或修正；
  6. AI 记录选择；
  7. AI 根据选择进入下一问。
```

### 1.2 人类的角色

人类不需要一次性写 PRD。

人类主要做：

```text
1. 选择；
2. 修改选项；
3. 否定错误方向；
4. 补充真实业务细节；
5. 确认冻结内容；
6. 判断哪些定位最重要；
7. 批准进入下一阶段。
```

### 1.3 AI 的角色

AI 作为 OCGS 开发主持人，主要做：

```text
1. 主持；
2. 提问；
3. 给选项；
4. 解释选项；
5. 记录决策；
6. 倒推门禁；
7. 生成草图；
8. 组织流程；
9. 防止抢答；
10. 防止讨论跑偏。
```

## 2. 与 OCGS-d 的关系

OCGS-d 的 8 步流程为：

```text
1. 讨论门禁
2. 生成能力
3. 能力检查
4. 生成解释器
5. 路由配置
6. 测试门禁路由
7. 人工测试
8. 封版
```

本流程重点补充的是第 1 步“讨论门禁”的操作方式：

```text
讨论门禁
  不再是自由聊天；
  而是 AI 主持式选择题流程。

AI 提问
  ↓
人类选择
  ↓
AI 记录
  ↓
AI 继续倒推
  ↓
形成门禁草图
  ↓
进入生成能力
```

## 4. 当前演示对象记录：深启 DeepLaunch

### 4.1 软件名称修正

原 2KeyRun 已更名为：

```text
深启 DeepLaunch
```

### 4.2 软件新增能力

```text
DeepLaunch 不仅支持程序快速启动，还支持工作流启动。
```

### 4.3 本次演示暂不把“工作流启动”作为第一宝物

主持判断：

```text
第一条任务应尽量简单，让用户先理解：
  一个格子 / 一个单键 / 一个程序 / 一个快速启动入口。

工作流启动作为第二阶段进阶宝物。
```

## 5. 当前案例宝物 Output

### 5.1 宝物定义

```text
OutputKey:
  deeplaunch.grid.program_binding.ready

OutputName:
  一个程序已经成功绑定到 DeepLaunch 的某个格子和单键，并可快速启动
```

### 5.2 宝物描述

```text
用户把一个外部可执行程序，与 DeepLaunch 中的某个格子 / 单键建立关联。
完成后，用户可以通过双击格子、键入单键，或右键菜单快速启动该程序。
```

### 5.3 FinalState

```text
1. 某个格子已绑定程序路径；
2. 可选参数已保存；
3. 格子名称已生成或手动设置；
4. 图标已自动获取；
5. 用户能通过双击格子或单键启动程序；
6. 如果支持右键菜单启动，也可通过右键菜单启动。
```

### 5.4 RiskLevel

```text
L1：低风险配置，可撤回。
```

原因：

```text
它修改的是 DeepLaunch 的本地配置，不是高风险不可逆操作。
```

## 6. 当前案例两条路径

### 6.1 路线 A：右键编辑路线

```text
打开 DeepLaunch
  → 进入格子区域
  → 选择一个空格子
  → 右键菜单 - 编辑
  → 打开编辑窗体
  → 绑定一个程序路径和参数
  → 可选：设置名称
  → 图标自动获取
  → 保存
  → 双击格子 / 键入单键
  → 成功启动程序
```

### 6.2 路线 B：拖拽快速路线

```text
从外部拖动一个可执行文件
  → 放到 DeepLaunch 的某个格子
  → 系统自动绑定程序路径
  → 自动获取图标和名称
  → 用户双击格子 / 键入单键
  → 成功启动程序
```

### 6.3 主持判断

```text
主演示路线：
  路线 A：右键编辑绑定程序

补充演示路线：
  路线 B：拖拽 exe 到格子快速绑定
```

理由：

```text
路线 A 有更多可教学节点，更能体现善用的价值。
路线 B 太快，适合展示“更快方式”，但不是第一主线。
```

## 7. 路线 A 的初步 AccessGateTree

```text
AppGate：启动 DeepLaunch
  ↓
MainField：进入主界面 / 格子区域
  ↓
GridCellGate：选择一个空格子
  ↓
ContextMenuGate：打开右键菜单
  ↓
EditGate：点击“编辑”
  ↓
EditFormField：进入编辑窗体
  ↓
ProgramPathGate：选择 / 填写程序路径
  ↓
ParameterGate：填写可选参数
  ↓
NameGate：可选设置名称
  ↓
SaveGate：保存配置
  ↓
LaunchVerifyGate：双击格子或键入单键
  ↓
Output：程序成功快速启动
```

---

## 8. 路线 B 的初步 AccessGateTree

```text
AppGate：打开 DeepLaunch
  ↓
MainField：进入格子区域
  ↓
DragSourceGate：在外部找到 exe 文件
  ↓
DropTargetGate：拖到空格子上
  ↓
AutoBindGate：DeepLaunch 自动绑定路径、名称、图标
  ↓
LaunchVerifyGate：双击格子或键入单键
  ↓
Output：程序成功快速启动
```

## 9. 已冻结的主持判断

```text
1. 演示软件采用“深启 DeepLaunch”，不再使用旧名 2KeyRun。
2. 第一演示宝物是：让一个程序与某个格子 / 单键建立关联，并能快速启动。
3. 路线 A“右键编辑绑定程序”为主路径。
4. 路线 B“拖拽 exe 到格子”为补充路径。
5. 工作流启动不进入第一条宝物，作为第二阶段进阶宝物。
6. 善用应以 DeepLaunch 这个具体软件演示“悬浮式软件任务陪跑”。
7. 后续讨论采用 AI 主导用户选择式流程。
```

## 11. 下一问候选：第一道门在哪里？

### 选项 A：第一道门是用户在善用里选择“深启 DeepLaunch 入门善用包”

```text
适合完整善用流程。
用户先打开善用，再由善用引导打开 DeepLaunch。
```

路径起点：

```text
善用 AppGate
  → 选择 DeepLaunch 善用包
  → 选择任务“绑定第一个程序”
  → 引导打开 DeepLaunch
```

### 选项 B：第一道门是用户已经打开 DeepLaunch 并看到格子区域

```text
适合快速演示。
省略善用自身选择过程，直接展示悬浮指导如何带用户操作 DeepLaunch。
```

路径起点：

```text
DeepLaunch 已打开
  → 善用识别/绑定窗口
  → 开始指导格子操作
```

### 选项 C：第一道门是用户在 DeepLaunch 中进入“格子区域”

```text
适合假设 DeepLaunch 已打开，但用户还不知道格子区域在哪里。
```

路径起点：

```text
DeepLaunch 主界面
  → 找到格子区域
  → 选择空格子
```

### 主持建议

```text
建议选择 A。
```

理由：

```text
A 最能展示善用完整价值：
  先选善用包；
  再选任务；
  再绑定目标软件窗口；
  再进入悬浮指导。
```

但如果目标是短视频快速演示，可以选择 B。

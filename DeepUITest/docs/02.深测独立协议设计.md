# 深测独立协议设计

## 1. 独立性声明

深测独立于 DeepGuide Journey Protocol，拥有自己的测试配置协议。

## 2. 测试配置模型核心对象

`
TestSuite
   TestCase[]
         UIElement[]
         Action[]
         Assertion[]
         Result
`

## 3. 对象定义

### TestSuite

一组测试用例的集合，绑定目标软件和版本。

字段：name, target_app, target_version, test_cases[], created_at, tags[]

### TestCase

操作序列 + 预期断言。

字段：id, title, steps(Action[]), assertions(Assertion[]), preconditions, priority

### UIElement

UI 元素定位，支持多种定位策略：

- 控件名（Name）
- 类名（ClassName）
- 坐标（Position）
- 图像特征（ImageMatch）

字段：id, locator_type, locator_value, fallback_locators[]

### Action

操作类型：
- 点击（Click）
- 输入（Input）
- 等待（Wait）
- 拖拽（Drag）
- 快捷键（Hotkey）
- 菜单选择（MenuSelect）

字段：type, target(UIElement), value, timeout, description

### Assertion

状态检查类型：
- 可见性（Visible/Hidden）
- 文本内容（TextEquals/TextContains）
- 启用状态（Enabled/Disabled）
- 位置（Position）
- 颜色（Color）

字段：type, target(UIElement), expected_value, tolerance

### Result

红绿灯机制：
-  green = 通过
-  yellow = 警告（非关键断言未满足）
-  red = 失败

## 4. 红绿灯机制

- 每个 TestCase 独立产生红绿灯结果
- TestSuite 汇总：全绿=通过，有黄=警告，有红=失败
- 汇总结果取最严重级别

## 5. Bug 记录格式

Bug 记录关联：
- 失败的 TestCase ID
- 截图（失败时刻）
- 环境信息（OS、分辨率、目标软件版本）
- 复现步骤（从 Action 序列自动生成）

## 6. AI 辅助生成

流程：输入开发文档/代码  AI 生成 TestCase 草稿  人工校正  纳入 TestSuite

AI 生成范围：Action 序列、Assertion 预期值、UIElement 定位建议

## 7. 后续可选集成 Journey Protocol

- 从旅程包的 Gate/Card 自动生成 UI 测试用例
- Gate  TestCase 入口条件
- Card 操作  Action 序列
- Route 条件  Assertion
- 此为可选集成，不影响深测独立运行

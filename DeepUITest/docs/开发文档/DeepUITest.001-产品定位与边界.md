# DeepUITest.001 - 产品定位与边界

> 状态：开发文档初版
> 用途：冻结深测第一阶段的产品定位、范围、边界和战略节奏

---

## 1. 产品名

```text
中文名：深测
英文名：DeepUITest
```

---

## 2. 一句话定位

```text
深测 DeepUITest 是面向 Windows 桌面程序，尤其是 Delphi VCL / FMX 项目的 UI 行为 Mock / 回归测试系统。
```

更工程化的表达：

```text
深测把桌面软件的关键行为链，变成可配置、可回放、可断言、可诊断、可学习、可封版的质量资产。
```

对外口语表达：

```text
AI 帮你改代码；深测帮你确认旧行为有没有坏。
```

---

## 3. 第一阶段定位

第一阶段采用混合定位：

```text
自用基础设施 + OCGS 样板工程
```

含义：

```text
1. 短期不急于商业化。
2. 不做大而全测试平台。
3. 先服务 DeepLaunch、GuidedUse、UniBase / DeepBase 等自研桌面软件。
4. 同时证明 OCGS 的行为链质量治理闭环。
5. 第二阶段再包装为 Delphi / VCL / FMX 开发者工具。
```

---

## 4. 支持范围

第一阶段支持：

```text
1. Windows 桌面程序
2. Delphi VCL
3. Delphi FMX on Windows
4. UI 行为 Mock / 回归测试
5. 配置端 Designer 与测试端 Runner 共享数据库
```

暂不支持：

```text
1. Web 自动化测试
2. 移动端测试
3. 接口测试
4. 性能测试
5. 安全测试
6. 企业级测试管理大平台
7. 大规模批量回归平台
8. 完整 CI/CD 平台
```

---

## 5. 核心区别

普通 UI 自动化工具常关注：

```text
点击按钮
输入文本
等待窗口
截图对比
脚本回放
```

DeepUITest 关注：

```text
用户要拿到什么 Output
必须通过哪些 Gate
动作是否真的执行
状态是否真的显现
断言是否足够强
失败是否能定位到门 / 步骤 / 断言 / 环境
版本是否可以封版
```

冻结句：

```text
DeepUITest 不是测按钮有没有点到，而是测用户能力链是否还能抵达宝物。
```

## 6. 产品形态

```text
1. DeepUITest Designer
   配置端，负责项目登记、代码/文档索引、测试配置创建、红绿灯审核、失败诊断查看。

2. DeepUITest Runner
   测试端，负责读取配置、执行行为链、采集证据、执行断言、写入结果。

3. DeepUITest DB
   共享数据库，保存项目、版本、测试链、断言、Runner 结果、灯色、Bug、HumanDecisionLog。

4. DeepUITestProbe.exe
   内置测试靶子程序，用于构造稳定可断言的启动目标。

5. AI 配置生成器
   后续模块，读取文档 / 源码 / 历史 Bug，生成候选测试配置，不直接生成可信最终脚本。
```

---

## 7. 第一被测对象

第一阶段优先守住：

```text
DeepLaunch
```

理由：

```text
1. 行为链短。
2. 风险低。
3. 价值直观。
4. OCGS 元素完整。
5. 便于演示。
6. 便于沉淀第一批 Bug 模式。
7. 便于复制到 GuidedUse 和 UniBase / DeepBase。
```

第一批三条命脉链：

```text
1. 已配置启动链：F1 + X -> 指定程序启动。
2. 配置生效链：绑定程序 -> 保存 -> F1 + X -> 指定程序启动。
3. F2 候选执行链：F2 -> 输入 / 转录 -> 1-9 候选 -> 执行 / 0 返回。
```

---

## 8. 禁止膨胀规则

第一阶段禁止：

```text
1. 不做万能 UI 自动化平台。
2. 不做完整测试管理系统。
3. 不做复杂企业权限。
4. 不做全自动可信 AI。
5. 不做大而全数据库。
6. 不把 Bug 库做成人工维护负担很重的知识库。
7. 不用 DeepUITest 拖慢 DeepLaunch / GuidedUse 主产品开发。
```

推进原则：

```text
主产品开发一条关键能力，深测补一条关键行为链。
```

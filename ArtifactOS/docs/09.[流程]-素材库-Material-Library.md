# 09 结构化素材库

> 系统编号：②
> 核心职责：素材的原子化录入、标签管理和引用复用
> 设计来源：Rahel Bailie「结构化复用」、Contentele「内容原子模型」

---

## 一、设计理念

### 1.1 核心问题

传统素材管理是"文件夹+标签"模式——素材散落在不同位置，使用时靠记忆搜索，复用靠手动复制粘贴。这导致：

- **找不着**：记得读过但不知道存在哪里
- **重复收集**：不同时间收集了同一素材的不同版本
- **拷贝扩散**：复制粘贴到多篇文章后，修改一处不会同步到其他文章
- **保鲜失控**：过时的数据/案例还在被引用

### 1.2 核心原则

1. **素材是最小复用单元**：素材不是"一篇文章"，而是"一个内容原子"
2. **引用复用，不拷贝复用**：文章通过ID引用素材，草稿阶段可读取最新版本；定稿/发布后必须保留引用版本与渲染快照
3. **素材有保鲜期**：数据、案例、引用都有时效性，过期自动标记
4. **素材有情绪标签**：不只是主题分类，还有情绪色彩标记，方便写作时按情绪调性筛选
5. **素材是证据来源**：素材原子可以支撑 `EvidenceClaim`，必须保留来源、版本、保鲜期和反证状态
6. **证据变更可传播**：素材被证伪、过期或召回时，要能反查受影响的 ClaimGraph、契约、定稿和发布物

## 二、内容原子模型

### 2.1 原子类型

| 类型 | 说明 | 示例 | 平均长度 |
|------|------|------|---------|
| `argument` | 论点/观点 | "编程的本质是抽象，写作的本质也是抽象" | 1-3句 |
| `case` | 案例/故事 | "王阳明龙场悟道的三个阶段" | 1-3段 |
| `data` | 数据/统计 | "2025年中国45岁以上转行率12.3%" | 1句 |
| `quote` | 引用/金句 | "写作是一种自我发现的行为" — Peter Elbow | 1句 |
| `analogy` | 类比/隐喻 | "学编程像学外语，语法是词汇表，算法是语法" | 1-2句 |
| `insight` | 个人洞察 | "我发现写文章和写函数的调试过程惊人相似" | 1-3句 |
| `hook` | 钩子/开头素材 | "35岁那年，我做了一个所有人都觉得疯了的决定" | 1-2句 |

### 2.3 保鲜期规则

| 保鲜期类别 | 默认有效期 | 到期处理 |
|-----------|-----------|---------|
| `evergreen` | 永不过期 | 每年复审一次 |
| `seasonal` | 6个月 | 到期标记为"待验证"，需人工确认后延期 |
| `time_sensitive` | 30天 | 到期自动标记为"已过期"，不再出现在筛选结果中 |

### 2.4 用量追踪

每个素材原子记录使用历史：

- `times_used`：被引用次数
- `used_in_contracts`：引用该素材的写作契约ID列表
- 复用价值 = `times_used` / `age_in_days`

高频复用的素材是"黄金原子"，应优先在写作契约中注入。

## 三、素材录入

### 3.1 录入方式

| 方式 | 说明 | 首期支持 |
|------|------|---------|
| 手动录入 | 在界面中填写原子结构 | ✅ |
| 快速捕获 | 浏览器插件/剪藏 → 一键生成原子草稿 | ❌（Phase 2） |
| 文章拆解 | 将已有文章自动拆解为原子 | ❌（Phase 4） |
| 对话提取 | 从聊天记录中提取有价值的原子 | ❌（Phase 5） |

### 3.2 录入最小字段

首期阶段，录入一个素材原子只需要填写：

```
必填：type, content, source.type
选填：tags.topic（至少1个）, freshness.category（默认evergreen）
```

其余字段系统自动填充默认值。

## 四、素材查询与筛选

### 4.1 查询维度

```
按主题：topic ∈ ["编程", "写作"]
按类型：type = "analogy"
按情绪：emotion ∈ ["震撼", "共鸣"]
按保鲜：freshness = "evergreen" AND verified
按用量：times_used ≥ 3（高频复用素材）
按关联：与写作契约中的主题关键词匹配
```

### 4.2 与写作契约的关联

当写作契约生成后，系统自动从素材库中匹配候选素材：

```
匹配算法（首期版本）：
1. 提取契约中的主题关键词
2. 在素材库中搜索 topic 标签匹配的原子
3. 按 情绪标签匹配度 × 保鲜状态 × 复用价值 排序
4. 返回 Top-N 候选素材
5. 策略门禁或人类确认后写入契约的 material_refs
```

## 五、引用复用机制

### 5.1 引用 vs 拷贝

```
❌ 拷贝模式（内容债务）：
  文章A ← 拷贝素材原文 ← 素材库
  文章B ← 拷贝素材原文 ← 素材库
  修改素材 → 文章A和B中的旧版本不一致 ✗

✅ 引用模式（ArtifactOS）：
  草稿A ← 引用 atom_id + version ← 素材库
  草稿B ← 引用 atom_id + version ← 素材库
  定稿/发布物 ← 保存 atom_id + version + rendered_snapshot
  修改素材 → 新草稿可读取新版本；已封存产出物不被静默改写 ✓
```

ODD约束：素材可以持续演进，但已通过质量门禁或已发布的产出物必须可回放当时使用的素材版本，不能因为素材库后来修改而失去证据链。

### 5.2 引用在契约中的表示

```json
{
  "material_refs": [
    {
      "atom_id": "atom_20260522_001",
      "atom_version": 1,
      "injection_point": "opening",
      "purpose": "作为开头的类比引入",
      "rendered_snapshot": null
    },
    {
      "atom_id": "atom_20260522_005",
      "atom_version": 2,
      "injection_point": "body_arg2",
      "purpose": "作为第二个论点的案例支撑",
      "rendered_snapshot": null
    }
  ]
}
```

### 5.3 渲染时展开

AI 写作引擎在组装上下文时，将 `material_refs` 中的原子ID和版本展开为实际内容注入上下文 Slot。写作产出物中保留原子ID、版本号和必要的 `rendered_snapshot`，便于追溯。

封存规则：

- 草稿阶段：`rendered_snapshot` 可为空，默认读取指定版本内容
- 定稿阶段：写入 `rendered_snapshot`，用于质量门禁和证据包
- 发布阶段：发布物引用定稿快照，不重新从素材库展开
- CTF阶段：素材原子被证伪、过期或召回时，引用该版本的 `ContentSpecSnapshot` 标记为 `stale/needs_review`
- ClaimGraph阶段：素材原子状态变化会传播到相关 `EvidenceClaim`，并触发反证或降置信度
- 召回阶段：若素材被证伪或过期，系统列出所有引用该版本的定稿/发布物，交人类决定是否召回

### 5.4 证据变更传播隔离

素材是证据来源，但证据变更不能默认造成全局雪崩。传播按隔离级执行：

| 隔离级 | 默认范围 | 触发条件 |
|--------|----------|----------|
| `isolated` | 当前任务或当前草稿 | 普通质量问题、低风险素材更新 |
| `strategy_unit` | 当前策略单元 + 时间窗口 | 默认级别，素材过期、来源补充、低中风险反证 |
| `account` | 当前账号全部策略单元 | 账号立场、账号禁区或长期事实基准变化 |
| `platform` | 某个平台全部相关内容 | 平台规则变化或平台风控反馈 |
| `global_review` | 进入全局影响分析，不自动召回 | 高风险事实错误、理论核心冲突、人类指定全局复审 |

传播规则：

- `EvidenceClaim` 依赖图默认按 DAG 校验，禁止循环支撑和循环反证
- 素材状态变化先生成影响分析，不直接改写已封存发布物
- 默认只标记 `stale/needs_review`，召回必须由红线规则或人类确认触发
- 发布物影响分析必须显示 `atom_id + atom_version + EvidenceClaim + strategy_unit + time_window`

### 5.5 素材版本更新传播

素材原子增加 `lineage` 字段，建模前驱-后继关系（§2.2）。原子永远不删除，只改 status。

**按文章状态的差异化处理**：

| 文章状态 | 系统动作 | 设计原则 |
|---------|---------|---------|
| **草稿**（drafting/reviewing） | 标记引用为 `stale`，提示有新版本可用，人类或策略决定是否更新到新版本 | 草稿未封存，引用仍是活的 |
| **已发布**（published/completed） | 标记为 `historical_data_superseded`，生成中性影响分析报告 | 已发布内容是历史记录——当时引用的数据是正确的，后来源数据被修正。这是中性的事实记录，不触发降权、不生成 CognitiveDisturbanceEvent、不影响策略评分、不追责 |
| **封存**（stored/frozen） | 标记为 `historical_data_superseded`，只记录 | 封存的含义是冻结，标注受影响是事实记录 |

**EvidenceClaim 反证传播**：素材 status→superseded 时，查找 `supported_claim_refs`，对应 EvidenceClaim 的 `falsification_status` 从 `supported` 降级为 `challenged`。传播范围按 `propagation_policy` 执行（默认 `strategy_unit`）。**仅对草稿和未发布内容触发**，已发布内容的 EvidenceClaim 不降级（历史断言在发表时刻是正确的）。

### 5.6 素材时效性检查

**Phase 1 最小方案**（素材 <200 个原子）：
- 录入时要求标注 `freshness.expires_at`（允许填"不确定"）
- 引用时展示距过期剩余天数，红色警告已过期素材
- 不建主动巡查系统

**Phase 3+ 扩展方案**（素材 ≥200 个原子）：
- 被动触发为主：每次引用时顺带检查 `expires_at`，零额外成本
- 主动巡查为辅：对高引用频次素材（`times_used > N`），按 `引用次数 × 距上次检查天数` 阈值触发批量巡检
- 数据修正与观点过时分开处理：数据修正是可验证事件（机器比对），观点过时是模糊判断（标记可疑 → 推送人工裁定）

## 六、素材质量规则

### 6.1 录入校验

| 规则 | 级别 | 说明 |
|------|------|------|
| 内容不为空 | ES | 素材原子必须有实际内容 |
| 类型合法 | ES | type 必须是7种原子类型之一 |
| 至少1个主题标签 | ES | 不能有没有主题分类的素材 |
| 长度合理 | 半ES | 按类型检查长度（如 data 不应超过3句） |
| 来源可追溯 | 半ES | 至少有 source.type |
| hash可比对 | ES | content_hash 必须能根据内容稳定计算 |

### 6.2 定期审计

- 每月：列出 `times_used = 0` 且 `age > 90天` 的素材，人工决定保留或归档
- 每季度：验证 `time_sensitive` 类型素材的数据是否仍然准确
- 每年：复审 `evergreen` 素材的长期有效性

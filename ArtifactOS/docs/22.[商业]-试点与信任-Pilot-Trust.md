# 22 商业化试点与信任规格

> 核心定位：首版 ArtifactOS 自用，但商业入口必须预留。商业化不是立刻卖大系统，而是把 SourcePack 诊断、影子运行和 30 天产出治理试点包装成可验证、可信任、可退出的服务化入口。

---

## 一、商业化证据阶梯

7 天影子运行只能证明内部运行可行性，不能证明市场成立。商业化证据按阶梯推进：

| 阶梯 | English Stage | 目标 |
|---|---|---|
| E0 | Internal Shadow Run | 自用 7 天影子运行，证明操作协议可跑 |
| E1 | Multi-Pack Dry Run | 2-3 个不同 SourcePack 干跑，证明通用装载 |
| E2 | Design Partner Pilot | 3 个设计伙伴试点，证明用户愿意投入材料和时间 |
| E3 | 30-Day Assisted Publishing | 30 天真实发布辅助，证明持续价值 |
| E4 | Paid Renewal Intent | 付费或续费意愿，证明商业价值 |

ArtifactOS 不把 E0 误当成市场成立。

---

## 二、最小商业 Offer

早期商业入口不是 SaaS 自助注册，而是受控试点包。

```text
SourcePack 诊断
  + 7 天影子运行
  + 30 天产出治理试点
```

### 2.1 交付物

| 交付物 | English Deliverable | 说明 |
|---|---|---|
| 源体系就绪报告 | SourceReadinessReport | 材料是否可装载、缺什么 |
| 源体系冲突报告 | SourceConflictReport | 哪些口径冲突、过期、敏感 |
| SourcePackManifest | SourcePackManifest | 可治理源体系清单 |
| 7 天影子运行报告 | ShadowRunReviewReport | 操作框架和偏差复盘 |
| 30 天产出计划 | 30-Day Artifact Plan | 每周主题、平台、产出形态 |
| 产出治理报告 | ArtifactGovernanceReport | 契约、门禁、版本、反馈 |
| 后续建议 | ContinuationRecommendation | 继续、暂缓、退出或扩展 |

### 2.2 适合购买者

- 理论型 / 方法论型个人 IP。
- 创始人驱动 B2B 公司。
- 专业服务机构。
- 高客单内容工作室。

### 2.3 不适合购买者

- 只想要爆款文案的人。
- 没有源体系的人。
- 强销售私域团队。
- 低价批量代写需求。
- 只想替代编辑、不愿整理源材料的团队。

## 四、替代方案地图

| 替代方案 | ArtifactOS 赢在哪里 | ArtifactOS 输在哪里 | 何时不该卖 |
|---|---|---|---|
| 普通 AI 写作工具 | 源体系、契约、证据、反馈闭环 | 上手更重 | 用户只要一次性文案 |
| ChatGPT Projects / 自建 GPT | 长期治理、门禁、事件账本 | 灵活闲聊不如直接聊天 | 用户只想个人临时助理 |
| Notion / Obsidian | 从知识到产出行动闭环 | 知识笔记体验不是重点 | 用户只想做知识管理 |
| 内容工作室 / 代写 | 可沉淀为用户资产 | 需要用户参与源体系整理 | 用户只想完全外包 |
| CMS / DAM | 源体系驱动生成和反馈反哺 | 不做企业内容资产管理全套 | 大企业要完整内容供应链 |
| 营销自动化 / CRM | 吸引信号结构化 | 不做接引成交 | 用户核心诉求是销售转化 |

## 五、Solo 与 Org 两种模式

### 5.1 个人片场模式

个人片场模式（Solo Studio Mode）默认隐藏复杂治理，只暴露：

- Amy 今日工作台。
- SourcePack 状态。
- 产出队列。
- 前夜审阅。
- 每日精选审阅。
- 7 天/30 天复盘。

六级会议仍在系统内部存在，但不要求个人用户逐层操作。

### 5.2 组织片场模式

组织片场模式（Org Studio Mode）打开：

- 年/半年/季/月/周/日 Case。
- 权限和审批。
- 多 SourcePack。
- 多账号、多平台。
- 多人协作和审计。
- 计划变更与边界变更。

## 六、商业信任规格

SourcePack 是用户思想资产、品牌资产和专业判断资产，因此商业化前必须预埋信任边界。

### 6.1 资产归属

- 用户拥有 SourcePack 原始材料和装载后的 Manifest。
- ArtifactOS 只保存运行所需结构和快照。
- 产出物版权按用户协议归属用户或组织。
- 系统不得把用户 SourcePack 用作其他客户默认模板。
- 用户的表达范本、反馈模式、运行证据和校正样本默认属于该用户或组织，不得跨客户复用。

### 6.2 数据隔离

- 所有核心表必须有 `tenant_id`。
- Phase 1 即使单用户，也必须写入 RLS 骨架。
- SourcePackSnapshot、Artifact、EventLedger、RecallCard 默认租户隔离。
- 跨租户学习默认禁止，除非未来有明确匿名化和授权机制。

### 6.3 导出与删除

商业客户必须能导出：

- SourcePackManifest。
- SourcePackSnapshot。
- Artifact。
- ArtifactVersion。
- PublicationPackage。
- EventLedger 摘要。
- ShadowRunReviewReport。

删除策略：

- 原始源文件可按用户要求删除。
- EventLedger 默认追加保留，但商业客户可要求隐私/安全删除。
- 删除必须生成删除记录（DeletionRecord），不能静默消失。

### 6.4 模型使用边界

- 用户 SourcePack 不用于训练公共模型。
- 高敏感 SourcePack 默认禁止发送到不合规模型端点。
- AI 输出不能自动成为证据。
- 人类确认和外部来源必须与 AI 假设分层保存。

## 七、定价假设

早期仅作为假设，不写入产品承诺：

| 包 | English Offer | 适用 |
|---|---|---|
| 诊断包 | Diagnostic Package | SourcePack 就绪度和冲突诊断 |
| 影子运行包 | Shadow Run Package | 7 天内部运行验证 |
| 试点包 | 30-Day Pilot | 30 天真实产出治理 |
| 托管包 | Managed Artifact Studio | Amy + 人类专家协助运营 |

定价不应按“生成多少篇文章”，而应按源体系治理、产出连续性、审校责任和运营节奏收费。

---

## 八、硬约束

1. 7 天自用影子运行不等于市场验证。
2. 商业试点必须先做 SourcePack 诊断。
3. 不服务没有源体系、只要模板文案的用户。
4. 不承诺爆款。
5. 不做私域成交系统。
6. 商业客户的 SourcePack 归客户所有。
7. 跨客户复用只能复用通用软件能力，不能复用客户源资产。
8. 试点失败也必须输出可交付诊断和退出建议。

# 15 Amy 工作台与准备动作协议

> 核心定位：Amy 总控台（Amy Cockpit）不是纯聊天产品，而是由 Amy 提前整理好的办公桌（Amy Desk）。常规事项点按钮处理，非常规事项才进入对话。

---

## 一、产品定位

人类不应该每天主动翻系统、找功能、查状态。Amy 应该像秘书一样，把今天需要看的文件、卡片、按钮和异常提前摆在办公桌前。

```text
Amy 总控台（Amy Cockpit）
  = Amy 办公桌（Amy Desk）
  + 工作托盘（Work Tray）
  + 工作卡（Work Card）
  + 准备动作面板（Prepared Action Panel）
  + 详情抽屉（Detail Drawer）
  + 对话窗口（Conversation Window）
```

核心原则：

> 常规工作由 Amy 提前整理成工作卡和按钮；非常规、模糊、跨对象的问题才进入对话。

Amy 工作台的目的不是让人类治理 AI，而是让人类用最少注意力推动源体系推广、合格产出物生产、质量校正和传播放大。后台的 AI 岗位、门禁、账本、状态机和能力注册只负责把复杂度压缩成可处理的工作卡。

Amy 是复杂治理结构的压缩器，不是聊天入口，也不是 AI 管理面板。案、会议、门禁、授权、事件账本、遗忘系统和投入复盘都在后台运行；人类日常只面对 Amy 压缩出的少量工作卡、日报、异常摘要、准备动作和必须裁决事项。

微信通道（Amy Weixin Channel）复用同一套准备动作协议，只是把按钮压缩成数字回复。

## 二、Amy Desk 技术选型

> **权威裁决见 docs/26（技术选型与运行时架构）。本节以 docs/26 为准。**

### 正式 Desk：Delphi VCL DeepShell

Amy Desk 正式前端使用 Delphi VCL + DeepBase DeepShell（参见 `docs/26.[技术]-技术选型与运行时架构-Stack-Decision.md` §1）。

- 主窗体继承 `TDeepMainForm`，通过 Service / Command / Provider 注入业务能力。
- 业务 UI 通过 Provider 注入，不从空 `TForm` 重复搭主界面基础设施。
- 长耗时任务不在 UI 线程同步执行。
- 可直接读写 PostgreSQL，但必须遵守命令表、状态表、RealPublishGate 和测试库隔离约束。

Desk / Engine 拆��：

```text
ArtifactOS.Desk   VCL DeepShell 主前端，人工启动 Engine
ArtifactOS.Engine Delphi 按需启动后端，活跃期间保持运行
ArtifactOS.Core   共享类型、PG contract helper、DB adapter、服务接口
```

### 诊断页面：Python amy_desk.py（过渡保留）

`backend/amy_desk.py` 提供基于浏览器的只读诊断页面，保留为开发调试和过渡用途，**不作为正式 Amy Desk 主交互**（参见 docs/26 §7）。

诊断页面入口：

```text
python amy_desk.py
-> http://127.0.0.1:8765/amy/today
```

诊断页面 URL：

| URL | 职责 |
|---|---|
| `/amy/today` | 今日 DayPlan / DaySubCase、发布卡片、验证状态 |
| `/amy/week` | 年会→周会→DayPlan 治理链概览 |
| `/amy/package?id=...` | 单个 PublicationPackage 详情、证据、手动触发 verify |
| `/amy/verify` | 待确认发布队列 |
| `/amy/accounts` | 平台账号浏览器面板：一个平台账号一个常驻浏览器 |
| `/amy/run` | 7 天 L3 real_publish 全绿面板 |

诊断页面不负责发布重试；发布失败重试属于 media_publish。

Amy Desk 的账号浏览器面板必须以 `(platform_id, account_id)` 展示运行态，而不是只按账号展示：

```text
zhihu/main       ready / busy / needs_login / risk_control
wechat/main      ready / busy / needs_login / risk_control
xiaohongshu/main ready / busy / needs_login / risk_control
```

人类查看、截图、刷新、关闭浏览器时，操作对象都是某个 `PlatformAccountSession / 平台账号会话`。同一账号在不同平台上的浏览器状态必须分开显示。

发布验证支持两种方式：

```text
自动验证：Amy Desk 调用 PublishedVerifier 访问 result_url，命中标题/正文则 published_confirmed。
人工验证：人类在 Package 页点击“打开发布链接”，确认页面可见后点击“人工确认已发布”。
```

人工确认不是绕过门禁；它只用于 URL 可访问但平台反爬或登录态导致自动 verifier 无法确认的情况。每次人工确认必须写入 `publish_verification_evidence.manual_mark`、`manual_marked_at` 和 `metadata.manual_verified=true`。

## 三、主界面结构

### 2.1 Amy 办公桌（Amy Desk）

Amy 办公桌是主界面第一屏。它不以菜单为中心，而以今日工作对象为中心：

```text
今日总览（Daily Overview）
Amy 今日办公桌（Amy Today Desk）
待决策（DecisionBrief Queue）
待审片（Artifact Review Queue）
异常中断（Interrupt Queue）
主动召回（Recall Queue）
每日精选审阅（Daily Calibration Review）
发布结果（Publication Result）
```

### 2.2 工作托盘（Work Tray）

工作托盘（Work Tray）只放 Amy 判断当前应进入人类视野的对象。它不是完整后台列表。

| 托盘（Tray） | 英文对象（English Object） | 内容（Content） |
|---|---|---|
| 今日待处理 | Today Tray | 今日案、今日子案、精选审阅 |
| 待审 | Review Tray | 批量审片、单产出物审阅 |
| 待决策 | Decision Tray | 决策简报、授权建议 |
| 异常 | Interrupt Tray | 红线、冻结、发布失败、越权 |
| 召回 | Recall Tray | 历史决策、失败教训、强信号 |
| 结果 | Result Tray | 发布结果、数据回收、日报周报 |

### 2.2a Amy 今日办公桌（Amy Today Desk）

Amy 今日办公桌是第一入口。它不展示完整后台对象，而是按人类注意力策略（HumanAttentionPolicy）和人类注意力预算（HumanAttentionBudget）整理今日事项。

| 区域 | English Area | 进入规则 |
|---|---|---|
| 必须我处理 | Must Review | 不处理会阻断发布、授权、红线处理或上层边界确认 |
| 建议我审阅 | Recommended Review | 不阻断流程，但适合沉淀校正范本或修正策略 |
| Amy 可自办 | Amy Can Handle | 已在授权策略内，默认自动处理并摘要汇报 |
| 等待结果 | Waiting / Monitoring | 已执行，等待发布验证、影子运行偏差或信号回收 |
| 异常与风险 | Exceptions / Risks | Unknown、越权、门禁失败、发布失败、证据缺口 |

任何工作卡进入 `Must Review` 都必须说明不处理后果；进入 `Amy Can Handle` 必须引用授权策略（DelegationPolicy）和介入策略（InterventionPolicy）。

默认注意力预算规则：

```text
每日 Must Review：目标 1-3 项；超过 3 项必须说明原因，超过 5 项视为注意力预算异常
每日 Recommended Review：最多 3 项
每日精选审阅：最多 1 项
晚间预计处理时长：15-30 分钟
```

注意力预算超额时，只有红线、SourcePack 主权、发布阻断和越权事项仍可提升为 `Must Review`；高价值但不紧急的事项降为 `Recommended Review` 或进入下次会议；低风险策略建议进入摘要；授权内事项由 Amy 自办并留痕；重复信号必须合并后再呈现。

### 2.3 详情抽屉（Detail Drawer）

工作卡默认只显示摘要和按钮。点击查看详情时，才展开详情抽屉：

```text
产出物预览（Artifact Preview）
版本差异（Version Diff）
门禁报告（Gate Report）
证据链（Evidence Chain）
召回来源（Recall Source）
发布包（PublicationPackage）
历史决策（Decision History）
```

### 2.4 对话窗口（Conversation Window）

对话窗口不是所有操作的起点，而是非常规操作的兜底：

- 按钮无法表达你的意图。
- 需要跨多张工作卡修改。
- 需要改变长期授权或策略。
- 需要解释为什么。
- 需要让 Amy 重新理解任务。

## 三、工作卡类型

Amy 办公桌默认只出现以下工作卡（Work Card）类型。

| 中文卡片 | English Card | 作用 |
|---|---|---|
| 今日总览卡 | DailyOverviewCard | 今天要做什么、哪些自动处理、哪些需要你看 |
| 今日子案卡 | DaySubCaseCard | 今天哪些主题行动、哪些不行动 |
| 批量审片卡 | ArtifactReviewBatchCard | 一批产出物是否发布、返工、暂存 |
| 单产出物卡 | ArtifactCard | 单篇文章、图文、视频的审阅和修改 |
| 决策简报卡 | DecisionBriefCard | Amy 必须请示你的事项 |
| 异常中断卡 | InterruptCard | 红线、冻结、发布失败、越权 |
| 主动召回卡 | RecallCard | 历史记录与当前事项相关 |
| 授权建议卡 | DelegationProposalCard | 建议提高或降低 Amy 自治程度 |
| 发布结果卡 | PublicationResultCard | 发布成功、失败、链接和后续复盘 |
| 每日精选审阅卡 | DailyCalibrationReviewCard | 每天 1 个建议认真审的产出物，用于系统校准 |
| 日报入口卡 | DailyReportEntryCard | 通过微信主动送达的日终摘要和完整日报入口 |

每张工作卡都必须提供：

```text
标题（Title）
摘要（Summary）
来源对象（Source Object）
推荐动作（Recommended Action）
准备动作面板（Prepared Action Panel）
详情入口（Detail Entry）
状态（Status）
优先级（Priority）
```

### 3.0a 质量结论呈现

Amy 不直接把完整质量报告推给人类。任何质量卡必须先压缩为：

```text
结论（Decision）：合格 / 不合格 / 可发布但低质量 / 高质量 / 冻结
原因（Why）：最关键的 1-3 个质量因子
风险（Risk）：源体系、事实、边界、平台、授权或发布包风险
动作（Action）：1-8 常用选项 + 9 重新生成 + 0 我来输入
影响预览（Impact Preview）：会改哪些产出物、部件、发布包或策略候选
```

`Qualified Artifact / 合格产出物` 与 `High Quality Artifact / 高质量产出物` 必须分开显示：

| 结论 | English | Amy 显示方式 |
|---|---|---|
| 合格 | Qualified | “可以进入发布安排”，并说明是否普通发布、暂存或抽检 |
| 高质量 | High Quality | “建议重点发布/认真审阅/沉淀为范本”，并说明传播放大理由 |

如果 `ArtifactPlan / 产出计划` 的 `primary_purpose_type / 主目的类型` 属于吸引、转发、概念种子或传播放大，Amy 必须显示 `ResonancePotential / 共鸣潜力` 是否达标；其他目的则只作为排序和优化指标显示。

### 3.1 日报详情页

日报详情页（DailyReportDetailView）是每日工作结束后的完整阅读面，适合手机和桌面打开。它由已存在的工作卡组成，而不是另外生成一套事实。

```text
日报详情页（DailyReportDetailView）
  -> 今日一句话结论（Executive Summary）
  -> 今晚必处理（Must Handle Tonight）
  -> 建议处理（Recommended）
  -> 可跳过（Optional）
  -> 今日完成事项（Completed Work）
  -> 已发布产出物（Published Artifacts）
  -> 未发布与返工项（Held / Reworked Items）
  -> 待决策（DecisionBrief Queue）
  -> 每日精选审阅（DailyCalibrationReview）
  -> 异常与风险（Interrupt / Risk）
  -> Amy 对明日的建议（Tomorrow Recommendation）
```

交付方式固定为：

```text
微信摘要入口（DailyReportEntryCard via Amy Weixin Channel）
  -> 打开日报详情页（DailyReportDetailView）
  -> 按工作卡处理或进入 Amy 对话
```

Phase 1 不提供邮件日报或邮件归档通道。

### 3.1a 日报详情页信息架构

日报详情页第一屏只放今晚真正需要处理的 1-3 项。其余工作卡折叠为“建议处理”和“可跳过”，避免把日报变成完整后台列表。

| 区域 | English Section | 规则 |
|---|---|---|
| 今晚必处理 | MustHandleTonight | 红线、明日特别文件、新案/边界案、需要人类确认的 NextDayPlan |
| 建议处理 | Recommended | 每日精选审阅、旧系统偏差解释、低风险返工建议 |
| 可跳过 | Optional | 普通发布结果、信息性召回、低优先级复盘 |
| 晚间提交 | EveningCommit | 汇总未处理项、已选动作和夜间自动处理范围 |

每张卡必须显示：

```text
处理要求（must_handle / recommended / optional / info_only）
预计耗时（estimated_minutes）
不处理后果（skip_effect）
当前状态（open / done / skipped / expired）
```

`EveningCommitCard` 在提交前必须提示：哪些必处理项未处理、哪些选项会触发夜间修正、哪些事项被跳过。人类可以一次性提交，Amy 再进入夜间处理。

## 四、每日精选审阅

### 4.1 定义

每日精选审阅（Daily Calibration Review）是 Amy 每天推荐给人类认真审阅的一个产出物（Artifact）。它不阻塞发布，目标是校准系统。

```text
发布审阅（Publish Review）问：这篇能不能发？
精选审阅（Calibration Review）问：这篇能不能代表我的判断？
```

### 4.2 选择逻辑

Amy 每天默认推荐 1 个产出物，除非当天没有合格候选，并必须说明没有推荐的原因。候选原因包括：

| 原因（Reason） | 含义（Meaning） |
|---|---|
| 高影响 | 将发布到核心账号或影响后续一批内容 |
| 高不确定 | 门禁分歧大、AI 自评不稳定 |
| 高代表性 | 能代表某个成熟案、平台或账号风格 |
| 高风险 | 理论显性高、易误读、边界敏感 |
| 高学习价值 | 新平台、新受众、新主题、新载体 |
| 高复用 | 后续多个产出物会参考它 |

### 4.3 默认流程

```text
候选产出物（Artifact Candidate）
  -> 每日精选审阅（DailyCalibrationReview）
  -> 人类选择（HumanReviewChoice）
  -> 校正范本（CalibrationExample）
  -> 保留模式库（RetainedPatternStore）
  -> 操作上下文包（OperationContextPack）
  -> 后续生成、门禁、改写、授权建议
```

### 4.4 校正规则

1. 每天最多推荐 1 个。
2. 默认每天推荐 1 个；没有推荐时必须记录 `no_candidate_reason`。
3. 不审不阻塞发布，但跳过必须记录 `skip_reason`。
4. 卡片必须显示“为什么选它”“建议审哪里”“预计耗时”。
5. 审了必须记录选择。
6. 范本必须区分正向、反向或混合。
7. 范本必须有适用范围。
8. 范本不能直接修改 SourcePack。
9. 范本影响后续系统时必须留下影响记录。
10. Amy 可以建议提高范本权重，但不能把一次审阅静默升级为长期规则。

### 4.4a 连续跳过精选审阅的应对策略

若每日精选审阅连续被跳过超过 5 天，Amy 不应继续推送相同策略的选择。必须执行以下调整：

```text
1. 降低首选按钮置信度 —— 将推荐动作从 '每日推荐' 降为 '建议审阅'
2. 切换到高分高不确定候选 —— 优先推送门禁分数高但 AI 自评不稳定、风险调和度低的产出物
3. 增加推荐理由强度 —— 在卡���说明 "这篇可能产生范本价值" 而非 "这篇代表性强"
4. 在日报中加注跳过趋势 —— DailyReport 摘要中显示 "最近 N 天未完成精选审阅"
5. 满 10 天仍未审时，暂停推送并记录 paused_due_to_skip_pattern
```

### 4.4b 每日页面流转

用户每天的交互不经过传统菜单，而是按以下顺序流转：

```text
Amy Today Desk（按注意力预算过滤今日事项）
  -> 打开第一张 Must Review 工作卡
  -> 点详情抽屉看完整门禁/证据/版本 diff
  -> 用 1-8/9/0 准备动作面板做选择
  -> 或按 0 进入自然语言对话 -> 系统生成 RevisionIntent + 四层影响预览 + 准备动作按钮
  -> 返回 Today Desk
  -> 晚上打开日报详情页（DailyReportDetailView）
  -> 审 YesterdayCompletions / TomorrowPublishReview / EveningCommit
```

日报详情页与 Amy Today Desk 的职责分离不允许合并：日报详情页是纵向深度审阅面（按时间线汇总当日所有已完成/异常/明日待审的工作卡），Today Desk 是横向广度总览面（按优先级展示当前时刻待处理事项）。两者过滤器粒度不同，时间锚点不同，合并成单页会让用户失去"当前时刻"的焦点。

### 4.4c 批量总编台容量

批量总编台（Artifact Review Desk）一次处理的产出物建议不超过 8 个。超过 8 个时，Amy 必须按片场或风险分组拆为多个子批次，每个子批次独立展示：推荐分组、风险分组、平台/账号列、门禁列、差异预览和例外项。整个片场的批量动作必须先生成 `BatchActionProposal / 批量动作提案`。

准备动作协议（Prepared Action Protocol）是 Amy 总控台、微信通道、移动端和未来语音端共享的选择规则。

### 5.1 两类操作

| 类型 | English Object | 用途 |
|---|---|---|
| 直接按钮 | Direct Action Button | 查看、展开、进入审阅、打开详情等低风险操作 |
| 编号选项面板 | Numbered Option Panel | 需要人类选择处理方案的操作 |

直接按钮可以没有编号；编号选项必须遵守十键规则。查看、展开、解释原因、打开详情、筛选列表等不改变业务状态的动作，不得占用 `1-8` 编号槽位。

### 5.2 十键规则

```text
1-8 = 常用选项（Prepared Options）
9   = 重新生成（Regenerate）
0   = 我来输入（Human Input）

固定按钮：
[返回上一级 Back]
[取消当次 Cancel Current]
```

### 5.3 编号槽位语义

`1-8` 是常用动作槽位，不是全系统固定动作。不同工作卡由 Amy 根据上下文填充，但语义应保持稳定。

| 编号 | 槽位原则 |
|---|---|
| `1` | Amy 推荐动作（Recommended Action），必须附推荐理由 |
| `2-3` | 最常见替代方案（Common Alternatives） |
| `4-5` | 修改、收缩、换角度、改变执行方式（Revision / Reframing） |
| `6` | 暂存、跳过、延后或缩小执行范围（Hold / Defer / Narrow） |
| `7` | 否决、冻结、反向范本或退出当前路径（Reject / Freeze / Negative Example） |
| `8` | 上下文内的第八个常规动作，常用于交给 Amy、局部试运行或授权内处理 |
| `9` | 重新生成（Regenerate），永远固定 |
| `0` | 我来输入（Human Input），永远固定 |

### 5.4 永久导航按钮

| 按钮 | 含义 | 是否改变业务状态 |
|---|---|---|
| 返回上一级（Back） | 回到前一个工作卡或选择面板，当前事项仍保留 | 否 |
| 取消当次（Cancel Current） | 退出本次交互，撤销尚未提交的当前操作 | 不改变原业务状态，只记录取消事件 |

`取消当次` 不等于否决、暂存、冻结或批准。

## 八、执行与留痕

| 动作类型 | 系统处理 |
|---|---|
| 查看类按钮 | 写入访问事件（ViewEvent），不改变业务状态 |
| `1-8` 常用选择 | 写入人类审阅选择（HumanReviewChoice）或回复命令（ReplyCommand） |
| `9` 重新生成 | 生成新的建议版本（SuggestionVersion），保留旧选项 |
| `0` 我来输入 | 打开对话输入，并绑定当前工作卡（Work Card） |
| 返回上一级 | 保留上下文，不生成业务决策 |
| 取消当次 | 结束本轮交互，写入取消事件（InteractionCanceledEvent） |

所有会改变业务状态的动作必须最终落成正式对象：

```text
MeetingDecisionRecord
ApprovalRecord
RevisionSession
CandidateProposal
PlanChangeProposal
DelegationPolicyChange
StrategyChangeProposal
CalibrationExample
```

候选提案卡（CandidateProposalCard）不得把原始信号列表直接推给人类。Amy 必须先完成聚合、去重、风险分级和推荐动作，再放到工作台：

| 区域 | English | 说明 |
|---|---|---|
| 必须裁决 | Must Decide | 高风险、高战略影响、越过授权边界 |
| 建议审阅 | Recommended Review | 高价值但不紧急，可作为校正范本或计划候选 |
| Amy 已合并 | Amy Merged | 重复误读、重复追问、低风险共鸣等降噪结果 |
| 观察中 | Observing | 未达阈值但值得继续看 |
| 已交接 | Handed Off | 只显示交接痕迹，不承接后续 |

`Must Decide / 必须裁决` 中凡涉及 `redline / 红线`、`source_boundary / 源边界`、`SourcePack / 源体系包`、`LighthouseStrategyObjective / 灯塔策略目标` 或 `CaseObjective / 案目标` 的卡片，Amy 只能整理证据、给出选项与风险提示，不能代替人类批准或应用变更。

投入论点卡（InvestmentThesisCard）用于呈现“是否加码、降频、保持、暂停或实验”的建议。Amy 不能只展示阅读量或点赞数，必须压缩成可裁决的办公桌材料：

| 区域 | English | 说明 |
|---|---|---|
| 建议加大投入 | Increase Candidates | 同时具备源体系相关、灯塔一致、同频共鸣、资产沉淀和风险可控证据 |
| 建议保持 | Hold Candidates | 信号稳定但不足以改变资源配置 |
| 建议降频 | Reduce Candidates | 疲劳、误读、成本或平台不适配上升 |
| 建议观察 | Observe Candidates | 未达阈值或噪声过载，需要继续采样 |
| 需要人类裁决 | Human Decision Required | 涉及红线、源边界、灯塔目标、案目标或大比例资源调整 |

每张 `InvestmentThesisCard / 投入论点卡` 必须展示：`Recommendation / 建议`、`Target / 投入对象`、`EvidenceSummary / 证据摘要`、`CounterEvidence / 反证`、`FailureCondition / 失败条件`、`ReviewDueAt / 复盘时间` 和 `CandidateProposal / 候选提案入口`。

投入评估卡（InvestmentAssessmentCard）是投入论点卡的证据展开层。Amy 默认折叠，只在用户点开时显示：

| 区域 | English | 内容 |
|---|---|---|
| 策略版本 | Policy Version | `InvestmentAssessmentPolicy / 投入评估策略` 编号、版本、批准状态 |
| 维度得分 | Dimension Scores | SourceFit、LighthouseFit、ResonanceQuality、RiskEnvelope 等关键维度 |
| 硬门槛 | Hard Gates | 源体系匹配、灯塔匹配、风险包络、证据强度是否通过 |
| 证据缺口 | Evidence Gaps | 缺哪些证据，导致观察、保持、人工审阅或失败 |
| 否决项 | Veto Results | 红线、源边界、灯塔漂移、算法噪声、人类注意力超预算 |
| 替代解释 | Alternative Hypotheses | 可能不是内容有效，而是热点、平台分发、偶然样本或噪声 |

Amy 可以推荐动作，但不能把评分表包装成确定结论。凡出现 blocking veto、证据缺口为 blocking、或硬门槛未通过，首选按钮不得是 `increase / 加码`。

默认种子差异（AssessmentPolicySeed Difference）必须在卡片上解释为“为什么这个平台这样看信号”，而不是“平台数据好所以加码”：

| 种子 | English | Amy 默认说明重点 |
|---|---|---|
| 知乎长文 | Zhihu Long-form | 收藏、长评、概念复述、长尾搜索是否支持知识沉淀 |
| 公众号文章 | WeChat Article | 阅读完成、聊天转发、收藏/星标、长期引用是否支持信任累积 |
| 小红书图文 | Xiaohongshu Image-text | 收藏、评论提问、卡片完读、场景适配是否支持低显性吸引 |
| X/Twitter 短帖 | X/Twitter Short Post | 转发、引用、串帖展开和概念扩散是否支持传播种子 |
| 视频/短视频 | Video / Short Video | 留存、完播、重看和评论理解是否支持有效显影 |

若当前策略实例来自种子覆盖，Amy 必须展示 `SeedVersion / 种子版本`、`OverrideSet / 覆盖集` 和关键覆盖项；凡覆盖项降低证据要求、放松否决项或扩大自动加码范围，必须放入 `Human Decision Required / 需要人类裁决`。

Amy 对平台种子信号的措辞必须是“该信号支持/不支持当前投入假设”，不得表述为“平台算法证明该方向正确”。无法稳定采集或归因不清的信号必须标注为 `Observation Only / 仅供观察`。

结果复盘卡（OutcomeReviewCard）用于呈现投入判断是否被证实。Amy 不展示数据墙，而展示原始论点、预期、实际、偏差解释和下一步动作：

| 区域 | English | 说明 |
|---|---|---|
| 有效，建议加码 | Validated Increase | 多周期证据支持，且风险、误读、疲劳可控 |
| 有效但需调整 | Validated with Adjustment | 方向成立，但需要换目的、角度、形态或显影高度 |
| 实验失败 | Failed Experiment | 小预算验证未达预期，需要修订再测、降频或归档 |
| 误读扩大 | Misread Expanded | 共鸣低、误读高，优先澄清或边界设定 |
| 疲劳上升 | Fatigue Rising | 同主题或同形态过密，建议降频、轮换或暂停 |
| 平台异常 | Platform Rule Shift | 平台规则或算法噪声导致不可归因 |
| 继续观察 | Continue Observe | 证据不足、窗口太短或样本太少 |

每张 `OutcomeReviewCard / 结果复盘卡` 必须展示：`OriginalRecommendation / 原始建议`、`ExpectedOutcome / 预期结果`、`ObservedOutcome / 实际结果`、`Baseline / 基线`、`Confounders / 干扰因素`、`AttributionHypotheses / 归因假设`、`ReviewResult / 复盘结论` 和 `NextCandidateProposal / 后续候选提案`。

凡复盘建议修改 `AssessmentPolicySeed / 评估策略种子`、`PurposePortfolio / 目的组合`、`LighthouseStrategyObjective / 灯塔策略目标` 或 `SourcePack / 源体系包`，Amy 只能生成候选卡，不能直接应用。

### 8.1 自然语言改稿闭环

`0 我来输入` 不是无限聊天。人类输入自然语言后，Amy 必须生成可确认的修改意图（RevisionIntent）：

```text
Human Input
  -> RevisionIntent
  -> PreparedActionPanel
  -> Diff / Package Preview
  -> HumanReviewChoice
  -> RevisionSession
```

即使是低风险批量修改，也至少要展示影响范围：涉及哪些产出物、哪些部件、哪些发布包、是否会改变门禁结果。Amy 不能把自然语言输入直接静默应用到一批产出物。

`RevisionIntent / 修改意图` 的影响预览必须分四层：

| 层级 | English Impact | 必须展示 |
|---|---|---|
| 内容影响 | `ContentImpact` | 会修改哪些 Artifact、ArtifactPart、版本、标题、正文、封面、标签或脚本 |
| 发布影响 | `PublicationImpact` | 哪些 PublicationPackage 作废并重建、哪些发布排期或 NextDayPlan 受影响 |
| 门禁影响 | `GateImpact` | 哪些 QualitySnapshot 失效、哪些 Gate 需要重跑、是否触发 SourceFidelityGate 或 PlatformRiskGate |
| 源体系边界影响 | `SourceBoundaryImpact` | 是否改变显性度、核心命题表达、边界姿态或需要人类主权裁决 |

若批量修改涉及 SourcePack 边界、理论显性度跨档、已发布内容召回、高风险断言、多个发布包作废或明日发布计划大改，必须生成 `BatchActionProposal / 批量动作提案`，不得在对话中直接应用。

### 8.2 复合产出物部件级审阅

复合产出物（Composite Artifact）必须支持部件级工作卡或详情抽屉：

| 部件 | English Part | 常见动作 |
|---|---|---|
| 封面 | CoverPart | 换标题、换图、降低信息密度 |
| 轮播图 | CarouselImagePart | 修改第 N 张、重排顺序、压缩文字 |
| 主文案 | PrimaryTextPart | 改开头、改结尾、降低理论显性 |
| 视频 | VideoPart | 改脚本、改镜头、改节奏 |
| 字幕 | SubtitlePart | 改术语、改断句、检查错字 |
| 标签 | TagPart | 增删标签、平台适配 |
| 发布包 | PublicationPackage | 检查账号、平台、附件、提交字段 |

每日精选审阅和批量审片都可以作用于 `artifact / artifact_part / rendition / publication_package` 四个层级。校正范本（CalibrationExample）必须记录作用范围，不能默认都是整篇文章。

### 8.3 批量总编台信息架构

批量总编台（Artifact Review Desk）必须按风险和平台分组，不以“所有稿件平铺列表”为默认。

| 区域 | English Area | 必须显示 |
|---|---|---|
| 推荐分组 | Recommended Group | Amy 建议发布、返工、暂存、冻结的数量 |
| 风险分组 | Risk Group | 红线、边界、证据缺口、平台适配异常 |
| 平台/账号列 | Platform / Account Columns | 目标平台、账号、受众、理论显性度 |
| 门禁列 | Gate Columns | StructureGate、EvidenceGate、PackageGate 结果 |
| 差异预览 | Diff Preview | 批量动作会改哪些产出物和部件 |
| 例外项 | Exclusions | 批准全部但排除 X、冻结单项、只发某平台 |

批量动作必须先生成影响预览。高风险项必须进入详情抽屉或单独工作卡，不能被“全部通过门禁项”批量吞掉。

## 九、硬约束

1. `1-8` 是常用选项，`9` 永远是重新生成，`0` 永远是我来输入。
2. `1` 永远是 Amy 推荐动作，必须附推荐理由。
3. 每个编号选项面板必须有返回上一级和取消当次。
4. 返回不改变业务状态。
5. 取消当次不等于否决、暂存、冻结或批准。
6. 微信与工作台必须使用同一个准备动作面板，不得各自生成一套选项。
7. 所有选择必须可追溯到工作卡、面板、选项、来源对象和执行结果。
8. `9` 重新生成必须保留旧建议版本，不能覆盖旧选项。
9. `0` 我来输入必须绑定当前工作卡，不能变成无上下文聊天。
10. 每日精选审阅每天最多推荐 1 个，不审不阻塞发布。
11. 每日日报必须通过微信摘要入口主动送达，并在日报详情页中提供完整阅读和处理能力。
12. Phase 1 不引入邮件通道。
13. 查看/展开/解释/打开详情等低风险动作不得占用 `1-8` 编号槽位。
14. 微信日报入口卡只能执行低风险入口动作，实质动作必须回到日报详情页或 Amy 总控台。
15. `0 我来输入` 后必须生成 RevisionIntent、diff 或影响范围预览，再由人类确认。

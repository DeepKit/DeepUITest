### 2.16 战略意图资产层与目的组合（Strategic Intent Asset Layer and Purpose Portfolio）

圆桌角色：

- 战略架构专家（Strategic Architecture Expert）
- 内容运营与灯塔传播专家（Content Operations and Lighthouse Propagation Expert）
- 未来 AI 能力与系统耐久性专家（Future AI Capability and System Durability Expert）

一致结论：

- `LighthouseStrategyObjective / 灯塔策略目标` 保存长期场域位置、身份占位、信任建立目标、受众状态路径、边界姿态、平台账号角色与非目标。
- `CaseObjective / 案目标` 保存某一时间案的战略任务、优先级、继承约束、成功判据与 `PurposePortfolio / 目的组合`。
- `PurposePortfolio / 目的组合` 不能是固定内容模板；它必须由灯塔目标、案目标、场域状态与人类注意力预算动态编译，并下发为单篇 `PurposeType / 目的类型`。
- AI/Amy 可以生成组合候选、绑定候选、排程与表达变体；不能自动修改灯塔目标、账号定位、源体系权威版本、大比例目的组合或边界姿态。
- 十年后模型能力增强时，产品的不可替代资产应是结构化战略意图、版本化目的组合、策略绑定和决策谱系，而非某一代生成提示词。

整改：

- 在 `01.[蓝图]-产品蓝图-Blueprint.md` 增加战略意图资产层能力边界。
- 在 `04.[模型]-案场与产出物模型-Case-Artifact-Model.md` 固化本轮圆桌结论和六层 Case 的目的组合编译关系。
- 在 `20.[治理]-会议体系与计划治理-Meeting-Governance.md` 增加目标、组合、权限和会议输入输出协议。
- 在 `24.[数据]-数据库模型与治理-Database.md` 增加 `lighthouse_strategy_objective / case_objective / purpose_portfolio` 数据表、索引、RLS 覆盖和硬约束。

复审追加整改：

- 月案必须输出 `MonthlyPurposePortfolio / 月度目的组合`，周案输出 `WeeklyPurposeAllocation / 周度目的分配` 与 `PurposeSlot / 目的槽位`，日案锁定单篇主目的与策略绑定；`ArtifactMix / 内容形态比例` 不得替代目的组合。
- `AttractionHandoff / 吸引交接` 仅保存公开信号与外部交接引用；禁止保存私聊状态、个人跟进任务或关系阶段；`PublicFollowupCandidate / 公开跟进候选` 只能生成新的公开产出物候选。
- 新增 `ExpressionDiversityPolicy / 表达多样性策略` 与 `FatigueSignalPolicy / 疲劳信号策略`，防止同目的内容机械化。
- `PurposePortfolio / 目的组合` 新增 `approval_mode / parent_purpose_portfolio_id / delegation_policy_id / auto_adjustment_proof`，区分人类批准与授权范围内派生，避免把周案/日案自动执行打回人工。
- `CaseObjective / 案目标` 增加可多目标标识、父级快照与提交快照区分，并要求时间范围和案类型一致。
- 新增 `trg_artifact_plan_binding_chain_guard`，避免单篇产出挂到错误灯塔、错误案目标、错误组合或错误平台账号。
- `PurposePortfolioItem / ArtifactPlanPurpose / QualitySnapshotRun` 表化为事实关系，UUID 数组仅作缓存。
- `PublicationPackage / ApprovalRecord` 必须绑定可发布 `QualitySnapshot / 质量快照`；新增 `RealPublishGateRun / 真实发布门运行` 与 `PublicationAttempt / 发布尝试`。
- 明确租户内引用必须使用复合外键或租户一致性触发器，RLS 必须有 `WITH CHECK`，不能将商业隔离风险留到后期。

### 2.17 场域状态（FieldState）

- 未来 AI 与数据库耐久性专家（Future AI and Database Durability Expert）

一致结论：

- `algorithm_noise_overload / 算法噪声过载` 是灰灯，必须阻断平台反馈自动推动策略变更。

### 2.18 候选提案信封（CandidateProposal Envelope）

圆桌角色：

- 战略架构专家（Strategic Architecture Expert）
- 内容运营与灯塔传播专家（Content Operations and Lighthouse Propagation Expert）
- 未来 AI 与数据库耐久性专家（Future AI and Database Durability Expert）

一致结论：

- `CandidateProposal / 候选提案` 应采用统一信封（Envelope）结构，而不是把机会、计划变更、策略变更、边界变更、反哺与校正范本压成一张万能表。
- 统一信封只管理来源、证据、作用范围、风险、去重合并、推荐会议、裁决和应用记录；具体变化继续由 `OpportunityCandidate / 机会候选`、`PlanChangeProposal / 计划变更提案`、`BoundaryChangeProposal / 边界变更提案`、`StrategyChangeProposal / 策略变更提案`、`BackfeedCandidate / 反哺候选` 与 `CalibrationExample / 校正范本` 承载。
- `CandidateProposal / 候选提案` 不是原始信号待办池。信号必须经过 `Aggregation Gate / 聚合门`、`Threshold Gate / 阈值门` 与 `Purpose Gate / 目的门` 后，才可形成给 Amy 和人类查看的 `CandidateProposalCard / 候选提案卡`。
- `CandidateDecision / 候选裁决` 与 `CandidateApplication / 候选应用` 必须分离；批准候选不等于直接修改正式计划或核心战略对象。
- 涉及 `redline / 红线`、`source_boundary / 源边界`、`SourcePack / 源体系包`、`LighthouseStrategyObjective / 灯塔策略目标` 或 `CaseObjective / 案目标` 的候选，Amy 只能准备材料与建议，不得自动裁决。

### 6A.1 已发现漏洞与整改

#### P0-CRIT-01：低风险自动调参需要白名单、禁区和调整带（AutoTune Boundary）

第 10 项蓝图选 B 后，若没有机制约束，平台反馈可能通过自动调参链悄悄改变源体系表达、灯塔位置或账号定位。

- 新增 `AutoTuneDenylist / 自动调参禁区`，SourcePack 核心内容、母板、核心原则、灯塔策略目标、案目标、账号长期定位、目的组合大比例变化、理论显性度跨等级调整、自动发布权限等级、高风险话题频率、红线边界、商业承诺边界、跨平台资源大比例迁移、StrategyUnitMaturity 升级和 DelegationPolicy 扩权不得自动调整。
- 新增 `AutoTuneBand / 自动调整带`，中间参数可小幅自动变化但不能跨档。
- 每次自动调参必须生成 `AutoTuneEvent / 自动调参事件`，可回滚、可追溯。
- 连续调参或接近边界时必须进入日报摘要或 Amy 工作台提示。

#### P0-CRIT-02：PublicationPackage 必须绑定唯一生效 QualitySnapshot（Package-QualitySnapshot Binding）

当前质量快照与发布包之间缺少强制一对一绑定。Artifact 修改后重跑门禁可能导致"发布时引用了一个 QualitySnapshot，但重新检查后实际对应的是另一个"。

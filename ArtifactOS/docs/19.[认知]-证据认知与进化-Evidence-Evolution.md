# 19 Part A: 知识进化控制台

> 系统编号：横切中枢
> 核心职责：以策略单元和认知扰动事件为对象，控制自动生成、证据化认知、策略演进、知识晋升、理论修正和边界裁决
> 战略定位：ArtifactOS 的长期形态不是写作辅助工具，而是源体系驱动的媒体产出物操作系统

---

## 一、战略目标

ArtifactOS 的长期目标是 **通用媒体产出物操作系统**。在知识型/理论型场景中，它表现为知识进化引擎；在品牌、产品、课程、研究、公关等场景中，它表现为可装载源体系、可生成产出物、可回收反馈证据、可由人类裁决反哺的产出控制层：

```text
自动观察现实扰动
-> 自动识别关键属性
-> 自动进行理论映射和假设生成
-> 自动拆解 EvidenceClaim
-> 自动生成内容、研究或策略行动
-> 自动评分、重写、发布、暂存或不写
-> 自动回收数据和反证
-> 自动提出策略、知识或理论映射演进建议
```

人类不再是固定流程节点，而是：

```text
抽检者 / 校准者 / 降权者 / 策略裁决者 / 理论核心裁决者
```

系统默认尽量少打扰人类。人类可以随时抽检、降权、暂停、召回、关闭某个策略单元的自动权限，或拒绝系统提出的理论修正提案。

## 二、策略单元

### 2.1 定义

自治权不授予整个系统，也不只授予账号，而是授予策略单元：

```text
StrategyUnit = 账号 + 平台 + 内容类型 + 理论介入方式
```

示例：

```text
知乎主账号 + 热点长文 + 高理论介入
微博副账号 + 快评短文 + 中理论介入
公众号 + 系列深文 + 高理论水平
小红书 + 轻解释卡片 + 低显性理论
```

### 2.2 策略单元配置

每个策略单元独立配置：

```json
{
  "strategy_unit_id": "su_zhihu_sub_hot_long_theory_high",
  "account_id": "sub",
  "platform": "zhihu",
  "content_type": "hotspot_longform",
  "theory_intervention": "high",
  "autonomy_level": "AL3",
  "entry_priority": ["hotspot_driven", "theory_driven"],
  "quality_profile_id": "qp_zhihu_theory_longform_v1",
  "max_rewrite": 3,
  "sampling_policy": {
    "random_sample_rate": 0.1,
    "risk_sample_boost": true,
    "new_strategy_sample_rate": 0.5
  },
  "on_pass": "auto_publish",
  "on_rewrite_exhausted": "downgrade_wait_human",
  "when_human_unavailable": "store_draft | publish_with_risk_mark | abandon",
  "publish_permission": "auto_when_passed",
  "strategy_version": 1
}
```

### 2.3 自治等级

每个策略单元独立拥有自治等级：

| 等级 | 名称 | 权限 |
|------|------|------|
| `AL0` | 人类主导 | 系统只辅助收集素材和生成候选 |
| `AL1` | 系统生成 | 系统可生成草稿，人类必审 |
| `AL2` | 系统重写 | 系统可自动评分和重写，发布仍需人类裁决 |
| `AL3` | 系统发布 | 达标后可自动发布，异常进入抽检/降权/等待 |
| `AL4` | 系统运营 | 自动追热点、选题、生成、发布、复盘和提出策略优化 |

长期目标是让成熟、低风险、表现稳定的策略单元进入 `AL3/AL4`。新策略、高风险策略或表现不稳定策略默认低自治。

### 2.4 认知成熟度

自治等级只说明系统“被允许做什么”，认知成熟度说明系统“是否真的会判断”。

```text
StrategyUnitCognitionScore =
  属性识别能力
+ 趋势预测能力
+ 介入有效能力
+ 证据校准能力
```

| 维度 | 评估问题 | 数据来源 |
|------|----------|----------|
| 属性识别 | 能否识别热点、理论、平台、读者中的关键属性 | CognitionTrace |
| 趋势预测 | 对阅读、互动、吸引信号、负反馈、理论风险的预测是否接近实际 | 发布反馈 / 数据回收 |
| 介入有效 | 重写、降理论介入、换角度、暂存、不写等动作是否改善结果 | 策略事件 / 质量报告 |
| 证据校准 | EvidenceClaim 是否被后续证据支持或反证 | ClaimGraph / 反证门禁 |

策略单元升权必须同时参考自治等级、质量表现和认知成熟度。

## 三、默认评分矩阵

系统提供默认评分维度，但每个策略单元都可以调整维度、权重、阈值和升降权规则。

### 3.1 六组默认维度

> Phase 1 实现三组子集（理论/内容/风险），Phase 3 扩展为完整六组。以下为完整定义。

| 分组 | 默认维度 |
|------|----------|
| 理论维度 | 理论介入度、理论准确性、理论推导力、理论新意 |
| 内容维度 | 观点力度、结构完整性、论证充分性、事实可靠性 |
| 阅读维度 | 可读性、节奏感、标题吸引力、开头钩子、结尾收束 |
| 平台维度 | 平台适配度、格式适配、平台风险、推荐机制适配 |
| 账号维度 | 账号调性一致性、历史风格一致性、目标读者匹配度 |
| 运营维度 | 吸引信号强度、互动潜力、收藏价值、高意向信号、热点时效 |

默认维度不超过 20 个。超过 20 个时必须拆成子画像或实验策略，不能把所有目标塞进一个总分。

### 3.2 决策不是单一总分

质量判断分三层：

```text
硬门禁：事实错误、平台红线、风险、账号禁区
底线分：可读性、理论不跑偏、结构完整、账号一致性
目标分：吸引信号、理论深度、观点锋利、收藏价值、传播性
```

决策逻辑：

```text
硬门禁不过 -> 返工 / 冻结 / 红灯
底线分不足 -> 自动重写 N 次
目标分不足 -> 按策略单元配置决定重写、降级、暂存或发布
质量分达标 -> 按自治等级和发布权限自动推进
```

### 3.3 重写和降级策略

默认处理链：

```text
评分不足
-> 自动重写 N 次
-> 仍未达标则降级
-> 若人类介入开关开启，进入人类待处理
-> 若人类无时间或关闭介入，按策略配置发布、存草稿、降级发布或放弃
```

可用动作集合：

```text
重写
换角度
降低理论介入度
降级为低风险内容
存草稿
等待人类
放弃
```

## 四、理论体系作为策略引擎

理论体系不是素材库，而是知识进化系统的策略引擎。

它参与：

```text
选题判断
热点解释
观点推导
立场生成
论证路径
表达转译
是否发布
```

### 4.1 理论参与深度

| 层级 | 说明 |
|------|------|
| A 理论作为素材 | 检索概念、术语、引用 |
| B 理论作为解释框架 | 用理论解释热点背后的结构 |
| C 理论作为观点生成器 | 根据理论推导观点、立场和判断 |
| D 理论作为策略引擎 | 决定选题、角度、论证路径、表达方式和发布策略 |

长期目标采用 `D`。不同策略单元可以降低理论显性程度，但不能改变核心理论原则。

### 4.2 理论核心不可变层

理论体系必须区分：

| 层 | 自动调整权限 |
|----|--------------|
| 核心原则 | 禁止 AI 自动修改 |
| 解释模型 | 可版本化演进，重大变更需人类确认 |
| 应用案例 | 可持续扩展 |
| 表达模板 | 可按平台和账号调整 |

运营数据可以影响理论表达方式，但不能改变理论原则。

## 五、双入口认知行动

ArtifactOS 同时支持两种入口：

```text
入口 1：热点驱动
热点 -> 理论映射 -> 观点生成 -> 内容/研究/策略行动

入口 2：理论驱动
理论命题 -> 热点/案例匹配 -> 内容/研究/策略行动
```

策略单元决定入口优先级：

| 场景 | 默认入口 |
|------|----------|
| 微博/X 快评 | 热点优先 |
| 知乎理论长文 | 热点与理论平衡 |
| 公众号深文 | 理论优先 |
| 系列内容 | 理论优先 |
| 吸引入口内容 | 热点优先 |

系统必须允许自动判断“不写”。拒绝写作也是策略能力，必须记录理由。

## 六、进化控制台

### 6.1 看板定位

进化控制台是 AI 知识进化控制塔，不是普通报表。它既看策略单元是否健康，也看系统的认知是否发生扰动、预测是否失准、证据是否过期、知识是否需要晋升或降权。

它承载：

```text
哪些策略单元正在自动运行
哪些策略单元被抽检
哪些策略单元已降权
哪些策略单元暂停
哪些策略单元正在实验
哪些策略单元可升级自治权
哪些策略单元等待人类处理
哪些 EvidenceClaim 被反证挑战
哪些知识需要复水或退休
哪些理论映射需要修正提案
哪些机会候选（OpportunityCandidate）等待进入会议
哪些计划变更提案（PlanChangeProposal）等待审议、延期或执行
```

### 6.2 一级对象

控制台有三个一级入口：

```text
一级A：策略单元健康度
一级B：认知扰动事件
一级C：计划治理队列（OpportunityCandidate / PlanChangeProposal / CaseChangeControl）
二级：策略单元下的内容行动 / ClaimGraph / 知识回写 / 研究假设 / 会议提案
三级：单篇文章 / 草稿 / 热点 / 理论映射 / EvidenceClaim / MeetingRecord 详情
```

每个策略单元展示：

```text
自治等级
当前灯色
质量趋势
理论表现
运营表现
风险状态
抽检率
重写次数
待处理建议
最近发布
策略版本
认知成熟度
最近扰动事件
EvidenceClaim 风险
TheoryRevisionProposal 状态
```

### 6.3 信号灯

| 灯色 | 含义 | 默认动作 |
|------|------|----------|
| 绿灯 | 策略运行健康 | 继续自动运行 |
| 黄灯 | 有优化建议 | 人类可点开查看，与 AI 协商 |
| 橙灯 | 策略明显失配 | 提高抽检率或建议降权 |
| 红灯 | 风险/失控 | 自动降权、暂停或等待裁决 |
| 蓝灯 | 发现新机会 | 生成机会候选（OpportunityCandidate），建议新策略、新热点入口、平台实验或计划变更提案 |
| 灰灯 | 数据不足、平台算法扰动或环境噪音过载 | 继续观察、转常青维护或探索模式，不做强判断 |

灯号背后的统一数据对象是 `CognitiveDisturbanceEvent`：

```json
{
  "disturbance_id": "cd_20260523_001",
  "strategy_unit_id": "su_zhihu_sub_hot_long_theory_high",
  "disturbance_type": "prediction_miss | theory_drift | evidence_stale | quality_anomaly | research_anomaly | algorithm_noise_overload",
  "light": "yellow",
  "evidence_refs": ["ev_gate_001", "pf_003"],
  "affected_scope": "article | strategy_unit | account | platform | theory",
  "suggested_intervention": "调整理论显性权重 -10%",
  "calibration_delta": 0.32,
  "consecutive_miss_count": 3,
  "human_needed": true,
  "cognition_trace_refs": ["ct_001"]
}
```

### 6.3a 灰灯避险

灰灯不是失败灯。它用于防止系统被平台短期算法和环境噪音绑架。

触发条件：

- 内部质量分、源体系忠实度和证据完整度都高，但外部反馈异常低
- 同平台同类内容整体流量异常波动
- 全网同质化内容暴增，当前策略难以区分真实失败和环境噪音
- 平台规则或推荐机制疑似变化，但未形成明确红线

默认动作：

```text
不自动降权
不判定理论失败
延长观察窗口
转入常青内容维护 / seed_contract 探索 / 小流量实验
必要时暂停同类自动发布，等待更多证据
```

灰灯期间可以提出 `StrategyChangeProposal`，但只能作为候选建议，不得自动写入策略。

### 6.4 黄灯调参机制

调参分为授权内低风险自动调参和需要人类确认的策略变更。第 10 项蓝图选择 B：系统可以在白名单��禁区和调整带约束下自动微调低风险参数；高层战略、源体系、灯塔目标、案目标、目的组合大比例、自动发布权限和边界变化仍必须进入候选与人类裁决。

```text
低风险信号
-> AutoTuneAllowlist / AutoTuneBand 校验
-> AutoTuneEvent 入账
-> digest（次日日报摘要中聚合展示）/ review_required（接近禁区或连续调参时）

白名单内低风险自动调参不得使用 silent_record（静默入账）生效档位。所有自动调参必须在 digest（日报/周报摘要）、review_required（需人类轻确认）或更高可见度档位记录。规则参见 `01.[蓝图]-产品蓝图-Blueprint.md` "不做静默调参"硬约束。

高层或越界信号
-> 策略单元亮黄灯/橙灯
-> StrategyChangeProposal / CandidateProposal
-> 人类查看原因、证据、影响范围和建议参数
-> 人类确认或继续修改
-> ArtifactEvolutionEvent
-> 策略版本升级
```

自动调参白名单（AutoTuneAllowlist）默认只包括：发布时间窗口微调、标题长度偏好、标题句式模板排序、开头钩子模板排序、结尾收束模板排序、标签数量上限、轮播页数小幅调整、摘要长度、分段密度、低风险抽检率上调、格式适配策略和非核心表达模板排序。

自动调参禁区（AutoTuneDenylist）包括：SourcePack 核心内容、母板、核心原则、灯塔策略目标、案目标、账号长期定位、目的组合大比例变化、理论显性度跨等级调整、自动发布权限等级、高风险话题频率、红线边界、商业承诺边界、跨平台资源大比例迁移、StrategyUnitMaturity 升到 M3/M4、DelegationPolicy 扩权。

中间参数必须受 AutoTuneBand 限制：理论显性度只能同档微调，目的组合只能在父级授权带内派生，发布频率只能在策略单元授权范围内小幅变化，连续变化或接近边界必须进入 digest 或 review_required。

原则：

```text
AI 可以提出策略、知识、证据和理论映射的演进建议
低风险自动调参必须可见、可回滚、可追溯
高层演进必须可解释、可协商、可裁决
```

黄灯协商的输出不只可能是 `StrategyChangeProposal`，也可能是：

| 输出对象 | 用途 |
|----------|------|
| `StrategyChangeProposal` | 调权重、阈值、发布动作、抽检率 |
| `KnowledgeHydration` | 将旧知识在当前策略单元中复水或禁用 |
| `EvidenceClaimPatch` | 补证据、降置信度、标记反证 |
| `TheoryRevisionProposal` | 提出理论映射或解释模型修正 |
| `BoundaryDecision` | 改成不写、只存草稿、等待人类或冻结 |

### 6.5 扰动到策略变更提案

系统发现需要调参时，不直接改参数，而是生成提案：

```text
CognitiveDisturbanceEvent
-> StrategyChangeProposal
-> 黄灯/橙灯/灰灯详情
-> 人类自然语言协商
-> 人类确认
-> ArtifactEvolutionEvent
-> 策略版本升级
```

自动生成 `StrategyChangeProposal` 的默认触发器：

| 触发器 | 灯号 | 默认建议 |
|--------|------|----------|
| 同维度 `calibration_delta` 连续 3 次超标 | 黄/橙 | 调整写/不写阈值、抽检率、理论介入度 |
| 重写次数长期超过策略上限 50% | 黄 | 降低复杂度、提高抽检或进入草稿池 |
| 源体系忠实度连续 WARN | 黄/红 | 锁定 S08 结构规格，禁止平台转译越界 |
| `algorithm_noise_overload` | 灰 | 延长观察、转常青维护或探索模式 |

任何提案默认 `requires_human_confirmation=true`。系统可以建议，不能静默调参。

### 6.6 计划治理队列

进化控制台不只显示策略是否健康，还要显示哪些机会和计划变更需要进入会议。它不是接引系统，也不是互动 CRM；它只负责把可能影响产出计划的信号推到正确会议层级。

```text
CognitiveDisturbanceEvent / SignalEvent / HumanFeedback / AIObservation
  -> OpportunityCandidate
  -> PlanChangeProposal
  -> 推荐会议（RecommendedMeeting）
  -> MeetingRecord
  -> PlanChangeLog
  -> CaseSnapshot
```

队列字段：

| 字段 | 英文 | 说明 |
|------|------|------|
| 机会候选 | OpportunityCandidate | 新平台、新媒体、新账号、新受众、新主题或新载体 |
| 计划变更提案 | PlanChangeProposal | 增加计划、减少计划、调整计划、授权变化 |
| 推荐会议 | RecommendedMeeting | 年会、半年会、季度会、月会、周会或日晨会 |
| 影响案 | AffectedCase | 可能被影响的 YearCase / HalfYearCase / QuarterCase / MonthCase / WeekCase / DayCase |
| 紧急度 | Urgency | 能等到下次周期会议，还是需要临时会议 |
| 证据来源 | EvidenceRefs | SignalEvent、RecallCard、Feedback、MeetingRecord 等 |
| 决策状态 | DecisionStatus | draft / waiting_meeting / approved / rejected / deferred / applied |

分派规则：

| 变化类型 | 默认会议 |
|----------|----------|
| 新增国外媒体方向、主海域调整、年度资源重配 | 半年会（Half-Year Meeting）或年案重开（YearCaseReopen） |
| 新平台实验、新主题季、新验证重点 | 季度会（Quarterly Meeting） |
| 本月灯塔位置、账号组合、产能预算调整 | 月会（Monthly Meeting） |
| 本周主题池、片场候选、今日子案候选调整 | 周会（Weekly Meeting） |
| 今日生产顺序、今日授权、异常处理 | 日晨会（Daily Meeting） |

硬约束：

- 蓝灯只代表“发现机会”，不代表自动进入正式计划。
- `PlanChangeProposal.status` 未达到 `approved/applied` 前，不得修改正式计划池。
- 涉及年度北极星、红线边界或源体系主权的变化，必须升级为 `BoundaryChangeProposal` 或 `YearCaseReopen`。
- 控制台可以合并相似候选，但合并记录必须保留来源和被合并项。

## 七、实验策略

系统支持主策略和实验策略隔离：

| 类型 | 用途 |
|------|------|
| 主策略 | 稳定运行，用于正式自动发布 |
| 实验策略 | 小流量试验，不污染主策略 |

实验策略可以配置为：

```text
只生成草稿不发布
小比例自动发布
只在低风险平台发布
只在人类抽检后发布
```

实验策略是否允许自动发布由策略单元配置决定。默认约束是：小流量、高抽检、可回滚。

实验结果进入进化控制台；稳定有效后，系统可亮蓝灯或黄灯，建议晋升为主策略。

## 八、反馈学习与分层共享

### 8.1 长期壁垒

ArtifactOS 的长期壁垒是：

```text
系统每次被现实纠正，都让下一轮判断更接近有效
```

反馈不是聊天记录，而是知识进化资产。它可能作用于本文、策略单元、账号、平台、理论映射或研究假设。

### 8.2 反馈作用范围

人类反馈默认分 5 个作用范围（枚举值定义见 `18.[交互]-交互修改与遗忘-Interaction-Forgetting` §3.3）：

| 范围 | 枚举值 | 含义 |
|------|--------|------|
| 本文级 | `article` | 只修正当前文章 |
| 策略单元级 | `strategy_unit` | 影响当前账号 + 平台 + 内容类型 + 理论介入方式 |
| 账号级 | `account` | 影响该账号在所有平台/内容类型下的风格或立场 |
| 平台级 | `platform` | 影响该平台的表达、格式、风险或推荐适配 |
| 理论层级 | `theory` | 影响理论映射、观点推导、理论解释方式 |

系统可以自动建议作用范围，人类可以修改。

### 8.3 分层共享学习

策略单元之间采用分层共享：

| 层 | 是否共享 |
|----|----------|
| 理论映射能力 | 可共享 |
| 热点识别能力 | 可共享 |
| 事实校验能力 | 可共享 |
| 质量评分能力 | 可共享 |
| 平台适配策略 | 默认隔离，可有平台级共享 |
| 账号风格 | 隔离 |
| 运营策略 | 按策略单元隔离 |

所有共享都必须记录版本、来源、适用范围和回滚路径。

### 8.4 反馈晋升

反馈学习采用分级晋升：

```text
单次反馈 -> 本文修正 / EvidenceClaim 降置信度
重复反馈 -> 策略单元规则 / KnowledgeHydration
跨文章有效 -> 共享规则 / ClaimGraph 结构更新
高风险错误 -> 反例库 / 红线 / TheoryRevisionProposal
```

系统可以建议晋升，人类可以确认、修改作用范围或降级为本文级。

# 14 证据化认知与知识进化机制

> 系统编号：横切机制
> 核心职责：把每次生成、判断、发布、反馈、反证和调参建模为可追溯的知识进化事件

## 一、核心定位

ArtifactOS 的核心不是“生成更多内容”，而是让知识体系在现实反馈中持续演进。

```text
现实扰动
-> 属性识别
-> 趋势预测
-> 理论映射 / 假设生成
-> 证据断言 / 反证检查
-> 内容、研究或策略行动
-> 场域反馈
-> 策略、知识、理论映射演进
```

内容生产只是知识进入现实的行动形式之一。科研、策略建议、研究报告和理论修正提案也属于行动形式。

---

## 二、核心对象

### 2.0 信号分层边界

发布前后产生的所有现实反馈必须分层处理：

```text
发布前：信号预期（SignalExpectation）
发布后：信号事件（SignalEvent）       # 事实
      -> 信号解释（SignalInterpretation） # AI 假说
      -> 归因决策（AttributionDecision）  # 受边界约束的动作
```

| 层级 | 对象 | 可做什么 | 不可做什么 |
|------|------|----------|------------|
| 预期层 | SignalExpectation | 记录产出计划（ArtifactPlan）的观察目标和预期信号 | 不作为真实反馈 |
| 事实层 | SignalEvent | 记录平台指标、评论、转发、收藏、人工反馈等事实 | 不解释原因 |
| 解释层 | SignalInterpretation | 由 AI 给出可能原因、置信度和反例 | 不直接改策略或理论 |
| 决策层 | AttributionDecision | 决定是否形成策略提案、保留模式候选或反哺候选 | 不自动证明源体系命题 |

规则：信号事件（SignalEvent）只能证明发生了什么，不能直接证明为什么发生，更不能直接证明理论为真。任何可能反补源体系的内容，只能形成反哺候选（BackfeedCandidate），等待人类裁决。

### 2.0a 共鸣质量与误读风险

发布后反馈必须区分“有热度”和“被正确理解”。系统不得把高流量、高点赞或高转发直接视为策略成功。

| 信号类型 | English Object | 含义 | 默认处理 |
|---|---|---|---|
| 同频共鸣信号 | `AlignedResonanceSignal` | 收藏、准确复述、深入公开追问、长期引用等说明源体系被正确接收 | 可进入绿灯、蓝灯或投入论点证据 |
| 扭曲共鸣信号 | `DistortedResonanceSignal` | 高互动但大量误读、断章取义、鸡汤化、玄学化或标题党化扩散 | 默认橙灯，不得自动加码 |
| 表层互动信号 | `SurfaceEngagementSignal` | 点赞、短评、围观等弱信号，不能证明理解或资产沉淀 | 仅作观察或排序辅助 |
| 负向风险信号 | `NegativeRiskSignal` | 投诉、平台风险、严重反驳、事实纠错、恶性传播 | 红灯或召回评估 |

`MisreadRiskAssessment / 误读风险评估` 属于解释层对象，不是事实层。它由评论语义、公开追问偏移、转发语境、人工标记、历史误读范本和平台风险信号生成，必须进入 `SignalInterpretation -> AttributionDecision` 链路。

灯号规则：高流量低误读可绿灯或蓝灯；高流量高误读默认橙灯；低流量高质量默认灰灯；负反馈异常或平台风险默认红灯。高流量高误读只能生成 `CalibrationExample`、`StrategyChangeProposal`、`ClarificationArtifactCandidate`、`BoundaryChangeProposal` 或 `BackfeedCandidate`，不得自动加码或直接修改 SourcePack。

### 2.2 EvidenceClaim

把文章、研究和策略中的关键判断拆成可证据化断言。

| 字段 | 含义 |
|------|------|
| `claim_text` | 断言文本 |
| `claim_type` | factual / theory_inference / value_judgment / operation_hypothesis |
| `source_refs` | 证据来源 |
| `confidence` | 当前置信度 |
| `freshness` | 保鲜期与过期状态 |
| `risk_level` | 风险等级 |
| `falsification_status` | untested / supported / challenged / falsified |
| `scope` | article / strategy_unit / account / platform / theory |
| `depends_on_claim_ids` | 该断言依赖的上游断言 |
| `edge_type` | supports / refutes / derives_from / contextualizes |
| `valid_time_window` | 断言适用的时间窗口 |
| `propagation_policy` | article / strategy_unit / account / platform / theory |

原则：AI 输出不能直接给自己做证据。若来源只是 AI 推断，必须标记为假设或候选断言。所有 EvidenceClaim 在创建和晋升时必须经过自我认证门禁（SelfCertificationGate），完整规则定义见 `docs/12.[流程]-质量门禁-Quality-Gate.md` §3.3 SES-06。数据库层约束 `CK_evidenceclaim_self_certification`（见 `docs/24.[数据]-数据库模型与治理-Database.md` §10.1a）为防止越过应用层的最后防线。

> **propagation_policy 语义**（与 `18.[交互]-交互修改与遗忘-Interaction-Forgetting` 的反馈作用范围统一）：
>
> | propagation_policy | 含义 | 传播行为 |
> |-------------------|------|---------|
> | `article` | 仅对本篇内容生效 | 不传播，断言生命周期随任务结束 |
> | `strategy_unit` | 在同一策略单元的所有内容中生效 | 写入策略单元知识库，S07 可注入 |
> | `account` | 在同一账号的所有策略单元中生效 | 写入账号级知识库，需人类确认 |
> | `platform` | 在同一平台的所有账号中生效 | 写入平台级知识库，需人类确认 |
> | `theory` | 对理论体系有效，跨账号跨平台 | 写入理论映射库，需人类确认 + 源体系忠实度门禁的 theory profile |

### Phase 1 最小可行字段集

Phase 1 表结构完整预埋所有字段，但运行时只实现以下子集：

**运行时必须实现的字段**：

| 字段 | 说明 | Phase 1 用途 |
|------|------|-------------|
| `claim_id` | 唯一标识 | CognitionTrace 引用、门禁引用 |
| `claim_text` | 断言文本 | 人类可读 |
| `claim_type` | fact / theory_derived / value_judgement / operation_hypothesis | 门禁按类型差异化处理 |
| `source_ref` | 来源引用（草稿段落 / 理论文本 / 外部数据） | 可追溯 |
| `confidence` | 置信度 0.0-1.0 | 门禁阈值判断 |
| `status` | candidate / active / challenged / retired / frozen | 生命周期管理 |
| `expires_at` | 保鲜期 | Phase 1 简化为统一 30 天 |
| `created_at` | 创建时间 | 审计 |

**预埋但不实现逻辑的字段**：`depends_on_claim_ids` / `edge_type` / `scope` / `propagation_policy` / `risk_level`。这些字段在表结构中存在，Phase 2 实现依赖边逻辑和 DAG 禁循环检查时启用。

### 2.2a EvidenceClaim 归属层级规则

EvidenceClaim 的 `scope` 字段决定断言的影响范围和传播粒度。scope 必须在断言创建时确定，创建后不可缩小（只能扩大或保持）。

**scope 确定规则**：

| scope | 含义 | 确定时机 | 确定者 |
|-------|------|---------|--------|
| `article` | 仅对本篇内容有效 | AI 生成时自动标注 | 写作引擎 |
| `strategy_unit` | 对同一策略单元下所有内容有效 | AI 生成时标注或质量门禁时补标 | 写作引擎 / 质量门禁 |
| `account` | 对同一账号下所有策略单元有效 | 质量门禁时标注或人类确认时升级 | 质量门禁 / 人类 |
| `platform` | 对同一平台下所有账号有效 | 人类确认时升级 | 人类 |
| `theory` | 对理论体系有效，跨账号跨平台 | 人类确认时标注或源体系忠实度门禁时标注 | 人类 / Source Fidelity Gate |

**门禁阶段的 scope 标注规则**：

1. **AI 生成阶段**：写作引擎抽取 EvidenceClaim 时，根据断言类型自动标注初始 scope
   - `factual` 断言 → `article`（除非涉及策略单元级规则）
   - `theory_inference` 断言 → `strategy_unit`（理论推导在同一策略单元内共享）
   - `value_judgment` 断言 → `article`（价值判断默认不推广）
   - `operation_hypothesis` 断言 → `strategy_unit`（运营假设按策略单元验证）

2. **质量门禁阶段**：门禁引擎可以补标或升级 scope
   - 如果断言命中 `strategy_unit` 级的禁忌或红线 → 升级到 `strategy_unit`
   - 如果断言涉及理论核心原则 → 升级到 `theory`
   - 如果断言存在跨账号影响（如平台规则类事实） → 标注为 `platform` 候选，等待人类确认

3. **人类确认阶段**：人类可以手动提升 scope
   - 人类确认"这条断言对所有账号都成立" → 升级到 `platform`
   - 人类确认"这条理论推导是正确的" → 升级到 `theory`

**规则约束**：
- scope 为 `platform` 或 `theory` 的断言，必须有人类确认记录（`ContentDecision`）
- 自动标注的 scope 可以在质量门禁中被修正，但修正必须记录原因
- `propagation_policy` 不得超越 scope 边界（`scope=article` 的断言 propagation 只能是 `isolated`）

### 2.2b ClaimGraph 复杂度控制

Phase 1 不实现完整图数据库，但必须把断言图谱的复杂度红线写入数据结构：

- `EvidenceClaim` 之间默认形成 DAG（有向无环图），禁止循环依赖和循环支撑
- 默认传播隔离级为 `strategy_unit + valid_time_window`
- 素材证伪、断言反证或证据过期时，先影响同策略单元、同时间窗口内的任务和发布物
- 只有 `risk_level=high/critical`、平台红线、事实错误，或人类确认后，才扩大到账号、平台或全局
- 图谱更新不得直接触发全盘召回，只能生成影响分析和召回候选

### 2.3 CognitiveDisturbanceEvent

把黄灯、红灯、异常数据和反证统一建模为认知扰动。

| 类型 | 触发 | 默认动作 |
|------|------|----------|
| `quality_anomaly` | 质量连续低分、重写失败 | 黄灯或橙灯 |
| `prediction_miss` | 预测与反馈明显偏离 | 黄灯，要求复盘 |
| `theory_drift` | 理论映射跑偏或核心原则被稀释 | 红灯或冻结 |
| `evidence_stale` | 关键证据过期或来源失效 | 冻结相关断言 |
| `negative_feedback_spike` | 发布后负反馈异常 | 红灯，召回评估 |
| `research_anomaly` | 出现反常证据或新问题 | 蓝灯，建议研究 |
| `algorithm_noise_overload` | 内部质量高但外部表现异常低，疑似平台机制或环境噪音 | 灰灯，延长观察窗口 |

扰动事件必须记录预测验证账本：

| 字段 | 含义 |
|------|------|
| `expected_signal` | 生成或发布前的预期 |
| `actual_signal` | 回收后的实际表现 |
| `calibration_delta` | 预期与实际的偏差 |
| `consecutive_miss_count` | 连续偏离次数 |
| `mutation_proposal_refs` | 由扰动触发的策略变更提案 |

当同一策略单元在同一维度连续 3 次 `calibration_delta` 超过阈值时，系统必须生成 `StrategyChangeProposal`，并在进化控制台亮黄灯或橙灯。该提案不得静默生效，必须等待人类确认或拒绝。

### 2.4 KnowledgeHydration

知识不是静态库存。人类反馈和历史规则要经过当前场景复水后才能注入写作或研究。

```text
干知识 + 当前账号 + 平台 + 内容类型 + 理论介入方式 + 目标读者 + 风险边界 = 活知识
```

系统不得把单次人类反馈直接晋升为全局规则。知识必须带上下文、置信度、证据和作用范围。

### 2.5 BoundaryDecision

高级自治必须知道何时停止。

| 决策 | 含义 |
|------|------|
| `write` | 可以进入内容或研究行动 |
| `draft_only` | 只生成草稿，不发布 |
| `store_candidate` | 暂存候选，等待更好时机 |
| `wait_human` | 需要人类裁决 |
| `freeze` | 风险或证据不足，冻结 |
| `not_write` | 明确不写，并记录理由 |

## 三、研究型扩展

ArtifactOS 面向科研和理论建设时，增加以下对象：

| 对象 | 作用 |
|------|------|
| `ResearchQuestion` | 从热点、异常或理论空缺中形成可研究问题 |
| `HypothesisContract` | 明确假设、适用边界、反证条件、所需证据 |
| `ClaimGraph` | 把断言、证据、反证和理论命题组织成图谱 |
| `FalsificationGate` | 主动寻找反例，不只寻找支持材料 |
| `TheoryRevisionProposal` | 当反常证据积累到阈值，提出理论映射或解释模型修正建议 |

理论核心原则禁止 AI 静默修改。系统只能提出提案，由人类确认、拒绝或要求继续收集证据。

### 片场级信号回收与归因

**双层回收架构**：平台级独立采集 + 片场级聚合归因。聚合只产生信号解释（SignalInterpretation）和归因决策（AttributionDecision），不直接改写理论或策略。

平台级：每个平台独立回收原始指标，维护自己的历史基线（rolling 30天均值），转化为超额表现率（实际/基线 - 1）。

片场级：同一片场（Studio）下的多个子片场（SubStudio）和产出物（Artifact）按发布包（PublicationPackage）回收信号事件。关键不在汇总数字，在于**差异分解**：
- 话题效应：所有平台都超预期 → 选题对了
- 策略效应：某平台显著跑赢 → 该平台策略配方是因果因子
- 噪音：差异不显著 → 不归因

**反馈回灌**：策略效应只生成策略变更提案（StrategyChangeProposal）；表达模式只生成保留模式候选（RetainedPatternCandidate）；新平台、新受众或年度工作缺口先生成机会候选（OpportunityCandidate），需要修改正式计划池时生成计划变更提案（PlanChangeProposal）；涉及源体系或理论边界时只生成反哺候选（BackfeedCandidate）。是否采纳由授权策略（DelegationPolicy）、介入策略（InterventionPolicy）、对应层级会议和人类裁决决定。

**A/B自然实验**：片场天然是多策略对比。不追求统计显著性（样本量不够），用贝叶斯更新——每次片场结果作为一次观测，逐步更新"理论介入度→效果"后验分布。积累10-20个片场后给出有指导意义的策略推荐。

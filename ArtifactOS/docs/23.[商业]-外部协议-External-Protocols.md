# 23 Part A: 吸引信号交接协议

> 核心定位：ArtifactOS 坚持“只发光、只吸引、不接引、不成交”。但媒体产出天然会产生共鸣、追问、误读和高意向信号，因此系统必须把这些信号结构化交接给外部承接系统，而不是在 ArtifactOS 内部做私域运营。

---

## 一、边界

ArtifactOS 做：

- 产出媒体产出物（Artifact）。
- 记录公开反馈和场域信号。
- 判断哪些信号代表同频、误读、传播种子或反哺候选。
- 生成交接对象（AttractionHandoff）。
- 把交接对象发送给外部系统或人工队列。

ArtifactOS 不做：

- 私聊接待。
- 销售成交。
- 咨询承接。
- 社群运营。
- 客服问答。
- 个人跟进任务。
- 私域状态维护。
- 医疗、法律、投资等高风险建议。

这保证系统不会从“吸引式灯塔”滑向“推销式漏斗”。

---

## 二、核心对象

| 中文对象 | English Object | 说明 |
|---|---|---|
| 共鸣信号 | ResonanceSignal | 读者收藏、转发、引用、长评、复述等同频迹象 |
| 读者问题 | ReaderQuestion | 公开评论或平台提问中的真实问题 |
| 高意向信号 | HighIntentSignal | 明确搜索更多、请求入口、询问体系或服务 |
| 误读风险 | MisreadRisk | 对源体系、边界或主张强度的误解 |
| 公开跟进候选 | PublicFollowupCandidate | 适合用下一篇公开内容回应的问题 |
| 外部目的地 | ExternalDestinationRef | 网站、小程序、CRM、人工队列或其他系统 |
| 吸引交接 | AttractionHandoff | ArtifactOS 向外部系统交出的结构化信号 |

---

## 三、信号分类

| 信号类型 | English Type | ArtifactOS 动作 |
|---|---|---|
| 同频共鸣 | `resonance` | 记录为 ResonanceSignal，可进入复盘 |
| 传播种子 | `repost_seed` | 提炼可传播点，不私聊催转发 |
| 公开追问 | `public_question` | 生成 PublicFollowupCandidate |
| 高意向 | `high_intent` | 生成 AttractionHandoff |
| 误读 | `misread` | 生成 MisreadRisk，可触发 FAQ 或边界文 |
| 反证/质疑 | `counter_signal` | 进入 SignalInterpretation / BackfeedCandidate |
| 噪声 | `noise` | 记录后进入遗忘系统，不主动交接 |

---

## 四、交接流程

```text
SignalEvent
  -> SignalInterpretation
  -> AttractionSignalClassification
  -> AttractionHandoffCandidate
  -> HandoffGate
  -> AttractionHandoff
  -> ExternalDestinationRef
```

### 4.1 HandoffGate

交接门禁（HandoffGate）检查：

1. 是否来自公开渠道或授权数据源。
2. 是否包含隐私或敏感内容。
3. 是否属于 ArtifactOS 不该承接的高风险咨询。
4. 是否需要先公开回应而不是私域交接。
5. 是否可能造成推销式打扰。
6. 是否试图保存或延续私聊上下文。

未通过时只能记录或生成公开跟进候选。

## 六、公开跟进优先

ArtifactOS 默认优先把读者问题转为公开产出，而不是私域互动：

```text
ReaderQuestion
  -> PublicFollowupCandidate
  -> ArtifactContract
  -> FAQ / 入口文 / 边界说明 / 系列文章
```

原因：

- 符合吸引式灯塔逻辑。
- 避免人类被私聊打断。
- 可让更多同频者看见同一回应。
- 公开回应本身也是产出物。

---

## 七、与 S0-S7 的关系

S0-S7 是受众认知状态假设，不是销售漏斗。

单个读者的 S0-S7 位置只能作为受众状态假设（AudienceStateHypothesis）记录，必须带证据引用、置信度、不确定性和替代状态；不得作为其真实心理或身份事实。

| 阶段 | ArtifactOS 处理 |
|---|---|
| S0-S2 | 主要通过公开内容显影和解释 |
| S3-S4 | 记录共鸣、转发点和误读 |
| S5-S6 | 可生成入口文、索引文、FAQ 或交接候选 |
| S7 | 记录传播种子，不做私域管理 |

S5-S7 出现高意向信号时，ArtifactOS 只生成交接对象，真正承接由外部系统处理。

### 7.1 硬边界（Hard Boundary）

`AttractionHandoff / 吸引交接` 只保存公开信号摘要、证据引用、允许动作和外部目的地引用：

- 不保存私聊状态（PrivateChatState）。
- 不生成个人跟进任务（PersonalFollowupTask）。
- 不维护用户关系阶段（RelationshipStage）。
- 不驱动私域回复（PrivateReply）。
- 不把高意向信号解释为成交线索（SalesLead）。

`PublicFollowupCandidate / 公开跟进候选` 只能生成新的公开产出物候选，例如入口文、FAQ、边界说明或系列文章，不能变成对某个个人的互动任务。

---

## 八、Phase 1 范围

Phase 1A 只做最小结构：

- `ResonanceSignal`
- `ReaderQuestion`
- `MisreadRisk`
- `PublicFollowupCandidate`
- `AttractionHandoff`
- `ExternalDestinationRef`

不做自动私信、CRM、客户管理、社群管理和成交流程。

---

## 九、硬约束

1. 吸引信号不能直接触发私聊。
2. 高意向不等于成交线索，必须经过 HandoffGate。
3. 公开问题优先生成公开跟进候选。
4. 误读优先生成边界说明或 FAQ 候选。
5. ArtifactOS 不保存或处理无关私域聊天。
6. 交接对象必须带来源和允许动作。
7. 外部承接系统的结果不能自动修改 SourcePack。
8. AttractionHandoff 不得保存私聊状态、个人跟进任务或关系阶段。
9. PublicFollowupCandidate 不得变成一对一互动任务。

# 23 Part B: 旧系统迁移与退出计划

> 核心定位：旧系统是当前真实生产和发布的兜底系统。ArtifactOS 不急于替换它，但必须有清晰迁移阶梯和退出条件，避免长期停留在影子记录层。

---

## 一、原则

1. 旧系统继续承担真实发布，直到 ArtifactOS 满足接管条件。
2. ArtifactOS 先做旁路验证，再逐步接管具体职责。
3. 每次接管只接管一个明确对象，不做整体替换。
4. 每个阶段都有回滚路径。
5. 旧系统退出不是删除，而是进入归档和回放状态。
6. **能力闭合度驱动**（裁决 #25C）：ArtifactOS 不以残缺可演示版本替换旧系统；进度按七层闭合度（规格→数据→流程→人机→影子→接管→退出）推进。首次真实运行采用第一接管面（First Operational Surface）方式，限定一个 SourcePack、一个主要平台和一个或少数成熟策略单元。
7. 某个接管面达到 `LegacyStage L3` 才表示有限真实接管；达到 `LegacyStage L4` 才表示该接���面成为主系统；达到 `LegacyStage L5` 才表示旧系统在该接管面归档。

---

## 二、迁移阶段

| 阶段 | 中文 | English | ArtifactOS 权限 | 旧系统职责 |
|---|---|---|---|---|
| LegacyStage L0 | 只读影子 | Read-only Shadow | 读取、生成、对照、记录偏差 | 全部真实生产发布 |
| LegacyStage L1 | 旁路助理 | Sidecar Assist | 生成建议、门禁报告、前夜预案 | 真实生成和发布 |
| LegacyStage L2 | 发布预检主责 | Publish Preflight Owner | 负责契约、门禁、发布包预检 | 最终发布执行 |
| LegacyStage L3 | 有限真实接管 | Limited Real Owner | 接管低风险成熟案真实发布 | 高风险和兜底 |
| LegacyStage L4 | 主系统 | Primary System | 常规生产和发布主责 | 备用与回滚 |
| LegacyStage L5 | 旧系统归档 | Legacy Archive | 只读回放和迁移证据 | 不再日常运行 |

---

## 三、阶段进入条件

### 3.1 LegacyStage L0 -> L1

条件：

- 连续 7 天 ShadowRun 完成。
- 每天有 DailyReport 和 NextDayPlan。
- ShadowRunObservation 能覆盖主要偏差。
- 微信摘要入口和 Amy 总控台可用。
- 旧系统未被干扰。

### 3.2 LegacyStage L1 -> L2

条件：

- ArtifactOS 门禁报告连续 14 天可用。
- 前夜审阅流程稳定。
- 旧系统发布前能使用 ArtifactOS 的 PublicationPackage 预检。
- 人类认为预检结果减少了返工。

### 3.3 LegacyStage L2 -> L3

条件：

- 第一接管面（一元论 SourcePack + 知乎 + 首接策略单元）的 7 天影子运行完成。
- 至少一个 StrategyUnit 达到 StrategyUnitMaturity M2。
- 低风险产出物连续 30 天无红线事故。
- ArtifactOS 发布包与旧系统真实发布偏差可解释。
- 回滚和暂停机制验证通过。
- RealPublishGate 所有输入可由数据库事实验证，不能只由界面按钮确认。
- SameDayException 未被滥用。
- 旧系统在该接管面降为兜底，不再做主责动作。

### 3.4 LegacyStage L3 -> L4

条件：

- 至少一个 StrategyUnit 达到 StrategyUnitMaturity M3，但升级必须有人类决策记录。
- SameDayException 未被滥用。
- 发布失败、召回、冻结、解封全链路可回放。
- 旧系统连续一个周期只作为兜底，没有主责动作。

### 3.5 LegacyStage L4 -> L5

条件：

- 旧系统所有仍需读取的数据已迁移或建立引用。
- ArtifactOS 能回放关键历史产出。
- 用户确认不再需要旧系统日常运行。

---

## 四、退出阈值

任一阶段出现以下情况必须停止升级或回退：

| 条件 | English Condition | 动作 |
|---|---|---|
| 真实发布受影响 | RealPublishInterference | 回退到上一阶段 |
| 红线错误 | RedlineFailure | 冻结对应 StrategyUnit |
| SourcePack 越界 | SourceBoundaryBreach | 停止相关产出 |
| 旧系统偏差不可解释 | UnexplainedLegacyDeviation | 延长影子期 |
| 人类负担上升 | HumanLoadIncrease | 降低通知和接管范围 |
| 微信通道不稳定 | WeixinInstability | 回退 Amy 总控台 |

## 六、回滚协议

ArtifactOS 每次接管动作必须有回滚方案：

```text
 takeover_action
   -> rollback_owner
   -> rollback_trigger
   -> rollback_steps
   -> data_integrity_check
   -> human_notification
```

回滚不等于删除 ArtifactOS 记录。所有接管、失败和回滚都写入 EventLedger。

旧系统在首接面保留完整的真实发布能力和历史数据作为回滚目标。ArtifactOS 出现红线级事故、持续发布失败不可恢复、回滚链路执行失败或 SourcePack 主权被错误使用时，可立即切回旧系统，原接管面降回 `LegacyStage L1` 或 `L0` 等待修复。旧系统不主动在同一接管面生产新内容，但可作为应急发布方。

---

## 七、Phase 1A 只做什么

Phase 1A 只完成 LegacyStage L0：

- 读取旧系统计划、暂存稿、报告和发布结果。
- 生成 ArtifactOS 影子候选。
- 生成 ShadowRunObservation。
- 生成 7 天复盘报告。
- 不接管真实发布。
- 不修改旧系统数据。

### 7A.1 旧系统知乎发布数据导入对照基线

旧系统的知乎历史发布数据通过三级导入进入 ArtifactOS 做对照基线：

```text
LegacyImportBatch
  -> LegacyExternalRef（每条知乎发布记录：URL、标题、发布日期、平台指标外部引用）
  -> LegacySnapshot（同日指标快照的哈希+mtime 冻结）
  -> ShadowRunComparisonPair（按 topic/platform/date 配对新系统模拟产物与旧系统真实产物）
```

导入规则：旧系统 URL 和平台指标作为外部事实引用保存，不完全复制正文；旧系统账号、发布时间窗口和主题标签作为对照配对键；旧系统无法追溯的隐式决策（如"为什么那天不发"）只在偏差中以 `unobservable` 标记。

### 7A.2 影子运行模拟发布数据的接管后归档

进入真实接管后，7 天 Shadow Run 期间积累的模拟发布数据不得直接混入真实发布记录，也不得删除：

```text
SimulatedPublicationAttempt（保留为 ShadowRunArchive）
ShadowRunObservation（保留为复盘材料）
DryRunAdapter 输出（保留为迁移证据）
```

所有模拟数据在 `run_mode='shadow'` 结束后标记 `archived_at`，复盘链路可回查，但不得进入 ProductionRecord 统计和 RealPublishGate 审计。

---

## 八、硬约束

1. 没有 ShadowRunReviewReport，不得进入 LegacyStage L1。
2. 没有回滚协议，不得接管真实发布。
3. 没有人类决策记录，不得让 Amy 自升 StrategyUnitMaturity M3/M4。
4. 旧系统退出必须是阶段性退出，不是一次性删除。
5. 旧系统数据迁移必须保留原始引用。
6. ArtifactOS 与旧系统不一致时，默认记录偏差，不默认判定谁对。

---

## 九、LegacySystemBridge 只读导入接口

旧系统迁移桥（LegacySystemBridge）首期只读，不接管、不回写、不删除旧系统数据。

| 对象 | 来源 | 目标用途 |
|---|---|---|
| `LegacyDailyPlan` | 旧每日计划 | 与 DayCase / NextDayPlan 对照 |
| `LegacyStagingArtifact` | 旧暂存稿 | 与 Artifact / ArtifactVersion 对照 |
| `LegacyQualityReport` | 旧质量报告 | 与 QualitySnapshot 对照 |
| `LegacyPublicationRecord` | 旧发布记录 | 与 PublicationRecord / SignalEvent 对照 |
| `LegacyPipelineOutput` | 旧生成流水线输出 | 偏差分析与样例回放 |

`LegacyImportBatch` 最小字段：

```yaml
legacy_import_batch:
  batch_id: string
  source_system: BetterCiv_tools
  source_root: D:\_Progs\.BetterCiv\tools
  imported_at: timestamp
  import_mode: read_only
  object_counts:
    daily_plan: integer
    staging_artifact: integer
    quality_report: integer
    publication_record: integer
  checksum_manifest: object
  errors: array
```

安全边界：LegacySystemBridge 不执行发布、不修改旧系统文件；旧系统数据进入 ArtifactOS 后必须带 `legacy_external_ref`；LegacyDiff 只能生成差异、候选或人工审阅卡，不能自动改变策略或 SourcePack。

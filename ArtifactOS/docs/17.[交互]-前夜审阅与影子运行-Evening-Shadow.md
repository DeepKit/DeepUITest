# 17 Part A: 前夜审阅与影子运行协议

> 核心定位：ArtifactOS 的默认发布节奏不是“当天审当天发”，而是“前夜审明日特别文件，次日轻确认与发布”。当天发布只作为受控例外；首个版本先做 7 天影子运行。

---

## 一、默认运行节奏

默认节奏固定为：

```text
D 日白天：生成 D+1 发布候选
D 日晚上：审 D+1 特别文件，确认明日预案
D 日夜间：Amy 按意见修正、重跑门禁、重建发布包
D+1 早上：轻确认夜间修正结果
D+1 白天：按确认后的发布计划执行
```

这替代“当天生成、当天审、当天发”的紧张模式。

核心原则：

> 人类前一晚做判断，Amy 夜间修正，次日早上只做轻确认，白天按预案执行。

---

## 二、今晚工作页

今晚工作页（Evening Work Page）是每日主操作面：

```text
今晚工作页（EveningWorkPage）
  -> 今日日报（DailyReport）
  -> 今日未收束事项（UnclosedItem）
  -> 明日预案（NextDayPlan）
  -> 明日待发布审阅（TomorrowPublishReview）
  -> 每日精选审阅（DailyCalibrationReview）
  -> 明日提醒规则（TomorrowReminderRule）
  -> 晚间提交（EveningCommit）
```

晚上要完成三件事：

1. 收束今天。
2. 审明天要发的重点文件。
3. 确认或调整明日预案。

---

## 三、明日待发布审阅

明日待发布审阅（TomorrowPublishReview）专门处理第二天计划发布的重点产出物。

```text
NextDayPlan
  -> TomorrowPublishBatch
    -> TomorrowPublishCandidate
      -> Artifact
      -> PlannedPublicationWindow
      -> EveningReviewStatus
      -> OvernightRevisionStatus
      -> MorningConfirmationStatus
```

### 3.1 批次动作

```text
1. 按 Amy 建议审阅
2. 全部推迟到后天
3. 只审重点文件
4. 只发已成熟案
5. 明天只生成不发布
6. 夜间自动返工低风险项
7. 冻结明日发布批次
8. 交给 Amy 按授权处理
9. 重新生成明日发布批次
0. 我来输入
[返回上一级] [取消当次]
```

### 3.2 单文件动作

```text
1. 同意 Amy 建议修正
2. 保持原稿明天发布
3. 降低理论显性
4. 重写标题
5. 重写开头
6. 推迟到后天
7. 冻结此稿
8. 交给 Amy 明早前处理
9. 重新生成此稿
0. 我来输入
[返回上一级] [取消当次]
```

### 3.3 硬约束

1. 默认不当天审当天发。
2. 第二天要发的重点文件，前一晚进入 TomorrowPublishReview。
3. 前一晚审阅后，Amy 必须有夜间修正窗口。
4. 夜间修正必须生成新版本和门禁记录。
5. 次日早上只做轻确认，不做完整审稿。
6. 如果前一晚未审，成熟案按授权策略执行，新案/高风险案不得自动发。

---

## 四、明日预案

明日预案（NextDayPlan）不是正式日案（DayCase），而是次日执行草案。

```text
DailyReport
  -> NextDayPlan
    -> NextDayPlanVersion
    -> TomorrowPublishBatch
    -> TomorrowReminderRule
    -> MorningLightConfirmation
```

次日到点后：

```text
已授权成熟案：
  NextDayPlan -> DayCase 自动提交

需确认新案/边界案：
  等待 MorningLightConfirmation

夜间或次日出现重大变化：
  Amy 生成差异提醒，不静默执行
```

### 4.1 NextDayPlan 必含字段

```text
来源日案（source_day_case_id）
目标日期（target_date）
父级约束快照（WeekCase / MonthCase Snapshot）
明日今日子案候选（DaySubCaseCandidate）
明日片场候选（StudioCandidate）
预计产出物（PlannedArtifact）
自动执行清单（AutoRunList）
待人类确认清单（NeedsHumanList）
明日待发布批次（TomorrowPublishBatch）
明日提醒规则（TomorrowReminderRule）
状态（draft / proposed / confirmed / promoted / canceled）
```

### 4.2 约束

1. NextDayPlan 必须受 WeekCase / MonthCase 边界约束。
2. NextDayPlan 不能静默改变授权策略。
3. NextDayPlan 不能越过红线。
4. 已确认 NextDayPlan 次日才能转为 DayCase。
5. 新案、边界案、红线案必须轻确认或请示。

---

## 五、当天例外发布

当天例外发布（SameDayException）是受控快车道，只处理“今天必须发，明天价值明显下降”的机会。

### 5.1 允许进入条件

| 条件 | English Object | 说明 |
|---|---|---|
| 突发热点 | BreakingHotspot | 新闻、行业事件、平台热议 |
| 强场域机会 | StrongFieldOpportunity | 同频受众短时间聚集 |
| 成熟模板可用 | MatureTemplateAvailable | 不是从零生成，只是成熟模板适配 |
| 发布窗口极短 | ShortPublicationWindow | 话题 6-12 小时衰减 |
| 人类明确要求 | HumanExplicitOverride | 人类指定今天必须发 |

### 5.2 不允许进入条件

```text
理论高风险
需要新概念解释
证据不足
平台规则不熟
新账号定位不稳定
涉及 SourcePack 边界
会造成长期策略改变
```

### 5.3 流程

```text
SignalEvent / FieldOpportunity
  -> SameDayOpportunity
  -> SameDayExceptionProposal
  -> FastGateResult
  -> Artifact / PublicationPackage
  -> FastReviewSummary
  -> ApprovalRecord
  -> SameDayPublicationRecord
```

FastGate 最低包含：

```text
红线检查（Redline Check）
事实风险检查（Fact Risk Check）
理论越界检查（Source Boundary Check）
平台适配检查（Platform Fit Check）
发布包完整检查（Package Check）
```

### 5.4 硬约束

1. SameDayException 是例外路径，不是默认调度策略。
2. 当天例外必须有机会原因和时间窗口。
3. 当天例外必须经过 FastGate。
4. 高理论风险、新概念、SourcePack 边界事项不能当天自动发。
5. 自动当天发布只允许成熟案和低风险平台。
6. 当天发布必须在日报中单独标记。
7. 当天例外不能静默改变长期策略。
8. 人类 override 也必须留痕。
9. 事实来源不稳时，只能草稿或延后。

## 六、成熟度与自动权限

成熟度（MaturityLevel）绑定到：

```text
策略单元（StrategyUnit）
  + 当前案约束（Case Constraint）
```

不绑定单篇产出物，也不全局泛化。

### 6.1 等级

本节的 `M0-M4` 只表示策略单元成熟度（StrategyUnitMaturity），不是开发里程碑；开发路线统一使用 Phase 命名。

| 策略单元成熟度（StrategyUnitMaturity Level） | 中文 | English | 权限 |
|---|---|---|---|
| M0 | 候选案 | Candidate Case | 只能提案和生成草稿 |
| M1 | 试运行案 | Trial Case | 可生成和门禁，发布必须审 |
| M2 | 稳定生产案 | Stable Production Case | 可自动生成、返工、暂存，发布谨慎 |
| M3 | 成熟发布案 | Mature Publishing Case | 可自动审片和发布低风险内容 |
| M4 | 成熟运营案 | Mature Operating Case | 可自动安排节奏和处理常规异常 |

### 6.2 权限矩阵

| 能力 | M0 | M1 | M2 | M3 | M4 |
|---|---|---|---|---|---|
| 生成草稿 | 可 | 可 | 自动 | 自动 | 自动 |
| 自动返工 | 否 | 可 | 自动 | 自动 | 自动 |
| 进入明日发布候选 | 否 | 可 | 自动 | 自动 | 自动 |
| 自动发布普通内容 | 否 | 否 | 视授权 | 可 | 可 |
| SameDay 自动发布 | 否 | 否 | 否 | 低风险可 | 低风险可 |
| 自动调整节奏 | 否 | 否 | 否 | 建议 | 可 |
| 改变长期策略 | 否 | 否 | 否 | 否 | 只能提案 |

该矩阵只定义策略单元成熟度的自治上限。任何真实发布仍必须通过真实发布门（RealPublishGate），不能只凭 StrategyUnitMaturity 或按钮授权执行。

### 6.3 升降级约束

1. Amy 可以建议升级，但不能自升到 StrategyUnitMaturity M3/M4。
2. Amy 可以自动降级或冻结。
3. StrategyUnitMaturity M3/M4 仍不能越过 SourcePack、红线、年度战略、账号长期定位。
4. StrategyUnitMaturity M3/M4 自动发布必须在日报中标记。
5. SameDay 自动发布只允许 StrategyUnitMaturity M3/M4 低风险事项。
6. 每次升级、降级、冻结都必须有证据和记录。

## 七、首个影子运行

首个版本先做 7 天影子运行（Shadow Run），不急于接管真实生产。

本节只定义原则。可执行规格、每日输入输出、工作卡、旧系统对照、偏差记录和 7 天复盘见 `17.[交互]-前夜审阅与影子运行-Evening-Shadow.md`。

```text
运行方式：影子运行（Shadow Run）
周期：连续 7 天
主平台：知乎（Zhihu）
目标受众：S1-S3
理论显性度：中显性（Medium Theory Visibility）
真实发布：旧系统继续承担
ArtifactOS：生成、审阅、留痕、预案和模拟调度
```

### 7.1 每日流程

```text
白天：
  Amy 生成次日候选产出物（TomorrowPublishCandidate）

晚上：
  微信发送今晚工作页入口（EveningWorkPage Entry）
  人类查看今日日报（DailyReport）
  人类审明日特别文件（TomorrowPublishReview）
  人类可审 1 个每日精选产出物（DailyCalibrationReview）
  人类确认明日预案（NextDayPlan）

夜间：
  Amy 按意见修改版本、重跑门禁、准备发布包

第二天早晨：
  只呈现轻确认（MorningLightConfirmation）和夜间改动摘要

第二天白天：
  新系统模拟执行；真实发布仍走旧系统
```

### 7.2 7 天后复盘指标

```text
每晚处理时间是否控制在 15-30 分钟
Amy 推荐是否大体正确
前夜审阅是否比当天赶审更稳
哪些按钮真正常用
哪些产出物被判为正向/反向范本
哪些事项本应自动处理却打扰了人类
哪些事项本应请示却被 Amy 放过
NextDayPlan 与真实次日动作偏差
SameDayException 是否被滥用
```

### 7.3 影子运行硬约束

1. 影子运行不接管真实发布。
2. 真实发布仍由旧系统兜底。
3. ArtifactOS 必须完整记录预案、审阅、门禁、模拟发布和偏差。
4. 每天必须生成 DailyReport 和 NextDayPlan。
5. 每天最多一个 DailyCalibrationReview。
6. 7 天结束后再确定 Phase 1 正式实现优先级。
7. 每天必须至少尝试生成 ShadowRunObservation；没有偏差也要记录为 `no_material_deviation`。
8. 旧系统对照只能形成偏差和候选，不能直接修改长期规则或 SourcePack。

## Part B: 首个 7 天影子运行规格

> 本部分来自原 17.[交互]-前夜审阅与影子运行-Evening-Shadow.md。前夜审阅协议见 Part A。

# 17 Part B: 首个 7 天影子运行规格

> 核心定位：首个 7 天影子运行（Shadow Run）是 ArtifactOS 的第一轮真实世界验收，不接管真实发布，不替代旧系统，只验证“源体系驱动、前夜审阅、Amy 工作台、微信摘要入口、旧系统对照、偏差学习”这一整套运行框架是否成立。

---

## 一、运行目标

7 天影子运行不是演示，也不是灰度上线。它要回答六个问题：

1. ArtifactOS 能否在不接管真实发布的情况下，完整生成次日内容计划。
2. Amy 能否把复杂后台工作压缩成少量可审工作卡（WorkCard）。
3. 前夜审阅（Evening Review）是否比当天赶审更稳定。
4. `1-8/9/0` 准备动作协议（Prepared Action Protocol）是否足够高效。
5. ArtifactOS 生成的计划与旧系统真实执行之间偏差在哪里。
6. 哪些规则、范本、召回、授权边界应该进入下一阶段实现。

验收对象不是单篇文章质量，而是运行框架：

```text
SourcePackSnapshot
  -> WeekCase / DayCase / DaySubCase
  -> Studio / SubStudio
  -> Artifact / PublicationPackage
  -> DailyReport / NextDayPlan
  -> ShadowRunObservation
  -> 7-Day Review
```

## 二、运行边界

### 2.1 默认配置

| 配置项 | English Object | 默认值 |
|---|---|---|
| 运行模式 | RunMode | `shadow` |
| 周期 | RunWindow | 连续 7 天 |
| 主平台 | PrimaryPlatform | 知乎（Zhihu） |
| 目标受众 | AudienceStageScope | S1-S3 |
| 理论显性度 | TheoryVisibility | 中显性（Medium） |
| 源体系 | SourcePack | 一元论 SourcePack |
| 真实发布 | RealPublishingOwner | 旧系统 |
| 新系统动作 | ArtifactOSAction | 生成、审阅、门禁、预案、模拟执行、偏差记录 |
| 人类入口 | HumanInterface | Amy 总控台 + 微信日报入口 |

### 2.2 允许做什么

- 生成次日候选产出物（TomorrowPublishCandidate）。
- 生成明日预案（NextDayPlan）。
- 生成今晚工作页（EveningWorkPage）。
- 通过微信发送日报入口卡（DailyReportEntryCard）。
- 让人类在日报详情页（DailyReportDetailView）审阅、选择、跳过或输入。
- 模拟发布调度、记录发布包、记录门禁结果。
- 读取旧系统的 staging、计划、报告和真实发布结果，形成对照。
- 生成影子运行观察记录（ShadowRunObservation）。

### 2.3 禁止做什么

1. 不接管真实发布。
2. 不替换旧系统的真实生产职责。
3. 不把微信当作完整审稿界面。
4. 不用邮件日报。
5. 不把当天审当天发设为默认路径。
6. 不因 7 天数据直接修改 SourcePack 母板。
7. 不把旧系统差异解释为 ArtifactOS 必然正确。
8. 不在影子运行期间自动升到 StrategyUnitMaturity M3/M4。
9. 不通过 RealPublishGate；Phase 1A 所有发布包必须 `simulation_only=true`。

## 三、运行节奏

默认节奏固定为：

```text
D 日白天：
  ArtifactOS 生成 D+1 候选、门禁报告、发布包草案

D 日晚上：
  Amy 生成今晚工作页
  微信发送日报入口卡
  人类审阅 D+1 特别文件、明日预案和每日精选审阅

D 日夜间：
  Amy 根据人类选择修正、重跑门禁、重建发布包

D+1 早上：
  Amy 提供轻确认摘要
  新案/边界案/红线案等待确认

D+1 白天：
  ArtifactOS 模拟执行
  旧系统继续真实发布

D+1 晚上：
  ArtifactOS 对照旧系统真实动作，形成偏差和日报
```

这意味着人类主要在晚上工作，早上只处理轻确认或异常。

### 3.1 日期字段语义

影子运行必须明确每个对象对应哪一天，避免把“今晚审明天”实现成“当天审当天发”。

| 字段 | English Field | 含义 |
|---|---|---|
| 日报归属日 | `report_for_date` | 日报总结的日期，通常是 D |
| 审阅目标日 | `review_target_date` | 今晚审阅的明日日期，通常是 D+1 |
| 旧系统真实动作日 | `legacy_actual_date` | 旧系统真实发布或执行的日期，通常是 D+1 |
| 生成时间 | `generated_at` | Amy 生成候选、预案或日报的时间 |
| 截止时间 | `cutoff_at` | 当天纳入日报或对照的事实截止时间 |

Day 0 是准备日，不要求有完整旧系统对照，但必须生成第 1 天的 `NextDayPlan` 草案和 `ShadowRunInputPack`。

## 四、每日输入

每天开始前，Amy 必须组装影子运行输入包（ShadowRunInputPack）。

| 输入 | English Object | 来源 | 必需性 |
|---|---|---|---|
| 源体系快照 | SourcePackSnapshot | SourcePack 装载器 | 必需 |
| 周案快照 | WeekCaseSnapshot | 会议体系 | 必需 |
| 当日日案 | DayCase | 会议体系 / Amy 草案 | 必需 |
| 今日子案候选 | DaySubCaseCandidate | 周案、信号、人工输入 | 必需 |
| 旧系统计划 | LegacyPlanRef | 原写作系统 | 必需 |
| 旧系统暂存稿 | LegacyStagingRef | 原写作系统 | 可选 |
| 旧系统报告 | LegacyReportRef | 原写作系统 | 可选 |
| 平台规则 | PlatformConstraint | 知乎适配器 | 必需 |
| 人类前一晚选择 | HumanReviewChoice | Amy 工作台 / 微信回复 | 从第 2 天起必需 |
| 强召回卡 | RecallCard | 遗忘系统 | 可选 |

输入包必须记录来源和时间点，不能用“当前目录最新文件”这种隐式事实作为证据。

## 五、每日输出

每天必须生成以下输出：

| 输出 | English Object | 说明 |
|---|---|---|
| 日报 | DailyReport | 当日工作、异常、旧系统对照、明日建议 |
| 日报入口卡 | DailyReportEntryCard | 微信摘要入口，不承载完整正文 |
| 日报详情页 | DailyReportDetailView | 完整阅读和处理页面 |
| 明日预案 | NextDayPlan | D+1 执行草案 |
| 明日预案版本 | NextDayPlanVersion | 每次重生成或人类修改后的版本 |
| 明日待发布批次 | TomorrowPublishBatch | D+1 候选发布批次 |
| 明日待发布候选 | TomorrowPublishCandidate | 具体候选产出物 |
| 工作卡 | WorkCard | Amy 摆在桌面上的可处理对象 |
| 准备动作面板 | PreparedActionPanel | `1-8/9/0` 选择面板 |
| 每日精选审阅 | DailyCalibrationReview | 每天最多一个认真审阅对象 |
| 影子运行日 | ShadowRunDay | 当天影子运行汇总 |
| 影子运行观察 | ShadowRunObservation | artifact/计划/门禁/旧系统偏差的结构化记录 |

如果某天人类完全没有打开系统，ArtifactOS 仍必须生成日报、明日预案和观察记录，但状态标记为 `human_not_reviewed`，不得伪造人工确认。

每日精选审阅（DailyCalibrationReview）默认每天推荐一个对象；如果没有合格对象，Amy 必须记录 `no_candidate_reason`。人类可以跳过，但必须记录 `skip_reason`。推荐卡应显示选择理由、建议审阅焦点和预计耗时。

## 六、今晚工作页

今晚工作页（EveningWorkPage）是 7 天影子运行的主操作页。

```text
EveningWorkPage
  -> DailyReportCard
  -> TomorrowPublishReviewCard
  -> NextDayPlanCard
  -> DailyCalibrationReviewCard
  -> LegacyDiffCard
  -> ExceptionCard
  -> EveningCommitCard
```

### 6.1 必备工作卡

| 工作卡 | English Object | 目的 |
|---|---|---|
| 今日日报卡 | DailyReportCard | 快速看当天发生了什么 |
| 明日发布审阅卡 | TomorrowPublishReviewCard | 审 D+1 重点候选 |

| 旧系统对照卡 | LegacyDiffCard | 看 ArtifactOS 与旧系统计划差异 |
| 异常卡 | ExceptionCard | 只呈现需要人类知道的异常 |
| 晚间提交卡 | EveningCommitCard | 收束当晚选择，触发夜间处理 |

每张卡必须标注处理要求：

```text

```

## 七、旧系统迁移桥

旧系统迁移桥（Legacy System Bridge）只做读取、对照和记录，不接管旧系统。

完整迁移阶段、接管条件、退出阈值和回滚协议见 `23.[商业]-外部协议-External-Protocols.md`。本规格只覆盖 LegacyStage L0 只读影子阶段，但影子运行的输入和对照对象必须与第一接管面（一元论 SourcePack + 知乎 + 首接策略单元）一致。

### 7.1 读取对象

| 旧系统资产 | English Object | ArtifactOS 对照 |
|---|---|---|
| staging 文章 | LegacyStagingArtifact | Artifact / ArtifactVersion |
| 每日计划 | LegacyDailyPlan | DayCase / NextDayPlan |
| 质量报告 | LegacyQualityReport | QualityGateResult / CognitionTraceCandidate |
| 发布记录 | LegacyPublicationRecord | PublicationRecord / ShadowRunObservation |
| 旧脚本输出 | LegacyPipelineOutput | ArtifactArchive / EventLedger seed |

### 7.2 对照类型

| 对照类型 | English Object | 说明 |
|---|---|---|
| 选题偏差 | TopicDeviation | 两边选择的话题不同 |
| 节奏偏差 | ScheduleDeviation | 计划发布时间或顺序不同 |
| 质量偏差 | QualityDeviation | 门禁/人工判断不同 |
| 理论显性偏差 | TheoryVisibilityDeviation | 理论表达强度不同 |
| 平台适配偏差 | PlatformFitDeviation | 标题、长度、格式或标签不同 |
| 发布动作偏差 | PublicationActionDeviation | 旧系统真实发布，新系统只模拟 |
| 人类选择偏差 | HumanChoiceDeviation | 人类选择与 Amy 推荐不同 |

### 7.3 记录规则

每个偏差都必须写成影子运行观察（ShadowRunObservation）：

```text
ShadowRunObservation
  -> observation_type
  -> artifactos_ref
  -> legacy_ref
  -> expected_action
  -> legacy_actual_action
  -> simulated_action
  -> deviation_type
  -> severity
  -> evidence_refs
  -> learning_candidate
```

旧系统是对照对象，不是自动真理源。ArtifactOS 也不是自动正确方。偏差只能说明“需要复盘”，不能直接生成长期规则。

## 八、模拟执行

影子运行中的模拟执行（Simulated Execution）必须尽量接近真实发布前流程，但最后一步不提交平台。

```text
Artifact
  -> ArtifactVersion
  -> QualityGateResult
  -> Rendition
  -> PublicationPackage
  -> SimulatedPublicationAttempt
  -> ShadowRunObservation
```

模拟执行必须检查：

1. 发布包是否完整。
2. 平台字段是否齐全。
3. 标题、正文、标签、封面或图片是否满足目标平台。
4. 是否命中红线或 SourcePack 边界。
5. 如果接入真实发布器，能否走到提交前一步。

模拟执行不允许点击最终发布按钮。

影子运行必须有技术级隔离，不得只依赖操作流程：

```text
run_mode in ('shadow', 'simulation') 时：
  PublicationPackage.simulation_only = true
  RealPublishGate = BLOCKED
  只能调用 DryRunAdapter / MockPublishingAdapter
  不得生成真实 platform_url
  PublicationRecord.status 只能为 simulated
  不得创建真实 media_publish job
```

模拟链路可以生成 `simulated_url`（例如 `simulated://zhihu/package/{id}`）供报告和前端引用，但不得与真实平台链接混用。数据库或服务层必须提供 `trg_shadow_publish_isolation_guard` 等硬校验，阻止误触真实发布。

- 每天有 NextDayPlan。

### Day 3-4：前夜审阅

目标：验证前夜审阅和夜间修正是否减少第二天压力。

验收：

- TomorrowPublishCandidate 能进入 evening_reviewing。

目标：识别 ArtifactOS 与旧系统之间最有价值的差异。

5. 哪些事情可以授权 Amy 自动处理。
6. 哪些事情必须保留人类裁决。
7. 旧系统迁移的下一步是什么。

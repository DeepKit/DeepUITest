# 20 会议体系与计划治理协议

> 文档性质：会议协议（Meeting Protocol）+ 计划治理规格（Plan Governance Specification）
>
> 适用产品（product）：演擎（ArtifactOS）
>
> 核心职责：定义年会、半年会、季度会、月会、周会、日晨会各自讨论什么、禁止讨论什么、产出什么结构化文件，以及全年如何动态增加计划、减少计划和调整计划。

---

## 一、总原则

ArtifactOS 的会议体系不是普通会议纪要系统，而是案场操作系统的上层治理协议。每一场会都必须生成结构化案（Case）或案的修订记录，供下层会议、秘书、AI 岗位、状态机、遗忘系统和审计系统引用。

### 1.1 六层计划层级

| 层级 | 会议（Meeting） | 输出案（Case） | 计划性质（Planning Nature） | 核心问题 |
|---|---|---|---|---|
| 年度 | 年会（Annual Meeting） | 年案（YearCase） | 战略执行（Strategic Execution） | 今年战略如何执行 |
| 半年 | 半年会（Half-Year Meeting） | 半年案（HalfYearCase） | 战略调整（Strategic Adjustment） | 年内哪些战略要加、减、调 |
| 季度 | 季度会（Quarterly Meeting） | 季案（QuarterCase） | 战略安排（Strategic Arrangement） | 本季度如何组织战略动作 |
| 月度 | 月会（Monthly Meeting） | 月案（MonthCase） | 战略落地（Strategic Landing） | 本月如何把战略变成可运行计划 |
| 每周 | 周会（Weekly Meeting） | 周案（WeekCase） | 战术安排（Tactical Arrangement） | 本周如何安排具体战术动作 |
| 每日 | 日晨会（Daily Meeting） | 日案（DayCase）/今日子案（DaySubCase） | 战术落地（Tactical Execution） | 今天执行什么，授权到哪一步 |

边界原则：

```text
年会定战略执行，不排日程。
半年会调战略，不重开全年方向。
季度会做战略安排，不新增脱离年案的主海域。
月会做战略落地，不推翻季案（QuarterCase）的战略安排。
周会做战术安排，不重设月案（MonthCase）的灯塔位置。
日晨会做战术落地，不重新战略化。
```

### 1.2 案与计划的关系

ArtifactOS 使用案（Case）承载计划（Plan）。二者关系如下：

| 中文 | 英文 | 说明 |
|---|---|---|
| 年案 | YearCase | 承载年计划（YearPlan）和年度战略执行边界 |
| 半年案 | HalfYearCase | 承载半年计划（HalfYearPlan）和战略调整记录 |
| 季案 | QuarterCase | 承载季度计划（QuarterPlan）和战略安排 |
| 月案 | MonthCase | 承载月度计划（MonthPlan）和战略落地 |
| 周案 | WeekCase | 承载周计划（WeekPlan）和战术安排 |
| 日案 | DayCase | 承载日计划（DayPlan）和战术落地 |
| 今日子案 | DaySubCase | 承载某主题当天是否行动、授权到哪一步 |

下层案只能继承、展开或提出变更。它不能静默改写上层案。

### 1.3 动态计划不是例外

年案（YearCase）不是一次年会写死全年。全年动态变化必须作为一等能力建模：

| 动作 | 英文 | 含义 |
|---|---|---|
| 增加计划 | AddPlan | 把新平台、新媒体、新主题、新受众、新内容形态纳入计划 |
| 减少计划 | DropPlan | 暂停、降级或移出低价值方向 |
| 调整计划 | RebalancePlan | 调整资源、优先级、平台组合、节奏或授权 |

系统可以随时发现机会，但不能静默改年案。任何新增、减少或调整都必须形成计划变更提案（PlanChangeProposal），再由对应层级会议处理。

### 1.4 战略意图资产层（Strategic Intent Asset Layer）

会议体系必须沉淀 `StrategicIntentAssetLayer / 战略意图资产层`。它不是写作模板，而是把长期灯塔、阶段案目标和目的组合固化为可追溯资产，供未来更强的 AI 放大执行。

| 对象 | English | 职责 |
|---|---|---|
| 灯塔策略目标 | LighthouseStrategyObjective | 定义长期要在哪个场域成为怎样的灯塔 |
| 案目标 | CaseObjective | 定义某个时间案要推进哪一段战略 |
| 目的组合 | PurposePortfolio | 定义本案中九类 PurposeType 的比例、数量、节奏和优先级 |
| 目的策略绑定 | PurposePolicyBinding | 把单篇目的、平台、账号、受众状态和媒体形态解析为蓝图、质量策略和 Amy 动作策略 |
| 决策谱系 | DecisionLineage | 记录目标、组合、绑定变化的理由、证据、批准人、版本和影响范围 |

`LighthouseStrategyObjective / 灯塔策略目标` 必须记录：

| 字段 | English | 说明 |
|---|---|---|
| 场域位置 | field_position | 选择哪个海域、媒体、平台或账号阵地 |
| 身份占位 | identity_positioning | 希望外部如何理解该账号或源体系 |
| 信任建立目标 | trust_building_goal | 长期建立哪一种可信度 |
| 受众状态路径 | audience_state_path | S0-S7 哪些人会被吸引，期望发生什么微迁移 |
| 边界姿态 | boundary_posture | 哪些误解、过度承诺或冲突方式必须挡住 |
| 平台账号角色 | platform_account_role | 每个平台和账号承担的战略功能 |
| 非目标 | non_goals | 明确不追求的受众、流量或表达方向 |

`CaseObjective / 案目标` 必须记录：

| 字段 | English | 说明 |
|---|---|---|
| 时间范围 | time_scope | year / half_year / quarter / month / week / day / day_sub |
| 战略任务 | strategic_task | 本期推进什么，而不是本期写几篇 |
| 目标优先级 | objective_priority | 本期更重吸引、解释、补证、边界还是放大 |
| 约束 | constraints | 继承的上层边界、本层禁区和必须覆盖项 |
| 成功判据 | success_criteria | 是否完成战略功能，而不是单看流量 |
| 目的组合 | purpose_portfolio | 本期 `PurposeType / 目的类型` 的组合策略 |

`PurposePortfolio / 目的组合` 不是固定模板。它必须由：

```text
LighthouseStrategyObjective / 灯塔策略目标
+ CaseObjective / 案目标
+ FieldState / 场域状态
+ HumanAttentionBudget / 人类注意力预算
  -> PurposePortfolio / 目的组合
  -> PurposePolicyBinding / 目的策略绑定
  -> ArtifactPlan / 产出计划
```

`FieldState / 场域状态` 是派生快照，不是事实源和战略裁决者。它只能把 `SignalEvent / 信号事件`、`SignalInterpretation / 信号解释` 与 `AttributionDecision / 归因决策` 压缩成会议可用的态势输入；当出现 `algorithm_noise_overload / 算法噪声过载` 灰灯时，平台反馈不得自动推动策略变更。

默认权限边界：

| 决策 | 默认权限 |
|---|---|
| 建立、修改、停用 LighthouseStrategyObjective | 人类裁决 |
| 年案、半年案的大方向和大比例 PurposePortfolio | 人类裁决，Amy 只能提交候选 |
| 季案、月案的主题战役和账号节奏 | 人类批准后 Amy 可拆解 |
| 周案、日案在已批准组合内的排程和变体 | Amy 可按 `delegated_within_band / inherited_projection` 自动生成，人类按注意力策略抽检 |
| 越过自动调整带的目的比例偏移 | 进入 PlanChangeProposal 或 BoundaryChangeProposal |
| 修改 SourcePack、账号定位、价值边界 | 人类裁决 |

## 二、通用会议协议

### 2.1 会议生命周期

所有会议遵循同一生命周期：

```text
会议准备（MeetingPreparation）
  -> 议程生成（AgendaDraft）
    -> 主动召回（ActiveRecall）
      -> 决策压缩（DecisionBrief）
        -> 人类裁决（HumanDecision）
          -> 案生成/修订（CaseCommit）
            -> 事件入账（EventLedger）
              -> 遗忘队列（ForgettingQueue）
```

### 2.2 通用输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 上层案快照 | ParentCaseSnapshot | 当前会议必须继承的目标、边界和授权 |
| 灯塔策略目标 | LighthouseStrategyObjective | 当前场域、账号和长期定位约束 |
| 上层案目标 | ParentCaseObjective | 上层案已经批准的战略任务、成功判据和目的组合 |
| 场域状态 | FieldState | 当前场域、平台、账号、主题和受众状态的派生快照 |
| 执行复盘 | ExecutionReview | 上一周期执行情况 |
| 信号摘要 | SignalReview | 信号事件、信号解释和归因决策摘要 |
| 召回卡 | RecallCard | 秘书主动带回的历史决策、失败教训、强信号和反哺候选 |
| 决策简报 | DecisionBrief | 需要人类判断的少数事项 |
| 机会候选 | OpportunityCandidate | 新平台、新媒体、新受众、新主题或新内容形态 |
| 计划变更提案 | PlanChangeProposal | 增加、减少或调整计划的正式提案 |

### 2.3 通用输出

| 输出 | 英文 | 说明 |
|---|---|---|
| 会议案 | MeetingCase | 本层会议生成或修订的案 |
| 案目标 | CaseObjective | 本层案的战略任务、约束、成功判据和目的组合 |
| 目的组合 | PurposePortfolio | 本层案的目的比例、数量、节奏、自动调整带和人类介入阈值 |
| 决策记录 | MeetingDecisionRecord | 人类批准、否决、延期、降权、冻结等结果 |
| 计划变更记录 | PlanChangeLog | 被批准或拒绝的计划变更历史 |
| 边界变更提案 | BoundaryChangeProposal | 下层想突破上层边界时产生 |
| 授权变更 | DelegationPolicyChange | 临时或长期授权调整 |
| 介入变更 | InterventionPolicyChange | 何时打扰人类的规则调整 |
| 事件记录 | EventLedgerEntry | 会议事实入账 |

### 2.4 通用禁止项

任何会议都不允许：

1. 静默修改上层案（Parent Case）。
2. 把召回卡（RecallCard）直接当成当前规则。
3. 把运营信号直接解释为理论正确或错误。
4. 自动修改源体系包（SourcePack）或理论母板（Canonical Mother Text）。
5. 绕过授权策略（DelegationPolicy）提高自动发布权限。
6. 在没有记录 PlanChangeProposal 的情况下增加或减少正式计划。

## 三、年会（Annual Meeting）

### 3.1 定位

年会（Annual Meeting）生成年案（YearCase）。年案承载年计划（YearPlan），性质是战略执行（Strategic Execution）。它不排 365 天每天写什么，而是定义全年写作与传播系统的最高边界。

### 3.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 源体系包 | SourcePack | 今年可显影的理论、品牌、产品、方法论或研究资料 |
| 人类年度意图 | HumanAnnualIntent | 人类对今年传播目标的判断 |
| 历史账本摘要 | EventLedgerSummary | 过去发布、反馈、失败和有效模式 |
| 年度机会候选 | AnnualOpportunityCandidates | 国外媒体、新平台、新账号形态、新受众等 |
| 平台/媒体观察 | FieldObservation | 国内外媒体、平台、账号生态变化 |
| 资源假设 | ResourceAssumption | 人类时间、AI 能力、发布资源、素材供给 |

### 3.3 议程

1. 源体系回看（SourcePack Review）：今年哪些概念、理论、价值边界值得显影。
2. 年度北极星（AnnualNorthStar）：今年最高传播目标是什么。
3. 年度主命题（AnnualMasterThesis）：今年反复显影的核心判断。
4. 主海域选择（PrimaryField Selection）：主要在哪些平台、媒体、账号、话题圈层发光。
5. 观察海域设定（ObservationField Setup）：哪些机会先观察，不重投入。
6. 受众阶梯（AudienceLadder）：S0-S7 中优先吸引哪些层级。
7. 年度主题轴（AnnualThemeAxes）：全年 3-7 个长期主题轴。
8. 案组合（CasePortfolio）：把年度主题轴拆成长期运行的案。
9. 授权基线（DelegationBaseline）：秘书默认可生成、审片、发布到什么程度。
10. 红线边界（RedlineBoundaries）：不写、不碰、不转译、不迎合。
11. 年度计划池（AnnualPlanPool）：正式纳入今年的计划。
12. 年度候选池（AnnualPlanCandidatePool）：全年关注但尚未正式启动的计划。

### 3.4 年案结构

```text
YearCase
  ├── ImmutableCore
  ├── AdjustableStrategy
  ├── DelegatedPlans
  └── OperatingLedger
```

#### 3.4.1 不可变核心（ImmutableCore）

这些字段只有重新开年案（YearCaseReopen）才能改：

| 字段 | 英文 | 说明 |
|---|---|---|
| 年度北极星 | AnnualNorthStar | 今年最高传播目标 |
| 年度主命题 | AnnualMasterThesis | 今年最核心的理论/品牌/方法论表达 |
| 价值边界 | ValueBoundaries | 哪些表达方式不符合价值立场 |
| 红线边界 | RedlineBoundaries | 不写、不碰、不转译、不迎合 |
| 源体系边界 | SourcePackBoundary | 哪些源体系可用，哪些只读不可改 |
| 年度非目标 | AnnualNonGoals | 今年明确不做什么 |

#### 3.4.2 年内可调战略（AdjustableStrategy）

这些字段可在半年会正式调整，季度会可提出提案：

| 字段 | 英文 | 正式变更入口 |
|---|---|---|
| 主海域 | PrimaryFields | 半年会 |
| 观察海域 | ObservationFields | 半年会，季度会可建议 |
| 受众阶梯 | AudienceLadder | 半年会 |
| 年度主题轴 | AnnualThemeAxes | 半年会可增减，季度会可重新排序 |
| 年度计划池 | AnnualPlanPool | 半年会正式增减 |
| 年度计划候选池 | AnnualPlanCandidatePool | 任意会议可追加候选 |
| 资源分配 | AnnualResourceAllocation | 半年会正式调整，季度会可建议 |
| 授权基线 | DelegationBaseline | 半年会正式调整；红线事件可临时降权 |
| 信号预期 | AnnualSignalExpectations | 半年会调整，季度会校准 |

#### 3.4.3 下层可展开计划（DelegatedPlans）

| 字段 | 英文 | 展开入口 |
|---|---|---|
| 季度安排槽 | QuarterPlanningSlots | 季度会 |
| 月度落地槽 | MonthLandingSlots | 月会 |
| 周战术槽 | WeekTacticalSlots | 周会 |
| 片场候选规则 | StudioCandidateRules | 月会/周会 |
| 产出物蓝图候选 | ArtifactBlueprintCandidates | 月会/周会提出，季度会确认 |
| 平台实验槽 | PlatformExperimentSlots | 季度会启动，月会落地 |

#### 3.4.4 运行记录（OperatingLedger）

| 字段 | 英文 | 说明 |
|---|---|---|
| 计划变更提案 | PlanChangeProposals | 新增、减少、调整计划的提案 |
| 机会候选 | OpportunityCandidates | 国外媒体、新平台、新受众等机会 |
| 信号摘要 | SignalReviews | 半年、季度、月、周反馈摘要 |
| 决策记录 | DecisionRecords | 人类批准、否决、降权、重开 |
| 边界突破请求 | BoundaryChangeRequests | 下层想突破上层边界时必须生成 |
| 反哺候选 | BackfeedCandidates | 可能反补源体系的候选，不自动采纳 |

### 3.5 输出

- 年案（YearCase）。
- 年度计划池（AnnualPlanPool）。
- 年度计划候选池（AnnualPlanCandidatePool）。
- 初始案组合（InitialCasePortfolio）。
- 年度授权基线（DelegationBaseline）。
- 年度红线边界（RedlineBoundaries）。

### 3.6 禁止讨论

- 不排每天写什么。
- 不讨论单篇标题。
- 不处理单个发布包（PublicationPackage）。
- 不因短期平台反馈修改理论边界。
- 不把机会候选直接变成执行计划，必须经过计划池归类。

## 四、半年会（Half-Year Meeting）

### 4.1 定位

半年会（Half-Year Meeting）生成半年案（HalfYearCase），性质是战略调整（Strategic Adjustment）。它不是重新开一次年会，而是在年案约束内正式处理新增计划、减少计划、资源重配和授权基线调整。

### 4.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 年案 | YearCase | 当前年度战略执行边界 |
| 半年信号复盘 | HalfYearSignalReview | 半年内事实信号、解释和归因决策 |
| 计划变更提案 | PlanChangeProposal | AddPlan / DropPlan / RebalancePlan |
| 机会候选池 | AnnualPlanCandidatePool | 全年积累的新机会 |
| 资源消耗报告 | ResourceConsumptionReport | 时间、AI 调用、产出、发布、复盘负担 |
| 授权事故报告 | DelegationIncidentReport | 自动发布、红线、召回、降权历史 |

### 4.3 议程

1. 战略执行评估（Strategic Execution Review）：年案执行是否偏离。
2. 增加计划（AddPlan）：哪些候选应进入年度计划池。
3. 减少计划（DropPlan）：哪些方向暂停、降级或移出。
4. 调整计划（RebalancePlan）：资源、优先级、平台节奏如何调。
5. 主海域调整（PrimaryFieldAdjustment）：主海域是否有效。
6. 受众阶梯调整（AudienceLadderAdjustment）：S0-S7 重点是否变化。
7. 授权基线调整（DelegationBaselineAdjustment）：哪些案可提高或降低自动化权限。
8. 年案修订记录（YearCaseRevision）：哪些字段被正式调整。

### 4.4 输出

- 半年案（HalfYearCase）。
- 年案修订记录（YearCaseRevision）。
- 计划变更记录（PlanChangeLog）。
- 调整后的年度计划池（UpdatedAnnualPlanPool）。
- 调整后的授权基线（UpdatedDelegationBaseline）。
- 下半年风险清单（SecondHalfRiskRegister）。

### 4.5 允许变更

| 动作 | 英文 | 权限 |
|---|---|---|
| 增加正式计划 | AddPlanToAnnualPlanPool | 允许 |
| 减少正式计划 | DropPlanFromAnnualPlanPool | 允许 |
| 资源重配 | ReallocateAnnualResource | 允许 |
| 主海域调整 | AdjustPrimaryField | 允许 |
| 授权基线提高 | RaiseDelegationBaseline | 允许，但必须有人类裁决 |
| 授权基线降低 | LowerDelegationBaseline | 允许 |

### 4.6 禁止讨论

- 不重新定义年度北极星，除非触发年案重开（YearCaseReopen）。
- 不修改红线边界，除非触发年案重开。
- 不安排每日执行。
- 不处理具体稿件质量。

## 五、季度会（Quarterly Meeting）

### 5.1 定位

季度会（Quarterly Meeting）生成季案（QuarterCase），性质是战略安排（Strategic Arrangement）。它把年案和半年案的战略转为本季度主题季、验证目标、平台实验和重点案。

### 5.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 年案 | YearCase | 年度战略执行边界 |
| 半年案 | HalfYearCase | 若存在，作为最新战略调整 |
| 年度计划池 | AnnualPlanPool | 可安排的正式计划 |
| 主题候选 | ThemeCandidate | 季度可显影主题 |
| 季度信号复盘 | QuarterSignalReview | 上季度事实与归因 |
| 平台实验候选 | PlatformExperimentCandidate | 可进入小规模实验的平台或媒体 |

### 5.3 议程

1. 季度主题季（ThemeSeason）：本季度核心主题组合。
2. 季度重点案（QuarterFocusCases）：本季度重点运行哪些案。
3. 季度验证目标（QuarterValidationGoals）：验证哪些表达、受众路径或平台假设。
4. 平台实验（PlatformExperiment）：哪些观察海域进入试验。
5. 受众路径安排（AudiencePathArrangement）：S0-S7 的季度迁移目标。
6. 季度风险点（QuarterRiskPoints）：哪些计划可能越界或过载。
7. 下发月度槽位（MonthPlanningSlots）：给月会的落地空间。

### 5.4 输出

- 季案（QuarterCase）。
- 主题季定义（ThemeSeasonDefinition）。
- 季度验证计划（QuarterValidationPlan）。
- 平台实验计划（PlatformExperimentPlan）。
- 月度落地约束（MonthLandingConstraints）。

### 5.5 允许变更

| 动作 | 英文 | 权限 |
|---|---|---|
| 重新排序年度主题轴 | ReorderAnnualThemeAxes | 允许 |
| 启动小规模平台实验 | StartPlatformExperiment | 允许 |
| 把机会候选转为实验 | CandidateToExperiment | 允许 |
| 生成计划变更提案 | CreatePlanChangeProposal | 允许 |
| 正式增加主海域 | AddPrimaryField | 不允许，需半年会 |

### 5.6 禁止讨论

- 不新增脱离年案的主海域。
- 不重排全年资源大盘。
- 不决定每天写什么。
- 不把单季反馈直接改成年度战略。

## 六、月会（Monthly Meeting）

### 6.1 定位

月会（Monthly Meeting）生成月案（MonthCase），性质是战略落地（Strategic Landing）。它把季度安排落成可运行的月度灯塔计划、账号节奏、目的组合、内容形态比例和产能预算。

### 6.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 季案 | QuarterCase | 本季度主题季和验证目标 |
| 月度场域状态 | MonthlyFieldState | 当前场域、平台、账号、受众、误读、共鸣、疲劳与灰灯摘要 |
| 月度信号复盘 | MonthSignalReview | 上月发布与反馈摘要 |
| 账号状态 | AccountState | 账号定位、受众、近期表现 |
| 平台规则变化 | PlatformRuleChange | 平台格式、敏感规则、发布限制变化 |
| 内容产能 | ArtifactCapacity | 本月可生产的产出物数量和类型 |
| 产出物蓝图候选 | ArtifactBlueprintCandidate | 新媒体形态或新载体候选 |

### 6.3 议程

1. 月度灯塔位置（MonthlyLighthousePosition）：本月在哪些位置发光。
2. 账号/平台组合（AccountPlatformMix）：哪些账号和平台投入多少。
3. 月度目的组合（MonthlyPurposePortfolio）：吸引、概念种子、解释、补证、边界设定等目的的比例、数量和节奏。
4. 内容形态比例（ArtifactMix）：长文、问答、图文、短视频、评论等媒体形态比例；它不能替代目的组合。
5. 本月主题池（MonthlyThemePool）：从季度主题季拆出的主题池。
6. 自动化授权范围（MonthlyDelegationScope）：哪些案本月允许秘书自动推进。
7. 月度产能预算（MonthlyCapacityBudget）：每天/每周可承载多少产出物。
8. 片场候选规则（StudioCandidateRules）：什么条件下开片场。

### 6.4 输出

- 月案（MonthCase）。
- 月度目的组合（MonthlyPurposePortfolio）。
- 月度主题池（MonthlyThemePool）。
- 平台/账号节奏（AccountCadence）。
- 内容形态比例（ArtifactMix）。
- 月度产能预算（MonthlyCapacityBudget）。
- 月度授权范围（MonthlyDelegationScope）。
- 周会输入包（WeeklyPlanningInputPack）。

### 6.5 允许变更

| 动作 | 英文 | 权限 |
|---|---|---|
| 调整月度主题池 | AdjustMonthlyThemePool | 允许 |
| 调整账号节奏 | AdjustAccountCadence | 允许 |
| 调整月度目的组合 | AdjustMonthlyPurposePortfolio | 允许，但不能越过季案边界和自动调整带 |
| 调整内容比例 | AdjustArtifactMix | 允许 |
| 临时降低授权 | TemporarilyLowerDelegation | 允许 |
| 提高长期授权 | PermanentlyRaiseDelegation | 不允许，需半年会 |

### 6.6 禁止讨论

- 不推翻季案（QuarterCase）的战略安排。
- 不把一次爆款当成战略调整。
- 不处理每日具体产出物。
- 不新增年度正式计划，最多生成 PlanChangeProposal。

## 七、周会（Weekly Meeting）

### 7.1 定位

周会（Weekly Meeting）生成周案（WeekCase），性质是战术安排（Tactical Arrangement）。它开始进入具体作战：本周开哪些片场、准备哪些今日子案、预授权哪些事项。

### 7.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 月案 | MonthCase | 月度灯塔、目的组合、主题池、账号节奏和产能预算 |
| 上周执行复盘 | WeekExecutionReview | 上周产出、发布、异常和信号 |
| 本周热点/机会 | WeeklyOpportunity | 本周值得纳入战术安排的热点或事件 |
| 待处理异常 | OpenExceptions | 发布失败、红线、质量问题、归因冲突 |
| 可用产能 | AvailableCapacity | 本周人类和 AI 可运行能力 |

### 7.3 议程

1. 本周主题战术（WeeklyThemeTactics）：本周打哪些主题。
2. 周度目的分配（WeeklyPurposeAllocation）：把月度目的组合拆成目的槽位（PurposeSlot）。
3. 本周片场候选（StudioCandidates）：准备开哪些片场。
4. 今日子案预案（DaySubCaseCandidates）：预生成哪些日会候选。
5. 预授权事项（PreAuthorizationItems）：哪些事情可提前授权秘书。
6. 本周风险与冻结点（WeeklyRiskPoints）：哪些内容需要谨慎或冻结。
7. 本周非目标（WeeklyNonGoals）：明确不做什么。

### 7.4 输出

- 周案（WeekCase）。
- 周度目的分配（WeeklyPurposeAllocation）。
- 目的槽位池（PurposeSlotPool）。
- 片场候选池（StudioCandidatePool）。
- 今日子案候选池（DaySubCaseCandidatePool）。
- 周授权建议（WeeklyDelegationRecommendation）。
- 周风险清单（WeeklyRiskRegister）。

### 7.5 允许变更

| 动作 | 英文 | 权限 |
|---|---|---|
| 选择本周主题 | SelectWeeklyThemes | 允许 |
| 建立片场候选 | CreateStudioCandidate | 允许 |
| 建立今日子案候选 | CreateDaySubCaseCandidate | 允许 |
| 调整目的槽位顺序 | ReorderPurposeSlots | 允许，不能改变月度目的组合大比例 |
| 预授权成熟案 | PreAuthorizeMatureCase | 允许，不能超过月度授权 |
| 新增年度计划 | AddAnnualPlan | 不允许，只能生成 PlanChangeProposal |

### 7.6 禁止讨论

- 不重设月案（MonthCase）的灯塔位置。
- 不新增年度级计划。
- 不逐字改稿。
- 不处理单个发布包的最终批准，除非它是上周遗留异常。

## 八、日晨会（Daily Meeting）

### 8.1 定位

日晨会（Daily Meeting）生成日案（DayCase）和今日子案（DaySubCase），性质是战术落地（Tactical Execution）。它只执行，不重新战略化。

日晨会不是默认完整审稿会。默认日常节奏是前一晚完成明日预案（NextDayPlan）和明日特别文件审阅，日晨会只做轻确认、异常处理和正式提升：

```text
前夜工作页（EveningWorkPage）
  -> 确认 NextDayPlan
  -> 审 TomorrowPublishCandidate
  -> 夜间修正
  -> 次日 Daily Meeting 轻确认
  -> DayCase / DaySubCase 正式执行
```

### 8.2 输入

| 输入 | 英文 | 说明 |
|---|---|---|
| 周案 | WeekCase | 本周战术安排 |
| 周度目的分配 | WeeklyPurposeAllocation | 本周目的槽位、数量和节奏 |
| 今日子案候选池 | DaySubCaseCandidatePool | 周会预备的候选 |
| 昨日异常 | YesterdayExceptions | 昨日未解决问题 |
| 强召回卡 | HighPriorityRecallCard | 与今日高度相关的历史记录 |
| 今日可用产能 | DailyCapacity | 今天能运行多少片场和产出物 |

### 8.3 议程

1. 提升明日预案（PromoteNextDayPlan）：把已确认的 NextDayPlan 转为今日 DayCase / DaySubCase。
2. 轻确认夜间改动（MorningLightConfirmation）：只看夜间修正摘要、门禁差异和异常。
3. 选择今日子案（SelectDaySubCases）：只处理前夜未覆盖或突发新增的主题行动。
4. 确认授权覆盖（DailyDelegationOverride）：秘书可生成、改稿、审片、发布还是只产出不发布。
5. 锁定目的槽位（LockPurposeSlot）：为每个今日子案锁定 `primary_purpose_type / 主目的类型`、目标受众状态和对应 `PurposePolicyBinding / 目的策略绑定`。
6. 开启片场（OpenStudio）：按账号、平台、受众、形态和理论显性度建立生成环境。
7. 处理当日决策简报（DailyDecisionBrief）：只处理必须当天裁决的事项。
8. 确认今日非目标（TodayNonGoals）：今天明确不做什么。

### 8.4 输出

- 日案（DayCase）。
- 今日子案（DaySubCase）。
- 当日目的槽位计划（DailyPurposeSlotPlan）。
- 片场（Studio）。
- 产出计划集（ArtifactPlanSet）。
- 产出计划（ArtifactPlan）：必须锁定 `primary_purpose_type / target_audience_state / purpose_policy_binding_id`。
- 当日授权记录（DailyAuthorizationRecord）。
- 轻确认记录（MorningLightConfirmationRecord）。

### 8.5 授权粒度

日晨会中，人类操作的最小授权对象是今日子案（DaySubCase）：

```text
案（Case）             = 长期目标、边界、默认授权
今日子案（DaySubCase） = 今天是否行动、授权到哪一步
片场（Studio）         = 授权后建立的生成环境
产出物（Artifact）     = 批量总编台中检查的具体结果
```

### 8.6 禁止讨论

- 不重设战略。
- 不新增年度计划，只生成机会候选（OpportunityCandidate）。
- 不把单篇表现解释为理论成功或失败。
- 不处理长期授权变化，除非红线中断。
- 不逐字修稿，修稿进入批量总编台（Artifact Review Desk）。
- 不把未审阅的高风险明日候选在早晨临时改成当天发布。

## 八A、前夜工作页（Evening Work Page）

前夜工作页不是第七类战略会议，而是日常运行中的审阅面。它服务于次日日晨会，避免早上赶审。

### 8A.1 定位

| 对象 | English | 说明 |
|---|---|---|
| 前夜工作页 | EveningWorkPage | 审明日特别文件、收束当日、确认明日预案 |
| 明日预案 | NextDayPlan | 次日执行草案，不是正式 DayCase |
| 明日待发布审阅 | TomorrowPublishReview | 前夜处理 D+1 重点候选 |
| 晚间提交 | EveningCommit | 人类当晚选择的收束记录 |

### 8A.2 输出

- 已确认或待轻确认的 NextDayPlan。
- TomorrowPublishCandidate 的前夜审阅状态。
- 夜间修正指令和门禁重跑要求。
- 每日精选审阅选择或跳过记录。
- 旧系统对照偏差候选。

### 8A.3 与日晨会关系

EveningWorkPage 负责判断和审阅

## 九、计划变更机制

### 9.0 CandidateProposalEnvelope

候选提案信封（CandidateProposalEnvelope）是所有候选进入会议治理前的统一入口。它不是正式变更对象，而是把来源、证据、作用范围、风险、去重合并、推荐会议和裁决入口统一起来。

```text
CandidateProposalEnvelope
  -> OpportunityCandidate / PlanChangeProposal / BoundaryChangeProposal
  -> StrategyChangeProposal / BackfeedCandidate / CalibrationExample
```

候选提案必须先经过三道门：

| 门禁 | English | 说明 |
|---|---|---|
| 聚合门 | Aggregation Gate | 同类信号按时间窗、平台、账号、产出物、概念归并 |
| 阈值门 | Threshold Gate | 达到强度、频次、风险或战略相关性后才进入候选 |
| 目的门 | Purpose Gate | 必须能映射到找场、立灯塔、发光或吸引同频者 |

候选提案卡（CandidateProposalCard）进入 Amy 工作台时，应展示建议动作、来源摘要、战略关联、风险等级、Amy 建议和可选按钮；不展示原始信号洪流。

裁决边界：

1. `CandidateDecision / 候选裁决` 与 `CandidateApplication / 候选应用` 必须分离；会议或 Amy 通过一项候选，不等于正式对象已经被修改。
2. `redline / 红线`、`source_boundary / 源边界` 以及涉及 `SourcePack / 源体系包`、`LighthouseStrategyObjective / 灯塔策略目标`、`CaseObjective / 案目标` 的候选，只能交由人类裁决。
3. 同类候选被合并后，必须保留 `CandidateSourceRef / 候选来源引用` 与 `CandidateMergeLink / 候选合并链路`，不能因降噪丢掉证据谱系。

### 9.0a InvestmentThesisLayer

投入论点层（InvestmentThesisLayer）进入会议时，不讨论“这条数据好不好看”，而讨论“该对象是否值得加码、降频、保持、暂停或实验”。

会议输入：

| 输入 | English | 说明 |
|---|---|---|
| 投入对象 | InvestmentTarget | 场域、平台、账号、主题、目的组合、产出系列或片场 |
| 投入评估运行 | InvestmentAssessmentRun | 证据窗口、策略版本、模型版本、建议、置信度、反证和不确定性 |
| 投入论点快照 | InvestmentThesisSnapshot | 预期结果、成功指标、失败条件、复盘时间和风险 |
| 投入结果复盘 | InvestmentOutcomeReview | 证实、证伪、不确定或噪声过载结论 |

会议输出：

| 输出 | English | 说明 |
|---|---|---|
| 保持观察 | Hold / Observe | 不改变计划，只继续采集证据 |
| 降频或暂停候选 | Decrease / Pause Candidate | 进入 `CandidateProposal / 候选提案`，不得静默修改计划 |
| 加码或实验候选 | Increase / Experiment Candidate | 必须说明源体系相关、灯塔一致、同频共鸣、资产沉淀和风险成本 |
| 资源配置决策 | ResourceAllocationDecision | 引用已批准候选裁决，随后由候选应用记录输出对象 |

裁决规则：

1. 平台热度不能单独触发加码；必须同时具备战略匹配与高质量共鸣证据。
2. 低流量不能单独证明理论、主题或灯塔失败；必须先排除平台不适配、形态不适配、机会窗口不足和算法噪声。
3. `algorithm_noise_overload / 算法噪声过载` 灰灯期间，会议只能输出观察、保持、暂停或人工复核候选，不能授权自动加码。

### 9.0b AssessmentPolicy

投入评估策略（AssessmentPolicy）是会议使用的版本化评分契约，不是 AI prompt。每次会议采纳投入建议时，必须能看到策略版本、维度得分、证据缺口、否决项和反证摘要。

核心维度：

| 维度 | English | 裁决含义 |
|---|---|---|
| 源体系匹配 | SourceFit | 是否服务 `SourcePack / 源体系包`，不可被流量抵消 |
| 灯塔匹配 | LighthouseFit | 是否强化身份占位、信任建立、边界姿态 |
| 案目标匹配 | CaseObjectiveFit | 是否符合当前年/季/月/周案任务 |
| 受众状态匹配 | AudienceStateFit | 是否吸引目标 `S0-S7 / 受众状态假设` 中的正确人群 |
| 共鸣质量 | ResonanceQuality | 收藏、转发、长评、引用、准确复述的质量 |
| 资产沉淀潜力 | AssetCompoundingPotential | 是否能沉淀为长期文章、概念、范本或素材 |
| 场域机会 | FieldOpportunity | 是否存在表达空位或机会窗口 |
| 执行成本 | ExecutionCost | 生成、审校、发布、维护和复盘成本 |
| 风险包络 | RiskEnvelope | 误读、争议、越界、身份稀释和平台政策风险 |
| 证据强度 | EvidenceStrength | 样本量、时间窗口、归因可信度和反证质量 |

动作映射：

| 建议 | Recommendation | 必须满足 |
|---|---|---|
| 加码 | Increase | 硬门槛通过，战略匹配强，共鸣质量高，证据强，风险可控 |
| 降频 | Decrease | 主题仍有价值，但疲劳升高、共鸣下降、成本偏高或优先级下降 |
| 保持 | Hold | 判断稳定，未达到加码或降频阈值 |
| 暂停 | Pause | 风险升高、误读严重、边界不清或人类注意力超预算 |
| 实验 | Experiment | 战略可能成立但证据不足，适合小预算和短周期验证 |
| 观察 | Observe | 信号太早、太弱、太噪或归因不清 |

人工裁决边界：

1. 从 `observe / 观察` 或 `experiment / 实验` 升级为长期 `increase / 加码`。
2. 影响 `SourcePack / 源体系包`、`LighthouseStrategyObjective / 灯塔策略目标`、身份占位、价值边界或非目标受众。
3. 降频或暂停年度/半年案中的主战略方向。
4. 证据强度不足但建议大幅调整 `PurposePortfolio / 目的组合`。
5. 多个 AI 角色结论冲突，且影响月案以上计划。

### 9.0c AssessmentPolicySeed

评估策略种子（AssessmentPolicySeed）是系统内置默认策略来源，不是运行时策略。会议中使用的是由种子、平台适配、媒体形态适配和用户覆盖编译出的 `InvestmentAssessmentPolicy / 投入评估策略实例`。

种子层级：

| 层级 | English | 可调整内容 | 不可调整内容 |
|---|---|---|---|
| 核心战略种子 | CoreStrategicSeed | 核心维度默认权重和硬门槛 | 不能被平台/形态覆盖 |
| 平台适配种子 | PlatformAdaptationSeed | 信号解释、曝光周期、平台格式偏好、平台规则 | 不能降低源体系、灯塔和边界门槛 |
| 形态适配种子 | MediaShapeAdaptationSeed | 生产成本、审阅成本、资产沉淀方式、共鸣表达方式 | 不能改变战略判断主权 |
| 覆盖集 | OverrideSet | 用户或会议批准的局部调整 | 不能绕过人工裁决边界 |

首版默认种子：

| 种子 | English | 重点信号 | 仅能触发观察/实验的信号 |
|---|---|---|---|
| 知乎长文 | Zhihu Long-form | 收藏、长评、概念复述、阅读后关注、长尾搜索 | 单日阅读波动、争议评论量 |
| 公众号文章 | WeChat Article | 阅读完成、转发到聊天、收藏/星标、长期引用 | 单日阅读量、朋友圈短期扩散 |
| 小红书图文 | Xiaohongshu Image-text | 收藏、评论提问、卡片完读、场景适配、关注意向 | 纯点赞、泛流量曝光 |
| X/Twitter 短帖 | X/Twitter Short Post | 转发、引用转述、串帖展开、跨圈层触达、概念扩散潜力 | 单条曝光、情绪化回复 |
| 视频/短视频 | Video / Short Video | 留存、完播、重看、评论理解准确度、片段转发 | 播放量、猎奇点击 |

以上重点信号是 `Initial Evidence Hypothesis / 初始证据假设`，不是平台算法事实。启用种子前必须核对当前可获得的信号字段与平台规则；启用后必须通过 `InvestmentOutcomeReview / 投入结果复盘` 校正。无法稳定采集或无法解释归因的信号，只能作为观察输入。

种子治理规则：

1. 任何单一平台热度信号只能触发 `observe / 观察` 或 `experiment / 实验`，不能直接触发 `increase / 加码`。
2. 新平台首次好数据最多生成实验候选，不能直接改变主题权重、账号定位或月度目的组合大比例。
3. 平台规则或 AI 能力变化时，只发布新的 `SeedVersion / 种子版本`；旧策略实例不自动迁移。
4. 种子升级、覆盖或降级必须生成可审阅差异，必要时进入 `CandidateProposal / 候选提案`。

### 9.0d OutcomeReview

投入结果复盘（OutcomeReview）进入会议时，会议不问“数据是否好看”，而问“当初的投入论点是否被现实证据支持，偏差如何解释，下一步应形成什么候选”。

复盘输入：

| 输入 | English | 说明 |
|---|---|---|
| 投入论点快照 | InvestmentThesisSnapshot | 当时为什么加码、降频、实验或观察 |
| 结果基线快照 | OutcomeBaselineSnapshot | 决策前基线、预期指标、资源配置、源体系和灯塔上下文 |
| 实际结果指标 | OutcomeActualMetric | 复盘窗口内采集到的实际指标 |
| 预期实际比较 | OutcomeExpectationComparison | 每个指标的预期、实际、差异和重要性 |
| 归因假设 | OutcomeAttributionHypothesis | 内容、平台、时机、标题、形态、账号、误读、噪声等竞争解释 |

复盘输出：

| 输出 | English | 说明 |
|---|---|---|
| 保持论点 | Keep Thesis | 证据支持，继续当前节奏 |
| 调整表达 | Adjust Expression | 方向仍成立，但需换目的、角度、标题、形态或显影高度 |
| 修订再测 | Revise And Retest | 实验失败但原因未明，低成本再测 |
| 降频或暂停候选 | Decrease / Pause Candidate | 疲劳、误读、成本或风险升高 |
| 种子校正候选 | Seed Correction Candidate | 平台信号解释或阈值假设需要修正 |
| 反哺候选 | Backfeed Candidate | 源体系边界、定义或解释可能需要补充，但不自动修改 |

异常处理：

1. `ExperimentFailed / 实验失败` 不直接判定主题失败；先区分平台不适配、形态不适配、表达角度错误和源体系相关度不足。
2. `MisreadExpanded / 误读扩大` 必须暂停放大，并生成澄清、边界设定或降频候选。
3. `FatigueRising / 疲劳上升` 必须降低同主题密度或轮换表达形态，不允许继续机械加量。
4. `PlatformRuleChanged / 平台规则变化` 先触发种子复查，不能把表现下降直接归咎于内容或源体系。
5. `LowTrafficHighAlignment / 低流量高同频` 可以继续窄场维护、换标题、换形态、换平台或延长观察。
6. `HighTrafficLowAlignment / 高流量低同频` 不能加码；误读高时必须降频或改写。

### 9.1 OpportunityCandidate

机会候选（OpportunityCandidate）是尚未进入正式计划的机会。它可以由任何会议、AI 岗位、人工观察或外部信号生成。

|---|---|---|

### 9.4 国外媒体示例

```text
国外媒体方向（Foreign Media Expansion）
  -> 机会候选（OpportunityCandidate）
  -> 平台研究案（PlatformResearchCase）
  -> 观察海域（ObservationField）
  -> 季度平台实验（QuarterPlatformExperiment）
  -> 半年会决定是否进入年度计划池（AnnualPlanPool）/主海域（PrimaryFields）
```

这个路径保证国外媒体全年被看见，但不会因为一时兴起打乱当前主线。

## 十、秘书与 AI 岗位

### 10.1 总制片秘书

总制片秘书（ExecutiveProducerSecretary）负责：

- 准备会议输入包（MeetingInputPack）。
- 根据当前会议层级过滤议题。
- 主动召回相关历史，生成召回卡（RecallCard）。
- 把复杂讨论压缩成决策简报（DecisionBrief）。
- 根据会议结果写入对应案（Case）。
- 生成计划变更提案（PlanChangeProposal）或边界变更提案（BoundaryChangeProposal）。

她不能：

- 越级修改上层案。
- 自动提高授权等级。
- 自动把机会候选转正式计划。
- 自动把信号解释为理论正确性。

### 10.2 AI 岗位按会议层级参与

| 岗位 | 英文 | 年会/半年会 | 季度/月会 | 周会/日会 |
|---|---|---|---|---|
| 场域侦察 AI | FieldScoutAI | 主海域、观察海域、国外媒体机会 | 平台实验与账号组合 | 热点和即时机会 |
| 策略分析 AI | StrategyAnalystAI | 年度计划池、资源分配 | 季度主题季、月度落地 | 周战术优先级 |
| 受众分析 AI | AudienceAnalystAI | AudienceLadder | AudiencePathArrangement | DaySubCase 受众状态 |
| 理论守门 AI | SourceBoundaryAI | SourcePackBoundary、RedlineBoundaries | 主题季理论边界 | 具体表达是否越界 |
| 复盘分析 AI | SignalReviewAI | 半年/年度信号摘要 | 季度/月度信号摘要 | 周/日异常 |
| 遗忘提炼 AI | ForgettingRefinerAI | 长周期保留模式 | 中周期策略候选 | 短期 RecallCard |

## 十二、首期实现范围

Phase 1 必须预埋完整会议与计划治理结构，但运行时可以先做最小闭环：

## 十三、硬约束

1. 年计划是战略执行，半年计划是战略调整，季度计划是战略安排，月度计划是战略落地，周计划是战术安排，日计划是战术落地。
2. 每场会只讨论本层级问题；越级问题必须生成 PlanChangeProposal 或 BoundaryChangeProposal。
3. 任意会议都可新增机会候选（OpportunityCandidate），但不能任意新增正式计划。
4. 年案（YearCase）的不可变核心只能通过 YearCaseReopen 修改。
5. 半年会（Half-Year Meeting）是年内战略调整的主要正式入口。
6. 季度会（Quarterly Meeting）可以安排实验，但不能静默新增主海域。
7. 月会（Monthly Meeting）负责落地，不负责重设战略。
8. 周会（Weekly Meeting）负责战术安排，不负责长期授权提高。
9. 日晨会（Daily Meeting）负责当天执行，不负责战略化讨论。
10. 所有会议输出必须写入 EventLedger，并由 ForgettingSystem 决定未来是否激活。

# 08 选题漏斗系统

> 系统编号：①
> 子品牌：观象 SignalScope
> 核心职责：从热点信号、异常信号、理论命题和研究问题中生成适配策略单元的内容/研究候选，并输出 RSC/CTF 前置对象
> 方法论来源：粥左罗「70%选题」、吕白「3-10-1聚焦」、吕白「三遍拆解法」

---

## 一、设计理念

### 1.1 核心公式

> **爆文 = 70% 选题 + 20% 大纲 + 10% 内容** — 粥左罗

选题是内容生产的第一道关，也是权重最大的关。选题错了，写得再好也不会爆。

### 1.2 核心原则

1. **选题是可以系统化的**：不靠灵感靠方法，通过漏斗筛选而非直觉判断
2. **爆款都是重复的**：先拆解已验证的爆款，再在70%相似度内创新（吕白）
3. **痛点 > 热点**：常青内容靠痛点驱动，热点内容靠时机驱动，两者并行
4. **策略单元优先**：同一个热点在不同账号、平台、内容类型和理论介入方式下应生成不同候选
5. **双入口并行**：热点可以触发选题，理论命题也可以主动寻找热点或案例承载
6. **选题输出是契约前置材料，不是标题**：漏斗的产出物不是"写这个主题"，而是可进入 RSC/CTF 的结构化需求语义帧和契约候选
7. **扰动是认知入口**：异常数据、反常反馈、理论冲突和证据过期也可以触发候选，不只热点触发
8. **知道 = 属性识别 + 趋势预测 + 介入能力**：选题阶段必须记录关键属性、趋势预测和建议介入动作

## 二、三层漏斗模型

```
┌─────────────────────────────────────────────────┐
│ 第一层：观象信号采集（宽口）                      │
│   热点 │ 异常 │ 理论命题 │ 常青 │ 爆款 │ 素材 │ 反证 │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│ 第二层：认知属性识别（收口）                      │
│   策略单元 │ 理论适配 │ 运营目标 │ 风险等级 │ 反证状态 │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│ 第三层：边界决策（10-3-1或自动调度）              │
│   候选 → 策略单元排序 → 写/研究/暂存/不写/实验    │
└──────────────────────┬──────────────────────────┘
                       ▼
       RequirementFrame → ContentSpecSnapshot
                       ▼
               ContractCandidate
```

## 三、第一层：信号采集

### 3.1 四类信号源

| 信号类型 | 来源 | 采集方式 | 优先级 |
|---------|------|---------|--------|
| **热点信号** | 微博热搜、知乎热榜、百度指数、微信指数 | 定时爬取/手动录入 | 高（有时效性） |
| **异常信号** | 数据反常、评论异动、策略失配、黄灯/红灯 | 数据回收/进化控制台 | 高（认知扰动） |
| **理论命题** | 理论体系中的概念、判断、推导链 | 理论库主动生成/人工录入 | 高（形成差异化观点） |
| **常青信号** | 读者痛点、群体共鸣、身份认同话题 | 手动录入 + 数据回收回灌 | 中（长期积累） |
| **爆款信号** | 同领域已验证的爆款文章/帖子 | 手动拆解录入 | 高（已验证） |
| **素材信号** | 素材库中可展开的内容原子 | 系统自动关联 | 中 |
| **反证信号** | EvidenceClaim 被挑战、证据过期、反例出现 | ClaimGraph/质量门禁 | 高（研究价值） |

### 3.2 信号数据结构

```json
{
  "signal_id": "sig_20260522_001",
  "signal_type": "trending | anomaly | theory | evergreen | viral_hit | material | falsification",
  "source": "微博热搜",
  "title": "35岁程序员转行",
  "description": "...",
  "captured_at": "2026-05-22T10:00:00+08:00",
  "expires_at": "2026-05-23T10:00:00+08:00",
  "metadata": {
    "heat_index": 8500,
    "related_keywords": ["中年转型", "程序员", "职场危机"],
    "competing_articles": 12
  }
}
```

### 3.3 信号保鲜期

| 信号类型 | 默认保鲜期 | 过期处理 |
|---------|-----------|---------|
| 热点信号 | 48小时 | 降级为历史参考，不进入漏斗 |
| 异常信号 | 7天 | 若未处理，进入进化控制台待办或转研究问题 |
| 常青信号 | 永不过期 | 定期（月度）重新评估优先级 |
| 爆款信号 | 30天 | 结构可复用，热点角度过时 |
| 素材信号 | 跟随素材保鲜期 | 素材过期则信号失效 |
| 反证信号 | 直到关闭 | 关闭前阻断相关断言自动晋升 |

## 四、第二层：垂直筛选

### 4.1 基础四维评估模型

每个进入第二层的信号，按四个维度打分（0-10分）：

| 维度 | 评估问题 | 评分标准 | 权重 |
|------|---------|---------|------|
| **覆盖人群** | 这个选题能触达多少人？ | 10=千万级，7=百万级，4=十万级，1=万级 | 30% |
| **痛点强度** | 读者有多在意这个话题？ | 10=切身利益/深层焦虑，5=有共鸣但不太痛，1=无感 | 30% |
| **传播属性** | 读者看完会转发吗？ | 10=社交货币（转发=表达自我），5=有价值会收藏，1=自用不分享 | 20% |
| **已验证性** | 有同类爆款吗？ | 10=同领域已有多次爆款，5=跨领域有类似爆款，1=全新无参考 | 20% |

### 4.2 综合评分

```
选题得分 = 覆盖人群×0.3 + 痛点强度×0.3 + 传播属性×0.2 + 已验证性×0.2
```

### 4.3 筛选阈值

| 得分区间 | 处理方式 |
|---------|---------|
| ≥ 7.0 | 进入第三层聚焦 |
| 5.0 - 6.9 | 标记为"储备选题"，暂不执行 |
| < 5.0 | 归档，不进入第三层 |

### 4.4 账号匹配过滤

筛选后还需与账号矩阵匹配（详见 05_账号矩阵系统）：

- 这个选题适合哪个账号？
- 该账号近期是否已覆盖过类似主题？
- 是否有竞品已在同领域发布？

### 4.5 策略矩阵评估

基础四维得分只回答“这个选题有没有传播潜力”，不能决定“这个策略单元该不该写”。进入内容行动流水线前，还要按策略单元评分：

| 维度 | 评估问题 | 示例 |
|------|----------|------|
| `strategy_unit_fit` | 是否适合当前账号、平台、内容类型和理论介入方式 | 知乎长文适合高理论，小红书卡片适合低显性理论 |
| `theory_fit` | 能否自然接入理论体系，是否能推出新观点 | 热点是否能映射到某个理论命题 |
| `theory_intervention_level` | 理论显性程度应高、中、低还是隐性转译 | 公众号可高，微博快评可中，小红书可低 |
| `traffic_potential` | 是否有吸引、互动或高意向信号潜力 | 热点速度、标题空间、争议度 |
| `theory_level` | 理论深度是否符合账号目标 | 深文要求高，轻内容要求可转译 |
| `readability` | 在目标平台是否可读 | 长句密度、概念密度、案例充足度 |
| `risk_level` | 是否触发事实、平台、账号或理论红线 | 医疗法律金融、平台敏感、理论误用 |
| `operation_goal_fit` | 是否服务当前策略目标 | 曝光、收藏、公开追问、系列沉淀、外部交接信号 |
| `claim_potential` | 是否能形成有价值的 EvidenceClaim | 可证、可反证、可沉淀 |
| `research_value` | 是否值得转成研究问题而非只写一篇内容 | 反常现象、理论空缺、长期争议 |

每个策略单元可以调整维度和权重。系统提供默认值，人类可通过进化控制台修改。

### 4.6 写/不写判断

内容行动流水线必须允许自动判断“不写”：

| 判定 | 处理 |
|------|------|
| `write_now` | 立即进入 RSC/CTF |
| `store_candidate` | 存入候选池，等待更合适窗口 |
| `experiment` | 进入实验策略，小流量或只生成草稿 |
| `do_not_write` | 不写，记录理由和证据 |
| `research_question` | 转入研究问题，不急于写内容 |
| `draft_only` | 只生成草稿，不发布 |

不写理由包括：理论映射牵强、风险过高、平台不合适、账号近期重复、热点质量低、运营目标不匹配。

### 4.7 属性识别与趋势预测记录

每个候选进入第三层前，必须生成最小 `CognitionTrace` 草案：

```json
{
  "observed_attributes": ["热点时效强", "理论映射自然", "平台风险中等"],
  "noise_attributes": ["无来源爆料", "情绪化评论"],
  "trend_prediction": {
    "expected_reading": "medium_high",
    "expected_collection": "high",
    "negative_feedback_risk": "medium"
  },
  "suggested_intervention": "write_now | draft_only | research_question | not_write"
}
```

## 五、第三层：精准聚焦（10-3-1）

### 5.1 聚焦流程

```
第二层输出（基础分与策略矩阵均达标的候选）
    │
    ▼
10个候选选题
    │
    │ 考虑：时效性、账号排期、素材就绪度、个人状态
    ▼
3个精选选题
    │
    │ 考虑：哪个最有把握？哪个素材最充分？
    ▼
1个执行选题或实验选题 → 生成 RequirementFrame → CTF规格快照 → 契约候选
```

### 5.2 选择依据

| 从10选3 | 从3选1 |
|---------|--------|
| 时效性：热点优先 | 素材就绪度：素材最充分的优先 |
| 策略单元适配：匹配当前账号/平台/理论介入方式 | 策略目标：最服务当前运营目标的优先 |
| 差异化：与竞品不同的优先 | 风险评估：敏感度最低的优先 |
| 素材就绪度：有现成素材的优先 | — |

## 六、爆款拆解（吕白方法）

### 6.1 三遍拆解法

对第二层筛选中标记为"已验证"的爆款内容，执行三遍拆解：

| 遍数 | 关注层面 | 拆解内容 |
|------|---------|---------|
| 第一遍 | 表面 | 选题方向、标题结构、封面设计 |
| 第二遍 | 结构 | 论证方式、段落节奏、情绪弧线、钩子位置 |
| 第三遍 | 细节 | 金句措辞、开头技巧、结尾升华、互动引导 |

### 6.2 拆解产出物

```json
{
  "viral_analysis_id": "va_001",
  "source_url": "https://...",
  "source_platform": "zhihu",
  "topic": "中年转型",
  "metrics": {
    "views": 150000,
    "likes": 3200,
    "favorites": 890,
    "comments": 456
  },
  "structure_analysis": {
    "title_pattern": "数字+身份+转折",
    "opening_type": "反常识断言",
    "body_structure": "问题→论证(3个案例)→升华",
    "closing_type": "开放式提问",
    "hook_count": 3
  },
  "reusable_patterns": [
    "数字+身份+转折标题模式",
    "反常识开头模式",
    "三案例论证结构"
  ]
}
```

### 6.3 70%模仿原则

> **爆款 = 70%与爆款相似 × 足够多的试验品** — 吕白

拆解后生成的内容不要求100%原创，而是：
- **70%** 结构/论证方式/节奏对标爆款
- **30%** 角度/案例/金句用自己的

## 七、漏斗输出：ContentSpec 前置对象

漏斗的最终产出物不是一段文字描述，也不直接等同于正式契约，而是三类前置对象：

1. `RequirementFrame`：RSC 可追问、可补槽的需求语义帧
2. `ContentSpecSnapshot`：CTF 形成的可信规格快照
3. `ContractCandidate`：规格快照审阅后形成的契约候选

只有当规格快照达到最低证据和审阅要求时，才生成契约候选：

```json
{

    "contract_candidate_id": "cc_20260522_001",
    "source_spec_snapshot_id": "snap_20260522_001",
    "status": "draft | ready | blocked",
    "blocking_reason": null,
    "suggested_must_land": [
      "编程思维的核心概念（抽象/分解/模式识别）",
      "写作困局的具体表现",
      "软件思维如何映射到写作方法"

    "suggested_taboos": ["不要贩卖焦虑", "不要贬低任何年龄段"],
    "viral_reference": "va_001",
    "suggested_word_count": [2000, 3500],
    "suggested_style": "first_person_narrative",

      "autonomy_level": "AL3",

      "publish_policy": "auto_publish_if_passed",
      "sample_policy": "risk_weighted"
    }

```

`status=ready` 的契约候选进入 05.[模型]-写作契约-Contract；`blocked` 返回 RSC/CTF 处理缺槽位、冲突或 stale 节点。

### 7.4 ContentDecision 与 SpecIssue

漏斗阶段产生的问题和人工裁决不写成临时 UI 状态，而写入规格事实层：

```json
{
  "spec_issue": {
    "issue_id": "issue_spec_001",
    "type": "missing_requirement | conflict | ambiguity | stale_source | no_source | low_confidence | coverage_gap",
    "severity": "high | medium | low",
    "affected_objects": ["rf_20260522_001", "bnd_topic_001"],
    "description": "目标读者尚未由策略单元或人类确认",
    "suggested_action": "请确认目标读者是否收窄到35岁以上转型者；高自治策略可由默认画像先行",
    "status": "open | resolved | deferred"
  },
  "content_decision": {
    "decision_id": "dec_20260522_001",
    "decision_action": "accept | reject | request_changes | lock | unlock",
    "accept_level": "low_risk | provisional | release | accountable",
    "target_objects": ["rf_20260522_001", "bnd_topic_001"],
    "decision": "目标读者定位为35岁以上有转型焦虑的知识工作者",
    "rationale": "该定位更符合账号近期选题和素材证据",
    "ai_instruction": "后续生成必须围绕中年转型视角，不要扩展为泛职场成长",
    "status": "accepted"
  }
}
```

`accepted` 的 `ContentDecision` 优先于 AI 推断；`lock` 后的对象只能由人工 `unlock` 或 override 证据解锁。

## 八、首期范围

### Phase 1 实现

- [ ] 手动录入信号（四类信号源）
- [ ] 理论命题入口（手动或理论库输出）
- [ ] 基础四维打分
- [ ] 策略矩阵评分（策略单元适配、源体系适配、吸引信号、理论水平、可读性、风险）
- [ ] 写/不写/暂存/实验 判定
- [ ] 10-3-1选择流程或策略化自动调度
- [ ] 生成 RequirementFrame
- [ ] 生成 ContentSpecSnapshot（轻量版）
- [ ] 生成 ContractCandidate
- [ ] 生成 SpecIssue（缺口、冲突、低置信、无来源）
- [ ] 记录 ContentDecision（人工确认、否定、补口、锁定）

### Phase 1 不含

- 全平台热点自动爬取（可先手动录入或少量来源）
- 爆款自动拆解（手动拆解录入）
- 数据回收自动训练评分模型

### 理论驱动选题机制

**Phase 1：AI候选 + 人拍板**

AI每周生成"理论选题候选单"（5-8个），每个候选包含：理论出处、拟切入的社会现象、推荐理由、与已发内容的差异化说明。人类选1-2个进入管线，可全部否决。不设固定发文频率，设"每周一次选题会"节奏——没有好选题就跳过，强制频率会逼出灌水内容。

被选/否决的记录反馈校准AI偏好。演进路径：Phase 1 人工决策 → Phase 2 偏好模型命中率50%+后自动+抽检 → Phase 3 常规自治。

**理论-话题双向匹配：Phase 1 最小方案**

维护人工标注的种子表（每条理论5-15个已验证话题域+映射路径）。新信号进入时LLM做一次语义匹配，输出候选+映射路径草稿+置信度。三道过滤：应用域声明收敛 → 映射路径质量分 → expression_policy门槛。人类确认的映射回灌种子表，200条以上再考虑向量检索。

**源体系映射沉淀：理论 profile 示例**

1. **因果原语池**：每次映射的 causal_primitives / required_relations / forbidden_relations 拆解入库，打 `[理论] + [语义标签]` 双索引。下次写新话题检索原语而非完整映射
2. **观点指纹库**：每次推导的新观点生成语义指纹，下次碰撞检测，重叠超阈值标记"已表达"，迫使系统往未覆盖空间探索
3. **映射深度计**：记录理论使用次数 × 原语覆盖率。深度越高，自动调高"探索新原语"权重

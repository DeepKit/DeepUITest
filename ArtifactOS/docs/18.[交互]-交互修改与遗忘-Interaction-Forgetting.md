## Part A：交互修改与反馈沉淀

> 原 `18.[交互]-交互修改与遗忘-Interaction-Forgetting系统.md`（~805 行），系统编号：附属系统。

### A.1 设计理念

人类在修改 AI 草稿时的每句话都携带创作判断（风格偏好、表达偏好、结构偏好、词汇禁忌、切入角度）。传统"改了就完了"的流程导致这些信号全部丢失。

核心原则：

1. 反馈是资产，不是一次性消耗
2. 采集零摩擦——人类只说自然语言，不填表单，系统自动归类
3. 沉淀有结构——反馈分类型、有上下文、可检索
4. 回注有闭环——沉淀知识在下次写作时自动注入 S07 Slot
5. 作用范围可控——反馈必须在 article/strategy_unit/account/platform/theory 五级中选择
6. 策略可校准——反馈还能调整评分矩阵、重写策略、抽检率和发布动作
7. 知识要复水——干知识不能脱离当前场景直接注入
8. 进化要留痕——知识晋升、降权、退休都必须形成 ArtifactEvolutionEvent
9. 全量先入账——反馈原文、上下文、diff、采纳/拒绝结果都进 EventLedger
10. 遗忘再激活——只有经过 ForgettingSystem 筛选的内容才进入 OperationContextPack
11. 召回可讨论——历史反馈被秘书主动召回时必须带 RecallCard 进会议

### A.2 与遗忘系统的关系

```text
Feedback / Revision / Decision
  -> EventLedger 全量记录
  -> ForgettingQueue 后台提炼
  -> RetainedPatternStore 保留模式
  -> OperationContextPack 最小注入
  -> RecallCard 主动召回
```

反馈第一目标不是立刻变成规则，而是形成可追溯事实��系统随后决定它应该被遗忘、压缩、降权、候选化还是激活。

### A.3 交互修改界面

详见 `15.[交互]-Amy工作台-Amy-Desk.md` §八（自然语言改稿闭环）和 §八.1（RevisionIntent 四层影响预览）。

交互修改关键规则：`0 我来输入` 后必须先生成 RevisionIntent → PreparedActionPanel → Diff/Package Preview → 人类确认 → RevisionSession。Amy 不能把自然语言输入静默应用到一批产出物。

批量修改影响预览必须分 ContentImpact / PublicationImpact / GateImpact / SourceBoundaryImpact 四层。涉及 SourcePack 边界、理论显性度跨档、已发布内容召回或多发布包作废时，必须先形成 BatchActionProposal。

### A.4 反馈作用范围

| 范围 | 枚举值 | 含义 |
|------|--------|------|
| 本文级 | `article` | 只修正当前文章 |
| 策略单元级 | `strategy_unit` | 影响当前账号+平台+内容类型+理论介入方式 |
| 账号级 | `account` | 影响该账号所有策略单元的风格或立场 |
| 平台级 | `platform` | 影响该平台表达、格式、风险适配 |
| 理论层级 | `theory` | 影响理论映射、观点推导、解释方式 |

系统可建议作用范围，人类可修改。理论层级的反馈只能形成 BackfeedCandidate，不得自动改 SourcePack。

## Part B：片场秘书、批量总编台与遗忘系统

> 原 `18.[交互]-交互修改与遗忘-Interaction-Forgetting.md`（~656 行）。

### B.1 片场组织模型

完整层级见 `04.[模型]-案场与产出物模型-Case-Artifact-Model.md` §2.1：

```text
年案 -> 半年案 -> 季案 -> 月案 -> 周案 -> 日案 -> 今日子案
  -> 片场 -> 产出计划集 -> 产出计划 -> 子片场 -> 产出物
```

片场是固定生成环境：账号 + 平台 + 受众状态 + 内容形态 + 理论显性度 + 声音包 + 质量画像 + 授权策略 + 操作上下文包。任一环境变量变化即建新片场。子片场一对一绑定产出物。

### B.2 总制片秘书（ExecutiveProducerSecretary）

秘书是人类代理人、片场总协调者。她不替代人类主权，而是在授权范围内代理日晨会、片场调度、批量校正、复审、发布排期和异常汇报。

秘书能力受 DelegationPolicy（授权等级）和 InterventionPolicy（打扰阈值）双重约束。秘书可以自动降级或冻结，但不能自升到 StrategyUnitMaturity M3/M4。

### B.3 Amy 压缩策略

详见 `25.[治理]-审阅整改记录-Review-Ledger.md` §11.2（第六轮整改记录）。

四步压缩：
1. 类型归并（同片场多产出物→BatchReviewCard）
2. 预算裁剪（按 HumanAttentionBudget 裁减，超预算项降级）
3. 状态压缩（QualityReport→结论/原因/风险/动作/影响预览 五要素）
4. 人类可覆盖

默认参数：同片场合并上限 8，低风险提案合并阈值每周 1 张，旧系统偏差同日同类合并，发布结果 3 天归档。

### B.4 批量总编台（Artifact Review Desk）

信息架构见 `04.[模型]-案场与产出物模型-Case-Artifact-Model.md` §60 和 `15.[交互]-Amy工作台-Amy-Desk.md` §4.4c。

核心规则：批量动作必须先生成影响预览。高风险项不可被"全部通过"批量吞掉，必须进入详情抽屉或单独工作卡。单批不超过 8 个产出物，超过则按片场或风险组拆分。改稿通过 RevisionSession/ArtifactVersion 留下版本证据。

### B.5 遗忘系统

核心原则：全量记录，有限激活；后台遗忘，前台清明。

```text
EventLedger 全量事实账本
  -> ForgettingQueue 后台提炼/衰减队列
  -> ForgettingRefiner 压缩、降权、候选化
  -> RetainedPatternStore 可复用模式库
  -> OperationContextPack 最小上下文注入
```

遗忘不是物理删除。默认做 decay / mute / compress / candidate / archive / deprecate。物理删除仅在隐私、安全或人类明确要求时执行（见 `24.[数据]-数据库模型与治理-Database.md` §10.1a 的 EventLedger 例外删除规则）。

### B.6 衰减与压缩管道

详见 `25.[治理]-审阅整改记录-Review-Ledger.md` §11.3（第六轮整改记录）。

五步凌晨管道：Decay（默认 stale_ttl=90 天，10%/30 天线性衰减）→ Mute（低于分数阈静音）→ Compress（同类合并为 pattern_candidate）→ Candidate（>=3 次重复或人工正反馈后进入 RetainedPatternStore）→ Archive（365 天超期归档）。

候选提名需同模式重复 >=3 次或人工正反馈 >=1 次，不违反 SourcePack 母板，不穿红线。历史召回必须带 RecallCard 进会议且不自动变成当前规则。

### B.7 保留分数

```text
retain_score =
  source_authority + human_decision_weight + repeated_validation
  + case_relevance + current_context_similarity + risk_weight
  - age_decay - contradiction_penalty
```

SourcePack 母板规则不参与自动衰减。红线事件进入冻结，不得注入。

## Phase 1 边界

> ArtifactOS 1.0 只交付以下遗忘系统子集。其余管道在后续版本演进。

| 模块 | Phase 1 交付 | 后续版本 |
|------|-------------|----------|
| EventLedger 全量记录 | ✅ 事件写入、追加不可变 | 压缩归档、物理删除 |
| ForgettingQueue 后台提炼 | ❌ 不交付 | 凌晨管道 Decay→Mute→Compress→Candidate→Archive |
| RetainedPatternStore | ❌ 不交付 | 可复用模式库、候选提名 |
| OperationContextPack 注入 | ✅ 仅 S00-S09 固定 slot（参见 `11.[流程]-写作流水线-Writing-Pipeline.md` §3.1） | 动态上下文选择 |
| 交互修改 RevisionSession | ✅ 单产出物改稿 + EventLedger 记录 | 批量修改、BatchActionProposal |
| 反馈作用范围 | ✅ article 级自动应用，其余级别人工确认 | 策略单元/账号/平台/理论层自动建议 |
| 召回 RecallCard | ❌ 不交付 | 秘书主动召回历史反馈 |

Phase 1 核心路径：人类修改 → EventLedger 记录 → S07 Slot 注入。遗忘管道和模式提炼延后。

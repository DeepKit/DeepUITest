# 候选包导出

## 概述

DeepFrames 只生产可供下游系统或人工使用的候选包，不负责平台账号、登录会话、浏览器上传、自动发布、最终平台标题、最终标签、最终简介、账号定位、排期、运营和数据复盘。

候选包导出阶段负责把音频、视频、封面、字幕、平台 metadata、AI 标注、质量快照和资产校验信息整理为稳定目录与 manifest。下游发布系统可以根据平台、账号定位和多版本标注选择候选包。

> 平台规格参数（画面比例、分辨率、码率等）详见 `07.platform-多平台适配-multi-platform.md`，本文档只定义 DeepFrames 的候选包产物。

## 导出架构

```text
DeepFrames 生产结果
  │
  ├─ audio_manifest + audio assets
  │    └─ audio candidate package
  │
  └─ video_ir + video assets
       └─ video candidate package
```

音频和视频候选包各自独立：

- 音频生产完即可生成音频候选包。
- 视频后续制作完再生成 B站或其他平台视频候选包。
- 不需要等音频、视频、多平台版本全部完成。
- 候选包是生产结果，不代表已经发布。

## 当前自用版默认导出

| 类型 | 默认平台 | 输出内容 |
|---|---|---|
| 音频候选包 | 音频平台通用 | 成品音频、封面、metadata、timestamps、audio manifest、quality snapshot |
| 视频候选包 | B站 | mp4、封面、字幕、标题、简介、标签、AI 声明、manifest、quality snapshot |

第一条完整链路默认生成：文章 -> 音频候选包 + B站视频候选包。

## 候选包目录

候选包目录保持独立，不与程序目录、数据库目录和 worker 临时目录混在一起。

```text
output/{project_id}/{content_unit_id}/{package_id}/
├── package_manifest.json
├── quality_snapshot.json
├── metadata.json
├── assets/
│   ├── audio/
│   ├── video/
│   ├── cover/
│   └── subtitle/
└── snapshots/
    ├── source_document.json
    ├── script_document.json
    ├── shot_document.json
    ├── audio_manifest.json
    └── video_ir.json
```

路径由 DB1 配置控制；候选包记录写入 DB2 `deepframes_candidate_package`，文件只作为资产载体。

## package manifest

`package_manifest.json` 是下游消费入口：

```json
{
  "schema_version": "1.0.0",
  "package_id": "pkg_...",
  "project_id": "proj_...",
  "content_unit_id": "unit_...",
  "target_platform": "bili",
  "delivery_type": "video",
  "variant_label": "main",
  "account_profile": null,
  "created_at": "2026-06-01T00:00:00Z",
  "assets": [],
  "metadata_uri": "metadata.json",
  "quality_snapshot_uri": "quality_snapshot.json",
  "source_trace": {
    "source_document_id": "...",
    "script_document_id": "...",
    "shot_document_id": "...",
    "audio_manifest_id": "...",
    "video_ir_id": "..."
  }
}
```

## 平台 metadata

每个平台独立生成标题、标签、描述和 AI 声明，但 DeepFrames 只把它们写入候选包，不执行发布。

### B站

```text
标题限制: ≤ 80 字，前 20 字权重最高
标签: 5-10 个
封面: 1920×1080
分区建议: 有声小说 / 知识等，由下游发布系统最终选择
AI 声明: 简介区建议注明
```

### 音频平台通用

```text
专辑/系列标题: 由候选包 metadata 提供
章节标题: 由 content_unit display_label 和脚本摘要生成
封面: 默认 1000×1000
简介: 200-500 字候选文案
```

### 其他平台

抖音、快手、小红书、视频号、YouTube 等平台规格保留在 DB2 `deepframes_platform_spec`。当前自用版不优先实现这些候选包，但 schema 必须支持后续扩展。

## AI 内容标注

各平台审核要求可能变化，因此 AI 标注作为平台规格的一部分保存：

| 平台 | 默认实现 |
|---|---|
| B站 | 简介区注明 |
| 抖音/快手 | 视频内嵌常驻标注 + 简介区注明 |
| 小红书 | 描述区标注 + 封面可选标注 |
| YouTube | 描述区注明 |
| 音频平台 | 预留字段 |
| 视频号 | 简介区注明 |

DeepFrames 负责生成候选标注文案和必要的视频内嵌标注资产；是否发布、如何填写由下游系统或人工决定。

## 多版本标注

同一内容可以生成多个候选包：

| 字段 | 说明 |
|---|---|
| `variant_kind` | `main/experiment/platform/account` |
| `target_platform` | 平台，如 `bili` |
| `account_profile` | 账号定位，可为空 |
| `expression_policy_json` | 表达策略，如准确优先、口语化、浓缩版 |
| `quality_snapshot_json` | 当前候选包质量摘要 |

多版本标注适用于什么平台、什么账号定位，由下游发布系统选择；DeepFrames 只负责生产并准确标记。

### 异步审阅包

Phase 1-4 候选包即为审阅包：`package_manifest.json` + `quality_snapshot.json` + snapshot 截图已足够支撑人工审阅。Phase 5+ 可扩展 HTML review package（内嵌播放器、逐 shot 对照、质量标注），当前不实现。

## 资产保留与清理

默认采用 **102C 策略**：保留最终候选包和关键快照，中间大文件按策略清理。102C 的目标是：候选包可复核、关键链路可追溯、磁盘空间可控。

### 资产分类

| 分类 | 例子 | 默认保留 | 清理规则 |
|---|---|---|---|
| C1 最终交付资产 | 最终 MP3/AAC、最终 MP4、封面、字幕、metadata | 长期保留 | 只有删除候选包时才允许进入清理周期 |
| C2 关键快照 | `package_manifest.json`、`quality_snapshot.json`、`audio_manifest.json`、`video_ir.json`、source/script/shot 快照、prompt/model/worker 版本引用 | 长期保留 | 不自动清理，用于复核和复现 |
| C3 可复现中间资产 | 逐帧图片序列、中间 WAV、raw video、capture cache、可再生背景图副本 | 短期保留 7-30 天 | 未被候选包引用且超过保留期后可清理 |
| C4 临时/失败资产 | worker 临时目录、失败 partial output、lint 之外的调试截图 | 立即或短期清理 | job 结束后清理；失败排查窗口默认 3 天 |

### 保护白名单

以下资产永远不得被自动清理：

- 被 `candidate_package.source_trace` 直接或间接引用的资产。
- `deepframes_asset.protected_until > NOW()` 的资产。
- `status = ready` 且属于 C1 / C2 分类的资产。
- 用户手动标记为 `keep` 的资产。

### 清理触发条件

清理任务由 DeepBase Scheduler 或用户手动触发：

| 触发 | 条件 |
|---|---|
| 定期清理 | 每日或每周扫描 C3/C4 资产 |
| 磁盘压力 | 输出目录剩余空间低于配置阈值（如 20GB） |
| 项目删除 | 用户删除项目或候选包后，解除引用保护再清理 |
| 手动清理 | 用户在 UI 中选择清理中间资产 |

### 清理审计

每次清理必须写入清理日志，记录：`asset_id`、原始 URI、byte_size、sha256、清理原因、触发者、清理时间、是否可恢复。文件删除后，DB 中 `deepframes_asset.status` 从 `ready` 或 `failed` 变为 `deleted`，保留 metadata，不物理删除资产记录。

清理任务不得删除已登记为 `ready` 且被候选包引用的资产。清理动作必须写日志，并保留可追溯的资产状态。

## 导出检查清单

候选包导出前检查：

- [ ] 文件完整可读取
- [ ] manifest、metadata、quality snapshot 存在
- [ ] 资产 SHA256、大小、时长、编码信息已记录
- [ ] AI 标注按平台规格生成
- [ ] 文件大小未超出平台限制
- [ ] 时长符合平台策略
- [ ] 红灯问题已处理；黄灯问题已记录并提醒
- [ ] 候选包可回溯到 source、prompt、model、worker 和质量门控版本

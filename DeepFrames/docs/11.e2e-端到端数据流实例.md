# 端到端数据流实例

> 本文档在架构阶段用一条真实文章走通完整数据流，验证 schema 是否真的能承载真实内容。
> 引用的章节切分、shot 编号、字段值均为示意——不要求 Agent 实际产出与此完全一致，但字段结构必须严格匹配。

**实例文章**: 玄幻小说《剑道长生》第一章"初入青云门"

> 第一章 初入青云门
>
> 夜色如墨，青云山巅的宗门大殿前，数百根石柱上的灵石灯依次亮起，把整座广场照得如同白昼。林远站在人群最末，手心全是汗。

>

>
> 林远咬紧牙关。就在执法长老准备宣布结果时，石碑突然亮起——不是普通的白色，而是刺目的金色。

> 整个广场安静了。
>
> "这是……"执法长老猛地站起身，死死盯着碑面上浮现的古老符文。
>
> 林远自己也愣住了。他体内的灵力——不，那不是灵力，那是他在砍柴时无意中领悟的剑意——正在石碑上刻画出一道道锋利的痕迹。

> "剑道天赋。"执法长老的声音在颤抖，"天级剑道天赋。"


## 实例验证的 Schema 结论

1. **文档链 schema 完整**: source → script → accuracy → variant → shot → manifest → IR → package 的字段级映射已覆盖实例中的所有数据
2. **content_unit 抽象正确**: 一章 = 1 个 content_unit，9-11 个 shot，3 个 group，不依赖 hardcoded `chapter` 概念
3. **A/B 差异维度可控**: 叙事语气差异导致 shot 数从 9 到 11，差异标注只标记语义偏差和不一致，不做全量比对
4. **规则引擎产出可量化**: Style Keeper 给出余弦值，Assembler 给出跨度值，Gate 给出分数——全部可比较、可设定阈值
5. **音频时间戳双坐标可用**: shot_local + global 时间戳在实例中清晰分层，拼接后 global 单调递增，local 不变
6. **候选包可回溯**: 从 pkg_a_ch01_bili 可追溯到 source_document、prompt template、model binding、quality snapshot 的完整链

# 多平台适配

## 概述

DeepFrames 需要将同一内容适配到多个平台的差异化规格。核心策略是**一次生产、多版本输出**，通过分层渲染和平台配置表实现。

## 平台规格配置表

| 平台 | 画面比例 | 分辨率 | 时长建议 | 码率 | 封面尺寸 | 优先级 |
|---|---|---|---|---|---|---|
| B站 | 16:9 | 1920×1080 | 5-30 分钟 | 8-12 Mbps | 1920×1080 | P0 |
| 喜马拉雅 | — | — | 10-60 分钟 | 128-192 kbps (音频) | 1000×1000 | P0 |
| 抖音 | 9:16 | 1080×1920 | ≤ 15 分钟 | 2-5 Mbps | 1080×1920 | P1 |
| 快手 | 9:16 | 1080×1920 | ≤ 15 分钟 | 2-4 Mbps | 1080×1920 | P1 |
| 小红书 | 3:4 / 1:1 | 1080×1440 | ≤ 15 分钟 | 2-5 Mbps | 1080×1440 | P1 |
| 视频号 | 9:16 | 1080×1920 | ≤ 30 分钟 | 3-6 Mbps | 1080×1920 | P2 |
| YouTube | 16:9 | 1920×1080 | 无上限 | 8-12 Mbps | 1280×720 | P2 |

## 分层渲染架构

将每个 shot 的画面分为三层，各层独立响应画面比例变化：

```
┌─────────────────────────┐
│ 背景层 (Background)      │  AI 生成的场景图，全屏铺满
│                         │
│   ┌───────────────┐     │
│   │ 主体层 (Subject) │   │  角色立绘/关键物体，根据比例调整位置和缩放
│   │               │     │
│   └───────────────┘     │
│                         │
│ ┌─────────────────────┐ │
│ │ 文字层 (Text)        │ │  字幕、标题，在安全区内定位
│ └─────────────────────┘ │
└─────────────────────────┘
```

每层定义平台适配规则：

```json
{
  "layers": {
    "background": {
      "source": "ai_generated",
      "prompt_prefix": "{theme.art_style}, {shot.scene_description}",
      "target_aspect_ratios": ["16:9", "9:16", "3:4", "1:1"]
    },
    "subject": {
      "position": {
        "16:9": { "x": "30%", "y": "50%", "scale": 0.4 },
        "9:16": { "x": "50%", "y": "45%", "scale": 0.5 },
        "3:4":  { "x": "50%", "y": "45%", "scale": 0.45 }
      }
    },
    "text": {
      "safe_zone": {
        "16:9": { "top": 85, "bottom": 100, "margin_x": 10 },
        "9:16": { "top": 82, "bottom": 95, "margin_x": 8 }
      },
      "max_chars_per_line": {
        "16:9": 20,
        "9:16": 14
      }
    }
  }
}
```

## 多后端 Composition 渲染

平台配置以 DB2 的 `deepframes_platform_spec` 为单一来源。Delphi 主程序读取同一份配置并生成 Video IR；HyperFrames worker 生成 HTML/CSS/JS composition，Remotion worker 在 `remotion.config.ts` 中注册 React Composition。以下示例需由数据库规格生成：

```typescript
const PLATFORM_CONFIGS = [
  { id: "bili", width: 1920, height: 1080, label: "B站横屏" },
  { id: "douyin", width: 1080, height: 1920, label: "抖音竖屏" },
  { id: "kuaishou", width: 1080, height: 1920, label: "快手竖屏" },
  { id: "xiaohongshu_3_4", width: 1080, height: 1440, label: "小红书 3:4" },
  { id: "xiaohongshu_1_1", width: 1080, height: 1080, label: "小红书 1:1" },
  { id: "wechat_video", width: 1080, height: 1920, label: "视频号" },
  { id: "youtube", width: 1920, height: 1080, label: "YouTube" },
];

// Remotion adapter: 每个 platform 注册独立 Composition，共享同一套 Video IR
PLATFORM_CONFIGS.forEach((config) => {
  registerComposition({
    id: config.id,
    component: VideoComposition,
    width: config.width,
    height: config.height,
    durationInFrames: totalFrames,
    fps: 30,
    props: { videoIr, platform: config.id },
  });
});
```

Remotion 组件内使用 `useVideoDimensions()` 动态适配：

```typescript
const { width, height } = useVideoDimensions();
const aspect = width / height;
const isVertical = aspect < 1;
```

HyperFrames adapter 使用同一份 `video_ir.json` 生成响应式 HTML composition，并通过 composition lint 检查安全区、字幕换行、水印区域和关键帧空白问题。

## AI 图像生成的构图适配

不同比例的背景图需要不同的构图提示词：

| 目标比例 | Prompt 附加 |
|---|---|
| 16:9 | "wide shot, horizontal composition, cinematic" |
| 9:16 | "vertical composition, tall frame, portrait orientation" |
| 3:4 | "medium shot, portrait composition" |
| 1:1 | "centered composition, square frame" |

切片器 Agent 输出 shot 时需附加 `target_aspect_ratios` 字段，图像生成阶段按目标平台数量并行生成多个版本。

## 素材缓存策略

同一场景不同比例的背景图：

```
assets/backgrounds/
├── shot_001_16x9.png
├── shot_001_9x16.png
├── shot_001_3x4.png
├── shot_002_16x9.png
└── ...
```

素材按 `{shot_id}_{aspect_ratio}.png` 命名，渲染时按目标平台选取。

## 长视频切分策略

不同平台对时长要求不同，需要对内容进行策略性切分：

| 平台 | 策略 |
|---|---|
| B站 | 按章节整章输出（5-30 分钟） |
| 喜马拉雅 | 按章节整章音频（10-60 分钟） |
| 抖音 | 从完整章节中提取精彩片段（1-3 分钟），或按自然段落切分 |
| 快手 | 同抖音策略 |
| 小红书 | 精华浓缩版（30 秒 - 3 分钟） |

切分逻辑由一个**切分 Agent** 负责：输入完整 `shot_document` + 目标平台时长约束，输出适配版本的子集。

## 平台差异化元数据

每个平台需要独立的标题、标签、描述生成策略：

```json
{
  "metadata_per_platform": {
    "bili": {
      "title_pattern": "{小说名}·第{N}章 | {悬念式概括}",
      "title_max_length": 80,
      "tags": ["有声小说", "{小说名}", "{类型}", "AI配音"],
      "cover_style": "信息密度高，含标题文字"
    },
    "douyin": {
      "title_pattern": "{强情绪一句话} #有声小说 #{小说名}",
      "title_max_length": 50,
      "tags_format": "#话题#格式",
      "cover_style": "视频首帧或高冲击力画面"
    },
    "xiaohongshu": {
      "title_pattern": "{口语化20字内} 📖",
      "title_max_length": 20,
      "description_style": "带表情的详细描述，SEO关键词",
      "cover_style": "精美插画风格，决定点击率"
    }
  }
}
```

## AI 内容标注

各平台对 AI 生成内容的审核要求：

| 平台 | 要求 | 实现方式 | `ai_label_mode` |
|---|---|---|---|
| 抖音/快手 | 必须标注"AI 生成" | 视频内嵌水印式常驻标注 + 简介区标注 | `persistent_watermark` |
| 小红书 | 需标注 AI 内容 | 描述区标注 + 封面注明 | `description_and_cover` |
| B站 | 无强制要求，建议标注 | 简介区注明 | `description_only` |
| YouTube | 需标注 AI 合成内容 | 描述区标注 | `description_only` |
| 视频号 | 建议标注 | 简介区注明 | `description_only` |

渲染阶段根据 `platform_spec.ai_label_mode` 决定是否添加常驻水印；片尾声明不能替代抖音/快手的常驻标注。

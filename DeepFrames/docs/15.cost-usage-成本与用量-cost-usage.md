# 成本与用量

## 概述

DeepFrames 当前不做 token/次数预算拦截或成本控制，但必须完整记录每次 provider 调用的用量数据。这些数据用于 prompt 优化、并行度调参、失败分析，并为 Phase 7 商业化提供成本基础。

## 记录维度

### Provider 调用记录

每次调用必须记录：

| 维度 | 字段 | 说明 |
|---|---|---|
| 调用标识 | `run_id` | 唯一调用 ID |
| 时间 | `created_at` | 调用发起时间 |
| Provider | `provider` | StepFun / fake |
| 模型 | `model` | 具体模型标识 |
| 能力 | `capability` | `llm/tts/asr/image_gen/image_edit` |
| Token | `token_input` / `token_output` | LLM token 消耗 |
| TTS | `tts_char_count` / `tts_duration_sec` | TTS 字数和音频时长 |
| ASR | `asr_duration_sec` | ASR 音频时长 |
| 图像 | `image_count` | 图像生成次数 |
| 重试 | `retry_count` | 重试次数（含 repair retry） |
| 耗时 | `latency_ms` | 总耗时 |
| 错误 | `error_code` | 错误码，null 表示成功 |
| 资产大小 | `asset_byte_size` | 产出资产大小 |

### 项目聚合

按 `project_id` 聚合：

| 维度 | 说明 |
|---|---|
| 总 token 消耗 | input + output |
| 总 TTS 字数 / 时长 | 分 provider 统计 |
| 总 ASR 时长 | 分 provider 统计 |
| 总图像生成次数 | 分 provider 统计 |
| 总 retry 次数 | 分 capability 统计 |
| 总耗时 | 分阶段统计（agent / audio / video / render） |
| 总产出时长 | 音频总时长 + 视频总时长 |
| 总产出资产大小 | 所有 ready 状态资产之和 |

### 生产效率指标

| 指标 | 计算 | 用途 |
|---|---|---|
| token 效率 | `产出时长 / token_total` | prompt 优化参考 |
| TTS 成功率 | `成功 TTS 调用 / 总 TTS 调用` | 451 触发率分析 |
| 图像一次通过率 | `无需 repair 的图像调用 / 总图像调用` | prompt 和 schema 调优 |
| Agent 结构化成功率 | `无需 repair 的 JSON 输出 / 总 LLM 调用` | prompt 和 schema 调优 |
| 渲染效率 | `视频时长 / render_time_sec` | worker 性能分析 |
| 降级率 | `degraded shots / 总 shots` | 质量趋势分析 |

## 数据存储

用量数据写入 `deepframes_prompt_run` 的扩展字段和 `deepframes_job_step.extra_json`。不做独立用量表；聚合查询通过 SQL VIEW 或应用层汇总。

### 记录时机

| 时机 | 记录内容 |
|---|---|
| LLM 调用完成 | `deepframes_prompt_run`：token、latency、raw_output 长度、error |
| TTS 调用完成 | `deepframes_prompt_run`：char_count、duration_sec、latency、error |
| ASR 调用完成 | `deepframes_prompt_run`：duration_sec、latency、error |
| 图像生成完成 | `deepframes_prompt_run`：image_count、latency、error |
| Worker 步骤完成 | `deepframes_job_step.extra_json`：render_time、frames_captured、lint 结果 |
| 候选包导出 | `deepframes_candidate_package.extra_json`：项目聚合摘要 |

## 不做的事项（当前）

| 功能 | 状态 | 原因 |
|---|---|---|
| token/次数预算拦截 | 不实现 | StepFun 按包月使用，DeepFrames 不做成本守门 |
| 成本估算 / 报价 | 不实现 | 自用版不需要 |
| 用量仪表盘 | 不实现 | 数据已记录，UI 后置 |
| 多 Provider 成本比较 | 不实现 | 当前只有 StepFun |
| 按用户/租户分账 | 不实现 | 单人单机 |
| 自动调 prompt 降低成本 | 不实现 | 只记录不自动优化 |
| 自动暂停/限流 | 不实现 | 用户手动控制生产节奏 |

## 商业化预留

Phase 7 商业化可能需要：

1. **用量配额**：基于聚合数据设定 token/时长上限。
2. **成本估算**：基于历史数据预估单项目成本。
3. **多 Provider 成本比较**：按 capability 比较不同 provider 的性价比。
4. **用量报告**：项目级、时间段级聚合报告。

这些不影响当前数据契约。`deepframes_prompt_run` 已记录所有必要维度，未来只需加 VIEW 或聚合查询。

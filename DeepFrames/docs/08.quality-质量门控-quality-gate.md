# 质量门控

## 概述

DeepFrames 在流水线各阶段设置质量门控（Quality Gate），通过 QA Agent 自动审核和可配置人工控制点确保输出质量。
## 控制点策略

人工控制点是生产参数，不是写死流程。系统支持在 Gate 1、Gate 2、Gate 3a、Gate 3b 和候选包导出前设置不同的停顿策略。

默认策略：全自动跑到候选包，只有红灯停止，黄灯只提醒。

| 结果 | 默认行为 |
|---|---|
| `pass` | 自动进入下一阶段 |
| `warn` / 黄灯 | 记录并提醒人类，继续生产 |
| `fail` / 红灯 | 停止当前任务，进入人工处理或返工 |
| 参数指定人工控制点 | 到达指定 Gate 时暂停，等待人工确认 |

控制点配置写入 DeepBase.Config；单次任务参数可以覆盖默认值，但不自动改写全局策略。

## Gate → 对象状态驱动矩阵

Gate 结果不仅是质量记录，也驱动对应业务对象和 job/step 的状态变化。状态写入必须由 Workflow application service 统一执行，禁止各模块绕过状态机直接改状态。

| Gate | 读取/检查对象 | 写入/驱动对象 | `pass` | `warn` | `fail` |
|---|---|---|---|---|---|
| Gate 1 | `source_document` / `script_document` / `accuracy_report` | `script_document` + preprocess job | `script_document.status = done`，preprocess job `done` | `script_document.status = done`，写入 warning issue，job 继续 | preprocess job `blocked_review`，`script_document.status = blocked_review` |
| Gate 2 | `shot_document` + QA / Style Keeper + 可选 `accuracy_report` | `shot_document` + agent job | `shot_document.status = done`，agent job `done` | `shot_document.status = done`，`quality_gate_result.gate_result = warn`，job 继续 | agent job `blocked_review`，问题 shot 对应 step `blocked_review` |
| Gate 3a | `audio_manifest` + audio assets | `audio_manifest` + audio assets + audio job | `audio_manifest.status = done`，音频 asset `ready`，audio job `done` | `audio_manifest.status = done`，音频 asset `ready`，写入 `quality_snapshot` warning，job 继续 | audio job `blocked_review`；执行错误 step 设 `failed`，质量门控需人工判断的 step 设 `blocked_review` |
| Gate 3b | `video_ir` / video assets / final mp4 | `video_ir` + video assets + video job | `video_ir.status = done`，视频 asset `ready`，video job `done` | `video_ir.status = done`，视频 asset `ready`，写入 warning，job 继续 | video job `blocked_review`；执行错误 step 设 `failed`，质量门控需人工判断的 step 设 `blocked_review` |
| 导出前检查 | `candidate_package` + package assets | `candidate_package` + package asset + package job | `candidate_package.status = done`，package asset `ready` | `candidate_package.status = done`，warning 永久写入 snapshot | package job `blocked_review`，不生成 `done` package |

`warn` 默认不改变 job 为 `blocked_review`；只有用户显式配置人工停顿时，才在 Gate 处暂停并设置 `human_review_status = pending_review`。`fail` 必须进入 `blocked_review`，除非用户在人工界面选择 `override_accept`，此时按 `12.db-state` 的 `review_action` 规则记录。

`accuracy_report.result` 与 `quality_gate_result.gate_result` 共享值域 `{pass, warn, fail}`，但前者属于脚本级准确性报告，后者属于 Gate 门控结果，分别写入不同表。若 job 最终为 `done` 且存在 `degraded` shot，则 `payload_json.completion_type = partial_degraded` 并记录 `payload_json.degraded_ratio`；若存在人工跳过的 shot，则使用 `partial_skipped`。

## Gate 1: 结构校验（预处理后）

### 自动检查项

- 章节切分是否完整（无遗漏段落）
- 角色列表是否覆盖所有对话角色
- 场景标注是否覆盖所有场景变化
- 数据格式是否符合 `source_document` / `script_document` 契约
- **来源元数据子检查**（搬运场景，`source_type = external_video` / `external_audio` / `local_file` 时）：校验 `origin_url` 或 `local_path`、`downloaded_at`、`asr_transcript` 是否齐备；缺失只标**黄灯提醒补全**，不阻塞全自动。`license_hint`（`self`/`authorized`/`unknown`）为描述性字段，供人工复核可选项，**不设授权硬门**——合规是 adapter 参数，用户自担合规责任（见 `01.arch` 边界声明、`17.lessons-y2a` A/B/C 分类）。

### 可选人工审核

是否暂停由控制点参数决定；默认不暂停，红灯除外：

```
[Gate 1] 章节切分结果:
  第1章: 12 个段落, 3 个角色, 4 个场景
  角色: 张三(5次), 李四(3次), 旁白
  [确认通过] [调整切分] [重新识别角色]
```

## Gate 2: 内容审核（Agent 输出后）

### `accuracy_report` 与 Gate 2 QA 的职责边界

两者都涉及"忠实度"，但检查对象和失败处理不同，不能混用：

| 报告 | 产生阶段 | 检查对象 | 主要问题 | 写入表 | 失败处理 |
|---|---|---|---|---|---|
| `accuracy_report` | `build_script(source_document)` | `script_document` 是否忠实于 `source_document` | 原文遗漏、事实歪曲、引用缺失、术语错误 | `deepframes_accuracy_report` | Gate 1 fail；回到脚本构建或人工修订 |
| Gate 2 QA | Agent 工作流后 | `shot_document` 是否忠实于 `script_document` 且适合音视频生产 | shot 遗漏、画面不匹配、风格漂移、情感错误、时长异常 | `deepframes_quality_gate_result` / `deepframes_eval_result` | Gate 2 fail；回流 Worker / Assembler / 人工接受 |

`accuracy_report` 可作为 Gate 2 QA 的输入参考，但 Gate 2 QA 不覆盖、不修改、不重算 `accuracy_report`。如果 Gate 2 发现脚本级错误，应生成 `upstream_accuracy_issue` 类型 issue，要求回到 `build_script` 阶段生成新的 `script_document` 和新的 `accuracy_report`。

### `accuracy_report` JSON 契约

```json
{
  "schema_version": "1.0.0",
  "source_document_id": "...",
  "script_document_id": "...",
  "coverage_ratio": 0.97,
  "faithfulness_score": 0.92,
  "issues": [
    {
      "type": "omission | distortion | unsupported_addition | term_mismatch | citation_missing",
      "severity": "warn | fail",
      "source_range": { "start": 120, "end": 260 },
      "script_range": { "start": 80, "end": 140 },
      "description": "脚本遗漏了原文中的关键限制条件",
      "suggestion": "补回该限制条件或标注为有意省略"
    }
  ]
}
```

### Gate 2 QA Agent

独立于 Worker Agent 的质量审核 Agent，默认使用 `deepseek-v4-pro`；最终模型可在生产前由用户配置。Gate 2 可读取上游 `accuracy_report` 作为原文忠实度参考，但自身产物是写入 `deepframes_quality_gate_result` 的门控结果，不覆盖脚本级 `accuracy_report`：

**输入**: 完整 `shot_document` + 原文 / `script_document` + 可选 `accuracy_report`

**检查项**:

| 检查维度 | 规则 | 不合格处理 |
|---|---|---|
| 文本完整性 | 字幕文本与原文覆盖率 ≥ 95% | 标记遗漏段落，回流 Worker |
| 画面匹配度 | 画面描述与文本内容的语义相关性 | 回流重做 |
| 情感一致性 | 情感标注与文本语境的匹配 | 修正 instruction |
| 风格统一性 | 同章节内画风/色调的一致性 | 修正 prompt |
| 转场连贯性 | 相邻 shot 的转场是否自然 | 调整 transition |
| 时长合理性 | 单 shot 时长 3-8 秒，无异常值 | 重新切分 |

**输出**:

```json
{
  "schema_version": "1.0.0",
  "gate": "gate2",
  "gate_result": "pass | warn | fail",
  "score": 0.85,
  "shot_document_id": "...",
  "script_document_id": "...",
  "accuracy_report_id": "...",
  "coverage_ratio": 0.96,
  "degraded_ratio": 0.08,
  "issues": [
    {
      "shot_id": "shot_023",
      "type": "text_omission | visual_mismatch | emotion_mismatch | style_inconsistency | transition_issue | duration_outlier | upstream_accuracy_issue",
      "severity": "warn | fail",
      "scope": "shot | group | chapter | upstream_script",
      "description": "画风从水墨切换到写实，与上下文不协调",
      "suggestion": "统一为中国水墨画风",
      "recommended_action": "accept | rework_worker | rework_splitter | rework_script | manual_edit"
    }
  ]
}
```

**阈值规则**:
- `score >= 0.80` 且无 hard issue：`pass`
- `0.60 <= score < 0.80` 或存在可人工接受的 soft issue：`warn`
- `score < 0.60` 或存在文本遗漏、schema 错误、关键镜头缺失等 hard issue：`fail`
- `degraded` shot 比例 > 20% 时，Gate 2 最高只能为 `warn`
- `degraded` shot 比例 > 40% 时，Gate 2 必须为 `fail`

### Style Keeper（确定性规则引擎）

横跨所有 shot 的风格一致性检查，独立于 QA Agent，**不调用 LLM**。完整规则见 `03.agent-Agent工作流-agent-workflow.md`：

- 主色调一致性：从 `background_prompt` 提取颜色描述词，与 `style_anchor.color_palette` 匹配
- 画风关键词一致性：与 `style_anchor.art_style` 做 embedding 余弦相似度检查，`cosine < 0.7` 标黄灯
- Group 内一致性：同组 prompt 两两比对，任意 pair `cosine < 0.8` 标黄灯
- Group 间过渡平滑性：相邻 `group_style` 的 `cosine < 0.5` 时提醒检查叙事意图
- 输出风格一致性报告和修正建议

### 可选人工审核

```
[Gate 2] QA 评分: 85/100, 风格一致性: 良好
  ⚠ shot_023: 画风不一致 (水墨→写实)
  ⚠ shot_045: 情感标注偏弱 (应"紧张"非"平静")
  [全部通过] [修正后通过] [重新生成]
```

## Gate 3a: 音频成品校验（音频线）

### 自动检查项

| 检查项 | 规则 |
|---|---|
| 音频容器 | `ffprobe` 可读取，编码/采样率/声道符合目标规格 |
| 拼接一致性 | `raw.wav` 实际时长与拼接计算时长（所有 shot 实际 duration + silence gaps）偏差 ≤ 100ms，否则红灯 |
| 估时偏差 | TTS 实际时长与 Agent 预估时长分开记录，写入 quality snapshot 作为黄灯提示或调参依据，不直接等同于拼接失败 |
| 音量标准 | 独立 loudnorm 测量结果为 -16 LUFS ± 1 |
| 静音异常 | 无非预期长静音段 |
| ASR 时间戳 | 单调递增，所有 word timestamp 不超过对应 shot duration |
| TTS 451 改写 | `tts_text_variant` 不改写 `shot_document`；相似度 ≥ 0.95 pass，0.85-0.95 warn，< 0.85 fail |
| manifest 完整性 | 所有引用文件存在，记录 file size 和 SHA256 |

## Gate 3b: 视频成品校验（视频线）

### 自动检查项

| 检查项 | 规则 |
|---|---|
| 视频容器 | `ffprobe` 可读取，视频轨存在 |
| 编码规格 | 分辨率、fps、codec、bitrate、pix_fmt 符合 `platform_spec` |
| Composition lint | Renderer Adapter 输出无空白帧、元素越界、字幕遮挡、资源缺失和不确定时间轴 |
| Snapshot QA | 首帧、关键帧、尾帧截图通过非空白、主体可见、安全区和平台标注检查 |
| 音轨 | `final-with-audio` 必须存在非静音音轨；`visual-preview` 不要求音轨 |
| 时长同步 | 全章偏差 ≤ 0.5 秒，任意 60 秒窗口音视频偏差 ≤ 50ms |
| 字幕同步 | timestamps 已按 fps 边界量化，且不越界 |
| AI 标注 | 平台要求 `persistent_watermark` 时，抽帧校验水印区域存在 |
| 文件大小 | 未超出目标平台限制 |
| manifest 完整性 | 记录 file size 和 SHA256 |

### 可选人工审核

用户可以按控制点参数预览音频或视频生产结果；默认自动导出候选包，红灯除外：

```
[Gate 3b] 自动检查: 全部通过
  视频: 12分34秒, 1080p, 156MB
  音频: 12分34秒, AAC, 非静音
  [预览播放] [导出平台包] [返回修改]
```

## 片段级编辑

支持用户选中任意 shot 进行定向修改，无需全章重来：

```
deepframes edit --shot shot_023 --field visual.background_prompt --value "新的画面描述"
deepframes edit --shot shot_023 --field audio.instruction --value "更激动的语气"
deepframes re-render --shot shot_023   # 只重新生成该 shot 的素材并渲染
```

### 编辑粒度

| 层级 | 操作 | 影响范围 |
|---|---|---|
| 片段级 | 修改单个 shot 的参数 | 仅该 shot |
| 章节级 | 修改风格预设后整章重渲染 | 当前章节 |
| 项目级 | 修改全局参数后批量更新 | 全部章节 |

### 预设结构

```json

  "visual": {
    "art_style": "中国水墨画与奇幻风格融合",
```

| 预设 ID | 适用类型 | 视觉特征 |
|---|---|---|
| `xuanhuan` | 玄幻/仙侠 | 水墨+奇幻，深色调 |
| `dushi` | 都市/现代 | 写实街景，明亮色调 |
| `lishi` | 历史/武侠 | 古典画风，暖色调 |
| `xuanyi` | 悬疑/推理 | 暗色调，高对比度 |

用户可在内置预设基础上自定义，或从零创建。

## 降级策略

当某个 shot 无法正常生成时，启动降级方案保证时间轴完整：

| 失败类型 | 处理策略 |
|---|---|
| 图像生成失败 | 模板化布局（排版骨架 + 主题配色渐变背景）+ 字幕，标记待补。不使用空白纯色填充——即使降级也保持视觉结构的完整性 |
| TTS 451 审查 | 音频线生成 `tts_text_variant` 后重试；相似度 ≥ 0.95 放行，0.85-0.95 黄灯人工确认，< 0.85 红灯进入 `blocked_review` |
| TTS 限流/超时 | 指数退避重试，最多 3 次 |
| Agent 推理异常 | 降级为简化模板（纯字幕+背景色） |
| 渲染崩溃 | 记录失败帧范围，支持从断点续渲染 |

降级生成的 shot 标记为 `degraded: true`，用户可在后续手动重新生成。

## 不可修复的质量问题

并非所有质量问题都能通过返工或降级解决。以下信号表明问题根源在输入层面（文章不适合、风格预设不匹配、参数组合错误），继续生产会浪费 API 调用和渲染时间，应该停止并从根本上修改输入或参数。

### 放弃当前参数组合的信号

| # | 信号 | 判据 | 建议动作 |
|---|------|------|---------|
| 1 | 降级蔓延 | 连续 2 轮 QA 回流后 `degraded` shot 比例仍 > 40% | 停止生产。检查文章是否适合当前风格预设。尝试更换 preset 或调整章节切分。 |
| 2 | 系统性低分 | QA 对同一项目连续 2 个 content_unit 评分 < 0.5 | 停止生产。检查文章内容与视觉/音频风格预设的根本匹配度。可能是文章类型不适合（如纯抽象论述无画面感）或风格预设选错了。 |
| 3 | 同类黄灯递增 | 同一 issue type 的黄灯数连续 3 次生产递增 | 停止生产。该维度的问题不是随机波动——是系统性缺陷。检查 prompt 模板或风格约束是否有矛盾。 |
| 4 | TTS 失败率 > 30% | 单次生产中 451 触发率超过 shot 总数的 30% | 停止音频线。文章可能包含大量敏感词，或 TTS 分段策略需要调整。人工 review 原文后再决定是否继续。 |
| 5 | 图像生成一致率 < 50% | Style Keeper 规则引擎标记的风格一致性偏差率超过 shot 总数的 50% | 停止视觉线。`group_style` 的约束可能太弱，或图像 API 对当前风格标签的生成不稳定。调整 group_style 或更换锚点策略后再重试。 |

### 根本不适合生产的内容信号

以下内容类型已知不适合当前 DeepFrames 管线，应在导入阶段或 Gate 1 就识别：

| 内容类型 | 为什么不适合 | 检测方式 |
|---------|------------|---------|
| 纯抽象论述 | 没有场景、角色、画面可描述。Agent 只能生成"一个人说话"的重复画面 | 文本分析：名词实体密度 < 每 100 字 2 个，或对话占比 < 10% |
| 数据密集型 | 大量数字、表格、统计数据无法转化为视觉画面 | 文本分析：数字占比 > 15% |
| 多语言混合 | StepFun TTS 仅支持中文，多语言段落无法配音 | 文本分析：非中文字符占比 > 20% |
| 极度口语化 | 语气词、方言、网络用语大量出现，TTS 表现不稳定 | 文本分析：非标准词典覆盖率 < 70% |

检测到不适合的内容时，Gate 1 标记为红灯并展示原因和建议（"该文章为纯抽象论述，建议选择'知识讲解'模板而非叙事类预设，或人工改写增加场景描写"）。用户可以选择继续（接受降级风险）或放弃。

### 操作指南

当触发"放弃当前参数组合"信号时，用户有以下选项：

1. **换风格预设** — 最常用的修复。玄幻 → 都市、保守 → 大胆。从头重跑。
2. **换文章切分策略** — 当前章节切分颗粒度不适合，调整 target_duration_sec 或手动指定切分点。
3. **人工预处理文章** — 在导入前对原文做改写（增加场景描写、去除数据、统一语言）。这是输入层面的修改，不在 DeepFrames 内完成。
4. **接受降级结果** — 确认知道这些问题，但仍然导出（在 quality_snapshot 中永久记录"已知缺陷"）。

所有放弃信号触发时，DeepFrames 记录完整的质量上下文（QA 评分历史、黄灯趋势、降级比例、使用的 prompt 版本和模型绑定）到 `deepframes_quality_gate_result`，便于后续分析和改进 prompt 模板。

## 生产内反馈

用户在生产过程中的选择、确认、手动编辑和 warning 处理行为只用于以下用途：

1. **写入 `deepframes_quality_gate_result` 和 `deepframes_eval_result`**：人工审核记录、编辑操作、选择偏好。
2. **支持人工复盘**：在 UI 中展示历史选择和趋势，帮助用户发现系统性偏好。
3. **支持未来 prompt 优化**：记录完整上下文后，人工可以基于数据修改 prompt 模板。

**当前不实现**：自动调 prompt、自动调阈值、自动训练模型、用户画像、自动 A/B winner 选择。学习系统是 Phase 7+ 的商业化/产品化决策，不影响当前数据契约。

## Provider 轻量边界

StepFun 是当前 reference implementation（参考实现），不是散落在 DeepFrames 业务代码中的唯一硬编码依赖。DeepFrames 业务层按能力角色调用：

- LLM / Chat
- TTS
- ASR
- Image Generation / Image Edit

当前只实现 StepFun adapter。业务层不得直接散落 StepFun HTTP 调用；provider-specific 参数只能存在于 DeepBase adapter、StepFun image adapter 或模型绑定配置中。当前不实现多 Provider 动态注册、自动路由、provider fallback、多 Provider UI 或成本比较。

工程开发期间允许使用 `fake provider` 返回固定结构化 JSON，以固化 schema、Repository、状态机、UI 和版本链。fake provider 不是生产 Provider；StepFun adapter 接入后仍保留它作为回归测试夹具。

## 基础配置

### 双端点架构

StepFun 存在两套 API 端点，使用不同的 API Key：

| 端点类型 | Base URL | API Key | 覆盖能力 |
|---------|----------|---------|---------|
| **Step Plan 端点** | `https://api.stepfun.com/step_plan/v1` | Step Plan API Key | Chat（LLM）、TTS、ASR、Image Gen/Edit |
| **标准端点** | `https://api.stepfun.com/v1` | 标准 API Key | ASR（需充值，Step Plan Key 优先） |

> **关键修正（POC 2d 验证）**: ASR SSE 端点使用 Step Plan 端点 `/step_plan/v1/audio/asr/sse` + Step Plan Key。Standard 端点对 ASR 返回 402（需单独充值）。当前只需一个 Step Plan Key 即可覆盖全部能力。

- **认证方式**: Bearer Token（Header: `Authorization: Bearer <key>`）
- **协议**: OpenAI 兼容（Chat），自定义协议（Audio/Image），SSE（ASR）

## DeepBase 接入规则

StepFun 是 DeepFrames 的 provider，不是独立于 DeepBase 的旁路客户端。

- Chat 能力优先通过 `DeepBase.LLM` provider adapter 接入。
- TTS / ASR 能力通过 `DeepBase.Speech` provider adapter 接入。
- 图像能力由 DeepFrames 的 StepFun image adapter 封装，但配置、密钥、日志和重试仍接入 DeepBase。
- API Key 使用 `DeepBase.Security.SaveSecret/LoadSecret` 保存，不写入 `.env`、JSON、INI、日志或 DB2 业务表。
- 网络调用不得阻塞 VCL UI 线程，使用后台任务或 worker queue。

## 接口详情

### Chat Completion

```
POST /chat/completions
```

请求体：
```json
{
  "model": "stepfun-flash-3.5",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."}
  ],
  "stream": false
}
```

支持流式输出（`stream: true`），支持 reasoning_content 返回推理过程。

### TTS 语音合成

```
POST /step_plan/v1/audio/speech
```

请求体：
```json
{
  "model": "stepaudio-2.5-tts",
  "input": "要合成的文本内容",
  "voice": "cixingnansheng",
  "instruction": "语气温柔，语速偏慢",
  "response_format": "wav"
}
```

参数说明：
- `voice`: 预置音色 ID，支持自定义克隆音色
- `instruction`: 情感/语速/语气控制指令（**限 200 字符**）
- `response_format`: mp3 / wav / opus / pcm

> **重要限制**：`stepaudio-2.5-tts` 不支持 `voice_label` 参数，只支持 `voice` + `instruction`。DeepFrames 的 `VoiceConfig` 枚举映射为中文 `instruction` 文本，不传入 `voice_label`。

> **括号转义**：`input` 中的括号 `()` 有特殊语义（内联指令）。当原文包含括号时（如"（心想）"），必须转义或移除，否则会被 TTS 引擎解读为控制指令。

> **采样率**：TTS 默认输出 24kHz。DeepFrames 工作流需要显式指定 `response_format: wav` 并在 manifest 中记录实际采样率。混音工程前统一重采样到 48kHz。

内置音色列表（常用）：
- `cixingnansheng` — 慈性男声
- 更多音色见官方文档

流式 TTS：
```
WSS wss://api.stepfun.com/step_plan/v1/realtime/audio
```

### ASR 语音识别

```
POST /step_plan/v1/audio/asr/sse        ← Step Plan 端点，使用 Step Plan Key（POC 2d 验证通过）
```

> **SSE 流式协议**：ASR 返回 Server-Sent Events 流。音频需 Base64 编码，嵌套在 `audio.data` 字段中。

**请求格式（嵌套 JSON）**：
```json
{
  "audio": {
    "data": "<base64-encoded audio>",
    "input": {
      "transcription": {
        "language": "zh",
        "model": "stepaudio-2.5-asr",
        "enable_itn": true,
        "enable_timestamp": true
      },
      "format": {
        "type": "mp3"
      }
    }
  }
}
```

**响应行为**（POC 2d 验证）：
- Delta 事件 `transcript.text.delta`：增量返回单字 + `start_time`/`end_time`（ms）
- Done 事件 `transcript.text.done`：完整识别文本 + usage 统计
- 每个单词一个 delta 事件，包含精确的时间戳（ms 精度）
- DeepFrames 累积所有 delta 事件，在 done 后拼接为完整 word-level 时间戳列表

在 DeepFrames 中用于两个场景：
1. 校验 TTS 音频内容与原文一致性
2. 获取逐字时间戳（word-level timestamp），供视频卡拉 OK 字幕同步使用

> **工程前 POC 要求**：ASR SSE 是整套 API 中集成风险最高的接口。工程启动前必须完成 POC，验证：(1) Delta 事件格式；(2) 时间戳在 Delta 中的字段路径；(3) Done 事件的完成标记；(4) 错误事件格式。POC 结果用于校准本节描述。

## 在 DeepFrames 中的使用场景

| 场景 | 接口 | 说明 |
|---|---|---|
| 小说文本分析 | Chat | 章节切分、角色识别、场景标注 |
| Agent 推理 | Chat | 各 Agent 节点的推理决策（Splitter/Worker/QA）；Style Keeper 是确定性规则引擎 |
| QA 审核 | Chat (`deepseek-v4-pro` 或人工指定模型) | 默认使用强模型做质量把关，最终模型选择生产前确定 |
| 角色配音 | TTS | 多角色多音色配音，结构化情感控制 |
| 字幕同步 | ASR | 校验音频内容 + 获取逐字时间戳 |
| 场景插画 | Image Gen | 视频背景、场景画面（多比例版本） |
| 封面制作 | Image Edit | 各平台封面（不同尺寸） |
| 元数据生成 | Chat | 平台差异化标题/标签/描述 |

## 注意事项

- 短中文文本可能触发内容审查（HTTP 451），确保输入为自然完整句子
- TTS 输出为二进制音频流，直接写入文件，非 JSON。生产中间格式优先 WAV/PCM，平台候选包阶段再转 MP3/AAC
- 图像生成 1-2 秒/任务，适合批量调用
- WebSocket 接口用于实时场景，批量生成用 REST 即可

# Worker 协议

## 概述

本文定义 DeepFrames 外部 worker 的最小协议 v0。Delphi 主程序负责 worker 生命周期管理；worker 只消费已编译的输入，输出标准化的结果。

## Worker 分类

| Worker | 输入 | 输出 | 实现语言 |
|---|---|---|---|
| HyperFrames render worker | Video IR JSON | HTML composition、snapshot、preview/final video | Node/TypeScript |
| Remotion render worker | Video IR JSON | React composition、snapshot、preview/final video | Node/TypeScript |
| FFmpeg / ffprobe | 源文件 + 编码参数 | 音频/视频文件、probe JSON | 二进制 |
| Chromium capture | HTML composition + 帧范围 | 帧序列、snapshot | 二进制 |

Node/TypeScript 只允许出现在 worker 内部实现中，不进入 DeepFrames 桌面主程序。

## 最小协议 v0

### 请求（request.json）

主程序为 worker 创建工作目录并写入 `request.json`：

```json
{
  "schema_version": "1.0.0",
  "job_id": "...",
  "step_id": "...",
  "logical_key": "...",
  "work_dir": "...",
  "input_manifest_uri": "...",
  "output_dir": "...",
  "cancel_file": "...",
  "heartbeat_interval_sec": 5,
  "timeout_sec": 7200,
  "limits": {
    "max_memory_mb": 4096,
    "max_parallelism": 4
  },
  "params": {}
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `schema_version` | 是 | 协议版本 |
| `job_id` | 是 | DB2 任务 ID |
| `step_id` | 是 | DB2 步骤 ID |
| `logical_key` | 是 | 幂等去重键 |
| `work_dir` | 是 | worker 专用工作目录 |
| `input_manifest_uri` | 是 | 指向已编译的 Video IR 或其他输入的 URI |
| `output_dir` | 是 | 输出目录 |
| `cancel_file` | 是 | 辅助取消信号文件路径 |
| `heartbeat_interval_sec` | 是 | 心跳间隔 |
| `timeout_sec` | 是 | 超时阈值 |
| `limits` | 否 | 资源限制 |
| `params` | 否 | worker 特定参数 |

Worker 不直接读取 `shot_document` 或 DB2 业务表；只消费 `input_manifest_uri` 指向的已编译快照。

### 进度（progress.json）

Worker 定期写入 `progress.json`：

```json
{
  "schema_version": "1.0.0",
  "job_id": "...",
  "step_id": "...",
  "percent": 42,
  "message": "rendering frames",
  "heartbeat_at": "2026-06-01T00:00:00Z"
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `percent` | 是 | 0-100 进度百分比 |
| `message` | 否 | 人类可读状态描述 |
| `heartbeat_at` | 是 | 心跳时间戳 |

主程序监控 `heartbeat_at`：超过 `heartbeat_interval_sec * 3` 未更新则判定 worker 无响应。

### 结果（result.json）

Worker 完成后写入 `result.json`：

```json
{
  "schema_version": "1.0.0",
  "job_id": "...",
  "step_id": "...",
  "status": "done",
  "exit_code": 0,
  "assets": [
    {
      "asset_type": "video",
      "uri": "output/movie_bili.mp4",
      "byte_size": 163577856,
      "sha256": "abc123...",
      "mime_type": "video/mp4",
      "duration_sec": 754.5,
      "width": 1920,
      "height": 1080,
      "fps": 30,
      "codec": "h264"
    }
  ],
  "metrics": {
    "frames_captured": 22635,
    "render_time_sec": 842,
    "lint_passed": true,
    "lint_warnings": 2
  },
  "stdout_tail": "",
  "stderr_tail": "",
  "error": null,
  "worker": {
    "name": "render-hyperframes",
    "version": "0.1.0"
  }
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `status` | 是 | `done` 或 `failed` |
| `exit_code` | 是 | 进程退出码 |
| `assets` | 是 | 输出资产列表，可为空数组 |
| `metrics` | 否 | 性能指标 |
| `error` | 否 | 错误信息 |
| `worker` | 是 | worker 名称和版本 |

## Worker 生命周期

### 启动

主程序职责：

1. 在 DB2 创建 `deepframes_job` 和 `deepframes_job_step`。
2. 创建工作目录，写入 `request.json`。
3. 写入已编译的 `input_manifest`（如 `video_ir.json`）。
4. 启动 worker 进程，注入路径参数。
5. 开始监控 heartbeat。

### 运行中

- Worker 定期更新 `progress.json`。
- 主程序轮询 `progress.json` 读取进度。
- 主程序监控 heartbeat 超时。

### 正常完成

1. Worker 写入 `result.json`。
2. Worker 退出，exit code = 0。
3. 主程序读取 `result.json`。
4. 主程序在一个事务内更新 `job_step`、登记 `asset`、记录 metrics。
5. 进入 Gate 校验。

### 取消

取消优先级：

1. **主取消通道**：主程序向 worker 进程发送 `CTRL-BREAK`（Windows）或 `SIGTERM`（Linux）。
2. **辅助取消信号**：主程序写入 `cancel_file`，worker 在正常轮询周期内提前感知。
3. **强制终止**：发送信号后等待 5 秒仍未退出，调用 `TerminateProcess` / `kill -9`。

强制终止后的 partial asset 不得登记为 `ready`，step 标为 `cancelled` 或 `failed`。

### 异常退出

- Worker 崩溃（非零 exit code，无 `result.json`）：主程序检查 `progress.json` 最后 heartbeat，记录 stderr，step 标为 `failed`。
- 超时未完成：主程序执行取消流程。
- 部分输出：已写入的 partial asset 保持 `temp` 状态，不登记为 `ready`。

## 错误码

render worker 统一错误码：

| 错误码 | 含义 | 主程序处理 |
|---|---|---|
| 0 | 成功 | 登记资产，进入 Gate |
| 1 | lint 红灯 | 展示 lint 结果，等待人工 |
| 2 | 图片加载超时 | 重试 1 次，仍失败标 degraded |
| 3 | Chromium 启动失败 | 检查 Chromium 路径，标 job failed |
| 4 | FFmpeg 编码失败 | 重试 1 次，检查磁盘空间 |
| 5 | 超时 | kill worker，标 job failed |
| 6 | 输入 manifest 解析失败 | 标 job failed，检查 Video IR schema |

## 安全与隔离

- Worker 工作目录由主程序创建和清理。
- Worker 不直接访问 DB1 或 DB2。
- Worker 不直接访问 `shot_document` 或业务表。
- Worker 只能读写 `work_dir` 和 `output_dir` 内的文件。
- 密钥不传递给 worker；worker 不需要 API key。
- 外部工具路径（Chromium、FFmpeg）由 DB1 配置，主程序注入。

## 传输细节

最小协议 v0 只定义文件契约（request.json / progress.json / result.json）。传输方式在工程阶段确定：

- **Phase 1-3**：文件系统直接读写（主程序和 worker 同机）。
- **Phase 4+**：可选引入 stdin/stdout 流式传输或 HTTP 回调，但文件契约不变。

## Render Worker 启动参数示例

```bash
node render-hyperframes/index.js \
  --video-ir path/to/video_ir.json \
  --mode snapshot|preview|render \
  --output-dir path/to/output/{job_id}/ \
  --chromium-path "C:\Program Files\Chromium\chrome.exe" \
  --ffmpeg-path "tools\ffmpeg\ffmpeg.exe" \
  --work-dir path/to/work/ \
  --cancel-file path/to/cancel.txt \
  --heartbeat-interval 5
```

Chromium 路径和 FFmpeg 路径由 DB1 配置，主程序在启动 worker 时注入。

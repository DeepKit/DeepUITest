# 音频流水线

## 概述

将 Agent 生成的镜头脚本中的文本通过 TTS 合成为音频。**音频流水线是独立运行的**，通常在 Agent 工作流完成后即可开始，不需要等视频。输出可供音频平台候选包使用，也可作为视频流水线的输入。

当前自用版不启用 BGM。音频线先保证人声表达准确、时长稳定、时间戳可靠；BGM 作为后续可选混音通道保留接口，不进入第一条完整生产链路。

## 流水线阶段

```
shot_document (Agent 输出，可导出 shots.json 快照)
  │
  ▼
┌──────────────┐
│ 1. 音色映射    │  角色 → voice ID + 结构化参数
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 2. 批量 TTS   │  并行调用，记录精确时长（秒）
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 3. ASR 回传   │  获取逐字时间戳（秒）
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 4. 可选 BGM    │  默认关闭，仅在任务参数显式启用时进入混音
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 5. 音频合并    │  人声拼接，按需混入 BGM，加入静音间隔
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 6. 后处理      │  音量标准化、元数据、写入时长
└──────┬───────┘
       │
       ▼
   podcast.mp3 + timestamps.json
```

### 1. 音色映射

结构化情感控制，取代自由文本 instruction：

```typescript
interface VoiceConfig {
  voice: string;
  defaultEmotion: Emotion;
  defaultPace: Pace;
  defaultPitch: Pitch;
}

type Emotion = "calm" | "tense" | "sad" | "happy" | "angry" | "mysterious";
type Pace = "slow" | "normal" | "fast";
type Pitch = "low" | "normal" | "high";

const voiceMap: Record<string, VoiceConfig> = {
  "旁白": { voice: "cixingnansheng", defaultEmotion: "calm", defaultPace: "slow" },
  "张三": { voice: "voice_clone_001", defaultEmotion: "happy", defaultPace: "normal" },
  "李四": { voice: "voice_clone_002", defaultEmotion: "mysterious", defaultPace: "slow" },
};
```

枚举值映射为中文 instruction（保持简洁，TTS 模型对简短指令效果更稳定）：

```typescript
function buildInstruction(shot: Shot, config: VoiceConfig): string {
  const emotionMap = {
    calm: "平静沉稳", tense: "紧张急迫", sad: "低落伤感",
    happy: "欢快愉悦", angry: "愤怒激烈", mysterious: "神秘低沉",
  };
  const paceMap = { slow: "语速偏慢", normal: "正常语速", fast: "语速偏快" };
  return `${emotionMap[shot.audio.emotion || config.defaultEmotion]}，${paceMap[shot.audio.pace || config.defaultPace]}`;
}
```

### 2. 批量 TTS

```typescript
async function synthesizeShot(shot: Shot): Promise<TTSResult> {
  const config = voiceMap[shot.character || "旁白"];
  const instruction = buildInstruction(shot, config);

  // 括号转义：原文中的 () 有 TTS 内联指令语义，必须移除或替换
  const sanitizedText = shot.text.replace(/[()]/g, "，");

  const response = await stepClient.tts({
    model: "stepaudio-2.5-tts",
    input: sanitizedText,
    voice: config.voice,         // 注意：传 voice ID，不传 voice_label
    instruction,                 // 限 200 字符，枚举值映射的中文短指令
    response_format: "wav",
  });

  // response.status === 451 时自动改写并校验（见错误处理）
  const duration = measureDuration(response.audio);  // 返回值单位: 秒

  return {
    shot_id: shot.id,
    audio: response.audio,
    duration,  // 秒
    sample_rate: 24000,  // stepaudio-2.5-tts 默认 24kHz，非 44.1kHz
  };
}
```

> **TTS 参数限制**：`stepaudio-2.5-tts` 只支持 `voice`（预置音色 ID）+ `instruction`（情感控制，限 200 字符），不支持 `voice_label`。DeepFrames 的枚举映射策略确保 instruction 始终在 200 字符以内。

> **采样率注意**：TTS 默认输出 24kHz。混音工程前需统一重采样到项目工作采样率（48kHz），重采样操作记录在 audio manifest 的 `resample_from` / `resample_to` 字段中。

### TTS 451 闭环处理

TTS 451 发生在音频流水线内部，此时 Gate 2 QA 已经完成。因此音频线不得原地改写 `shot_document`，只能生成音频专用的 `tts_text_variant`：

1. 原始 `shot.audio.text` 触发 451。
2. 音频线生成 `tts_text_variant`，只用于 TTS 输入，不修改 `shot_document`。
3. 改写记录写入 `audio_manifest.tts_rewrite_log[]`，包含原文、改写文本、触发原因、相似度、审核状态。
4. 对 `tts_text_variant` 调用 TTS，并使用 ASR 回传文本与原始 shot 文本做语义相似度校验。
5. 相似度 ≥ 0.95：Gate 3a 可 `pass`，但记录 warning。
6. 0.85 ≤ 相似度 < 0.95：Gate 3a `warn`，展示给用户确认。
7. 相似度 < 0.85：Gate 3a `fail`，audio job 进入 `blocked_review`，由用户选择人工改写、跳过或回到 Agent 阶段。

```json
{
  "shot_id": "shot_023",
  "tts_text_variant": "改写后的 TTS 输入文本",
  "original_text": "原始 shot 文本",
  "reason": "tts_451",
  "similarity": 0.93,
  "gate3a_result": "warn",
  "human_review_status": "pending_review"
}
```

**并行策略**: 令牌桶控制，默认 5 路并发，监控 API 延迟动态调整。

**shot 级别 checkpoint**: 每完成一个 shot 的 TTS 即写入 `deepframes_job_step` 和 `deepframes_asset`，断点续跑时跳过已完成的。

### 3. ASR 逐字时间戳

对每个已生成的音频调用 ASR (`stepaudio-2.5-asr`)。**ASR 端点是 SSE 流式协议**（非一次性 JSON），走标准端点 `/v1` 而非 `/step_plan/v1`。

**ASR 调用流程**：
1. 音频 Base64 编码后发送到 `POST /v1/audio/asr/sse`
2. 设置 `enable_timestamp: true` 以获取逐字时间戳
3. 累积 Delta 事件中的 word-level 片段（增量返回）
4. Done 事件到达后，拼接为完整时间戳列表

**DeepFrames 内部处理**：ASR SSE 的增量 Delta 事件由 DeepFrames 的 ASR adapter 累积并转换为统一的 word-level 时间戳格式。下游（视频流水线、字幕同步）只消费最终拼接后的 `timestamps.json`，不感知 SSE 协议细节。

```json
{
  "shot_id": "shot_001",
  "words": [
    { "text": "夜色", "start": 0.0, "end": 0.42 },
    { "text": "笼罩着", "start": 0.42, "end": 0.88 },
    { "text": "古城", "start": 0.88, "end": 1.30 },
    { "text": "，", "start": 1.30, "end": 1.45 },
    { "text": "远处", "start": 1.45, "end": 1.80 },
    { "text": "传来", "start": 1.80, "end": 2.15 },
    { "text": "悠扬的", "start": 2.15, "end": 2.70 },
    { "text": "笛声", "start": 2.70, "end": 3.20 },
    { "text": "。", "start": 3.20, "end": 3.50 }
  ]
}
```

所有时间值单位为**秒**（ASR 原始输出为毫秒级，DeepFrames 统一转换）。`timestamps.json` 汇总所有 shot 的逐字时间戳，供视频流水线使用。
### 时间戳双坐标

音频 manifest 必须同时保存两种时间戳：

- `shot_local_start` / `shot_local_end`：相对当前 shot 的时间，便于返工单个 shot。
- `global_start` / `global_end`：相对整条候选音频的时间，供字幕和视频时间轴消费。

拼接或调整静音间隔后，重新生成 global timestamps，不修改原始 local timestamps。

### 4. 可选 BGM 通道

BGM 默认关闭。只有任务参数或生产配方显式启用时，才进入 BGM 匹配与混音；关闭时，音频合并阶段只处理人声、静音间隔、响度标准化和元数据。

**BGM 来源**:
- 免版权音乐库（按风格标签匹配）
- 未来可接入 AI 音乐生成

**混音规则**:

| 场景 | BGM 音量 | 人声音量 |
|---|---|---|
| 旁白叙述 | -20 dB | 0 dB |
| 角色对话 | -25 dB | 0 dB |
| 动作场景 | -15 dB | 0 dB |
| 场景切换 | 渐入/渐出 1 秒 | — |
| 章节开头 | 单独播放 3-5 秒 | — |

BGM 风格由风格预设控制：

| 预设 | BGM 风格 |
|---|---|
| 玄幻仙侠 | 古风器乐（古筝、箫） |
| 都市现代 | 轻电子、Lo-Fi |
| 历史武侠 | 古典民乐、鼓乐 |
| 悬疑推理 | 暗调钢琴、弦乐 |
| 言情青春 | 吉他、钢琴抒情 |

### 5. 音频合并

FFmpeg 按时间轴拼接所有 shot 音频。中间格式统一使用 WAV/PCM，避免 MP3 encoder padding 导致字幕和音轨累计漂移：

### 采样率与编码策略

音频中间链路默认使用 WAV/PCM，并在 manifest 中记录真实技术参数。

| 阶段 | 默认 | 说明 |
|---|---|---|
| TTS shot 输出 | WAV/PCM，采样率按 provider 返回记录 | 不强行假设 provider 恒定 44100 Hz |
| 混音工程 | 48000 Hz / 2ch / PCM16 优先 | 更贴近视频封装和 AAC 工作流 |
| 喜马拉雅候选包 | MP3，44100 Hz，128-192 kbps | 导出阶段转码 |
| 视频候选包音轨 | AAC，48000 Hz，192-320 kbps | 与 MP4 mux 对齐 |

如果 provider 返回 44100 Hz，可以在混音前统一重采样到项目采样率；重采样必须记录在 audio manifest 的 `resample_from` / `resample_to` 字段中。ASR timestamps 以秒为单位保存，不以 sample index 作为跨系统契约。
**静音间隔规则**:
- 同角色连续对话: 300ms
- 不同角色切换: 500ms
- 旁白与对话切换: 400ms
- 章节间: 1-2 秒

```bash
# 合并前先用 ffprobe 校验所有 shot 音频采样率/声道/编码一致；静音间隔使用同规格 silence segment
ffmpeg -f concat -safe 1 -i concat.txt -ar 48000 -ac 2 -c:a pcm_s16le output/raw.wav
```

### 6. 后处理

```bash
# 第一遍：测量响度（EBU R128），输出 JSON measurement
ffmpeg -i raw.wav -af "loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json" -f null - 2> loudnorm_pass1.json

# 第二遍：使用 measured_* 参数做线性校正（参数来自第一遍 JSON）
ffmpeg -i raw.wav -af "loudnorm=I=-16:TP=-1.5:LRA=11:measured_I=<input_i>:measured_TP=<input_tp>:measured_LRA=<input_lra>:measured_thresh=<input_thresh>:offset=<target_offset>:linear=true:print_format=json" normalized.wav

# 转为目标格式（音频平台）
ffmpeg -i normalized.wav -c:a libmp3lame -b:a 128k -ar 44100 final.mp3

# 转为目标格式（B站视频内嵌 AAC）
ffmpeg -i normalized.wav -c:a aac -b:a 192k -ar 48000 final_bili.aac

# 元数据写入
ffmpeg -i final.mp3 \
  -metadata title="第1章 - 初入江湖" \
  -metadata artist="DeepFrames" \
  -metadata album="小说名·有声书" \
  -metadata track="1" \
  chapter_01.mp3
```

**写入 audio manifest**: 精确测量的 `duration`、音轨 URI、timestamps URI、BGM 启用状态和合并后总时长写入 `audio_manifest` 与 `deepframes_asset`。音频流水线不原地改写 `shot_document`；如需保留修正信息，生成新的版本化资产或 manifest。

合并完成后必须校验 `output/raw.wav` 实际时长与**拼接计算时长**（所有 shot 实际 duration + silence gaps）偏差 ≤ 100ms，否则 Gate 3a 失败。这里的 100ms 是音频拼接工程一致性阈值，不是 Agent 预估时长阈值；TTS 实际时长与 `shot.audio.estimated_duration` 的差异记为估时偏差，进入 quality snapshot 作为黄灯提示或调参依据，不直接等同于拼接失败。

**输出文件**:
```
output/{job_id}/
├── audio/
│   ├── shots/           # 每个 shot 的独立音频
│   │   ├── shot_001.wav
│   │   ├── shot_002.wav
│   │   └── ...
│   ├── chapter_01.mp3       # 合并后完整音频
│   ├── timestamps.json      # 逐字时间戳
│   └── audio_manifest.json  # duration、音轨、timestamps 和校验信息
└── shot_document.json       # Agent 输出快照，只读引用，不原地改写
```

## 与视频流水线的关系

音频和视频是两条独立流水线，通过 asset store 中登记的 manifest 和只读快照关联；文件只是资产载体，不是状态真相：

```
音频流水线输出                    视频流水线消费
──────────────                  ──────────────
chapter_01.mp3        ──────→   视频音轨
audio_manifest.json   ──────→   帧数计算与音频资产引用
timestamps.json       ──────→   卡拉 OK 字幕
```

视频流水线只有在 `final-with-audio` 模式下要求这些文件存在；静默预览、估时预览、图片生成和模板检查可在没有音频资产时独立运行。

## 角色音色管理

自定义克隆流程：
1. 收集角色参考音频（3-10 秒）
2. 调用声音克隆 API 创建音色
3. 调用声音预览 API 验证效果
4. voice ID 写入音色映射表

## 注意事项

- 避免过短中文文本（< 5 字），易触发 451 内容审查
- 长文本分段合成后拼接，单次 TTS 输入建议 ≤ 500 字
- 克隆音色需确保样本质量，噪音过大会影响效果
- BGM 默认关闭；启用时需确认无版权问题，建议使用免版权音乐库
- 所有时间值统一为秒
